# 02.04 · URLSearchParams and Shareable Filter URLs

> [!info] [[02.00 Interactivity and Responsive Design|Lesson 2]] · Week 6 · Tasks COM-03, CORE-15 (UI) · Priority 🟡 Supporting
> **Builds on:** [[01.03 Query Strings and GET Parameters in PHP]] · [[02.01 Progressive Enhancement and Script Organisation]]
> **Used for:** the filter chips and sort controls on Explore, Exchange and My Garden.

## 1. Definitions
> [!note] Shareable URL
> A URL is **shareable** when it contains everything needed to rebuild the page: the search text, every filter, the sort order and the page number. Copy it, send it, open it tomorrow, and the same results appear.

> [!note] URLSearchParams
> **`URLSearchParams`** is a built-in JavaScript object for reading and changing the query string of a URL without cutting strings by hand.

## 2. Why it is used
The roadmap states the requirement: *"Filters build a GET query string so URLs are shareable, as the wireframes require."* Keeping the filter state in the address gives four things for free:
- **Sharing:** "look at these free succulents near Kurunegala" is a link.
- **The Back button** returns to the previous set of filters.
- **Reload** does not lose the filters.
- **The server does the filtering,** so the page works without JavaScript and, in stage B, the same parameters go straight into the query.

The alternative, hiding and showing cards with JavaScript, loses all four and cannot work once results come in pages of 12.

## 3. How it works
**Step 1, HTML only.** The filters are a form with `method="get"`. Submitting it puts every field in the address.

```php
<form method="get" action="<?= e(url('exchange.php')) ?>" data-filters>
  <label for="q">Search</label>
  <input id="q" type="search" name="q" value="<?= e($q) ?>">

  <fieldset>
    <legend>Type</legend>
    <label><input type="radio" name="type" value="" <?= $type === '' ? 'checked' : '' ?>> Any</label>
    <label><input type="radio" name="type" value="swap" <?= $type === 'swap' ? 'checked' : '' ?>> Swap</label>
    <label><input type="radio" name="type" value="free" <?= $type === 'free' ? 'checked' : '' ?>> Free</label>
  </fieldset>

  <label for="sort">Sort by</label>
  <select id="sort" name="sort">
    <option value="newest" <?= $sort === 'newest' ? 'selected' : '' ?>>Newest</option>
    <option value="nearest" <?= $sort === 'nearest' ? 'selected' : '' ?>>Nearest</option>
  </select>

  <button class="btn btn-primary" type="submit">Apply</button>
</form>
```
Result: `exchange.php?q=pothos&type=swap&sort=nearest`. PHP reads the values, validates them ([[01.03 Query Strings and GET Parameters in PHP]]) and prints the controls **already set** to match, so the form always shows the current state.

**Step 2, JavaScript.** Apply the filters as soon as one changes, and keep the address tidy.

## 4. Syntax
```js
const params = new URLSearchParams(window.location.search);   // from the current address

params.get('q');                 // 'pothos', or null if absent
params.has('type');              // true or false
params.set('sort', 'nearest');   // add or replace
params.append('tag', 'aroid');   // add another value with the same name
params.getAll('tag');            // every value of a repeated name
params.delete('page');           // remove
params.toString();               // 'q=pothos&type=swap&sort=nearest'

new URLSearchParams(new FormData(form));   // straight from a form's current values
```
It **encodes** values for you: a search for `ferns & mosses` becomes `q=ferns+%26+mosses`.

## 5. Example: apply on change
```js
const filterForm = document.querySelector('form[data-filters]');

if (filterForm) {
  filterForm.addEventListener('change', () => {
    const params = new URLSearchParams(new FormData(filterForm));

    for (const [key, value] of [...params]) {
      if (value === '') params.delete(key);     // leave empty filters out of the address
    }
    params.delete('page');                      // new filters start again at page 1

    const query = params.toString();
    window.location.assign(query ? `${filterForm.action}?${query}` : filterForm.action);
  });
}
```
`window.location.assign()` loads the new address, exactly as if the user had clicked Apply. The page is rebuilt by PHP with the new filters. With JavaScript off, the Apply button does the same job.

## 6. Active chips with a remove link
Above the results, each active filter appears as a chip that removes itself. PHP builds each chip's link from the current parameters minus one:

```php
<?php
// The current query string with one parameter taken out
function query_without($key)
{
    $params = $_GET;
    unset($params[$key], $params['page']);

    return $params ? '?' . http_build_query($params) : '';
}
?>
<?php if ($type !== ''): ?>
  <a class="chip is-selected" href="<?= e(url('exchange.php' . query_without('type'))) ?>">
    <?= e(listing_type($type)['label']) ?> <span aria-hidden="true">×</span>
    <span class="visually-hidden">Remove filter</span>
  </a>
<?php endif; ?>
```
A chip is a plain link. No JavaScript is needed to remove a filter.

## 7. Reload or not?
| | **Reload the page** (above) | **`fetch` and `history.pushState`** |
|---|---|---|
| How | `location.assign(newUrl)` | Fetch new results, replace part of the page, update the address by script |
| Code | A few lines | Much more: loading states, errors, focus, the Back button handled by hand |
| Server | Unchanged | Needs an endpoint that returns results alone |

The reloading version meets the requirement and stays within the stage F rule. The second is an optional refinement for later.

## 8. Common mistakes
- **Filtering in JavaScript by hiding cards.** The address does not change, nothing is shareable, and it fails with pagination.
- **Controls that do not reflect the address.** The URL says `type=swap` and the radio shows Any.
- **Building the query by joining strings.** `'?q=' + text` breaks on `&`, `#` and spaces.
- **Keeping `page=3` after a filter changes.** The new result may have one page.
- **Empty parameters in the address:** `?q=&type=&sort=`. Remove them.
- **Trusting the values.** `sort=whatever` must fall back to a default on the server. In stage B, never place a parameter into SQL directly: [[04.04 Search, Filters and Pagination]].
- **POST for a search.** It cannot be bookmarked, and Back asks to "resubmit the form".
- **A script that assumes the form exists** on every page. Check first.
