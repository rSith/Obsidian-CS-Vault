## What this lesson is about
The pages exist and look right. Now they need to **respond**: tabs switch, dialogs open, forms point out mistakes, filters update the address, a chosen photo appears before upload, and everything works on a phone.

One rule governs all of it in stage F:

> [!important] JavaScript in stage F is UI-only
> It changes what is **shown**. It saves nothing. Anything that changes data waits for stage B. And every form must still work as a plain HTML form when JavaScript is switched off.

## The project's JavaScript rules
From `CLAUDE.md`:
- Vanilla JavaScript only. No jQuery, no framework, no build step.
- Names in `camelCase`.
- Scripts load with `defer`.
- No inline `onclick` in the HTML.
- No `console.log` left behind.
- Three files: `app.js` (tabs, modals, toasts, navigation), `forms.js` (validation, upload preview), `filters.js` (chips, sort, query strings).

## The UI freeze
At the end of week 7 every page and every state S1–S6 matches its wireframe with mock data, passes the 375 / 768 / 1024 px check and shows no console errors. `develop` is merged into `main` and tagged `v0.5-ui`.
