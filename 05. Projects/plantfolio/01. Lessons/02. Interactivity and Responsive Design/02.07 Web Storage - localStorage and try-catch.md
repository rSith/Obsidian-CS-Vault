# 02.07 · Web Storage: localStorage and try-catch

> [!info] [[02.00 Interactivity and Responsive Design|Lesson 2]] · Week 7 · Task COM-07 (UI) · Priority 🟡 Supporting
> **Builds on:** [[02.01 Progressive Enhancement and Script Organisation]] · [[02.05 Sessions and Cookies]]
> **Used for:** the × on "How the exchange works" (Community page, Exchange tab), which hides the strip for good on that browser.

## 1. Definitions
> [!note] Web Storage
> **Web Storage** is a small key–value store that the browser keeps for each website. JavaScript can save text in it and read it back later. Two versions exist: **`localStorage`** keeps the data until it is deleted (closing the browser does not clear it), **`sessionStorage`** forgets it when the tab is closed.

> [!note] Key and value
> Every entry is a **key** (its name, e.g. `plantfolio.hide.exchange-steps`) and a **value**. Both are always **text**: saving the number `1` stores the string `"1"`.

> [!note] try … catch
> **`try { … } catch (error) { … }`** runs the code in `try`; if a line there throws an error, the script does not stop: it jumps to `catch` and carries on from there.

## 2. Why PlantFolio uses it
The Exchange tab shows a four-step strip, "How the exchange works". A member who has read it once can hide it with ×, and it should stay hidden next time. That choice:
- belongs to **one browser on one device**, not to the account;
- is **not important**: if it is lost, the strip simply shows again.

So it does not belong in the database (stage B would need a new column for a cosmetic choice) or in a cookie (a cookie is sent to the server with every request, and the server does not need it). `localStorage` is the right size of tool: the browser keeps it, the server never sees it.

**Rule of thumb:** browser storage only for *conveniences* (a hidden hint, a remembered tab, a draft). Anything that must be safe, shared between devices or seen by the server goes to the server ([[02.05 Sessions and Cookies]]).

## 3. How it works
1. The page prints the strip **visible**, with its × button `hidden`. Without JavaScript the strip always shows and there is no × that could not keep its promise.
2. `community.js` runs. It reads the key. If the value is `"1"`, it hides the strip.
3. It shows the × (`button.hidden = false`).
4. A click on × hides the strip and saves `"1"` under the key.
5. Next visit: step 2 finds `"1"` and hides the strip at once.

Why **try … catch**? Reading or writing `localStorage` can **throw an error**: in some private windows, when the user blocks site data, when the storage is full, or inside some embedded frames. Without `try`, that error would stop the whole script, and the filter panel on the same page would stop working too. With `try`, the worst case is that the strip shows again.

## 4. Syntax
```js
localStorage.setItem('key', 'value');   // save (text only)
localStorage.getItem('key');            // read: the text, or null if never saved
localStorage.removeItem('key');         // forget one entry
```

```js
try {
  // code that might throw
} catch (error) {
  // what to do instead; may be empty, with a comment saying why
}
```

## 5. Example in PlantFolio
```php
<?php // community.php: the strip, with an × that only JavaScript shows ?>
<section class="exchange-steps" aria-labelledby="steps-title" data-dismissible="exchange-steps">
  <div class="exchange-steps-head">
    <h2 class="label exchange-steps-title" id="steps-title">How the exchange works</h2>
    <button type="button" class="icon-btn" data-dismiss aria-label="Hide how the exchange works" hidden><?= icon('x') ?></button>
  </div>
  <ol class="exchange-steps-list">…</ol>
</section>
```

```js
// community.js: works for any section with data-dismissible="<name>"
document.querySelectorAll('[data-dismissible]').forEach((section) => {
  const key = 'plantfolio.hide.' + section.dataset.dismissible;
  const button = section.querySelector('[data-dismiss]');

  let hidden = false;
  try {
    hidden = localStorage.getItem(key) === '1';
  } catch (error) {
    hidden = false;            // storage blocked: just show the strip
  }

  section.hidden = hidden;
  button.hidden = false;       // only now can the choice be remembered

  button.addEventListener('click', () => {
    section.hidden = true;
    try {
      localStorage.setItem(key, '1');
    } catch (error) {
      // hidden for this visit only; it comes back next time
    }
  });
});
```
The key starts with `plantfolio.` so it can never clash with another script on the same site.

## 6. Common mistakes
- **No try … catch.** Works on your laptop, breaks the whole page in a private window.
- **Expecting numbers or true/false back.** `getItem()` returns text: compare with `'1'`, not `1` or `true`. Objects need `JSON.stringify()` to save and `JSON.parse()` to read.
- **Storing secrets or important data.** Any script on the page can read `localStorage`, the user can delete it, and it never reaches the server.
- **Showing a control that cannot work.** The × is `hidden` in the HTML and shown by the script, so a page without JavaScript never offers a button that does nothing.
- **Forgetting it is per browser.** Hiding the strip on the laptop does not hide it on the phone. Here that is fine; for a real setting it is not.

## 7. Exam and viva focus
- **localStorage vs sessionStorage vs cookies:** how long each lasts, and which one is sent to the server (only cookies).
- **Why not the database?** It is a per-device convenience; losing it costs nothing.
- **Why try … catch?** Storage access can throw (private mode, blocked data, full storage); one failure must not stop the other scripts on the page.
- **Viva:** "I hid the strip on my phone; why does it show on my laptop?" · "What happens in a private window?" · "Where is this value stored, and who can see it?"
