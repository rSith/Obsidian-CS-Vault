# 02.99 · Lesson Summary: Interactivity and Responsive Design

> [!abstract] Back to [[02.00 Interactivity and Responsive Design]] · Progress: [[PlantFolio Week 05 - Pages D and Interactivity A]] · [[PlantFolio Week 06 - Interactivity B and Responsive Pass]] · [[PlantFolio Week 07 - AI Pages and UI Freeze]]

## Must know
- **Progressive enhancement:** HTML works alone; CSS makes it look right; JavaScript makes it convenient. Forms POST normally first.
- **Stage F JavaScript is UI-only.** It saves nothing.
- **Scripts load with `defer`:** downloaded in parallel, run after the HTML is read, in order.
- **Hooks are `data-*` attributes** (`data-modal-open`), read with `dataset`. Classes are for looks; `.is-active` and ARIA attributes are for state. **No inline `onclick`.**
- **`<button type="button">`** for actions. A button with no type submits its form.
- **Tabs:** links first; then `role="tablist"`, `tab`, `tabpanel`, `aria-selected`, arrow keys.
- **Modals: `<dialog>` with `showModal()`** gives the backdrop, the focus trap, Esc and focus return. A backdrop click arrives with the dialog as its target.
- **A destructive dialog names the item:** "Delete Monty?"
- **Toasts:** `role="status"`, `textContent`, a timer that is cleared before a new one starts, an Undo for reversible actions. Never for errors.
- **Focus:** into what opens, back to the opener on close, trapped while modal, always visible.
- **Validation in the browser is for people; on the server it is for safety.** Both, always, with the same rules.
- **Three layers:** HTML attributes → the Constraint Validation API (`validity`, `noValidate` set by script) → server-only checks.
- **Errors:** beside the field, in words, on blur and on submit; `aria-invalid` and `aria-describedby`; focus the first one.
- **Debounce** a live check. "Available" is a hint; the `UNIQUE` rule decides.
- **Filters live in the URL** (a GET form). `URLSearchParams` reads and builds query strings and encodes values. Reset `page` when a filter changes.
- **Uploads:** `enctype="multipart/form-data"`; `accept` and `capture`; check size and type in the browser for speed, on the server for safety; a dropped file is placed into the real input.
- **Mobile first:** base styles for the phone, `min-width: 768px` and `1024px` on top.
- **Phone patterns:** bottom bar, bottom sheet for filters, table → stacked cards with `attr(data-label)`, floating button, 44 px targets, 16 px inputs, `dvh`, safe-area padding.
- **Test on a real phone;** `base_url` must be the computer's network address for that.

## Key code
```js
document.addEventListener('click', (event) => {
  const opener = event.target.closest('[data-modal-open]');
  if (opener) document.getElementById(opener.dataset.modalOpen).showModal();
});

form.noValidate = true;
if (!input.validity.valid) { event.preventDefault(); input.focus(); }

const params = new URLSearchParams(new FormData(filterForm));
params.delete('page');
window.location.assign(`${filterForm.action}?${params}`);

input.files = event.dataTransfer.files;
```
```css
@media (min-width: 768px) { .bottom-bar { display: none; } }
.stack-table td::before { content: attr(data-label); }
.modal::backdrop { background: rgba(43, 43, 40, 0.5); }
```

## Important comparisons
| `defer` | `async` |
|---|---|
| Runs after the HTML, in order | Runs when it arrives, any order |

| Client-side validation | Server-side validation |
|---|---|
| Fast feedback; can be bypassed | The real check; always required |

| Modal | Toast |
|---|---|
| Blocks until answered | Passes by itself |
| Decisions, small tasks | Confirmations, Undo |

| Confirmation dialog | Undo |
|---|---|
| Before a destructive, permanent action | After a small, reversible one |

| Mobile first | Desktop first |
|---|---|
| Base = phone, `min-width` adds | Base = desktop, `max-width` removes |

| `vh` | `dvh` |
|---|---|
| Fixed viewport height | Follows the phone's address bar |
