# 02.05 · Upload Preview with the File API

> [!info] [[02.00 Interactivity and Responsive Design|Lesson 2]] · Week 6 · Task CORE-16 (UI) · Priority 🟡 Supporting
> **Builds on:** [[00.05 HTML Forms]] · [[07.03 DOM Manipulation and Events]]
> **Used for:** the photo area on Add / Edit Plant, Plant Identifier and Health Check: preview, drag-and-drop, and an early size and type check.

## 1. Definitions
| Term | Meaning |
|---|---|
| **File API** | The browser features that let a page read files the user has chosen |
| **`File`** | An object describing one chosen file: `name`, `size` (bytes), `type` (MIME type) |
| **`FileReader`** | An object that reads a file's contents into memory |
| **Object URL** | A temporary address for a file held in memory, made by `URL.createObjectURL()` |
| **MIME type** | A label for a file's format: `image/jpeg`, `image/png` |

## 2. Why it is used
- **Confidence.** The user sees the photo they picked before anything is uploaded, and can change it.
- **Speed.** A 12 MB photo is refused in the browser at once, not after a long upload.
- **Phones.** The right attributes open the camera directly.

> [!warning] These checks are for convenience, not security
> A browser check can be bypassed, and the `type` it reports is only a guess from the file's name. The server checks the real content of every upload in stage B: [[04.02 Secure File Uploads in PHP]].

## 3. How it works: the input
```html
<form method="post" action="plant-form.php" enctype="multipart/form-data">
  <label class="upload-zone" for="photo" data-upload-zone>
    <span>Drop a photo here, or tap to choose</span>
    <input class="visually-hidden" id="photo" name="photo" type="file"
           accept="image/jpeg,image/png" capture="environment" aria-describedby="photo-error">
  </label>
  <p class="field-error" id="photo-error"></p>
  <img id="photo-preview" alt="Preview of the chosen photo" hidden>
</form>
```
| Attribute | Does |
|---|---|
| `type="file"` | The file picker |
| `accept="image/jpeg,image/png"` | Greys out other files in the picker. A hint only. |
| `capture="environment"` | On a phone, opens the **rear camera** directly |
| `enctype="multipart/form-data"` on the form | **Required.** Without it the file is not sent at all. |

The drop zone is a **`<label>`** for the input. Clicking or tapping it opens the picker, and the input stays reachable by keyboard, with no JavaScript.

## 4. Syntax
```js
const file = input.files[0];        // the first chosen file, or undefined
file.name;                          // 'monty.jpg'
file.size;                          // bytes: 5 MB = 5 * 1024 * 1024
file.type;                          // 'image/jpeg'

// Way 1: FileReader, named in the roadmap
const reader = new FileReader();
reader.addEventListener('load', () => { preview.src = reader.result; });
reader.readAsDataURL(file);         // reads the file as a long text address (a data URL)

// Way 2: an object URL, lighter on memory
preview.src = URL.createObjectURL(file);
URL.revokeObjectURL(preview.src);   // later, when the preview is replaced
```
`FileReader` is **asynchronous**: `readAsDataURL` returns at once, and the result arrives in the `load` event.

## 5. Example: check, preview, drag-and-drop
```js
const MAX_BYTES = 5 * 1024 * 1024;
const ALLOWED_TYPES = ['image/jpeg', 'image/png'];

const zone = document.querySelector('[data-upload-zone]');
const input = document.querySelector('#photo');
const preview = document.querySelector('#photo-preview');
const error = document.querySelector('#photo-error');

function problemWith(file) {
  if (!ALLOWED_TYPES.includes(file.type)) return 'Choose a JPG or PNG photo.';
  if (file.size > MAX_BYTES) return 'That photo is larger than 5 MB. Choose a smaller one.';
  return '';
}

function handleFile() {
  const file = input.files[0];
  if (!file) return;

  const problem = problemWith(file);
  error.textContent = problem;
  if (problem) {
    input.value = '';                 // forget the rejected file
    preview.hidden = true;
    return;
  }

  const reader = new FileReader();
  reader.addEventListener('load', () => {
    preview.src = reader.result;
    preview.hidden = false;
  });
  reader.readAsDataURL(file);
}

input.addEventListener('change', handleFile);

// Drag-and-drop
['dragenter', 'dragover'].forEach((type) => {
  zone.addEventListener(type, (event) => {
    event.preventDefault();           // without this the browser will not allow a drop
    zone.classList.add('is-dragover');
  });
});

zone.addEventListener('dragleave', () => zone.classList.remove('is-dragover'));

zone.addEventListener('drop', (event) => {
  event.preventDefault();             // stop the browser opening the file in the tab
  zone.classList.remove('is-dragover');

  input.files = event.dataTransfer.files;   // hand the dropped file to the real input
  handleFile();
});
```
The key line is `input.files = event.dataTransfer.files`. The dropped file is placed **into the ordinary file input**, so the form submits it the normal way. Dragging and choosing end in the same place, and the server needs one piece of code.

## 6. The limits must agree
The same three numbers appear in several places:

| Rule | Browser | Server (stage B) | Config |
|---|---|---|---|
| JPG or PNG only | `accept`, `ALLOWED_TYPES` | `finfo` check | |
| At most 5 MB | `MAX_BYTES` | size check | `max_upload_mb` |
| Resized to 1600 px | | image resize | `max_image_px` |

If the browser allows 10 MB and the server 5 MB, the user uploads for a minute and is then refused. Keep them equal. PHP itself also has limits (`upload_max_filesize` and `post_max_size` in `php.ini`) that must not be lower than the project's.

## 7. Common mistakes
- **No `enctype="multipart/form-data"`.** The most common reason "the file does not arrive".
- **Trusting `file.type` or `accept`** as a security check.
- **Megabytes written wrongly.** 5 MB is `5 * 1024 * 1024` bytes, not `5000`.
- **No `preventDefault()` on `dragover`.** The `drop` event then never fires.
- **A drop zone made of a `div` with a click handler.** Keyboard users cannot use it.
- **Uploading with `fetch` on drop** and leaving the form's input empty. Two code paths, and one works without JavaScript.
- **Not clearing a rejected file.** It is still submitted with the form.
- **A preview with no `alt`.**
- **Different limits in the browser and on the server.**
- **Forgetting the phone.** There is no drag-and-drop on a phone; the tap-to-choose path must be complete in itself.
- **Reading very large files into memory** with `FileReader` when an object URL would do.
