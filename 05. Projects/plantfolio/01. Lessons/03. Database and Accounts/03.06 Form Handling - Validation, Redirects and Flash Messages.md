# 03.06 · Form Handling: Validation, Redirects and Flash Messages

> [!info] [[03.00 Database and Accounts|Lesson 3]] · Week 8 · Tasks CORE-07, CORE-26 · Priority 🔴 Core
> **Builds on:** [[02.03 Client-Side Form Validation]] · [[03.05 CSRF Tokens]] · [[03.02 PDO and Prepared Statements]]
> **Used for:** every form in the project. Registration is the first and the pattern for the rest.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Server-side validation** | PHP checking every submitted value against the rules, whatever the browser did |
| **Post/Redirect/Get (PRG)** | After a successful POST, the server answers with a redirect, and the browser loads the next page with GET |
| **Flash message** | A message stored in the session, shown on the next page once, then deleted |
| **Repopulating** | Putting the user's own input back into the form when it has errors |

## 2. Why it is used
- **The browser cannot be trusted.** JavaScript can be switched off and requests can be sent by hand. The server is the only place a rule can really be enforced.
- **A refresh must not repeat the action.** Without PRG, pressing F5 after "Add plant" adds the plant again, and the browser shows a "resubmit the form?" warning.
- **The user needs to be told what happened,** on the page they land on after the redirect.

## 3. How it works: one file, two requests
```text
GET  register.php            → show the empty form
POST register.php            → check token → validate
          ├─ errors          → show the form again, with messages and the user's input
          └─ valid           → save → flash message → redirect ──▶ GET dashboard.php (shows the message)
```

## 4. Syntax: the pieces
```php
<?php
// Is this a submission?
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // …handle it
}

// Read and clean
$email = trim((string) ($_POST['email'] ?? ''));

// Common checks
$errors = [];
if ($email === '') {
    $errors['email'] = 'Enter your email address.';
} elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors['email'] = 'Enter a valid email address, like name@example.com.';
}
if (mb_strlen($username) < 3 || mb_strlen($username) > 20) {
    $errors['username'] = 'Use 3 to 20 characters.';
}

// Redirect (PRG)
header('Location: ' . url('dashboard.php'), true, 303);
exit;
```
- **`mb_strlen`** counts characters. `strlen` counts bytes, which is wrong for Sinhala, Tamil and emoji.
- **`$errors` is keyed by field name,** so each message can be printed beside its field.
- **303 See Other** tells the browser to fetch the new address with GET.

## 5. Flash messages
```php
<?php
// includes/flash.php

function flash_set(string $message, string $type = 'success'): void
{
    $_SESSION['flash'] = ['message' => $message, 'type' => $type];
}

/** Returns the waiting message and removes it, so it is shown once. */
function flash_get(): ?array
{
    $flash = $_SESSION['flash'] ?? null;
    unset($_SESSION['flash']);

    return $flash;
}
```
The header prints it if there is one, using the toast or alert component. The message survives the redirect because it is in the session, and disappears after being shown because `flash_get()` deletes it.

## 6. Example: registration from top to bottom
```php
<?php
require_once __DIR__ . '/../includes/helpers.php';
require_once __DIR__ . '/../includes/db.php';
require_once __DIR__ . '/../includes/auth.php';
require_once __DIR__ . '/../includes/flash.php';

$errors = [];
$old = ['username' => '', 'email' => '', 'full_name' => ''];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    csrf_verify();

    // 1. Read
    $old['username']  = strtolower(trim((string) ($_POST['username'] ?? '')));
    $old['email']     = trim((string) ($_POST['email'] ?? ''));
    $old['full_name'] = trim((string) ($_POST['full_name'] ?? ''));
    $password         = (string) ($_POST['password'] ?? '');          // not trimmed

    // 2. Validate: the same rules as the browser, enforced here
    if (!preg_match('/^[a-z0-9._]{3,20}$/', $old['username'])) {
        $errors['username'] = 'Use 3 to 20 lowercase letters, numbers, dots or underscores.';
    }
    if (!filter_var($old['email'], FILTER_VALIDATE_EMAIL)) {
        $errors['email'] = 'Enter a valid email address.';
    }
    if ($old['full_name'] === '' || mb_strlen($old['full_name']) > 100) {
        $errors['full_name'] = 'Enter your name.';
    }
    if (strlen($password) < 8) {
        $errors['password'] = 'Use at least 8 characters.';
    }

    // 3. Save
    if (!$errors) {
        try {
            $stmt = db()->prepare('INSERT INTO users (username, email, password_hash, full_name)
                                   VALUES (:username, :email, :hash, :full_name)');
            $stmt->execute([
                'username'  => $old['username'],
                'email'     => $old['email'],
                'hash'      => password_hash($password, PASSWORD_DEFAULT),
                'full_name' => $old['full_name'],
            ]);

            // 4. Log in, flash, redirect
            session_regenerate_id(true);
            $_SESSION['user_id'] = (int) db()->lastInsertId();
            flash_set('Welcome to PlantFolio. Add your first plant to get started.');

            header('Location: ' . url('dashboard.php'), true, 303);
            exit;
        } catch (PDOException $error) {
            if ($error->getCode() !== '23000') {
                throw $error;                                         // not a duplicate: a real problem
            }
            $errors['username'] = 'That username or email is already in use.';
        }
    }
}

$page_title = 'Sign up';
include __DIR__ . '/../includes/header.php';
?>
<form method="post" action="<?= e(url('register.php')) ?>" data-validate>
  <?= csrf_field() ?>

  <div class="field">
    <label class="field-label" for="username">Username</label>
    <input class="input" id="username" name="username" value="<?= e($old['username']) ?>"
           required minlength="3" maxlength="20" pattern="[a-z0-9._]+"
           aria-describedby="username-error" <?= isset($errors['username']) ? 'aria-invalid="true"' : '' ?>>
    <p class="field-error" id="username-error"><?= e($errors['username'] ?? '') ?></p>
  </div>

  <!-- email, full name and password fields follow the same pattern -->

  <button class="btn btn-primary" type="submit">Create account</button>
</form>
<?php include __DIR__ . '/../includes/footer.php'; ?>
```
What to notice:
- **All the logic is above the header include.** The redirect happens before any output.
- **The duplicate check is the database's `UNIQUE` rule,** caught as error code `23000`. Asking "is it taken?" first and then inserting leaves a gap in which someone else can take the name.
- **The form is repopulated** with `e($old[…])`. **The password field is not**: never send a password back.
- **The same markup works with the browser script.** `aria-invalid` and the `.field-error` element are the ones [[02.03 Client-Side Form Validation]] fills. The server just fills them first.

## 7. Validate, then escape: two different jobs
| | **Validation** | **Escaping** |
|---|---|---|
| When | On input | On output |
| Question | Is this value acceptable? | How do I print this value safely? |
| Result | Accept or reject | The same value, represented safely |

A valid bio can still contain `<`. It is stored as typed and escaped by `e()` when printed. Do not strip characters "to be safe": that damages legitimate text and gives a false feeling of security.

## 8. Common mistakes
- **Only client-side validation.**
- **Rules that differ** between browser and server.
- **No redirect after success.** Refresh repeats the insert.
- **Redirecting after an error.** The messages and the user's input are lost. Re-show the form in the same request.
- **Not repopulating.** One wrong field and the user retypes six.
- **Repopulating the password.**
- **`strlen` on user text.**
- **Trimming or lower-casing a password.**
- **A check-then-insert for uniqueness** with no `UNIQUE` constraint behind it.
- **Catching every exception as "duplicate".** Check the code.
- **Forgetting `exit` after the redirect.**
- **Showing the raw database error** to the user.
- **Accepting extra fields.** Read only the fields you expect. Never loop over `$_POST` into a query: a visitor could add `failed_logins` or `user_id`.

## 9. Exam and viva focus
- **Why validate on the server when the browser already does?**
- **Describe the Post/Redirect/Get pattern** and the problem it solves.
- **What is a flash message, and where is it stored?**
- **Validation vs sanitisation vs escaping.**
- **HTTP status codes 302, 303, 400, 403, 405.**
- **Why let the database enforce uniqueness?** A race condition between two requests.
- **Mass assignment:** accepting whatever fields a request contains.
