# 03.99 · Lesson Summary: Database and Accounts

> [!abstract] Back to [[03.00 Database and Accounts]] · Progress: [[PlantFolio Week 08 - Database, Accounts and Sessions]]

## Must know
- **Schema:** InnoDB (foreign keys, transactions), **utf8mb4** (all scripts and emoji), re-runnable (`DROP TABLE IF EXISTS` first).
- **Constraints are the last line of defence:** `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY`.
- **`ON DELETE`:** `CASCADE` deletes children, `SET NULL` keeps them unlinked, `RESTRICT` refuses. Each relationship needs a decision.
- **XAMPP's "MySQL" is MariaDB.**
- **PDO:** one connection; `ERRMODE_EXCEPTION`; `FETCH_ASSOC`; **`EMULATE_PREPARES` off**; `charset=utf8mb4`.
- **Prepared statement:** SQL with placeholders first, values separately. A value can never become SQL.
- **Placeholders are for values only.** Column names and sort directions come from a whitelist; `LIMIT` needs `PARAM_INT`.
- **Transaction:** several queries succeed together or are all rolled back.
- **Passwords are hashed, not encrypted:** `password_hash()` to store, `password_verify()` to check. Salted, slow, one-way. Never MD5 or SHA.
- **One generic login error.** **Lock for 15 minutes after 5 failures.**
- **Session:** data on the server, a random ID in a cookie. Store only `user_id`.
- **`session_regenerate_id(true)` at login** defeats session fixation. Logout empties, removes the cookie and destroys.
- **Cookie flags:** `HttpOnly`, `Secure`, `SameSite=Lax`.
- **`session_start()` and `header()` before any output; `exit` after every redirect.**
- **CSRF:** another site makes the browser send a request with the user's cookie. Defence: a random per-session token in every POST form, checked first with `hash_equals()`. **A GET never changes data.**
- **Form handling:** read → validate on the server → on errors re-show with the user's input → on success save, flash, **redirect (PRG)**.
- **Validate on input, escape on output.** Let the `UNIQUE` rule decide duplicates (error code `23000`).
- **Authentication ≠ authorisation.** The user ID comes from the **session**, and every private query includes `AND user_id = :user_id`.
- **Someone else's private item answers 404,** the same as one that does not exist.

```php
$stmt->execute(['id' => $id, 'user_id' => $current_user['id']]);

```

## Important comparisons
| Hashing | Encryption |
|---|---|
| One-way | Reversible with a key |
| Passwords | Data to be read again |

| Authentication | Authorisation |
|---|---|
| Who are you? | May you do this? |
| Login | Checked on every request |

| Session | Cookie |
|---|---|
| Data on the server | Data in the browser |

| CSRF | XSS |
|---|---|
| A forged request from another site | A script injected into your own page |
| Token on every POST | Escape every output |

| Validation | Escaping |
|---|---|
| On input: accept or reject | On output: represent safely |

| `CASCADE` | `SET NULL` | `RESTRICT` |
|---|---|---|
| Children deleted | Children kept, unlinked | Delete refused |

| 403 | 404 |
|---|---|
| Exists, not allowed | Nothing here (used for private items) |
