# 03.04 · PHP Sessions and Login State

> [!info] [[03.00 Database and Accounts|Lesson 3]] · Week 8 · Tasks CORE-09, CORE-10 · Priority 🔴 Core
> **Parent concept:** [[02.05 Sessions and Cookies]], which explains what sessions and cookies are. This note covers how PlantFolio uses them in PHP.
> **Used for:** staying logged in between pages, `require_login()`, and logout.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Session** | Data the **server** keeps about one visitor between requests |
| **Session ID** | A long random code that identifies one session |
| **Session cookie** | The cookie that carries the session ID in the browser. PHP names it `PHPSESSID`. |
| **`$_SESSION`** | The PHP array holding the current visitor's session data |
| **Session fixation** | An attack where the victim is made to use a session ID the attacker already knows |
| **Session hijacking** | Stealing a valid session ID to act as that user |

## 2. Why it is used
Every request starts from nothing ([[00.01 How a PHP Page Is Served]]). After a correct password, something has to tell the *next* page "this is still Nimali". The session does that. Without it, a member would have to send their password with every click.

## 3. How it works
```text
1. Login succeeds. PHP creates a session and stores  user_id = 1  on the server.
2. PHP sends the browser a cookie:  PHPSESSID=k3f9…   (only the random ID, no data)
3. Every later request carries that cookie automatically.
4. session_start() reads the ID, finds the stored data and fills $_SESSION.
5. The page reads $_SESSION['user_id'] and knows who is asking.
```
The **data stays on the server**. The browser holds only the key. Whoever holds the key *is* that user, which is why the key must be protected.

## 4. Syntax
```php
<?php
session_start();                       // before any output, on every page that uses the session

$_SESSION['user_id'] = 1;              // store
$id = $_SESSION['user_id'] ?? null;    // read
unset($_SESSION['flash']);             // remove one item

session_regenerate_id(true);           // new session ID; the old one stops working
session_destroy();                     // end the session
```

## 5. Example: the three moments
### Starting the session safely
```php
<?php
// includes/auth.php, loaded at the top of every page

session_set_cookie_params([
    'httponly' => true,                              // JavaScript cannot read the cookie
    'samesite' => 'Lax',                             // not sent with most cross-site requests
    'secure'   => config('app_env') === 'production' // HTTPS only, once the site has HTTPS
]);
session_start();
```
| Flag | Protects against |
|---|---|
| `HttpOnly` | A script injected by XSS reading the session cookie |
| `Secure` | The cookie travelling over plain HTTP, where it can be seen |
| `SameSite=Lax` | The cookie being sent with requests started by another site: [[03.05 CSRF Tokens]] |

### Logging in
```php
<?php
$result = attempt_login($email, $password);          // see the password note

if ($result['ok']) {
    session_regenerate_id(true);                     // rule from CLAUDE.md
    $_SESSION['user_id'] = $result['user_id'];

    header('Location: ' . url('dashboard.php'));
    exit;
}
```
**Why regenerate?** If an attacker tricked the victim into using a session ID the attacker chose, that ID would now be a logged-in session. Issuing a fresh ID at login makes the old one worthless. That defeats **session fixation**.

### Protecting a page, and knowing the user
```php
<?php
function current_user(): ?array
{
    if (empty($_SESSION['user_id'])) {
        return null;
    }

    $stmt = db()->prepare('SELECT id, username, full_name, email, location, avatar, created_at
                           FROM users WHERE id = :id');
    $stmt->execute(['id' => $_SESSION['user_id']]);

    return $stmt->fetch() ?: null;
}

function require_login(): array
{
    $user = current_user();

    if ($user === null) {
        header('Location: ' . url('login.php'));
        exit;                                        // stop: nothing below may run
    }

    return $user;
}
```
```php
<?php
// At the top of a private page such as garden.php
require_once __DIR__ . '/../includes/helpers.php';
require_once __DIR__ . '/../includes/db.php';
require_once __DIR__ . '/../includes/auth.php';

$current_user = require_login();
```
`$current_user` now comes from the database and has the same keys the mock had. The session stores **only the user's ID**; the row is read fresh on each request, so a changed name or a deleted account takes effect at once.

### Logging out
```php
<?php
// logout.php: reached by a POST form with a CSRF token, not by a link
$_SESSION = [];                                                  // empty the data

$params = session_get_cookie_params();
setcookie(session_name(), '', time() - 3600, $params['path']);   // tell the browser to drop the cookie

session_destroy();                                               // delete it on the server

header('Location: ' . url(''));
exit;
```

## 6. Two rules that cause most bugs
> [!warning] `session_start()` and `header()` must run before any output
> Cookies and redirects are sent in the response **headers**, which go out before the page body. One character of output first, even a blank line before `<?php`, and they fail with "headers already sent". Logic first, HTML after.

> [!warning] Always `exit` after a redirect
> `header('Location: …')` only *asks* the browser to go elsewhere. PHP keeps running the rest of the file, and the protected content is still produced and sent. `exit` stops it.

## 7. Common mistakes
- **No `session_regenerate_id(true)` at login.**
- **Forgetting `exit` after `header('Location: …')`.** A private page is then sent to people who are not logged in.
- **Output before `session_start()`.**
- **Storing the whole user row, or the password,** in the session.
- **Trusting a user ID from a form field or the URL** instead of the session.
- **Logout as a plain link.** Another site could log a user out with an image tag. Use a POST form with a token.
- **Logout that only redirects.** The session is still alive and the Back button shows private pages.
- **A redirect target taken from the URL unchecked** (`login.php?next=https://evil.example`). An **open redirect**. Accept only local paths.
- **`require_login()` on some private pages and forgotten on one.** Check every page in the Access column of the page table.
- **Thinking a logged-in user may do anything.** Logging in says who you are, not what is yours: [[03.07 Access Control and Ownership Checks]].
