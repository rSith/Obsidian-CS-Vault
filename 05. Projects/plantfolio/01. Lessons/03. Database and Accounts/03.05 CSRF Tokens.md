# 03.05 · CSRF Tokens

> [!info] [[03.00 Database and Accounts|Lesson 3]] · Week 8 · Task CORE-11 · Priority 🔴 Core
> **Builds on:** [[03.04 PHP Sessions and Login State]] · [[13.01 Web Security and Major Threats]]
> **Used for:** every form that changes something: log in, add a plant, delete, mark done, express interest, rate, log out.

## 1. Definitions
> [!note] CSRF
> **Cross-site request forgery** is an attack where another website makes a logged-in user's browser send a request to your site without the user intending it. The request arrives with the user's session cookie, so your site believes the user made it.

> [!note] CSRF token
> A **CSRF token** is a secret random value that the site puts in each of its own forms and checks on every submission. Another site cannot know it, so it cannot build a valid request.

## 2. Why it is used
Browsers attach a site's cookies to **every** request to that site, whichever page started the request. So:

```html
<!-- On evil.example, visited by Nimali while she is logged in to PlantFolio -->
<form action="https://plantfolio.example/plant-delete.php" method="post" id="f">
  <input type="hidden" name="id" value="42">
</form>
<script>document.getElementById('f').submit();</script>
```
The browser sends the POST **with Nimali's session cookie**. Without a defence, PlantFolio deletes plant 42. Nimali saw nothing and clicked nothing.

The rule in `CLAUDE.md`: *"a per-session token in every POST form, checked on every POST."*

## 3. How it works
```text
1. On first use, the server makes a random token and keeps it in the session.
2. Every form the server prints contains it in a hidden field.
3. On every POST, the server compares the submitted token with the one in the session.
4. Missing or different → reject the request.
```
The attacker's page can make the browser *send* a request, but it cannot *read* PlantFolio's pages, so it never learns the token. Its forged form has none, and step 3 rejects it.

## 4. Syntax: three helpers
```php
<?php
// includes/auth.php

/** The visitor's token, created the first time it is needed. */
function csrf_token(): string
{
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));    // 64 unpredictable characters
    }

    return $_SESSION['csrf_token'];
}

/** The hidden field to print inside every POST form. */
function csrf_field(): string
{
    return '<input type="hidden" name="csrf_token" value="' . e(csrf_token()) . '">';
}

/** Stop the request unless the submitted token matches. Call this first in every POST handler. */
function csrf_verify(): void
{
    $sent = $_POST['csrf_token'] ?? '';

    if (!is_string($sent) || !hash_equals(csrf_token(), $sent)) {
        http_response_code(403);
        exit('This form has expired. Go back, reload the page and try again.');
    }
}
```
| Function | Why this one |
|---|---|
| `random_bytes(32)` | Cryptographically secure randomness. `rand()` and `uniqid()` are predictable. |
| `bin2hex()` | Turns the raw bytes into text that fits in a form field |
| `hash_equals()` | Compares in constant time, so the time taken reveals nothing about the token |

## 5. Example: a protected form and its handler
```php
<form method="post" action="<?= e(url('plant-delete.php')) ?>">
  <?= csrf_field() ?>
  <input type="hidden" name="id" value="<?= e($plant['id']) ?>">
  <button class="btn btn-danger" type="submit">Delete <?= e($plant['nickname']) ?></button>
</form>
```
`csrf_field()` is printed without `e()` because it returns HTML the project built, with its own value already escaped. It is the same reasoning as `icon()`.

```php
<?php
// plant-delete.php
require_once __DIR__ . '/../includes/helpers.php';
require_once __DIR__ . '/../includes/db.php';
require_once __DIR__ . '/../includes/auth.php';

$current_user = require_login();

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);                 // this address only accepts POST
    exit;
}

csrf_verify();                               // 1. is this our own form?

$id = filter_input(INPUT_POST, 'id', FILTER_VALIDATE_INT);

$stmt = db()->prepare('DELETE FROM plants WHERE id = :id AND user_id = :user_id');   // 2. is it theirs?
$stmt->execute(['id' => $id, 'user_id' => $current_user['id']]);

header('Location: ' . url('garden.php'));
exit;
```
Three separate checks, each for a different attack: logged in ([[03.04 PHP Sessions and Login State]]), a genuine form (this note), the owner ([[03.07 Access Control and Ownership Checks]]).

## 6. With `fetch`
A request sent by JavaScript needs the token too. Print it once in the page head and send it as a header:

```php
<meta name="csrf-token" content="<?= e(csrf_token()) ?>">
```
```js
const token = document.querySelector('meta[name="csrf-token"]').content;

await fetch('api/mark-done.php', {
  method: 'POST',
  headers: { 'X-CSRF-Token': token },
  body: new FormData(form),
});
```
The server then accepts the token from `$_POST['csrf_token']` or from the header (`$_SERVER['HTTP_X_CSRF_TOKEN']`). If the form already contains the hidden field, `new FormData(form)` carries it and nothing more is needed.

## 7. What a token does not do
| It does not | Because | Covered by |
|---|---|---|
| Protect GET requests | Only POST is checked. So **a GET must never change data.** | [[01.03 Query Strings and GET Parameters in PHP]] |
| Stop XSS | A script injected into your own page can read the token | [[00.04 Output Escaping in PHP]] |
| Check who owns what | A valid token only proves the form was yours | [[03.07 Access Control and Ownership Checks]] |
| Replace `SameSite` cookies | The two work together; `SameSite=Lax` blocks many cases, the token blocks the rest | [[03.04 PHP Sessions and Login State]] |

## 8. Common mistakes
- **A form without the field.** One unprotected form is enough. Search the project for `method="post"` and check each.
- **Printing the token and never checking it.**
- **Checking with `==` or `===`** instead of `hash_equals()`.
- **A predictable token:** the user ID, a timestamp, `md5(time())`.
- **A delete or logout link** (`<a href="delete.php?id=42">`). A GET cannot be protected this way.
- **Checking the token after doing the work.** Verify first.
- **The token in the URL.** URLs are logged and shared.
- **Forgetting the login form.** It needs a token too.
- **An unhelpful failure.** A session can expire while a form is open; the message should say to reload and try again.
- **Believing that requiring POST is itself the protection.** The attacker's form is a POST.
