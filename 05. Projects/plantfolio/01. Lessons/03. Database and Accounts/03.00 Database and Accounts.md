# 03 · Database and Accounts

> [!info] Lesson map
> **Roadmap:** Stage B, week 8 (23–29 Nov 2026) · [[00. PlantFolio Overview|Project Overview]]
> **Progress:** [[PlantFolio Week 08 - Database, Accounts and Sessions]] · **Quick revision:** [[03.99 Summary - Database and Accounts]]

## What this lesson is about
Stage B turns the pages from a picture of a site into a site. This first week creates the database and builds accounts: **register, log in, stay logged in, log out**. It is also where the security rules in `CLAUDE.md` stop being future plans and become checks on every change.

Each note answers one question an attacker, or an examiner, will ask:

| Question | Note |
|---|---|
| How is the data stored, and what stops bad data getting in? | 03.01 |
| How does PHP talk to the database without SQL injection? | 03.02 |
| What happens if the database is stolen? Can passwords be read? | 03.03 |
| How does the site know who you are on the next page? | 03.04 |
| Can another website make you submit a form here? | 03.05 |
| What does the server do with a form it receives? | 03.06 |
| Can you open or change something that is not yours? | 03.07 |

## Topic structure
```text
Database and Accounts
├── The database
│   ├── schema.sql: types, InnoDB, utf8mb4, keys, foreign-key rules
│   └── seed.sql: demo data built from the mock data
├── Talking to it
│   └── PDO: one connection, prepared statements, transactions
├── Accounts
│   ├── Registration: validate, hash the password, insert
│   ├── Login: verify, lock after 5 failures, start the session
│   └── Sessions: regenerate on login, destroy on logout
└── Protecting every request
    ├── CSRF token on every POST
    ├── Server-side validation, redirect, flash message
    └── require_login() and ownership checks
```

## The security rules, and where each is explained
| Rule in `CLAUDE.md` | Note |
|---|---|
| PDO prepared statements only; emulated prepares off; exceptions on | 03.02 |
| Escape with `e()` everywhere | [[00.04 Output Escaping in PHP]] |
| `password_hash()` and `password_verify()`; one generic login error; lock for 15 min after 5 failures | 03.03 |
| `session_regenerate_id(true)` on login; logout destroys the session | 03.04 |
| A per-session CSRF token in every POST form, checked on every POST | 03.05 |
| `require_login()` on private pages; check ownership before every edit or delete | 03.07 |
| Uploads: `finfo`, 5 MB, random names, resize | [[04.02 Secure File Uploads in PHP]] |
| Real credentials only in `config/config.php` | [[06.06 Environment Variables and Configuration]] |

> [!note] One fact about XAMPP
> The "MySQL" that XAMPP installs is **MariaDB** (version 10.4 on this computer), a compatible fork of MySQL. Everything in these notes works on both. Where the two differ, the note says so.

## Order of work, from the roadmap
schema → `db.php` → registration → username check → login, logout, sessions → `auth.php` → CSRF → lockout → settings saves. Then the tests TC-001 – TC-011, TC-028 and TC-029.
