# 01.05 · Dropdown Menus with `<details>` and `<summary>`

> [!info] [[01.00 Building Pages|Lesson 1]] · Week 1 · Task CORE-06 · Priority 🟡 Useful
> **Builds on:** [[01.01 Page Skeleton - Header, Footer and Navigation]] · [[00.06 Component CSS and the Style Guide]]
> **Used for:** the Plant Tools menu, the account menu, the visitor menu on phones and the "+" sheet in the bottom bar.

## 1. Definitions
| Term | Meaning |
|---|---|
| **`<details>`** | An HTML element that hides its content until the user opens it |
| **`<summary>`** | The first child of `<details>`: the part that is always visible and is clicked to open or close |
| **`open`** | The attribute the browser adds to `<details>` while it is open |
| **Disclosure widget** | The general name for "click to show more" |

## 2. Why PlantFolio uses it
- Stage F allows no JavaScript that the page depends on, and `app.js` does not exist until week 5. The header still needs four menus.
- The browser already knows how to open and close `<details>`: with a click, with Enter or Space, and it tells a screen reader "collapsed" or "expanded". None of that has to be written.
- One CSS component, `.menu`, serves all four menus. Only the position of the panel differs.

## 3. How it works
```text
<details class="menu">            closed: only the summary is drawn
  <summary> Plant Tools </summary>     ← click, Enter or Space
  <div class="menu-panel"> … </div>    ← drawn only while <details> has the attribute open
</details>
```
1. The user activates the `<summary>`.
2. The browser adds `open` to the `<details>` element and draws the rest of its content.
3. CSS places that content as a floating panel instead of pushing the page down.
4. A second click removes `open` again.

Several `<details>` elements that share the same **`name`** attribute form a group: opening one closes the others. PlantFolio gives every menu `name="site-menu"`.

## 4. Syntax
```html
<details class="menu" name="site-menu">
  <summary class="nav-link">Plant Tools</summary>
  <div class="menu-panel">
    <a class="menu-item" href="…">Plant Identifier</a>
    <a class="menu-item" href="…">Health Check</a>
  </div>
</details>
```
```css
.menu { position: relative; }                 /* the panel is placed against this box */

.menu > summary { list-style: none; cursor: pointer; }          /* remove the small triangle */
.menu > summary::-webkit-details-marker { display: none; }      /* the same, for Safari */

.menu-panel {
  position: absolute;                          /* floats over the page, takes no room in the layout */
  top: calc(100% + var(--space-8));            /* just under the summary */
  left: 0;
  z-index: 60;                                 /* above the sticky header (50) */
}

.menu[open] .menu-chevron { transform: rotate(180deg); }   /* style the open state with [open] */
```

## 5. Example: the "+" button of the phone bottom bar
The same component, with one extra class that changes where the panel appears.
```php
<details class="menu bottom-bar-add" name="site-menu">
  <summary class="bottom-bar-plus" aria-label="Add or check a plant"><?= icon('plus') ?></summary>
  <div class="menu-panel menu-panel-sheet">
    <?php foreach ($add_links as $link): ?>
      <a class="menu-item" href="<?= e(url($link['href'])) ?>"><?= icon($link['icon']) ?> <?= e($link['label']) ?></a>
    <?php endforeach; ?>
  </div>
</details>
```
```css
.menu-panel-sheet {
  position: fixed;                                               /* against the screen, not the button */
  top: auto;
  right: var(--space-16);
  bottom: calc(var(--bottom-bar-height) + var(--space-32));      /* just above the bar */
  left: var(--space-16);
}

.bottom-bar-add[open] .bottom-bar-plus .icon { transform: rotate(45deg); }   /* + becomes × */
```
- The summary shows only an icon, so it has an **`aria-label`**. Icons are hidden from screen readers.
- The links are an array at the top of `includes/footer.php`. The HTML only loops over it.

## 6. What it does not do
| Missing | Effect | Plan |
|---|---|---|
| Close on a click outside | The menu stays open until its button is clicked again or another menu opens | A few lines in `app.js`, week 5 |
| Close on the Escape key | Same | Week 5 |
| The `name` group in old browsers | Two menus can be open at once | Accepted: nothing breaks |

This is [[02.01 Progressive Enhancement and Script Organisation|progressive enhancement]]: the menu works with HTML and CSS alone, and JavaScript later makes it nicer.

## 7. Common mistakes
- **`<summary>` not the first child** of `<details>`. The browser then invents its own summary, "Details".
- **No `position: relative` on the wrapper.** The absolute panel is then placed against the page and appears in the wrong corner.
- **A panel hidden behind the header or the page.** Check `z-index`.
- **An icon-only summary without `aria-label`.** It is announced as an unnamed button.
- **Hiding the panel yourself with `display: none`.** The browser already hides it while `<details>` is closed.
- **Using it for a form control.** A choice that is submitted with a form is a `<select>` or radio buttons, not a menu of links.
