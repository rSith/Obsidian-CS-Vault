# 01.01 · Page Skeleton: Header, Footer and Navigation

> [!info] [[01.00 Building Pages|Lesson 1]] · Week 1–2 · Task CORE-06 · Priority 🔴 Core
> **Builds on:** [[00.03 PHP Includes and Partials]] · [[00.06 Semantic HTML]] · [[05.07 Navigation Design]]
> **Used for:** `includes/header.php` and `includes/footer.php`, which wrap every page.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Page skeleton** | The parts every page shares: `<head>`, site header, navigation, footer, script tags |
| **Landmark** | A semantic region a screen reader can jump to: `<header>`, `<nav>`, `<main>`, `<footer>` |
| **Active-page highlight** | Marking the navigation link of the page you are on |
| **Skip link** | A hidden first link, "Skip to content", for keyboard users |

## 2. Why it is used
- Fifteen pages must have the same navigation. One file each for the top and the bottom of the page means one change updates all of them.
- The `<head>` (fonts, stylesheets, viewport) is easy to get subtly wrong. Written once, it is right everywhere.
- Until CORE-06 is done, `index.php` and `styleguide.php` each repeat the font and stylesheet links. Their comments say these "move into `includes/header.php`".

## 3. How it works
```text
header.php   <!doctype html> … <head> … </head>
             <body>  <header> logo + navigation </header>  <main>
───────────  the page's own HTML  ───────────
footer.php   </main>  <footer> … </footer>  mobile bottom bar  <script defer>  </body></html>
```
A tag opened in `header.php` (`<main>`, `<body>`) is closed in `footer.php`. The page file supplies only what goes between.

The page hands information to the header through variables set **before** the include:
```php
$page_title = 'My Garden';
include __DIR__ . '/../includes/header.php';
```

## 4. Syntax: what the head must contain
```php
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title><?= e($page_title) ?> · PlantFolio</title>
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Lora:ital,wght@0,600;1,400&family=Poppins:wght@400;500;600&display=swap">
  <link rel="stylesheet" href="<?= e(url('assets/css/variables.css')) ?>">
  <link rel="stylesheet" href="<?= e(url('assets/css/components.css')) ?>">
  <link rel="stylesheet" href="<?= e(url('assets/css/layout.css')) ?>">
</head>
```

| Line | Why |
|---|---|
| `lang="en"` | Screen readers choose the right pronunciation |
| `charset="utf-8"` | Sinhala, Tamil and emoji display correctly |
| `viewport` | Without it a phone pretends to be 980 px wide and no media query fires: [[06.04 Making Pages Responsive]] |
| `<title>` | The browser tab, bookmarks and search results. Different on every page. |
| `preconnect` | Lets the browser open the connection to the font server early |
| `url(…)` | Every address is built from `base_url`: [[00.03 PHP Includes and Partials]] |

Scripts go in the footer or the head with **`defer`**, so they run after the HTML is read: [[02.01 Progressive Enhancement and Script Organisation]].

## 5. Example: navigation that knows the current page
```php
<?php
// True when the browser asked for this file, e.g. is_current('garden.php')
function is_current($file)
{
    return basename($_SERVER['SCRIPT_NAME']) === $file;
}

$nav_items = [
    'dashboard.php' => 'Home',
    'garden.php'    => 'My Garden',
    'explore.php'   => 'Explore',
    'exchange.php'  => 'Exchange',
];
?>
<a class="skip-link" href="#main">Skip to content</a>
<header class="site-header">
  <a class="logo" href="<?= e(url('')) ?>">PlantFolio</a>
  <nav aria-label="Main">
    <ul class="nav-list">
      <?php foreach ($nav_items as $file => $label): ?>
        <li>
          <a class="nav-link" href="<?= e(url($file)) ?>"<?= is_current($file) ? ' aria-current="page"' : '' ?>><?= e($label) ?></a>
        </li>
      <?php endforeach; ?>
    </ul>
  </nav>
</header>
<main id="main">
```
```css
.nav-link[aria-current="page"] {
  color: var(--color-forest);
  font-weight: var(--weight-semibold);
}
```
- `$_SERVER['SCRIPT_NAME']` is the path of the requested file; `basename()` keeps only `garden.php`.
- **`aria-current="page"`** tells a screen reader "this is the page you are on", and the CSS styles that same attribute. One attribute gives the meaning and the look.
- The names and classes here are an illustration. The real markup follows the wireframes.

## 6. Two navigations
The wireframes show a **public** header (Log in, Sign up) and a **logged-in** header (the member's avatar and menu).

| Stage | How the header decides |
|---|---|
| F | A variable from the mock data, for example whether `$current_user` is set |
| B | The session: [[03.04 PHP Sessions and Login State]] |

The header chooses with one `if`. The page files do not change between stages.

## 7. The mobile bottom bar
On a phone the main navigation becomes a bar fixed to the bottom of the screen: Home, Garden, +, Exchange, Profile.

```css
.bottom-bar {
  position: fixed;
  inset: auto 0 0 0;                              /* left, right and bottom edges */
  display: flex;
  justify-content: space-around;
  padding-bottom: env(safe-area-inset-bottom);    /* clear the home indicator on newer phones */
  background: var(--color-white);
  border-top: 1px solid var(--color-line);
}

.bottom-bar a {
  min-width: 44px;
  min-height: 44px;                               /* touch target */
}

main {
  padding-bottom: 72px;                           /* so the bar never covers the last content */
}

@media (min-width: 768px) {
  .bottom-bar { display: none; }                  /* tablets and up use the top navigation */
  main { padding-bottom: 0; }
}
```
More on phone layouts in [[02.06 Mobile Patterns - Bottom Bar, Sheets and Stacked Tables]].

## 8. One rule that matters later
> [!warning] Nothing may be printed before the header is included, and logic comes first
> In stage B a page may need to **redirect** (`header('Location: …')`) or start a **session**. Both must happen **before any output**, even one blank line. A page that prints HTML and then decides to redirect fails with "headers already sent". This is the practical reason for the project's rule: PHP logic at the top, HTML below.

## 9. Common mistakes
- **A tag opened in the header and never closed,** or closed twice. Validate one page's HTML to check.
- **A space or blank line before `<?php`** at the top of an included file. It is output, and it breaks redirects later.
- **The same `<title>` on every page.**
- **No viewport meta tag.**
- **Highlighting the active link with a class only,** so a screen reader cannot tell which page is current.
- **Two `<h1>` elements,** one in the header and one in the page. The logo is not a heading.
- **`<div class="nav">`** where `<nav>` belongs.
- **A fixed bar covering the last content** because `<main>` has no bottom padding.
- **Hard-coded addresses** such as `href="/plantfolio/public/garden.php"`. Use `url()`.
- **Navigation that differs from page to page.** Consistency is a usability rule: [[05.07 Navigation Design]].
