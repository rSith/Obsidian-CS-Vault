# 01.04 · Rendering States: Empty, Owner and Visitor Views

> [!info] [[01.00 Building Pages|Lesson 1]] · Weeks 2–4 and 7 · Tasks CORE-25, CORE-21, COM-08 · Priority 🔴 Core
> **Builds on:** [[00.02 PHP Basics for Templates]] · [[05.08 UI Design Principles]]
> **Used for:** the empty garden (S1), a plant page seen by its owner or by a visitor, and the listing page before and after "I'm interested".

## 1. Definitions
| Term | Meaning |
|---|---|
| **State** | One of the distinct situations a page can be in |
| **Empty state** | What a page shows when there is nothing to list yet |
| **Conditional rendering** | Choosing which HTML to send, with `if` |
| **Flag** | A true/false variable that names a condition, such as `$is_owner` |

## 2. Why it is used
A wireframe usually shows the **full** state: a garden with eighteen plants. Real users meet the other states first. A new member's garden is empty. A visitor must not see Edit and Delete. A listing must not reveal a phone number to someone who has not expressed interest. A page that handles only the full state is unfinished, and the last example is a privacy failure.

The wireframes list six shared states:

| State | What | Covered in |
|---|---|---|
| S1 | Empty garden | This note |
| S2 | Analysing (AI working) | [[05.07 Confidence Thresholds and Honest AI Results]] |
| S3 | Low confidence, "Not sure" | [[05.07 Confidence Thresholds and Honest AI Results]] |
| S4 | Rate-a-trader modal | [[02.02 Tabs, Modals, Toasts and Focus]] |
| S5 | Log-update modal | [[02.02 Tabs, Modals, Toasts and Focus]] |
| S6 | Confirm and toast | [[02.02 Tabs, Modals, Toasts and Focus]] |

## 3. How it works
1. At the **top** of the file, work out each condition once and give it a name.
2. In the **HTML**, branch on those names.

```php
<?php
$has_plants = count($plants) > 0;
$is_owner   = $plant['user_id'] === $current_user['id'];
?>
```
A named flag reads like a sentence in the template (`if ($is_owner)`) and the rule lives in one place. If the rule changes, one line changes.

## 4. Example A: the empty garden (S1)
A good empty state has three parts: a picture, **one line that says what is going on**, and **one clear next step**. That is exactly what `partials/empty-state.php` is specified to show.

```php
<?php if ($has_plants): ?>
  <div class="card-grid">
    <?php foreach ($plants as $plant): ?>
      <?php partial('plant-card', ['plant' => $plant]); ?>
    <?php endforeach; ?>
  </div>
<?php else: ?>
  <?php partial('empty-state', [
      'message'      => 'Your garden is empty. Add your first plant to start its story.',
      'action_label' => 'Add a plant',
      'action_url'   => url('plant-form.php'),
  ]); ?>
<?php endif; ?>
```
The keys passed to the partial are an illustration; the partial's own first comment defines what it expects.

**Checking it in stage F.** The mock user has plants, so the empty state never appears by itself. Temporarily set `$plants = [];` at the top of the page, check the result against the wireframe, and remove the line. An empty **search** result is a different empty state with a different message ("No plants match 'xyz'") and a different next step ("Clear filters").

## 5. Example B: owner or visitor
The Plant Profile (P05) has edit controls for its owner. A visitor sees an owner card and a like button instead.

```php
<?php if ($is_owner): ?>
  <a class="btn btn-secondary" href="<?= e(url('plant-form.php?id=' . $plant['id'])) ?>">Edit</a>
  <button class="btn btn-danger" type="button">Delete</button>
<?php else: ?>
  <?php partial('avatar', ['member' => $owner]); ?>
  <button class="btn btn-secondary" type="button">Like</button>
<?php endif; ?>
```

> [!warning] Hiding a button is not security
> Leaving the Edit button out of the HTML only tidies the page. Anyone can still type `plant-form.php?id=42` or send the delete request by hand. In stage B the **server checks ownership before every edit and delete**: [[03.07 Access Control and Ownership Checks]]. The two work together: the interface does not offer what the server would refuse.

A **private** plant goes one step further. To anyone but its owner it answers **Not found**, as if it did not exist. Saying "this plant is private" would confirm that it exists.

## 6. Example C: contact details on a listing
Listing Detail (P11) has two states: **A**, before the visitor has expressed interest, and **B**, after.

```php
<?php if ($has_expressed_interest): ?>
  <h3>Contact <?= e($owner['full_name']) ?></h3>
  <?php if ($listing['share_email']): ?>
    <p><?= e($owner['email']) ?></p>
  <?php endif; ?>
  <?php if ($listing['share_phone']): ?>
    <p><?= e($owner['phone']) ?></p>
  <?php endif; ?>
<?php else: ?>
  <p>Contact details are shared after you express interest.</p>
  <button class="btn btn-primary" type="submit">I'm interested</button>
<?php endif; ?>
```
Two rules from `CLAUDE.md` are visible here: details appear **only after** interest, and **only the fields the owner chose** to share.

> [!warning] Never send hidden data
> If the email were printed in state A and hidden with CSS (`display: none`), it would still be in the page source for anyone to read. In state A the server must **not send it at all**. The same holds for the mock data: do not print it "for later".

## 7. Keeping templates readable
- **One page file, several states.** Do not copy `plant.php` into `plant-visitor.php`. Two copies drift apart.
- **Avoid deep nesting.** If a branch is long, move it into a partial.
- **Decide in PHP, not in CSS.** A class such as `.is-owner` that reveals controls is the hidden-data mistake again.
- **Give every state a wireframe check**, not only the full one.

## 8. Common mistakes
- **Building only the full state.** The first thing a new user sees is the empty one.
- **An empty state with no next step:** "No plants." and nothing else.
- **A blank area** where a list would be, with no message at all.
- **Hiding with CSS** what should not be sent.
- **Showing controls that will be refused,** or refusing without ever hiding them.
- **"This plant is private"** for someone else's private plant.
- **Repeating the condition** in ten places instead of one flag.
- **Comparing IDs of different types.** `'1' === 1` is false. Mock IDs are integers; check what the session and the database give you in stage B.
- **Forgetting the logged-out visitor.** There may be no `$current_user` at all on a public page.

## 9. Exam and viva focus
- **What is an empty state, and what makes a good one?** It explains and offers one next step.
- **Authentication vs authorisation:** who you are vs what you may do.
- **Client-side hiding vs server-side enforcement:** why only the second is security.
- **Privacy by design and data minimisation:** send only what is needed. See [[10.10 GDPR]].
- **Feedback and error prevention** as usability principles: [[05.08 UI Design Principles]].
- **Viva:** "What does a brand-new member see on the Dashboard?" · "Why does a private plant say Not found?" · "Where exactly is the owner's phone number before I click I'm interested?"
