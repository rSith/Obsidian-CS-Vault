# 05.01 · Calling the ML Service from PHP with cURL

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Weeks 11 and 13 · Tasks ML-02, ML-11 · Priority 🔴 Core
> **Builds on:** [[02.04 HTTP Protocol]] · [[06.05 REST API Design and Status Codes]] · [[04.02 Secure File Uploads in PHP]] · [[01.01 HTTP Requests and REST APIs in Python]] (the same idea from Python)
> **Used for:** `includes/ml-client.php`, the only code that talks to Flask.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Service** | A separate program that does one job and is reached over HTTP |
| **cURL** | A library for making HTTP requests from code. PHP has it built in. |
| **Multipart request** | The request format that can carry a file, the same one an upload form uses |
| **Timeout** | The longest time to wait for a reply before giving up |
| **Fallback** | What the program does instead when a dependency fails |
| **API contract** | The agreed request and response format between two programs |

## 2. Why it is built this way
**Why a separate service?** The models need Python (TensorFlow). The site is PHP. Two programs, each in the language that suits it, talking over HTTP.

**Why does only PHP talk to Flask?**

| If the browser called Flask directly | With PHP in the middle |
|---|---|
| Flask must be reachable from the internet | Flask listens on `127.0.0.1` only |
| Login, CSRF and upload checks must be rebuilt in Python | PHP has already done them |
| The browser's cross-origin rules get in the way | One origin |
| Nothing is recorded | PHP logs every prediction in `ml_predictions` |

**Why a fallback?** `CLAUDE.md`: *"If Flask is offline, pages fall back to manual entry — the site must never break because of ML."* The ML features are an extension. A stopped Python process must not stop someone adding a plant.

## 3. How it works
```text
1. The user submits a photo to a PHP page.
2. PHP checks and stores it with the upload handler → a file in public/uploads/.
3. PHP sends that file to Flask:   POST http://127.0.0.1:5000/predict/disease   (multipart field "image")
4. Flask replies with JSON, or does not reply in time.
5. PHP validates the reply. Anything unexpected counts as "no result".
6. PHP stores the result in ml_predictions, chooses the confidence word and shows the page.
   No result → the page shows the manual form and a short message.
```
The reply, from the draft contract in `ml-service/README.md`:
```json
{
  "model_version": "disease-mobilenetv2-v1",
  "predictions": [
    {"label": "Tomato___Early_blight", "confidence": 0.92},
    {"label": "Tomato___Septoria_leaf_spot", "confidence": 0.05},
    {"label": "Tomato___healthy", "confidence": 0.02}
  ]
}
```

## 4. Syntax: the cURL options that matter
| Option | Does |
|---|---|
| `CURLOPT_POST` | Make it a POST request |
| `CURLOPT_POSTFIELDS` | The fields to send. An array containing a `CURLFile` makes the request multipart. |
| `CURLOPT_RETURNTRANSFER` | Return the reply as a string instead of printing it |
| `CURLOPT_CONNECTTIMEOUT` | Seconds to wait for the connection to open |
| `CURLOPT_TIMEOUT` | Seconds allowed for the **whole** request |

## 5. Example: the client
```php
<?php
// includes/ml-client.php: the only code that calls the Flask service (ML-02)

/**
 * Send a stored photo to the ML service.
 * $endpoint is 'species' or 'disease'. Returns the decoded reply, or null if anything at all went wrong.
 */
function ml_predict(string $endpoint, string $image_path): ?array
{
    if (!in_array($endpoint, ['species', 'disease'], true) || !is_file($image_path)) {
        return null;
    }

    $mime = (new finfo(FILEINFO_MIME_TYPE))->file($image_path);

    $curl = curl_init(rtrim(config('ml_service_url'), '/') . '/predict/' . $endpoint);
    curl_setopt_array($curl, [
        CURLOPT_POST           => true,
        CURLOPT_POSTFIELDS     => ['image' => new CURLFile($image_path, $mime, 'photo')],
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_CONNECTTIMEOUT => 3,
        CURLOPT_TIMEOUT        => config('ml_timeout_seconds'),     // 10 seconds
    ]);

    $body   = curl_exec($curl);
    $status = curl_getinfo($curl, CURLINFO_RESPONSE_CODE);
    curl_close($curl);

    // Offline, too slow, or an error status: no result
    if ($body === false || $status !== 200) {
        return null;
    }

    // Validate the shape before trusting it
    $data = json_decode($body, true);
    if (!is_array($data) || !isset($data['predictions']) || !is_array($data['predictions'])) {
        return null;
    }

    $predictions = [];
    foreach ($data['predictions'] as $item) {
        if (isset($item['label'], $item['confidence']) && is_string($item['label']) && is_numeric($item['confidence'])) {
            $predictions[] = [
                'label'      => $item['label'],
                'confidence' => max(0.0, min(1.0, (float) $item['confidence'])),
            ];
        }
    }
    if (!$predictions) {
        return null;
    }

    return [
        'model_version' => (string) ($data['model_version'] ?? 'unknown'),
        'predictions'   => array_slice($predictions, 0, 3),
    ];
}
```
In the page:
```php
<?php
$result = ml_predict('disease', config('upload_dir') . '/' . $photo);

if ($result === null) {
    $ai_unavailable = true;          // the template shows the manual form and a short message
} else {
    $top = $result['predictions'][0];
    $level = confidence_level($top['confidence']);     // High, Medium or Not sure: decided in PHP
}
```
One return value, `null`, covers every failure: service stopped, timeout, error status, broken JSON, wrong shape. The page needs only one `if`.

## 6. Recording every call
The table plan has `ml_predictions` for *"every recognition or diagnosis"* (ML-11): `user_id`, `plant_id`, `type`, `predicted_label`, `confidence`, `image_path`, `model_version`, `created_at`.

```php
<?php
$stmt = db()->prepare(
    'INSERT INTO ml_predictions (user_id, plant_id, type, predicted_label, confidence, image_path, model_version)
     VALUES (:user_id, :plant_id, :type, :label, :confidence, :image_path, :model_version)'
);
$stmt->execute([
    'user_id'       => $current_user['id'],
    'plant_id'      => $plant_id,                       // null when identifying a new plant
    'type'          => 'disease',
    'label'         => $top['label'],
    'confidence'    => $top['confidence'],
    'image_path'    => $photo,
    'model_version' => $result['model_version'],
]);
```
Why keep it: the result can be shown again without re-running the model; `model_version` says which model gave which answer; and the log is the raw material for checking the model later ([[08.06 Model Versioning and Retraining]]). Storing the prediction is separate from the **user's** decision: the plant's species or health status changes only when they press Save.

## 7. The first step: a hello-world call
Task ML-02 is deliberately small: prove the two programs can talk **before** any model exists.
1. Flask has only `GET /health`, returning `{"status": "ok"}`.
2. A PHP page calls it and shows the reply.
3. **Stop Flask.** The page must show the fallback within the timeout and not break.

Step 3 is the one that matters. Doing it in week 11 means the offline behaviour is designed in, not patched on at Gate 3.

## 8. Common mistakes
- **No timeout.** If Flask hangs, every visitor's page hangs with it.
- **A page that shows a PHP error when Flask is stopped.**
- **Calling Flask from JavaScript in the browser.**
- **Trusting the reply.** A confidence of `"high"` or `7.3`, or a missing key, must not reach the page or the database.
- **A hard-coded address.** Use `ml_service_url` from the config, so it can differ per machine.
- **Sending the original 12 MB photo.** Send the stored, resized file.
- **Deciding the confidence word in Python.** The contract says PHP decides, so the limits live in one place: `confidence_level()`.
- **Saving the AI's answer as the plant's species automatically.** The user decides.
- **Not logging failed or low-confidence calls.** Those are the most informative ones later.
- **Retrying in a loop** when the service is down. The user waits 30 seconds for nothing.
- **Calling the service during page load for something the user did not ask for.**

## 9. Exam and viva focus
- **Why split a system into services?** Different languages and strengths, independent failure, independent deployment. And the cost: a network call that can fail.
- **What is cURL?**
- **`multipart/form-data`:** when it is needed.
- **Timeouts and graceful degradation:** a system that loses a feature without failing.
- **What is an API contract, and why agree it before coding?**
- **Synchronous vs asynchronous calls:** the page waits here; a queue would be the alternative.
