# 05.06 · Evaluating an Image Classifier

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Week 12 · Tasks ML-06, ML-08, DEP-08 · Priority 🔴 Core
> **Parent concepts:** [[Model Evaluation]] · [[04. Concepts/Machine Learning/Classification|Classification]]. Precision, recall and the two-class confusion matrix are explained in [[05.03 Alert Metrics - Precision, Recall and Lead Time]]. This note extends them to many classes.
> **Used for:** the Gate 3 numbers, and the model card.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Accuracy** | The share of predictions that are correct |
| **Top-1 accuracy** | The model's first choice is correct |
| **Top-3 accuracy** | The correct class is among the model's three highest-scoring choices |
| **Confusion matrix** | A table of actual classes against predicted classes |
| **Per-class precision** | Of the photos the model called class X, the share that really are X |
| **Per-class recall** | Of the photos that really are X, the share the model found |
| **Macro average** | The plain average of a metric over the classes, each class counting equally |

## 2. Why it is used
Gate 3 has two numeric targets: **≥ 90 % test accuracy** for disease detection, and **top-3 measured** for recognition. One accuracy figure does not show *which* diseases are confused, or whether a rare class is being failed. The confusion matrix and the per-class figures do, and they are what an examiner asks about.

**Why top-3 for recognition?** The Plant Identifier shows the top match and two alternatives, and the user picks. The feature succeeds whenever the right species is **somewhere in the three**. Top-3 accuracy measures the feature as it is actually used.

## 3. How it works: a worked example
A small test set of 150 photos, three classes, 50 each. Rows are what the photo **really** is; columns are what the model **said**.

| Actual ↓ / Predicted → | Healthy | Early blight | Late blight | Total |
|---|---|---|---|---|
| **Healthy** | **45** | 3 | 2 | 50 |
| **Early blight** | 4 | **40** | 6 | 50 |
| **Late blight** | 1 | 7 | **42** | 50 |
| **Total predicted** | 50 | 50 | 50 | 150 |

The diagonal (bold) holds the correct predictions.

$$\text{Accuracy} = \frac{45 + 40 + 42}{150} = \frac{127}{150} \approx 84.7\,\%$$

For **Early blight**:

$$\text{Precision} = \frac{40}{3 + 40 + 7} = \frac{40}{50} = 0.80 \qquad \text{Recall} = \frac{40}{4 + 40 + 6} = \frac{40}{50} = 0.80$$

- Precision reads **down the column**: of 50 photos called Early blight, 40 were.
- Recall reads **along the row**: of 50 real Early blight photos, 40 were found.

**What the off-diagonal cells say:**
- Early and Late blight are confused with each other (6 and 7). They look alike; that is a forgivable error, and both lead to similar advice.
- **Sick called Healthy** (4 and 1) is the costly one. The member is told nothing is wrong.

## 4. Not all mistakes cost the same
| Mistake | Consequence for the member |
|---|---|
| Disease A called disease B | Wrong advice, but they know something is wrong |
| Healthy called sick | Worry, and unneeded treatment |
| **Sick called healthy** | **The problem is ignored** |

The **recall of each disease class** therefore deserves particular attention, and it is one reason the interface never states a result as a certainty.

## 5. Syntax
```python
import numpy as np
import tensorflow as tf
from sklearn.metrics import classification_report, confusion_matrix

# True labels and predictions for the whole test set, in the same order
y_true = np.concatenate([labels.numpy() for _, labels in test_ds])
probabilities = model.predict(test_ds, verbose=0)
y_pred = probabilities.argmax(axis=1)

print(confusion_matrix(y_true, y_pred))
print(classification_report(y_true, y_pred, target_names=test_ds.class_names, digits=3))

# Top-3 accuracy
top3 = np.argsort(probabilities, axis=1)[:, -3:]              # the three best positions per photo
top3_accuracy = np.mean([y_true[i] in top3[i] for i in range(len(y_true))])
```
`test_ds` must be loaded with `shuffle=False`, or the labels and the predictions will not line up.

`classification_report` prints precision, recall and F1 for every class, plus the macro and weighted averages.

| Average | Each class counts | Use when |
|---|---|---|
| **Macro** | Equally | You care about every class, including small ones |
| **Weighted** | By its number of photos | You want a figure close to overall accuracy |

## 6. Example: the two test sets side by side
| Model | Test set (PlantVillage) | Phone photos (n = 25) |
|---|---|---|
| Baseline CNN | 86 % | 36 % |
| MobileNetV2, fine-tuned | 96 % | 60 % |

The numbers are invented to show the layout. A table like this, with the sample size stated, is the honest result. The gap between the columns is **domain shift**: [[05.05 Image Datasets - Splits, Augmentation and Domain Shift]].

With 25 photos, one photo is 4 percentage points. "60 % (15 of 25)" is more truthful than "60 %".

## 7. The model card (task DEP-08)
Each model gets a short card in `docs/`: *"data, classes, metrics, limitations."* A reader should learn from one page whether the model fits their use.

| Section | Contains |
|---|---|
| **Model** | Name and version, architecture, date trained |
| **Intended use** | A helper that suggests a likely condition; the user decides |
| **Not intended for** | Houseplants outside the supported crops; a replacement for expert advice |
| **Training data** | Dataset, source and licence, number of images, the split, augmentation |
| **Classes** | The full list |
| **Metrics** | Test accuracy, per-class precision and recall, the confusion matrix, phone-photo results with the sample size |
| **Limitations** | Lab-style photos, food crops only, classes that are often confused |
| **How it is used in the app** | Confidence words, the 60 % limit, manual fallback |

## 8. Common mistakes
- **One accuracy number,** nothing else.
- **Evaluating on validation data and calling it the test result.**
- **A shuffled test dataset,** so labels and predictions do not match. Accuracy then looks like chance.
- **Reading the matrix the wrong way round.** State which axis is actual and which is predicted.
- **Top-3 accuracy presented as if it were accuracy.** Say which it is.
- **Hiding the phone-photo result.**
- **Percentages on tiny samples** with no count.
- **Ignoring which errors happen,** especially sick called healthy.
- **Tuning on the test set after seeing the matrix.** That turns it into a validation set. Go back to validation data to improve.
- **Comparing models on different test images.**
- **Accuracy on an unbalanced test set.** A class with 5 photos barely affects it.
