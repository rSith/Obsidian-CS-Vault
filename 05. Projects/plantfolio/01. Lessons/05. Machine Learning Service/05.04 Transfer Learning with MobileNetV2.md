# 05.04 · Transfer Learning with MobileNetV2

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Weeks 11–12 · Tasks ML-05, ML-07 · Priority 🔴 Core
> **Builds on:** [[05.03 Convolutional Neural Networks]] · [[Neural Network]] · [[Deep Learning]]
> **Used for:** the disease model (target ≥ 90 % test accuracy), and possibly the recognition model.

## 1. Definitions
> [!note] Transfer learning
> **Transfer learning** means starting from a model that was already trained on a large, general task, and adapting it to your own smaller task, instead of training from nothing.

| Term | Meaning |
|---|---|
| **Pretrained model** | A model whose weights were already learned on a big dataset |
| **ImageNet** | A dataset of over a million photos in 1,000 everyday categories, the usual source of pretrained image models |
| **Base** (backbone) | The pretrained convolutional layers that turn a picture into features |
| **Head** | The new final layers you add for your own classes |
| **Freezing** | Marking layers as not trainable, so their weights stay as they are |
| **Fine-tuning** | Unfreezing some pretrained layers and training them gently on your data |

## 2. Why it is used
- **Little data.** PlantVillage has tens of thousands of images. Models that learn vision from scratch need millions.
- **Little time.** Training from scratch takes days; adapting a pretrained model takes minutes to hours on a free Colab GPU.
- **Better results.** The early layers of any image model learn edges, colours and textures. Those are just as useful for leaves as for cats. Only the last layers are specific to the original task.

**Why MobileNetV2?** It is small (about 3.5 million weights, roughly 14 MB) and fast, built for phones. That suits a service running on a laptop CPU, and it loads quickly.

## 3. How it works: two phases
```text
Phase 1: feature extraction
   [ MobileNetV2 base, FROZEN ] ──▶ [ new head: pooling → dropout → Dense(38, softmax) ]  ← only this trains
   A few epochs, normal learning rate.

Phase 2: fine-tuning
   [ base: early layers frozen | last layers UNFROZEN ] ──▶ [ head ]                       ← both train
   More epochs, a learning rate about 100 times smaller.
```
**Why two phases?** The new head starts with random weights. If the whole network trained at once, the large, random errors from the head would flow back and wreck the carefully learned base. Train the head first; then adjust the base slightly.

**Why a tiny learning rate in phase 2?** The pretrained weights are already good. They need a nudge, not a rewrite.

## 4. Example: the training code
```python
import json
import tensorflow as tf
from tensorflow.keras import layers

IMAGE_SIZE = (224, 224)
num_classes = len(train_ds.class_names)              # train_ds comes from the dataset note

# Random changes applied only while training
augment = tf.keras.Sequential([
    layers.RandomFlip("horizontal"),
    layers.RandomRotation(0.1),
    layers.RandomZoom(0.1),
    layers.RandomContrast(0.2),
])

base = tf.keras.applications.MobileNetV2(input_shape=IMAGE_SIZE + (3,),
                                         include_top=False,       # leave out ImageNet's own 1,000-class head
                                         weights="imagenet")
base.trainable = False                                            # Phase 1: freeze

inputs = tf.keras.Input(shape=IMAGE_SIZE + (3,))
x = augment(inputs)
x = layers.Rescaling(1 / 127.5, offset=-1)(x)        # pixels 0-255 → -1 to 1, as MobileNetV2 expects
x = base(x, training=False)                          # keep its batch-normalisation layers in inference mode
x = layers.GlobalAveragePooling2D()(x)
x = layers.Dropout(0.2)(x)
outputs = layers.Dense(num_classes, activation="softmax")(x)
model = tf.keras.Model(inputs, outputs)

model.compile(optimizer=tf.keras.optimizers.Adam(1e-3),
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])
model.fit(train_ds, validation_data=val_ds, epochs=5)

# Phase 2: unfreeze the last part of the base and continue gently
base.trainable = True
for layer in base.layers[:-30]:
    layer.trainable = False

model.compile(optimizer=tf.keras.optimizers.Adam(1e-5),            # 100 times smaller
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])
stop_early = tf.keras.callbacks.EarlyStopping(patience=3, restore_best_weights=True)
model.fit(train_ds, validation_data=val_ds, epochs=15, callbacks=[stop_early])

# Save the model and the class order together
model.save("disease.keras")
with open("disease_classes.json", "w") as f:
    json.dump(train_ds.class_names, f)
```
What each choice is for:

| Line | Reason |
|---|---|
| `include_top=False` | Drop the original 1,000-class output; add our own |
| `Rescaling(1 / 127.5, offset=-1)` **inside the model** | The scaling travels with the model file. The Flask service sends raw pixels and cannot get it wrong: [[05.02 Serving a Keras Model with Flask]]. |
| `training=False` on the base | MobileNetV2 has batch-normalisation layers whose statistics must not be disturbed by small batches |
| Augmentation layers inside the model | Active during `fit`, automatically off during prediction |
| **`compile` again** after changing `trainable` | The change only takes effect when the model is compiled |
| `EarlyStopping(restore_best_weights=True)` | Stops when validation loss stops improving and keeps the best version |
| Saving `class_names` | The model outputs positions. This file says which class each position is. |

## 7. Common mistakes
- **Fine-tuning everything at a normal learning rate.** Accuracy collapses in the first epoch.
- **Forgetting to compile again** after changing `trainable`. Nothing actually unfreezes.
- **Scaling outside the model,** then scaling differently (or not at all) in the service.
- **`training=True` on the base** by leaving the argument out.
- **Augmenting the validation or test images.**
- **Too many epochs** with no early stopping.
- **Not saving the class order,** or saving it from a differently ordered dataset.
- **Choosing settings by test accuracy.** Choices are made on validation data; the test set is used once.
- **Reporting only the final model.** The baseline CNN beside it is what gives the number meaning.
- **Losing the model** because it was only in the Colab session.
