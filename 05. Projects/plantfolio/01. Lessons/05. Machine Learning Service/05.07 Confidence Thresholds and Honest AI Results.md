# 05.07 · Confidence Thresholds and Honest AI Results

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Weeks 7 and 14 · Tasks ML-12 – ML-14, ML-17 · Priority 🔴 Core
> **Builds on:** [[14.05 Ethical Considerations and Limitations of AI]] · [[09.04 Responsible AI in Health]] · [[05.06 Evaluating an Image Classifier]]
> **Used for:** how every AI result is worded and shown, the states S2 (Analysing) and S3 (Not sure), and the helper `confidence_level()`.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Confidence** | The score the model gives its chosen class, between 0 and 1 |
| **Threshold** | A cut-off: results below it are treated differently |
| **Calibration** | How well confidence matches reality: of predictions made with 80 % confidence, are about 80 % correct? |
| **Human in the loop** | A person reviews the result and makes the final decision |
| **Abstaining** | The system declining to answer when it is unsure |

## 2. Why it is used
The design system fixes the rule, and `CLAUDE.md` repeats it:

> **High ≥ 80 %** (green) · **Medium 60–79 %** (amber) · **Not sure < 60 %** (grey). *AI suggests, the user decides — nothing is saved until the user presses Save.*

Three reasons this is the right design and not excess caution:
1. **The model is sometimes wrong,** and far more often on real phone photos than on its test set ([[05.05 Image Datasets - Splits, Augmentation and Domain Shift]]).
2. **A model always answers.** Shown a photo of a cat, a disease classifier still returns one of its 38 classes.
3. **A wrong answer stated confidently does harm:** a healthy plant is treated, or a sick one is left.

## 3. How it works: what the number is, and is not
The model ends with a softmax, which shares 100 % among **the classes it knows** ([[05.03 Convolutional Neural Networks]]).

| The score **is** | The score **is not** |
|---|---|
| How strongly the model prefers this class **over its other classes** | The probability that the answer is correct |
| Useful for ranking the top three | A measure of whether the photo is of a supported plant at all |
| Comparable between photos for the same model | Comparable between different models |

> [!warning] High confidence on the wrong kind of photo
> Given something unlike its training data (a houseplant, a blurry photo, a hand), a network can still output 95 % for one class. The scores must sum to 1, so "none of these" is not an available answer. A threshold reduces this problem and does **not** remove it. That is why the page also states which crops are supported.

## 4. The rule in code
```php
function confidence_level($confidence)
{
    $percent = round($confidence * 100);

    if ($percent >= 80) {
        return ['key' => 'high', 'label' => 'High'];
    }
    if ($percent >= 60) {
        return ['key' => 'medium', 'label' => 'Medium'];
    }

    return ['key' => 'low', 'label' => 'Not sure'];
}
```
This is the project's own helper. Two details:
- **The word is decided from the rounded percentage.** A score of 0.796 is displayed as "80 %". Deciding from the raw 0.796 would print "Medium" beside "80 %", which contradicts the rule the user can see.
- **It lives in PHP, in one place.** The Flask service returns numbers only. The words and limits cannot differ between pages.

## 5. Example: the three results a member can see
| Score | Shown as |
|---|---|
| 0.92 | **Early blight** · Confidence **High** 92 % · the explanation and action plan · two alternatives · Save buttons |
| 0.67 | **Possibly early blight** · Confidence **Medium** 67 % · alternatives shown prominently · advice to compare with the reference description |
| 0.41 | **Not sure** (state S3): *no diagnosis is named as the answer.* Tips for a better photo, the supported-crops list, and the manual form |

`CLAUDE.md`: below 60 % a result is *"never shown as an answer"*. The possible classes may appear as "things to compare", not as a conclusion.

A template sketch:
```php
<?php if ($ai_unavailable): ?>
  <div class="alert">Automatic analysis is unavailable right now. You can still log the plant's health yourself.</div>
<?php elseif ($level['key'] === 'low'): ?>
  <h2>Not sure</h2>
  <p>The photo did not match any supported condition closely enough. Try one leaf, in good light, on a plain background.</p>
<?php else: ?>
  <h2><?= e($diagnosis_name) ?></h2>
  <?php partial('confidence-meter', ['prediction' => $top]); ?>
<?php endif; ?>
```
The confidence meter always shows the **word and the number together**, never colour alone.

## 6. The states around the result
| State | What the user sees | Why |
|---|---|---|
| **S2 Analysing** | A progress message; buttons disabled | The call can take up to 10 seconds. Disabled buttons prevent a second submission. |
| **S3 Not sure** | No answer; guidance and the manual path | Abstaining is better than guessing |
| **Unavailable** | A short notice and the manual form | The site must never break because of ML |
| **Out of scope** | "Health Check supports these crops: …" | The model has not seen other plants |

## 7. The user decides
| Rule | In the interface |
|---|---|
| Nothing is saved automatically | Explicit **Save to plant story** and **Use this species** buttons |
| AI-filled fields are marked | A "Filled by AI" tag on the Add Plant form, and the fields stay editable |
| Alternatives are offered | The top three, each with a Use button |
| There is always a manual path | The ordinary form works without the AI |
| The limits are stated | An honesty note and the supported-crops statement |

Every prediction is still **logged** in `ml_predictions` ([[05.01 Calling the ML Service from PHP with cURL]]). Logging what the model said is different from acting on it.

## 8. Are 80 and 60 the right numbers?
They are fixed by the design system. They can be **checked** with validation data: for each threshold, what share of results would be shown, and how accurate are those?

| Shown only if confidence ≥ | Share of photos answered | Accuracy of those answers |
|---|---|---|
| 0 (always answer) | 100 % | 84 % |
| 60 % | 88 % | 91 % |
| 80 % | 71 % | 96 % |

The numbers are invented to show the idea. A higher threshold answers fewer photos and is right more often. That trade-off, measured on your own validation and phone photos, is good material for the report. If the labels turn out badly miscalibrated (many "High" results that are wrong), that is a finding to report and discuss with the team before changing a design-system rule.

## 9. Words matter
- **"Likely"** and **"Possibly"**, not "Your plant has".
- **An action plan of small, safe steps** (remove affected leaves, improve air flow, re-check in 7 days), not a chemical prescription.
- **The disease guidance text** (task ML-15) should come from a reliable source and be credited.
- The 7-day re-check reminder (ML-16) builds the uncertainty into the flow: look again.

## 10. Common mistakes
- **Showing the top class whatever its score.**
- **Calling the score "the probability your plant is sick".**
- **A threshold treated as protection against unsupported plants.**
- **Deciding the word from the unrounded number.**
- **The thresholds written in two places** (PHP and Python, or two pages).
- **Colour only** for the confidence level.
- **Auto-saving the diagnosis** to the plant's health status.
- **No manual path** when the AI fails or abstains.
- **A spinner with enabled buttons.** The user clicks again and sends two requests.
- **"Not sure" presented as an error.** It is a correct and useful outcome.
- **Claims in the report that the interface carefully avoids,** such as "diagnoses plant diseases".
- **Changing the fixed limits** without the team's agreement.
