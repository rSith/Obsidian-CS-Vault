# 05.02 · Serving a Keras Model with Flask

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Weeks 11 and 13 · Tasks ML-01, ML-09, ML-10 · Priority 🔴 Core
> **Builds on:** [[06.04 Flask Routing and JSON APIs]] (routes, JSON, status codes in Flask) · [[06.05 REST API Design and Status Codes]] · [[00.02 Python Virtual Environments]]. Those explain Flask itself; this note covers what is special about serving a model.
> **Used for:** `ml-service/app.py`.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Model serving** | Running a trained model behind an interface so other programs can ask it for predictions |
| **Inference** | Using a trained model to make a prediction. No learning happens. |
| **Preprocessing** | Turning the raw input (a photo file) into the exact form the model was trained on |
| **Batch** | A group of inputs processed together. A model always expects a batch, even of one. |
| **Class index** | The position of a class in the model's output: output 3 means the fourth class |

## 2. Why it is used
A trained model is a file. Something must load it, accept a photo, prepare the photo, run the model and report the answer in the agreed format. That is this small Flask app, and nothing more: no database, no login, no HTML.

## 3. How it works
```text
start-up:   load the model file and its list of class names   ← ONCE
request:    photo bytes → open as an image → RGB → 224 × 224 → array of shape (1, 224, 224, 3)
            → model.predict → 38 numbers that sum to 1 → take the three largest
            → JSON: {"model_version": …, "predictions": [{label, confidence} × 3]}
```
Three ideas carry the whole note:
1. **Load once.** Loading a model takes seconds. Doing it per request would make every prediction slow.
2. **Preprocess exactly as in training.** Same size, same colour order, same scaling.
3. **Keep the class order.** The model outputs positions, not names. The list of names must be the one saved at training time.

## 4. Example: the service
```python
# ml-service/app.py: the ML API. Only PHP calls it (ML-01, ML-10).
import json
from pathlib import Path

import numpy as np
import tensorflow as tf
from flask import Flask, jsonify, request
from PIL import Image, UnidentifiedImageError

MODELS_DIR = Path(__file__).parent / "models"
MODEL_VERSION = "disease-mobilenetv2-v1"
IMAGE_SIZE = (224, 224)
ALLOWED_TYPES = {"image/jpeg", "image/png"}

app = Flask(__name__)
app.config["MAX_CONTENT_LENGTH"] = 5 * 1024 * 1024            # refuse bodies over 5 MB with status 413

# Loaded once, when the service starts
disease_model = None
disease_classes = []
if (MODELS_DIR / "disease.keras").exists():
    disease_model = tf.keras.models.load_model(MODELS_DIR / "disease.keras")
    disease_classes = json.loads((MODELS_DIR / "disease_classes.json").read_text())


def load_image(file_storage) -> np.ndarray:
    """Turn an uploaded file into a batch of one image: shape (1, 224, 224, 3), values 0-255."""
    image = Image.open(file_storage.stream).convert("RGB").resize(IMAGE_SIZE)
    return np.expand_dims(np.asarray(image, dtype="float32"), axis=0)


@app.get("/health")
def health():
    return jsonify(status="ok", models={"disease": disease_model is not None})


@app.post("/predict/disease")
def predict_disease():
    if disease_model is None:
        return jsonify(error="The disease model is not loaded."), 503

    file = request.files.get("image")
    if file is None:
        return jsonify(error="Send the photo in a field named 'image'."), 400
    if file.mimetype not in ALLOWED_TYPES:
        return jsonify(error="Only JPG and PNG photos are accepted."), 415

    try:
        batch = load_image(file)
    except (UnidentifiedImageError, OSError):
        return jsonify(error="The file could not be read as an image."), 400

    probabilities = disease_model.predict(batch, verbose=0)[0]   # one row of scores, one per class
    top3 = np.argsort(probabilities)[::-1][:3]                   # positions of the three largest

    return jsonify(
        model_version=MODEL_VERSION,
        predictions=[
            {"label": disease_classes[i], "confidence": float(probabilities[i])}
            for i in top3
        ],
    )


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000)                         # this computer only
```
Reading it:
- **`np.expand_dims(..., axis=0)`** turns one image of shape `(224, 224, 3)` into a batch of shape `(1, 224, 224, 3)`.
- **`np.argsort(p)[::-1][:3]`** sorts positions by score, largest first, and keeps three.
- **`float(...)`** is needed: NumPy's number types cannot be written to JSON.
- **Status codes** follow the contract: `400` bad image, `415` wrong type, `503` model not loaded.
- **`host="127.0.0.1"`** means only programs on the same computer (PHP) can reach it.
- The scaling of pixel values to the range the model expects is **inside the model**, as a layer. So the service sends plain 0–255 pixels and cannot get the scaling wrong: [[05.04 Transfer Learning with MobileNetV2]].

## 5. Running it
```powershell
cd ml-service
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python app.py                        # http://127.0.0.1:5000

curl http://127.0.0.1:5000/health
curl -F "image=@leaf.jpg" http://127.0.0.1:5000/predict/disease
```
- **`requirements.txt` pins versions.** A model saved with one TensorFlow version may not load with another.
- **Model files are not in Git** (too large). `ml-service/models/README.md` holds the download link; the class-name JSON files are committed.
- The service can start **without** a model file. `/health` then reports it, and the prediction route answers 503. That lets ML-01 and ML-02 be finished before any model is trained.

## 6. The class list
```json
["Apple___Apple_scab", "Apple___Black_rot", "Apple___Cedar_apple_rust", "Apple___healthy"]
```
The training notebook writes this file from the dataset's class order (`train_ds.class_names`), in the same step as saving the model. If the order differs by one position, every prediction is confidently wrong and nothing reports an error.

Labels such as `Tomato___Early_blight` are the dataset's names. PHP turns them into words for people ("Early blight on tomato") and looks up the guidance text for each (task ML-15).

## 7. Common mistakes
- **Loading the model inside the route.** Seconds per request.
- **Preprocessing that differs from training:** another size, BGR instead of RGB, scaling done twice or not at all. The single most common reason a model that scored 95 % gives nonsense when served.
- **A class list typed by hand,** or sorted differently from training.
- **Returning NumPy numbers** without `float()`.
- **No check on the upload.** A text file sent as `image` crashes the route with a 500.
- **`debug=True`,** or `host="0.0.0.0"`, which opens the service to the whole network.
- **An HTML error page** where the PHP client expects JSON.
- **No size limit.**
- **The model file committed to Git.**
- **Forgetting the batch dimension.** "Expected shape (None, 224, 224, 3), found (224, 224, 3)".
- **Putting the confidence words in the reply.** The contract says PHP decides them.
- **Mixing this app's packages into another project's environment.** It has its own `venv`.

## 8. Exam and viva focus
- **Training vs inference.**
- **What is model serving, and why load the model once?**
- **Why must serving preprocess exactly like training?** The model has learned patterns in that exact representation. This mismatch is called **training–serving skew**.
- **What does a softmax output look like?** One score per class, between 0 and 1, summing to 1.
- **REST endpoints and status codes** used here: 200, 400, 413, 415, 503.
- **Why bind to `127.0.0.1`?**
- **Why is a model versioned in its replies?**
