# 05.05 · Image Datasets: Splits, Augmentation and Domain Shift

> [!info] [[05.00 Machine Learning Service|Lesson 5]] · Weeks 11–12 · Tasks ML-03, ML-06, ML-08 · Priority 🔴 Core
> **Parent concepts:** [[Data Preprocessing]] · [[04. Concepts/Machine Learning/Machine Learning Pipeline|Machine Learning Pipeline]] · [[Model Evaluation]]
> **Used for:** preparing PlantVillage, and understanding why a model that scores 95 % in the notebook may disappoint on a phone photo.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Dataset split** | Dividing the images into parts with different jobs: training, validation, test |
| **Stratified split** | A split that keeps each class in the same proportion in every part |
| **Data augmentation** | Making altered copies of training images (flipped, rotated, brightened) so the model sees more variety |
| **Class imbalance** | Some classes have many more images than others |
| **Domain shift** | The images the model meets in use differ from the ones it was trained on |
| **Out-of-distribution input** | Something the model was never trained to recognise at all |

## 2. Why it matters
Two questions decide whether the ML features can be trusted:
1. **Is the reported accuracy honest?** That depends on the split.
2. **Will it hold on a member's phone photo?** That depends on how far real photos are from the training photos.

The roadmap asks for both: a 70/15/15 split (ML-03), and evaluation *"on the test set + 20–30 phone photos"* (ML-06).

## 3. The dataset
**PlantVillage** is a public collection of about 54,000 leaf photos in 38 classes. Each class is a crop with a condition, such as `Tomato___Early_blight` or `Tomato___healthy`, across 14 crop species.

| Property | Consequence |
|---|---|
| **Food crops only:** tomato, potato, pepper, apple, grape, corn and others | Houseplants such as monstera or pothos are not in it |
| **One leaf, flat, on a plain background, good light** | A leaf on a plant, on a balcony, in shade looks different |
| **Classes of unequal size** | Overall accuracy can hide weak classes |
| **Several photos of the same leaf** | A careless split puts near-identical images in training and test |

## 4. How it works: the three parts
```text
All images ──▶  70 % training      the model learns from these
                15 % validation    you choose settings and decide when to stop with these
                15 % test          looked at ONCE, at the end, for the reported number
```
| Part | Used for | How often |
|---|---|---|
| Training | Fitting the weights | Every epoch |
| Validation | Comparing models, tuning, early stopping | Every experiment |
| Test | The final, honest measurement | **Once** |

Rules:
- **Split first, augment afterwards.** Augmenting first puts versions of the same photo on both sides.
- **Stratify,** so every class appears in all three parts.
- **Fix the random seed,** so the split is the same every run and results can be compared.
- **Keep copies of one leaf together** in one part where you can tell.
- **Never tune on the test set.** Each look lets your choices fit it.

## 5. Example: loading the split and augmenting
With the images already copied into `train/`, `val/` and `test/`, one sub-folder per class:
```python
import tensorflow as tf

IMAGE_SIZE = (224, 224)

def load(folder: str, shuffle: bool) -> tf.data.Dataset:
    return tf.keras.utils.image_dataset_from_directory(
        folder, image_size=IMAGE_SIZE, batch_size=32, shuffle=shuffle, seed=42)

train_ds = load("data/train", shuffle=True)
val_ds = load("data/val", shuffle=False)
test_ds = load("data/test", shuffle=False)

print(train_ds.class_names)        # folder names, in alphabetical order: the class order to save
```
```python
from tensorflow.keras import layers

augment = tf.keras.Sequential([
    layers.RandomFlip("horizontal"),       # a mirrored leaf is still the same disease
    layers.RandomRotation(0.1),            # up to about 36 degrees either way
    layers.RandomZoom(0.1),
    layers.RandomContrast(0.2),
    layers.RandomBrightness(0.2),
])
```
Placed at the start of the model, these layers change images **only during training**. Each epoch the model sees a slightly different version of every photo.

| Augmentation | Imitates |
|---|---|
| Flip, rotation | A leaf held at another angle |
| Zoom | A photo taken closer or further |
| Brightness, contrast | Different light |

Choose only changes that could happen in real photos and **do not change the answer**. Turning a leaf grey would remove the very colour change that marks a disease.

## 6. Class imbalance
If one class has 5,000 images and another 150, a model can score well overall while failing the small one.
- **Look at per-class results,** not only overall accuracy: [[05.06 Evaluating an Image Classifier]].
- **Class weights** make mistakes on rare classes cost more during training.
- **More augmentation** for small classes.

## 7. Domain shift: the central risk
The model learns from laboratory-style photos. Members will send phone photos of plants in pots.

> [!warning] Test-set accuracy is not real-world accuracy
> The study that introduced deep learning on PlantVillage reported accuracy above 99 % on its own held-out images, and about 31 % when the trained model was tested on photos taken under different conditions (Mohanty, Hughes and Salathé, 2016). The test split measures how well the model handles **more photos like the training ones**. It says little about photos unlike them.

That is why ML-06 adds **20–30 real phone photos**, and why that second number belongs in the report beside the first, however low it is.

What the project does about it:

| Measure | Where |
|---|---|
| Augmentation that imitates phone conditions | Training |
| **Tips beside the upload:** one leaf, fill the frame, good light, plain background | Plant Identifier and Health Check pages |
| **A supported-crops statement** and a scope message for other plants | Health Check page |
| **"Not sure" below 60 %** | [[05.07 Confidence Thresholds and Honest AI Results]] |
| Reporting both accuracies honestly | The report and the model card |

The tips matter more than they look: asking the user for a photo **closer to the training photos** is the cheapest way to shrink the gap.

## 8. The phone-photo set
For ML-06 and ML-08, the team collects its own labelled photos.
- **Label each one** with the true class before running the model.
- **Vary them:** different phones, light, backgrounds, distances.
- **Include hard cases** on purpose, and a few plants that are **not** in the supported list, to see what the model does with them.
- **Keep them out of training.** They are a test set.
- 25 photos is a small sample: one photo is 4 percentage points. Report the count with the percentage.

## 9. Common mistakes
- **Augmenting before splitting.**
- **Tuning on the test set,** or re-running the test after every change.
- **No fixed seed,** so each run has a different split.
- **Reporting only test-set accuracy** and letting the reader assume it holds in use.
- **Only overall accuracy** on unbalanced classes.
- **Augmentations that destroy the signal** (removing colour) or never occur (vertical flips of whole potted plants).
- **Augmenting validation and test images.**
- **Phone photos taken to look like the dataset.** They then measure nothing new.
- **Claiming the model diagnoses houseplants.** It has never seen one.
- **Datasets committed to Git.** The `.gitignore` excludes `ml-service/data/` and `datasets/`.
- **Not crediting the dataset.** Add its source and licence to `docs/credits.md`.
