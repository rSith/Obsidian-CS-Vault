# 06.99 · Lesson Summary: Testing and Delivery

> [!abstract] Back to [[06.00 Testing and Delivery]] · Progress: [[PlantFolio Week 15 - Testing]] · [[PlantFolio Week 16 - Delivery]]

## Must know
- **Ready (MS-5):** security review done, journeys A–D pass, a usability test held, **no open Critical or High issues**.
- **A test case** has an ID, preconditions, exact steps, test data, an expected result, the actual result and a status. Two people must reach the same verdict.
- **Positive tests** show a feature works. **Negative tests** show it refuses wrong input properly. **Boundary tests** check on the limit and one step either side.
- **The standing wrong inputs:** empty forms, a wrong password, oversized and wrong-type files, `<script>` in text, `' OR '1'='1` in search, another user's ID in the address.
- **Journeys** string pages together: D first visit · A add an unknown plant · B diagnose a sick plant · C swap a plant (two accounts).
- **Regression:** after every fix re-run the failed case, the cases around it and the journeys. Run everything once more on the release candidate.
- **Defects** are logged with steps, expected and actual results, severity and status. "Fixed" needs a re-test.
- **Security review, two passes:** search the code for each rule, then attack the running site with two accounts and the developer tools.
- **Twelve checks:** SQL injection · XSS · CSRF · access control · password storage · brute force · sessions · uploads · privacy leaks · information leaks · changes by GET · the ML service.
- **Start from a list of every file** in `public/` and `public/api/`.
- **Production:** `app_env` = `production`; errors hidden and logged; a real database user; HTTPS and a `Secure` cookie; web root = `public/`; development pages removed.
- **The fresh-install test:** a teammate, a clean computer, the README only. Remember the GD extension and the model download.
- **Release:** release pull request `main ← develop` → tag `v1.0` → GitHub release with the SQL dump and notebooks.
- **The demo must not depend on the internet or on the ML service starting.** Have the backup video.

## Important comparisons
| Verification | Validation |
|---|---|
| Built the product right | Built the right product |

| Positive test | Negative test |
|---|---|
| Valid input is accepted | Invalid input is refused properly |

| Black-box | White-box |
|---|---|
| By behaviour, from outside | With knowledge of the code |

| Functional | Non-functional |
|---|---|
| What it does | How well: speed, usability, security, accessibility |

| Development | Production |
|---|---|
| Errors shown; fake data | Errors hidden and logged; real data |

| Critical / High | Medium / Low |
|---|---|
| Must be fixed before release | May be listed as known issues |

## Exam and viva focus

- 🔴 What did the security review find, and what is still unprotected?

- 🟡 Equivalence partitioning and boundary value analysis, with an example.
- 🟡 Levels of testing; regression testing; verification vs validation.
