# 00.01 · How a PHP Page Is Served

> [!info] [[00.00 Project Foundations|Lesson 0]] · Stage 0 and week 1 · Priority 🔴 Core
> **Builds on:** [[00.01 How Websites Work]] · [[02.04 HTTP Protocol]] · [[02.06 Client-Server and Three-Tier Architecture]]
> **Used for:** understanding why the project's folders are arranged as they are, and what happens between typing an address and seeing a page.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Web server** | A program that waits for requests from browsers and sends files back. Here it is **Apache**. |
| **PHP** | A language that runs **on the server**. It builds an HTML page and hands it to the web server. |
| **XAMPP** | One installer that gives you Apache, PHP and MySQL on your own computer. |
| **Web root** (document root) | The folder whose contents the web server is allowed to send to browsers. |
| **Server-side rendering** | The server builds the finished HTML. The browser only displays it. |

## 2. Why it matters in PlantFolio
- It explains the folder structure: only `public/` is meant to be reachable; `includes/`, `partials/` and `config/` are locked.
- It explains why you must start Apache, and why double-clicking a `.php` file does not work.
- It explains the security rule that the browser never sees PHP code or passwords.

## 3. How it works
```text
1. You type      http://localhost/plantfolio/public/garden.php
2. Browser ───── GET /plantfolio/public/garden.php ─────▶ Apache
3. Apache finds  C:\xampp\htdocs\plantfolio\public\garden.php
4. The file ends in .php, so Apache hands it to PHP
5. PHP runs it from top to bottom:
      require helpers.php, mock-data.php      (later: db.php, auth.php)
      load the data
      include header.php → print the HTML → include footer.php
6. PHP returns finished HTML ──▶ Apache ──▶ Browser
7. The browser reads the HTML and asks for the CSS, JavaScript and images it mentions
```

| Address | File on disk |
|---|---|
| `http://localhost/` | `C:\xampp\htdocs\` |
| `http://localhost/plantfolio/public/` | `C:\xampp\htdocs\plantfolio\public\index.php` |
| `http://localhost/plantfolio/public/assets/css/variables.css` | `…\public\assets\css\variables.css` |

- A request for a **folder** is answered with its `index.php`.
- A **`.css`, `.js` or `.svg`** file is sent exactly as it is. A **`.php`** file is **executed**, and only its output is sent.
- "View source" in the browser therefore shows HTML, never PHP.

## 4. Every request starts from nothing
PHP forgets everything when a request ends. A variable set while building one page does not exist for the next page. That is why a site needs:
- a **database**, to keep data: [[03.02 PDO and Prepared Statements]];
- **sessions**, to remember who is logged in: [[03.04 PHP Sessions and Login State]].

HTTP itself works the same way; it is called **stateless**: [[02.04 HTTP Protocol]].

## 5. Why some folders are locked
`includes/`, `partials/` and `config/` each contain a file named `.htaccess` with one line:

```apache
Require all denied
```

`.htaccess` is a settings file that Apache reads for that folder. This line makes Apache refuse every request for a file in it.

| Who asks | How | Result |
|---|---|---|
| A browser | `http://localhost/plantfolio/includes/helpers.php` | **403 Forbidden** |
| A PHP page | `require __DIR__ . '/../includes/helpers.php';` | Works |

The second works because PHP reads the file **from the disk**, not through Apache. The lock is on the web door only.

On a real host the web root is set to `public/` itself, so the other folders are not reachable at all: [[06.03 Production Configuration and Release]].

## 6. Example: the smallest page
```php
<?php
// public/hello.php
require_once __DIR__ . '/../includes/helpers.php';

$name = 'Nimali';
?>
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Hello</title>
</head>
<body>
  <p>Hello, <?= e($name) ?>. It is <?= e(date('H:i')) ?>.</p>
</body>
</html>
```
The browser receives `<p>Hello, Nimali. It is 14:05.</p>`. Reload and the time changes, because PHP ran again.

## 7. Settings and errors
- Settings live in `config/config.php`, which returns an array. `config('base_url')` reads one value: [[00.03 PHP Includes and Partials]].
- `config.php` is **not in Git**; `config.example.php` is. Passwords stay on each computer: [[06.06 Environment Variables and Configuration]] explains the idea.
- In development PHP shows errors on the page. In production they must be hidden from visitors and written to a log.

## 8. Common mistakes
- **Opening the file directly** (`file:///C:/xampp/…`). The browser shows the PHP code as text. Always go through `http://localhost/`.
- **Apache is not running.** "This site can't be reached". Start it in the XAMPP Control Panel.
- **Apache will not start.** Another program is using port 80.
- **The project is not inside `htdocs`.** Apache cannot see it.
- **Editing `php.ini` and not restarting Apache.** The change is not read.
- **Expecting a variable to survive** from one page to the next.
- **Putting a secret or a helper file in `public/`.** Anything there can be requested by anyone.
- **A blank white page.** A PHP error with error display switched off. Look in the Apache or PHP error log.
