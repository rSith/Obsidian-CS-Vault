# 00.03 · PHP Includes and Partials

> [!info] [[00.00 Project Foundations|Lesson 0]] · Week 1 · Priority 🔴 Core
> **Builds on:** [[00.02 PHP Basics for Templates]]
> **Used for:** the page pattern every page follows, and the reusable pieces in `partials/`.

## 1. Definitions
| Term | Meaning |
|---|---|
| **Include** | Pulling the contents of another PHP file into the current one, at that line |
| **Partial** | A small template for one reusable piece of a page, such as a plant card |
| **`__DIR__`** | A built-in value: the full path of the folder that the current file is in |
| **Scope** | The part of the code where a variable exists |

## 2. Why it is used
- **Write once.** The header, the footer and a plant card appear on many pages. Each is one file. A change in that file changes every page.
- **Small files.** A page file says what the page contains; the details live elsewhere.
- **Consistency.** Every page gets the same helpers and the same navigation.

## 3. How it works: four ways to include
| Statement | If the file is missing | Loads the same file twice? |
|---|---|---|
| `include` | A warning; the page carries on | Yes |
| `require` | A **fatal error**; the page stops | Yes |
| `include_once` | A warning | No |
| `require_once` | A fatal error | No |

Which to use:
- **`require_once`** for files that **define functions** (`helpers.php`, later `db.php`, `auth.php`). The page cannot work without them, and loading a function twice is an error.
- **`include`** for files that **print HTML** and may appear several times (a partial).

## 4. Always build the path from `__DIR__`
```php
require_once __DIR__ . '/../includes/helpers.php';
```
A relative path such as `'../includes/helpers.php'` is resolved from the file the *browser asked for*, not from the file the line is written in. It works in one page and breaks when the same line runs from a file in another folder. `__DIR__` is always the folder of the file you are reading, so the path means the same thing everywhere.

## 5. The page pattern
Every page in the project follows this order:

```php
<?php
require_once __DIR__ . '/../includes/helpers.php';
require_once __DIR__ . '/../includes/mock-data.php';   // stage F; replaced by db.php and auth.php in stage B

$page_title = 'My Garden';
include __DIR__ . '/../includes/header.php';
?>
<!-- the page's own HTML -->
<?php include __DIR__ . '/../includes/footer.php'; ?>
```
`header.php` can read `$page_title`, because an included file shares the variables of the place it is included from.

## 6. Scope: the reason for the `partial()` helper
An included file sees **all** the page's variables and can **overwrite** them. A partial that uses `$type` internally would silently change the page's own `$type`. The project avoids this with a helper:

```php
function partial($partial_name, array $partial_data = [])
{
    extract($partial_data);   // ['plant' => $row] becomes the variable $plant

    include __DIR__ . '/../partials/' . $partial_name . '.php';
}
```
- The partial now runs **inside a function**. A function has its own scope, so the partial's variables cannot leak into the page, and the page's cannot leak in.
- The partial receives exactly what it is given, by name.
- `extract()` turns array keys into variables.

> [!warning] `extract()` is safe only on arrays you build yourself
> Used on `$_GET` or `$_POST`, it would let a visitor create or overwrite any variable in your code. Here the array is written by the page, so it is safe.

## 7. Example: one partial, two data sources
```php
<?php
// partials/status-badge.php
// Expects $status: thriving, stable, needs_attention or sick.
?>
<span class="badge badge-<?= e(str_replace('_', '-', $status)) ?>"><?= e(health_label($status)) ?></span>
```
```php
<?php foreach ($mock_plants as $plant): ?>
  <?php partial('plant-card', ['plant' => $plant]); ?>
<?php endforeach; ?>
```
The card partial expects **one row-shaped array** named `$plant`. In stage B the loop will run over rows from MySQL and the partial will not change at all: [[00.07 Mock Data Shaped Like Database Rows]].

Each partial starts with a comment saying which variable it expects. That comment is its contract.

## 8. A file can also return a value
`config/config.php` contains no HTML. It ends with `return [ … ];`, and `require` hands that array back:

```php
function config($key)
{
    static $config = null;              // keeps its value between calls

    if ($config === null) {
        $config = require __DIR__ . '/../config/config.php';
    }

    return $config[$key] ?? null;
}
```
The `static` variable means the file is read once per request, however many times `config()` is called.

## 9. Common mistakes
- **Relative paths without `__DIR__`.** "Failed to open stream: No such file or directory".
- **`include` for a file the page depends on.** The page continues half-built after a warning. Use `require_once`.
- **Loading a function file twice** with `require`. "Cannot redeclare function".
- **A partial that relies on a page variable** it was never given. It works on one page and fails on another.
- **Passing the wrong key:** `partial('plant-card', ['p' => $plant])` leaves `$plant` undefined inside.
- **Logic inside a partial.** A partial displays. Queries and decisions belong in the page or in a helper.
- **A partial for something used once.** The project's rule: make one only when the same markup appears on two or more pages.
- **`extract()` on user input.**
