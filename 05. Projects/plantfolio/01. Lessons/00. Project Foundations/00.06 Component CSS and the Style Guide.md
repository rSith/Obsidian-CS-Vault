# 00.06 · Component CSS and the Style Guide

> [!info] [[00.00 Project Foundations|Lesson 0]] · Week 1 · Task CORE-05 · Priority 🔴 Core
> **Builds on:** [[00.08 CSS Selectors, Pseudo-classes and the Cascade]] · [[00.05 CSS Custom Properties and Design Tokens]]
> **Used for:** `public/assets/css/components.css` and `public/styleguide.php`.

## 1. Definitions
| Term | Meaning | Example |
|---|---|---|
| **Component** | A reusable piece of interface with its own styles | A button, a badge, a card |
| **Base class** | The class that gives a component its shape | `.btn` |
| **Modifier** | An extra class that changes one aspect | `.btn-primary`, `.btn-sm` |
| **State class** | A class that says what condition the component is in | `.is-active`, `.is-selected` |
| **Utility** | A small class that does one job anywhere | `.visually-hidden` |
| **Style guide** | A page that shows every component in one place | `styleguide.php` |

## 2. Why it is used
- PlantFolio has 15 pages and no CSS framework. Without shared components every page would style its own buttons, and no two would match.
- A component is **built once, checked once against the wireframe, and reused**. A fix is made in one place.
- The style guide lets a reviewer check all components at 375 px and 1024 px without visiting 15 pages.

## 3. How it works: base plus modifiers
```html
<button class="btn btn-primary">Add plant</button>
<button class="btn btn-secondary btn-sm">Mark done</button>
<a class="btn btn-primary" href="plant-form.php">Add plant</a>
```
```css
.btn {                                   /* shape, shared by every button */
  display: inline-flex;
  align-items: center;
  gap: var(--space-8);
  min-height: 44px;                      /* touch target */
  padding: var(--space-8) var(--space-16);
  border: 1px solid transparent;
  border-radius: var(--radius-input);
  font-family: var(--font-body);
  font-weight: var(--weight-semibold);
  cursor: pointer;
  transition: background var(--transition-fast);
}

.btn-primary {                           /* one look */
  background: var(--color-leaf);
  color: var(--color-white);
}

.btn-primary:hover {
  background: var(--color-leaf-dark);
}
```
The snippet shows the pattern; the real rules are in `components.css`. The naming rule from `CLAUDE.md`: kebab-case, simple modifiers.

**Why single classes?** Every rule has the same low **specificity**, so the order in the file decides which one wins and nothing needs `!important`. Specificity is explained in [[00.08 CSS Selectors, Pseudo-classes and the Cascade]].

## 4. States
A control must look different in each condition. These come from the browser or from ARIA attributes, not from extra classes where one can be avoided.

| State | Selector | Note |
|---|---|---|
| Pointer over it | `:hover` | |
| Being pressed | `:active` | |
| Focused by keyboard | `:focus-visible` | Not shown after a mouse click |
| Switched off | `:disabled`, `[aria-disabled="true"]` | Links have no `disabled`, so they use the attribute |
| Has an error | `[aria-invalid="true"]` | The same attribute a screen reader announces |
| Current tab, chosen chip | `.is-active`, `.is-selected` | Set by PHP now, by JavaScript from week 5 |

Styling `[aria-invalid="true"]` directly keeps the look and the meaning tied together: an input cannot look invalid without also being announced as invalid.

## 5. The base layer
Three decisions at the top of `components.css` affect every page:

```css
*, *::before, *::after {
  box-sizing: border-box;                /* padding and border count inside the width */
}

:focus-visible {
  outline: var(--focus-outline);         /* a visible ring for keyboard users */
}

@media (prefers-reduced-motion: reduce) {
  * {
    transition: none !important;         /* respect "reduce motion" in the system settings */
  }
}
```
Again a sketch of the idea. The reduced-motion rule is one of the few accepted uses of `!important`: it must beat every component.

## 6. Real controls, restyled
The project keeps native HTML controls and changes their look, instead of building imitations from `div`s.

| Component | Built from | What you get for free |
|---|---|---|
| Toggle switch | A real checkbox | Keyboard, focus, form submission, screen-reader support |
| Segmented control (Swap / Free / Either) | Radio buttons | Exactly one choice, arrow keys, works without JavaScript |
| Checkbox and radio | The built-in ones, recoloured with `accent-color` | All normal behaviour |

`.visually-hidden` hides an element from sight and keeps it for screen readers. `display: none` hides it from everyone.

## 7. Icons
`icon('droplet')` prints the SVG code into the page (inline SVG).
- `stroke="currentColor"` makes the icon take the colour of the surrounding text.
- Its size is in `em`, so it scales with that text.
- It is `aria-hidden="true"`: the words beside it carry the meaning. A button with only an icon needs an `aria-label`.

## 8. Example: reading the style guide
`styleguide.php` loads the helpers and the mock data, then prints each component with loops like this one:

```php
<?php foreach ($health_statuses as $status => $meaning): ?>
  <div class="sg-status-row">
    <?php partial('status-badge', ['status' => $status]); ?>
    <span><?= e($meaning) ?></span>
  </div>
<?php endforeach; ?>
```
How to use it:
1. Open `http://localhost/plantfolio/public/styleguide.php` beside wireframe p7.
2. Check each component at 375 px and at 1024 px in the browser's device toolbar.
3. Tab through the page: is the focus ring always visible?
4. A new component is added here **first**, then used on a page.

Classes starting with `sg-` belong to the gallery page only. The page is for development and is removed or protected before release.

## 9. Common mistakes
- **Overriding a component for one page** (`.dashboard .btn { … }`). The next page then looks different. Add a modifier to the component instead.
- **A raw value** in a component instead of a token.
- **Long selectors** such as `main .cards .card h3 a`. They break when the HTML changes and are hard to override.
- **`!important` to win an argument** between two rules. Fix the selectors.
- **`outline: none`** with nothing in its place. Keyboard users lose track of where they are.
- **A `div` with a click handler** where a `<button>` belongs.
- **Colour as the only signal.** Every badge contains its word.
- **A touch target smaller than 44 × 44 px** on a phone.
- **Using a component on a page before it is in the style guide.**

## 10. Exam and viva focus
- **What is a CSS component, and why build a design system?** Reuse, consistency, maintainability.
- **Specificity:** inline styles beat IDs, which beat classes, which beat elements. Why low and equal specificity is easier to maintain.
- **Pseudo-classes:** `:hover`, `:focus`, `:focus-visible`, `:disabled`.
- **`box-sizing: border-box`** and the box model: content, padding, border, margin.
- **Internal, external and inline CSS:** why an external stylesheet is preferred.
- **Why prefer native form controls?**
