# 04.99 · Lesson Summary: Core Features

> [!abstract] Back to [[04.00 Core Features]] · Progress: [[PlantFolio Week 09 - Core Features and Gate 1]] · [[PlantFolio Week 10 - Community, Exchange and Gate 2]]

## Must know
- **Wiring recipe:** write a query that returns the mock array's shape → swap it in → the page must look the same → delete the mock → make the forms save → test. **One array at a time.**
- **CRUD:** Create `INSERT` (POST) · Read `SELECT` (GET) · Update `UPDATE` (POST) · Delete `DELETE` (POST).
- **Every write:** POST, `csrf_verify()` first, user ID from the session, server validation, prepared statement with named columns, `AND user_id = :user_id`, flash, redirect, `exit`.
- **`rowCount()` of 0** means "no such row" **or** "nothing changed".
- **One form for add and edit;** an ID in the address decides.
- **Delete the database row first, then the files.** `CASCADE` removes child rows; PHP removes files.
- **Uploads, five defences:** check `error` and `size` → check the **content** with `finfo` against a whitelist → random name with your own extension → re-encode through GD while resizing → the uploads folder never executes code.
- **Never trust `$_FILES[…]['name']` or `['type']`.** Store only the file name in the database.
- **GD must be enabled** in `php.ini` (it was off on this computer).
- **Reminders:** `next_due = last_done + interval_days`. Nothing runs in the background; "due" is worked out when someone looks. Store dates, calculate the state.
- **One clock:** PHP's date, passed into each query.
- **A reminder's owner is reached through its plant.**
- **Search:** `LIKE :q` with the wildcards in the value; escape `%` and `_`; conditions built from fixed text and placeholders; `ORDER BY` from a whitelist; `LIMIT` and `OFFSET` bound as integers.
- **Pagination:** offset = (page − 1) × 12; count with the same `WHERE`; a stable `ORDER BY`; page links keep the filters.
- **Fixed conditions** (`is_public = 1`, `status = 'open'`) are always in the query.
- **Counts and averages are calculated, not stored.** Two one-to-many joins multiply counts: use subqueries. `AVG` of nothing is `NULL`.
- **Rating rules:** score 1–5, **`UNIQUE (rater_id, listing_id)`**, never yourself, only the two traders, only after the exchange, rater from the session.

```sql
UPDATE care_reminders
SET last_done = :today, next_due = DATE_ADD(:today2, INTERVAL interval_days DAY)
WHERE id = :id;

SELECT (SELECT COUNT(*) FROM plants p WHERE p.user_id = u.id) AS plant_count,
       (SELECT ROUND(AVG(r.score), 1) FROM user_ratings r WHERE r.rated_id = u.id) AS rating_avg
FROM users u WHERE u.id = :id;
```

## Important comparisons
| `INNER JOIN` | `LEFT JOIN` |
|---|---|
| Only rows with a match | Every left row; `NULL` where no match |
| Plants that have a reminder | All plants |

| Stored value | Derived value |
|---|---|
| Must be kept up to date | Always agrees with the data |

| Whitelist | Blacklist |
|---|---|
| Accept only known good | Reject known bad |
| Safer | Always incomplete |

| Browser upload check | Server upload check |
|---|---|
| Speed and convenience | The actual protection |

| Offset pagination | Keyset pagination |
|---|---|
| Page numbers; slow on deep pages | Fast; next and previous only |

| `COUNT(*)` | `COUNT(column)` |
|---|---|
| All rows | Rows where the column is not `NULL` |
