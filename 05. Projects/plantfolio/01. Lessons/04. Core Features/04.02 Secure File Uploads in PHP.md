# 04.02 · Secure File Uploads in PHP

> [!info] [[04.00 Core Features|Lesson 4]] · Week 9 · Task CORE-17 · Priority 🔴 Core
> **Builds on:** [[02.05 Upload Preview with the File API]] (the browser side) · [[13.08 Code Injection]] · [[13.10 Best Practices for Securing a Website]]
> **Used for:** `includes/upload.php`, which handles every plant photo, health-log photo and avatar.

## 1. Definitions
| Term | Meaning |
|---|---|
| **`$_FILES`** | PHP's array describing each uploaded file |
| **Temporary file** | Where PHP first stores an upload. It is deleted when the request ends unless you keep it. |
| **MIME type** | A label for a file's real format, such as `image/jpeg` |
| **`finfo`** | A PHP class that works out a file's type by **reading its content** |
| **GD** | PHP's image library: open, resize and save pictures |

## 2. Why it is used
An upload form lets a stranger put a file on your server. That is the most dangerous thing a website offers. The worst case: someone uploads `shell.php`, then opens `…/uploads/shell.php` in a browser, and Apache **runs it**. They now control the site.

The rule in `CLAUDE.md` lists the defences: *"check MIME with `finfo` (JPG/PNG), max 5 MB, random file names, resize to 1600 px, never execute uploaded files."*

## 3. How it works: what arrives
```php
<?php
// After submitting <input type="file" name="photo"> in a multipart form:
$_FILES['photo'] = [
    'name'     => 'my plant.jpg',          // chosen by the user: NEVER trust or use as a path
    'type'     => 'image/jpeg',            // claimed by the browser: NEVER trust
    'tmp_name' => 'C:\xampp\tmp\phpA1.tmp', // where PHP put the file
    'error'    => 0,                       // 0 = UPLOAD_ERR_OK
    'size'     => 2483921,                 // bytes
];
```
Two of the five values come from the user and can be anything. Only `tmp_name`, `error` and `size` come from PHP.

## 4. The five defences
| # | Defence | Stops |
|---|---|---|
| 1 | Check `error` and `size` | Failed, missing or oversized uploads |
| 2 | Check the **content** with `finfo`, against a whitelist | `shell.php` renamed to `photo.jpg` |
| 3 | A **random name** with an extension **you** choose | Overwriting files, path tricks such as `../../index.php`, guessable addresses |
| 4 | **Re-encode** the image through GD while resizing | Hidden data inside the file; huge images; location data in the photo |
| 5 | The uploads folder **never executes** anything | A script that got through anyway |

## 5. Example: the handler
```php
<?php
// includes/upload.php: one function for every photo upload (CORE-17)

/**
 * Check, resize and store an uploaded photo.
 * Returns ['ok' => true, 'file' => 'a3f9….jpg'] or ['ok' => false, 'error' => 'message for the user'].
 */
function save_uploaded_photo(array $file): array
{
    // 1. Did the upload itself work, and is it within the limit?
    if (($file['error'] ?? UPLOAD_ERR_NO_FILE) !== UPLOAD_ERR_OK || !is_uploaded_file($file['tmp_name'])) {
        return ['ok' => false, 'error' => 'The photo could not be uploaded. Try again.'];
    }
    if ($file['size'] > config('max_upload_mb') * 1024 * 1024) {
        return ['ok' => false, 'error' => 'That photo is larger than ' . config('max_upload_mb') . ' MB.'];
    }

    // 2. What is it really? Read the content, ignore the name and the browser's claim.
    $extensions = ['image/jpeg' => 'jpg', 'image/png' => 'png'];      // the whitelist
    $mime = (new finfo(FILEINFO_MIME_TYPE))->file($file['tmp_name']);
    if (!isset($extensions[$mime])) {
        return ['ok' => false, 'error' => 'Choose a JPG or PNG photo.'];
    }

    // 3. Open it as an image. A file that is not a real image fails here.
    $image = $mime === 'image/jpeg'
        ? @imagecreatefromjpeg($file['tmp_name'])
        : @imagecreatefrompng($file['tmp_name']);
    if ($image === false) {
        return ['ok' => false, 'error' => 'That file could not be read as a photo.'];
    }

    // 4. Shrink it so the long side is at most max_image_px
    $width  = imagesx($image);
    $height = imagesy($image);
    $max    = config('max_image_px');

    if (max($width, $height) > $max) {
        $scale = $max / max($width, $height);
        $image = imagescale($image, (int) round($width * $scale), (int) round($height * $scale));
    }

    // 5. Save under a random name, with the extension WE decided
    $name   = bin2hex(random_bytes(16)) . '.' . $extensions[$mime];
    $target = config('upload_dir') . '/' . $name;

    $saved = $mime === 'image/jpeg' ? imagejpeg($image, $target, 85) : imagepng($image, $target);
    imagedestroy($image);

    if (!$saved) {
        return ['ok' => false, 'error' => 'The photo could not be saved.'];
    }

    return ['ok' => true, 'file' => $name];
}
```
Using it:
```php
<?php
if (!empty($_FILES['photo']['name'])) {
    $upload = save_uploaded_photo($_FILES['photo']);

    if ($upload['ok']) {
        $photo = $upload['file'];              // store this file name in plants.photo
    } else {
        $errors['photo'] = $upload['error'];
    }
}
```
- **The database stores only the file name.** The file lives in `public/uploads/`. `photo_url()` in the helpers is the one line that changes to point there.
- **Re-encoding** means the saved file is a new image drawn by GD. Anything hidden in the original is gone, including the **location data** phones embed in photos.
- When a photo is replaced, delete the old file.

> [!warning] GD must be switched on
> The image functions above come from the GD extension. On this computer it was **not loaded** on 8 Oct 2026: `C:\xampp\php\php.ini` had `;extension=gd`. Remove the semicolon, restart Apache, and add the step to the README so each teammate does the same. Without GD the page stops with "Call to undefined function imagecreatefromjpeg()".

## 6. The uploads folder must not run code
Put a `.htaccess` file in `public/uploads/`:
```apache
# Never treat anything in this folder as a script
<FilesMatch "\.(php|phtml|phar|pl|py|cgi)$">
    Require all denied
</FilesMatch>
```
Even if a script were somehow saved there, Apache refuses to serve it.

> [!note] One detail with Git
> The project's `.gitignore` ignores everything in `public/uploads/` except `.gitkeep`. A `.htaccess` placed there would be ignored too, and teammates would not receive it. Add an exception line for it, as was done for `.gitkeep`.

## 7. Limits in three places
| Where | Setting | This computer |
|---|---|---|
| The project | `max_upload_mb` in `config.php` | 5 |
| PHP | `upload_max_filesize` and `post_max_size` in `php.ini` | 40M each |
| The browser | `MAX_BYTES` in the script | 5 MB |

PHP's limits must be **at least** the project's. If a request is larger than `post_max_size`, PHP discards it entirely: `$_POST` and `$_FILES` arrive **empty**, and the page sees a form with no fields and no CSRF token. Treat that case as "the file was too large".

## 8. Common mistakes
- **Trusting `$_FILES['photo']['type']`** or the file's extension.
- **Saving under the user's file name.** `../../public/index.php`, or simply two people uploading `IMG_0001.jpg`.
- **A blacklist of bad extensions** instead of a whitelist of good types. There is always one more extension.
- **`move_uploaded_file()` straight into the web root** with no checks.
- **No size limit,** or only the browser's.
- **Allowing SVG.** An SVG file can contain scripts.
- **An uploads folder that executes PHP.**
- **Storing the image in the database** as binary data. Store the path; keep files on disk, as the project's rules say.
- **Not deleting the old photo** when it is replaced.
- **Phone photos that appear sideways.** Phones record the rotation in the photo's metadata, which re-encoding removes. Read it with `exif_read_data()` and rotate before saving.
- **Showing PHP's own upload error** to the user.
- **Committing uploads to Git.**

## 9. Exam and viva focus
- **Risks of file upload:** remote code execution, overwriting files, denial of service through large files, malware distribution.
- **Defences:** whitelist by content type, size limit, rename, store outside the web root or disable execution, re-process images.
- **What must an upload form have?** `method="post"` and `enctype="multipart/form-data"`.
- **Whitelist vs blacklist validation.**
- **Why is the client-supplied MIME type untrustworthy?**
- **Path traversal:** using `../` to escape the intended folder.
- **Defence in depth:** several independent protections, so one failure is not fatal.
- **Viva:** "I rename `virus.php` to `leaf.jpg` and upload it. Follow it through your code." · "Why are the file names random?" · "What is stored in the `plants.photo` column?"
