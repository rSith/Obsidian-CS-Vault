# 05.04 · Prediction Intervals and Quantile Regression

> [!info] [[05.00 Evaluation and Alerts|Lesson 5]] · Roadmap Phase 5 · Priority 🟡 Supporting
> **Parent concept:** [[Regression]]
> **Used for:** the `lower` and `upper` columns of every forecast, and the shaded band on the dashboard chart.

## 1. Definitions
> [!note] Point forecast
> A **point forecast** is a single number: "262 cases".

> [!note] Prediction interval
> A **prediction interval** is a range that the real value should fall inside with a stated probability: "between 180 and 390 cases, with 80 % probability".

> [!note] Quantile
> The **quantile** $q$ of a quantity is the value that it falls below with probability $q$. The 0.9 quantile is the level that is exceeded only 10 % of the time. The 0.5 quantile is the median.

> [!note] Quantile regression
> **Quantile regression** trains a model to predict a chosen quantile instead of the average.

## 2. Why it is used
"262 cases" hides how sure the model is. "262, probably between 240 and 290" and "262, anywhere between 90 and 700" call for different decisions. Showing the range is more honest, and it lets an alert depend on **how likely** a high count is.

## 3. How it works: the pinball loss
Ordinary regression minimises squared error and learns the average. Quantile regression minimises the **pinball loss**, which punishes being too low and being too high **by different amounts**:

$$L_q(y, \hat{y}) = \begin{cases} q \cdot (y - \hat{y}) & \text{if } y \ge \hat{y} \quad \text{(forecast too low)} \\ (1 - q) \cdot (\hat{y} - y) & \text{if } y < \hat{y} \quad \text{(forecast too high)} \end{cases}$$

### Worked example, $q = 0.9$
The truth is 100.

| Forecast | Off by | Loss |
|---|---|---|
| 80 (too low) | 20 | $0.9 \times 20 = 18$ |
| 120 (too high) | 20 | $0.1 \times 20 = 2$ |

Being too low costs nine times as much as being too high. To keep the loss small, the model pushes its forecasts **up**, until the truth is below them about 90 % of the time. That is the 0.9 quantile.

With $q = 0.5$ both sides cost the same, and the model learns the **median**.

## 4. Syntax
Train one model per quantile:
```python
from sklearn.ensemble import HistGradientBoostingRegressor

def fit_quantile(q: float):
    return HistGradientBoostingRegressor(loss="quantile", quantile=q, learning_rate=0.05,
                                         max_iter=300, early_stopping=False,
                                         random_state=42).fit(X_train, y_train)

models = {q: fit_quantile(q) for q in (0.1, 0.5, 0.9)}
lower, median, upper = (models[q].predict(X_val) for q in (0.1, 0.5, 0.9))
```
From the 0.1 quantile to the 0.9 quantile is an **80 % prediction interval**.

## 5. Example: check the interval
An interval is only useful if it is **honest**. Two checks:

```python
from sklearn.metrics import mean_pinball_loss

coverage = ((y_val >= lower) & (y_val <= upper)).mean()   # should be close to 0.80
width = (upper - lower).mean()                             # narrower is better, IF coverage holds
mean_pinball_loss(y_val, upper, alpha=0.9)                 # the score for one quantile
```

| Coverage of an 80 % interval | Meaning |
|---|---|
| About 0.80 | Well **calibrated**: it means what it says |
| 0.55 | Too narrow: the model is over-confident |
| 0.97 | Too wide: honest but not useful |

A narrow interval with correct coverage is the goal. Report both numbers.

## 6. Using intervals for alerts
A forecast of the average is smoother than reality, so it rarely crosses the Warning line ([[05.02 Endemic Channel and Alert Thresholds]]). Quantiles give a graded rule:

| Situation | Meaning | Alert |
|---|---|---|
| Even the **lower** quantile is above the line | Very likely to exceed it | Warning, high confidence |
| The **median** is above the line | More likely than not | Warning |
| Only the **upper** quantile is above the line | Possible | Watch |
| Nothing is above the line | Unlikely | Normal |

Choose the rule on validation data, and score it with [[05.03 Alert Metrics - Precision, Recall and Lead Time]].

## 7. Two intervals that are often confused
| | **Confidence interval** | **Prediction interval** |
|---|---|---|
| About | An estimated quantity, such as an average or a weight | One future observation |
| Answers | Where is the true *average*? | Where will *next week's count* fall? |
| Width | Narrower | Wider, because single values scatter |

A forecast needs a **prediction** interval.

## 8. Common mistakes
- **Reporting an interval without checking its coverage.**
- **Checking coverage on the training data.** Use validation data.
- **Quantile crossing.** Separate models can give a lower bound above the median. Sort the three predictions for each row.
- **Too little data for extreme quantiles.** The 0.99 quantile needs far more data than the 0.9.
- **Calling it a confidence interval.**
- **Using Poisson's formula for the range** when the data is overdispersed: [[04.05 Poisson Regression for Counts]].
- **Hiding the uncertainty on the dashboard** because the band looks wide. The width is information.
