# 04.06 · Gradient Boosting

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🔴 Core
> **Parent concepts:** [[Decision Trees]] · [[Random Forest]]. Read those first. This note covers boosting, the other way to combine trees.
> **Used for:** usually the strongest model on a table of features like this project's.

## 1. Definitions
> [!note] Ensemble
> An **ensemble** combines many simple models into one stronger model.

> [!note] Gradient boosting
> **Gradient boosting** builds decision trees **one after another**. Each new tree is trained to correct the errors left by all the trees before it. The final prediction is the sum of all the trees.

## 2. Why it is used
- It finds **non-linear** patterns without being told: "rain helps up to a point, then stops helping".
- It finds **interactions**: "rain matters more when it is also warm".
- It needs **no scaling** of features.
- scikit-learn's version accepts **missing values** directly.
- On tabular data it is very often the most accurate method available.

## 3. How it works
For squared error:
1. Start with one number for every row: the average of the target. Call the current prediction $F_0$.
2. Work out the **residuals**: what is still wrong, $r_i = y_i - F_0(x_i)$.
3. Fit a **small tree** $h_1$ to predict those residuals.
4. Add a fraction of it to the model: $F_1 = F_0 + \nu \cdot h_1$.
5. Repeat from step 2 with the new residuals, hundreds of times.

$$F_m(x) = F_{m-1}(x) + \nu \cdot h_m(x)$$

$\nu$ is the **learning rate**, a number such as 0.05. Taking small steps makes the model slower to build and better at generalising.

> [!example] A tiny example
> Truth is 100. Start at the average, 60. The residual is 40. Tree 1 predicts 35; with $\nu = 0.1$ the model moves to $60 + 3.5 = 63.5$. The residual is now 36.5. Tree 2 works on that, and so on. Each tree makes a small correction.

For other losses (Poisson, quantile), "residual" is replaced by the **gradient** of the loss, which is where the name comes from.

## 4. Bagging vs boosting
| | **[[Random Forest]] (bagging)** | **Gradient boosting** |
|---|---|---|
| Trees are built | Independently, in parallel | One after another |
| Each tree learns | The target, on a random sample | The errors of the trees so far |
| Trees are | Deep | Shallow |
| Combined by | Averaging | Adding |
| Mainly reduces | Variance (instability) | Bias (systematic error) |
| More trees | Never hurts | Can overfit |
| Tuning | Little needed | Matters |

## 5. Syntax
```python
from sklearn.ensemble import HistGradientBoostingRegressor

model = HistGradientBoostingRegressor(
    loss="poisson",            # suits counts; "squared_error" is the default
    learning_rate=0.05,        # step size
    max_iter=400,              # number of trees
    max_depth=4,               # how deep each tree may grow
    min_samples_leaf=20,       # smallest group a leaf may hold
    l2_regularization=1.0,
    early_stopping=False,      # see the warning below
    random_state=42,
)
model.fit(X_train, y_train)
```

| Setting | Higher value means | Risk |
|---|---|---|
| `learning_rate` | Bigger steps | Overfitting; unstable |
| `max_iter` | More trees | Overfitting if the learning rate is not lowered |
| `max_depth` | More complex trees | Overfitting |
| `min_samples_leaf` | Simpler trees | Underfitting |

`learning_rate` and `max_iter` work as a pair: halve one, roughly double the other. XGBoost and LightGBM are other libraries built on the same idea, with similar settings.

> [!warning] Early stopping and time
> Early stopping halts training when a held-out score stops improving. In scikit-learn the held-out part is a **random** sample of the training rows, and it switches on by itself for more than 10,000 rows. A random sample of a time series is too easy to predict ([[04.01 Time-Based Splits and Time-Series Cross-Validation]]). Set `early_stopping=False` and choose `max_iter` with your time folds.

## 7. A limit that matters for outbreaks
> [!warning] Trees cannot predict beyond what they have seen
> A tree's prediction is an average of training values in a leaf. It can never output a number larger than the largest it was trained on. If the next epidemic is bigger than any in the training years, a tree model **will under-predict it**. Linear and Poisson models can extend a trend; trees cannot.
>
> Ways to soften this: predict a **rate** or a **ratio to recent cases** instead of the raw count; keep a linear or Poisson model alongside and compare them during outbreaks; and state the limit in your report.

## 8. Common mistakes
- **A high learning rate with many trees.** Training error falls to nearly zero and validation error rises.
- **Tuning on the test set.**
- **Leaving early stopping on** with time-ordered data.
- **Judging by training error.** A boosted model can fit the training data almost perfectly.
- **Ignoring the extrapolation limit** in a project about unusually high counts.
- **Scaling the features "to be safe".** Harmless, but unnecessary for trees.
- **Not fixing `random_state`,** so results change from run to run.

## 9. Exam and viva focus
- **Define** ensemble learning and gradient boosting.
- **Bagging vs boosting:** the table above. This is the most likely question.
- **What does each new tree learn?** The residuals (errors) of the current model.
- **Role of the learning rate:** shrinks each tree's contribution; smaller is slower and usually more accurate.
- **Weak learner:** a simple model only a little better than guessing, such as a shallow tree.
- **How does boosting overfit, and how is that controlled?** Too many or too deep trees; control with learning rate, tree depth, leaf size, early stopping.
- **Why can tree models not extrapolate?** Predictions are averages of training targets.
