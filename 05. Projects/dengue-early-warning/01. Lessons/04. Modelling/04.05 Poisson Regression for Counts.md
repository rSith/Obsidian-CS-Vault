# 04.05 · Poisson Regression for Counts

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🟡 Supporting
> **Parent concepts:** [[Regression]] · [[Linear Regression]]
> **Used for:** a model built for what dengue data actually is: whole numbers that are never negative.

## 1. Definitions
> [!note] Count data
> **Count data** records how many times something happened: 0, 1, 2, 3, … It is never negative and never a fraction.

> [!note] Poisson regression
> **Poisson regression** is a regression model for counts. It predicts the **expected count** and guarantees that the prediction is positive.

## 2. Why it is used
Ordinary linear regression assumes the errors are about the same size everywhere and can go either way. Case counts break both assumptions:

| Property of case counts | Problem for linear regression |
|---|---|
| Never below zero | It can predict −15 cases |
| Skewed: many small weeks, a few huge ones | The huge weeks dominate the squared error |
| Spread grows with the level: quiet weeks vary by a few cases, peak weeks by hundreds | It assumes the same spread everywhere |
| Effects multiply: rain raises cases by a *percentage* | It assumes effects *add* a fixed number |

## 3. How it works
**The Poisson distribution** gives the probability of seeing $k$ events when the expected number is $\lambda$:

$$P(Y = k) = \frac{\lambda^{k} e^{-\lambda}}{k!} \qquad \text{mean} = \text{variance} = \lambda$$

**The model** predicts the expected count $\mu$ through a logarithm:

$$\log(\mu) = w_1 x_1 + w_2 x_2 + \dots + b \qquad\Longleftrightarrow\qquad \mu = e^{\,w_1 x_1 + w_2 x_2 + \dots + b}$$

- The exponential is always positive, so **$\mu$ can never be negative**.
- The logarithm here is called the **link function**.
- Effects are **multiplicative**. Raising $x_j$ by one unit multiplies the expected count by $e^{w_j}$.

**The loss** it minimises is the Poisson deviance, not squared error:

$$D = 2\sum_{i}\left[\,y_i \log\frac{y_i}{\mu_i} - (y_i - \mu_i)\right]$$

It judges an error **relative to the level**: being wrong by 20 when the truth is 30 costs far more than being wrong by 20 when the truth is 2,000.

## 4. Syntax
```python
from sklearn.linear_model import PoissonRegressor
from sklearn.metrics import mean_poisson_deviance
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(StandardScaler(),
                      PoissonRegressor(alpha=0.01, max_iter=500))
model.fit(X_train, y_train)            # y must be >= 0
pred = model.predict(X_val)            # always > 0

mean_poisson_deviance(y_val, pred)
```
`alpha` is an L2 penalty, as in [[04.03 Regularisation - Ridge and Lasso]]. Tree models can use the same loss: `HistGradientBoostingRegressor(loss="poisson")`, see [[04.06 Gradient Boosting]].

## 5. Example: reading a weight
Suppose the weight for standardised four-week rainfall is $w = 0.18$.

$$e^{0.18} \approx 1.20$$

Reading: *"When four-week rainfall is one standard deviation higher, expected cases are about 20 % higher, other things equal."* A percentage is much easier to explain to a health officer than "plus 9.1 cases".

## 6. Districts of different sizes
Colombo has many times the population of a small district, so it has more cases for the same risk. Two ways to handle this:
- model the **rate** `cases / population` and weight each row by population:
  ```python
  model.fit(X_train, y_train / pop_train, poissonregressor__sample_weight=pop_train)
  ```
  and multiply the prediction by population to get cases back;
- or include the district as a feature and let the model learn each district's level.

## 7. Overdispersion
> [!warning] Real outbreaks vary more than Poisson allows
> Poisson assumes variance = mean. Epidemic data nearly always has **variance much larger than the mean**. This is **overdispersion**. The predicted *average* is still usable, but any uncertainty range worked out from the Poisson formula would be far too narrow. The standard remedy is the **negative binomial** model, which has an extra parameter for the spread (available in `statsmodels`). For uncertainty in this project, use [[05.04 Prediction Intervals and Quantile Regression]] instead.

## 8. An alternative: log-transform the target
Train an ordinary model on $\log(1 + y)$ and convert back:
```python
model.fit(X_train, np.log1p(y_train))
pred = np.expm1(model.predict(X_val))
```
This also keeps predictions positive and tames the skew. The converted predictions tend to be a little low on average, because the average of logs is not the log of the average.

## 9. Common mistakes
- **Squared-error regression on raw counts**, then surprise at negative predictions.
- **Not scaling the features.** `PoissonRegressor` is regularised and its solver converges poorly on unscaled data.
- **Reading weights as additive.** They are multiplicative: use $e^{w}$.
- **Trusting Poisson uncertainty** when the data is overdispersed.
- **Forgetting population** when comparing districts.
- **Comparing models on different scales.** Compare all models on the same metric in **case units**, such as MAE on the original counts.

## 10. Exam and viva focus
- **When is Poisson regression used?** The target is a count.
- **Poisson distribution:** formula; mean = variance = $\lambda$.
- **Link function:** $\log(\mu) = w \cdot x + b$; why it keeps predictions positive.
- **Interpret a coefficient:** a one-unit rise multiplies the expected count by $e^{w}$.
- **Overdispersion:** variance greater than the mean; remedy is the negative binomial.
- **Linear vs Poisson regression:** additive vs multiplicative effects; any real number vs positive only; constant spread vs spread that grows with the mean.
- **Generalised linear model (GLM):** linear regression, logistic regression and Poisson regression are members of one family that differ in their link and distribution. See [[Logistic Regression]].
