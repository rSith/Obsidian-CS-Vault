# 04.03 · Regularisation: Ridge and Lasso

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🔴 Core
> **Parent concepts:** [[04. Concepts/Machine Learning/Linear Regression|Linear Regression]] · [[Multiple Linear Regression]] · [[04. Concepts/Machine Learning/Regression|Regression]]. Read those first; this note adds only the penalty.
> **Used for:** the first real model, and for seeing which features carry weight.

## 1. Definition
> [!note] Regularisation
> **Regularisation** adds a **penalty for large weights** to a model's cost function. The model must then fit the data *and* keep its weights small, which stops it from fitting noise.

> [!note] Overfitting
> **Overfitting** is when a model learns the training data too closely, including its random noise, and so predicts new data badly.

## 2. Why it is used
- This project has many features that are almost copies of each other: rain at lag 2, lag 4, lag 6, rolling rain. Plain linear regression handles such features badly. It can give one a huge positive weight and its neighbour a huge negative weight that nearly cancel out. Predictions on new data then swing wildly.
- There are only a few hundred weeks per district. Few examples plus many features is the recipe for overfitting.

## 3. How it works
Plain linear regression chooses weights $w$ to minimise the squared error:

$$J(w, b) = \frac{1}{2m}\sum_{i=1}^{m}\left(\hat{y}_i - y_i\right)^2$$

Regularisation adds a second term:

$$\text{Ridge (L2):}\quad J = \frac{1}{2m}\sum_{i=1}^{m}\left(\hat{y}_i - y_i\right)^2 + \frac{\lambda}{2m}\sum_{j=1}^{n} w_j^2$$

$$\text{Lasso (L1):}\quad J = \frac{1}{2m}\sum_{i=1}^{m}\left(\hat{y}_i - y_i\right)^2 + \frac{\lambda}{m}\sum_{j=1}^{n} \lvert w_j \rvert$$

- $m$ = number of examples, $n$ = number of features.
- $\lambda$ sets the strength of the penalty. scikit-learn calls it `alpha`.
- The intercept $b$ is not penalised.

| $\lambda$ | Effect |
|---|---|
| $0$ | Ordinary linear regression |
| Small | Weights shrink slightly |
| Large | Weights pushed towards zero; the model becomes too simple (**underfitting**) |

| | **Ridge (L2)** | **Lasso (L1)** |
|---|---|---|
| Penalty | Sum of squared weights | Sum of absolute weights |
| Effect on weights | Shrinks all of them; none becomes exactly zero | Sets some **exactly to zero** |
| So it also does | Stabilises correlated features | **Feature selection** |
| With correlated features | Shares the weight among them | Keeps one, drops the rest, fairly arbitrarily |
| Use when | Many related features (this project) | You want a short list of features |

## 4. Scaling comes first
> [!important] Standardise the features before regularising
> The penalty treats every weight alike. Rainfall is in hundreds of millimetres and a sine value lies between −1 and 1, so their weights are on very different scales and would be penalised unfairly. **Standardising** puts every feature on the same scale:
> $$z = \frac{x - \mu}{\sigma}$$
> where $\mu$ and $\sigma$ are the mean and standard deviation of that feature **in the training data**.

## 5. Syntax
```python
from sklearn.linear_model import Ridge, RidgeCV, LassoCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(StandardScaler(), Ridge(alpha=1.0))
model.fit(X_train, y_train)

# Let cross-validation choose alpha, using the time folds from note 04.01
model = make_pipeline(StandardScaler(),
                      RidgeCV(alphas=[0.01, 0.1, 1, 10, 100], cv=folds))
model.fit(X, y)
model[-1].alpha_          # the chosen strength
model[-1].coef_           # one weight per feature
```

Reading: the newest case count matters most; four-week rainfall adds to it; `rain_lag2` adds almost nothing beyond the others. Check the signs against biology: more rain and more warmth should raise cases ([[00.03 Dengue Transmission and the Mosquito Life Cycle]]). The numbers here are invented.

## 7. Common mistakes
- **Not scaling.** The penalty then punishes features according to their units.
- **Scaling with statistics from all the data.** Fit the scaler on training data only, inside a pipeline: [[04.04 scikit-learn Pipelines and ColumnTransformer]].
- **Choosing `alpha` on the test set.**
- **Reading too much into the weights of correlated features.** Ridge shares weight among them, so no single one tells the whole story.
- **Assuming a zero weight in Lasso means the feature is useless.** Its information may be carried by a correlated feature that was kept.
- **Predicting negative cases.** A linear model can. Clip predictions at zero, or use [[04.05 Poisson Regression for Counts]].

## 8. Exam and viva focus
- **Define** regularisation, overfitting and underfitting.
- **Write the Ridge cost function** and name each term.
- **L1 vs L2:** the comparison table above.
- **What happens as $\lambda \to 0$ and as $\lambda \to \infty$?** Ordinary regression; all weights towards zero.
- **Bias–variance trade-off:** more regularisation raises bias and lowers variance.
- **Why standardise first?** So the penalty treats all features equally.
- **How is $\lambda$ chosen?** Cross-validation.
