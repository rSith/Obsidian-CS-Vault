# 04.01 · Time-Based Splits and Time-Series Cross-Validation

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🔴 Core
> **Parent concept:** [[Model Evaluation]]
> **Used for:** every accuracy number in the project. If the split is wrong, no later result can be trusted.

## 1. Definitions
> [!note] Time-based split
> A **time-based split** divides the data by date: the model **trains on earlier weeks** and is **tested on later weeks**.

> [!note] Time-series cross-validation
> **Time-series cross-validation** repeats that several times, moving forward through time, and averages the results. It is also called **walk-forward validation**.

## 2. Why it is used
The usual method, shuffling the rows and taking 20 % as a test set, is wrong here. With shuffling, the model trains on week 30 and is tested on week 29. Because neighbouring weeks are nearly identical, it scores very well without learning anything useful. In real use it will only ever predict weeks **after** its training data, so that is how it must be tested.

## 3. How it works: three sets
```text
2012 ─────────────────────── 2021 │ 2022 ───── 2023 │ 2024 ──────────▶
            TRAIN                 │   VALIDATION    │      TEST
   the model learns from this     │ choose the model│ opened ONCE, at the end
```

| Set | Used for | How often |
|---|---|---|
| **Train** | Fitting the model | Every experiment |
| **Validation** | Comparing models, tuning settings, choosing thresholds | Every experiment |
| **Test** | One final, honest measurement | **Once** |

The years are an example. Choose them from the data you actually have.

## 4. How it works: walk-forward folds
One validation period can be lucky or unlucky. Using several gives a steadier estimate.

```text
Fold 1:  train ████████░░ gap ░░ validate ▓▓▓▓
Fold 2:  train ████████████░░ gap ░░ validate ▓▓▓▓
Fold 3:  train ████████████████░░ gap ░░ validate ▓▓▓▓
                                                        time ─▶
```
Each fold trains on everything before its validation block. The training set grows; this is an **expanding window**.

## 5. The gap
> [!important] Leave a gap of $h$ weeks between training and validation
> A row made at week $t$ has its answer at week $t + h$. The last $h$ training rows therefore have answers that fall **inside the validation period**. Without a gap, the model has already seen some validation outcomes. Dropping the last $h$ weeks before each validation block fixes this.

## 6. Syntax
For **one series** already sorted by time, scikit-learn does it directly:
```python
from sklearn.model_selection import TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5, gap=4)      # gap counted in ROWS
```

For this project's table, with **many districts per week**, split on the **dates** yourself:
```python
import numpy as np

def time_folds(df, n_splits=3, val_weeks=52, gap_weeks=4):
    """Yield (train_positions, val_positions). `df` must have a 0..n-1 index."""
    weeks = np.sort(df["week_start"].unique())
    for i in range(n_splits, 0, -1):
        val_end = len(weeks) - (i - 1) * val_weeks
        val_start = val_end - val_weeks
        train_end = val_start - gap_weeks
        train = df.index[df["week_start"].isin(weeks[:train_end])]
        val = df.index[df["week_start"].isin(weeks[val_start:val_end])]
        yield train, val

df = df.reset_index(drop=True)
folds = list(time_folds(df))
```
Every district's rows for a given week land on the same side of the split. The list `folds` can be passed as `cv=folds` to scikit-learn's search tools.

## 7. Example: tuning with the folds
```python
from sklearn.model_selection import GridSearchCV

search = GridSearchCV(model, {"model__alpha": [0.1, 1, 10, 100]},
                      cv=folds, scoring="neg_mean_absolute_error")
search.fit(X, y)
search.best_params_, -search.best_score_
```
`neg_mean_absolute_error` is the error with a minus sign, because scikit-learn always treats bigger scores as better.

## 8. Common mistakes
- **`train_test_split(X, y)` with its default shuffle.** The classic error.
- **`TimeSeriesSplit` on a table sorted by district.** It splits by row position, so the "later" rows are simply later districts. Sort by date, or split on dates.
- **`gap=4` on a table with 25 districts per week.** That is 4 rows, not 4 weeks.
- **No gap at all.**
- **Looking at the test set after every experiment.** It slowly becomes a second validation set and stops being honest.
- **Putting a whole epidemic in only one set** without noticing. Check what each period contains.
- **Fitting the scaler before splitting:** [[04.04 scikit-learn Pipelines and ColumnTransformer]].

## 9. Exam and viva focus
- **Why not a random split for time-series data?** It trains on the future and tests on the past; neighbouring weeks are too similar.
- **Train vs validation vs test:** fit, choose, final check.
- **What is walk-forward (expanding-window) validation?** Draw the diagram.
- **k-fold vs time-series cross-validation:** k-fold uses every fold as test once in any order; time-series CV always tests on data later than the training data.
- **Why a gap?** The target of the last training rows lies inside the validation period.
- **Why touch the test set only once?** Every look lets you fit your choices to it.
