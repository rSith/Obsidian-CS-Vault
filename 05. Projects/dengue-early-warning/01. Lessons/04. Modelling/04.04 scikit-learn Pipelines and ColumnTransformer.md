# 04.04 · scikit-learn Pipelines and ColumnTransformer

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🔴 Core
> **Not the same as** [[Machine Learning Pipeline]], which is the whole workflow from problem to deployment. This note is about one scikit-learn class.
> **Used for:** keeping scaling and encoding inside cross-validation, and saving preprocessing and model as one object.

## 1. Definitions
> [!note] Pipeline
> A scikit-learn **`Pipeline`** chains preprocessing steps and a model into **one object**. Calling `fit` or `predict` on it runs every step in order.

> [!note] ColumnTransformer
> A **`ColumnTransformer`** applies **different preprocessing to different columns**: for example scaling to numeric columns and one-hot encoding to the district column.

## 2. Why it is used
1. **It prevents leakage.** A scaler learns a mean and standard deviation. If it learns them from all the data, the validation rows have influenced the training. Inside a pipeline, each cross-validation fold fits the scaler on that fold's training rows only.
2. **It guarantees the same steps at prediction time.** The live system cannot forget to scale, or scale differently.
3. **One file to save.** The saved object contains the preprocessing and the model together.

## 3. How it works
Every step except the last is a **transformer**; the last is an **estimator** (the model).

| Method | A transformer | A pipeline |
|---|---|---|
| `fit(X, y)` | **Learns** from the data (a mean, a list of categories) | Fits each transformer in turn, then the model |
| `transform(X)` | **Applies** what it learned | |
| `fit_transform(X)` | Both at once | |
| `predict(X)` | | **Transforms** with what was learned, then predicts |

```text
fit:      X_train ─▶ scaler.fit_transform ─▶ encoder.fit_transform ─▶ model.fit
predict:  X_new   ─▶ scaler.transform     ─▶ encoder.transform     ─▶ model.predict
```
Nothing is ever *learned* from `X_new`. That is the whole point.

## 4. Syntax
```python
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import Ridge
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric = ["rain_lag4", "rain_sum4", "temp_mean8", "cases_last", "cases_change",
           "year_sin", "year_cos"]
categorical = ["district"]

preprocess = ColumnTransformer([
    ("num", StandardScaler(), numeric),
    ("cat", OneHotEncoder(handle_unknown="ignore"), categorical),
])

model = Pipeline([
    ("preprocess", preprocess),
    ("model", Ridge(alpha=1.0)),
])

model.fit(X_train, y_train)          # X_train is a DataFrame with the columns above
pred = model.predict(X_val)
```
Columns not listed are **dropped** by default (`remainder="drop"`). That is a useful safety net: a column you forgot about cannot slip into the model.

## 5. Example: tuning and saving
```python
from sklearn.model_selection import GridSearchCV
import joblib

search = GridSearchCV(model,
                      {"model__alpha": [0.1, 1, 10, 100]},   # step name, two underscores, parameter
                      cv=folds, scoring="neg_mean_absolute_error")
search.fit(X, y)

best = search.best_estimator_
joblib.dump(best, "models/model_v1.joblib")       # preprocessing + model in one file

loaded = joblib.load("models/model_v1.joblib")    # later, in src/predict.py
loaded.predict(X_new)
```
To swap the model, change one line: replace `Ridge(alpha=1.0)` with another estimator. The preprocessing stays.

```python
model[:-1].get_feature_names_out()    # the column names after preprocessing
model[-1]                             # the fitted model itself
```

## 6. Common mistakes
- **Scaling the whole dataset first, then splitting.** This is the leak the pipeline exists to prevent.
- **Calling `fit_transform` on validation or test data.** Only `transform` (or let the pipeline do it).
- **Saving the model without its preprocessing.** The live code then has to rebuild the scaling by hand, and gets it slightly wrong.
- **Passing a NumPy array** when the `ColumnTransformer` selects columns by name. Keep `X` as a DataFrame.
- **Forgetting the double underscore** in parameter names: `model__alpha`, not `model_alpha`.
- **Loading the file with a different scikit-learn version.** Record the version next to the saved model: [[08.06 Model Versioning and Retraining]].
- **Loading a `.joblib` file from someone you do not trust.** Loading runs code from the file.

## 7. Exam and viva focus
- **What is a pipeline and why use one?** Chains steps; prevents leakage; same steps for training and prediction; one object to save.
- **`fit` vs `transform` vs `fit_transform`:** learn; apply; both.
- **Why fit the scaler on training data only?** Validation and test data must stay unseen.
- **Transformer vs estimator.**
- **What is hyperparameter tuning?** Searching for the settings that are not learned from data, such as `alpha`, using cross-validation.
- **Parameter vs hyperparameter:** learned from data (weights) vs set before training (`alpha`, tree depth).
