# 04.07 · SHAP and Feature Importance

> [!info] [[04.00 Modelling|Lesson 4]] · Roadmap Phase 4 · Priority 🟡 Supporting
> **Used for:** explaining why the best model predicts what it does, and checking that its reasons make biological sense.

## 1. Definitions
> [!note] Feature importance
> **Feature importance** is a score for each feature saying how much the model relies on it.

> [!note] SHAP value
> A **SHAP value** says how much one feature pushed **one particular prediction** up or down, compared with the model's average prediction. SHAP stands for *SHapley Additive exPlanations*.

## 2. Why it is used
- **Trust.** A health officer will not act on "the model says so". "Warning, because cases are rising and the last four weeks were unusually wet" is a reason.
- **Checking.** If the top feature makes no biological sense, suspect a bug or [[03.03 Data Leakage]].
- **Simplifying.** Features that contribute nothing can be removed.

## 3. Four ways to measure importance
| Method | Idea | Works with | Weakness |
|---|---|---|---|
| **Coefficients** | Size of each weight after scaling | Linear models | Misleading when features are correlated |
| **Impurity importance** | How much each feature improved the splits during training | Tree models | Measured on training data; favours features with many distinct values |
| **Permutation importance** | Shuffle one feature's column and see how much the error grows | Any model | Correlated features hide each other |
| **SHAP** | Share each prediction fairly among the features | Any model; fast for trees | Slower; needs care to read |

| | **Global explanation** | **Local explanation** |
|---|---|---|
| Question | Which features matter overall? | Why did the model predict *this* for Colombo *this* week? |
| Tools | Permutation importance; average of absolute SHAP values | SHAP values for one row |

## 4. How SHAP works
Every prediction is split into a starting point plus one contribution per feature:

$$f(x) = \phi_0 + \sum_{j=1}^{n} \phi_j$$

- $\phi_0$ = the **base value**: the model's average prediction.
- $\phi_j$ = the SHAP value of feature $j$ for this row. Positive pushes the prediction up, negative pushes it down.
- They always **add up exactly** to the prediction.

The values come from game theory: the prediction is treated as a payout shared among "players" (the features), each paid according to its average contribution over all the orders in which features could be added.

## 5. Syntax
**Permutation importance** is the simplest place to start. It works on the whole pipeline and the original column names.
```python
from sklearn.inspection import permutation_importance

result = permutation_importance(model, X_val, y_val, n_repeats=10, random_state=42,
                                scoring="neg_mean_absolute_error")
importance = pd.Series(result.importances_mean, index=X_val.columns).sort_values()
importance.plot.barh(xlabel="Increase in MAE when the feature is shuffled")
```

**SHAP** for a tree model inside a pipeline:
```python
import shap

names = model[:-1].get_feature_names_out()
X_val_t = pd.DataFrame(model[:-1].transform(X_val), columns=names)   # preprocessed features

explainer = shap.TreeExplainer(model[-1])        # the tree model itself
shap_values = explainer(X_val_t)

shap.plots.beeswarm(shap_values)                 # global: all rows, all features
shap.plots.waterfall(shap_values[0])             # local: one prediction
```
If the encoder produces a sparse matrix, set `OneHotEncoder(sparse_output=False)` so the result fits in a DataFrame.

## 6. Example: one prediction explained
| | Contribution |
|---|---|
| Base value (average prediction) | 120 |
| `cases_last` = 290 (high) | +95 |
| `rain_sum4` = 310 mm (wet) | +40 |
| `year_cos` (season) | +12 |
| `temp_mean8` | −5 |
| **Prediction** | **262** |

In words: *"The forecast is 262 cases, well above the usual 120, mainly because recent cases were already high and the last four weeks were very wet."* The numbers are invented.

**Reading a beeswarm plot:** each dot is one row. Features are listed from most to least important. A dot's position along the axis is its SHAP value; its colour is the feature's own value (red high, blue low). Red dots on the right for `rain_sum4` mean "high rainfall pushes predictions up".

## 7. The sanity check
For this project you expect recent cases, lagged rainfall and season near the top. Worry if:
- a feature with no biological meaning is first;
- one feature explains almost everything and the error is suspiciously low;
- rainfall pushes predictions the *wrong* way at every lag.

## 8. Common mistakes
- **Importance is not causation.** "The model uses rainfall" does not prove rainfall causes dengue.
- **Correlated features share the credit.** Rain at lag 2 and lag 4 each look half as important as they are together.
- **Explaining on the training data.** Use validation data, which the model has not memorised.
- **Using impurity importance alone** for tree models.
- **Forgetting the scale.** With a Poisson loss, SHAP values for a tree model are on the **log** scale, not in cases.
- **Explaining the wrong object:** passing raw features to an explainer built for the model that sits *after* preprocessing.
- **One dramatic waterfall plot** presented as if it described every prediction.

## 9. Exam and viva focus
- **Why interpret a model?** Trust, debugging, accountability, finding leakage.
- **Global vs local explanation.**
- **Permutation importance:** shuffle a feature, measure the drop in performance.
- **SHAP:** additive; base value plus contributions equals the prediction; based on Shapley values from game theory.
- **Black-box vs interpretable model:** boosted trees and neural networks vs linear regression and single decision trees.
- **Limit:** importance does not show cause and effect.
