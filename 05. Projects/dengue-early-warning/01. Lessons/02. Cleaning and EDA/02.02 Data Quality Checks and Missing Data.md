# 02.02 · Data Quality Checks and Missing Data

> [!info] [[02.00 Cleaning and EDA|Lesson 2]] · Roadmap Phase 2 · Priority 🔴 Core
> **Parent concept:** [[Data Preprocessing]]. This note covers the checks and the missing-data choices that matter for a weekly district table.

## 1. Definitions
> [!note] Data quality check
> A **data quality check** is a test that the data obeys a rule it must obey, such as "one row per district per week" or "cases are never negative".

> [!note] Missing data
> **Missing data** is a value that should exist but does not. In pandas it appears as `NaN` or `NaT`.

## 2. Why it is used
A model cannot tell a real zero from a hole, or a typing error from an outbreak. Every problem you do not find here becomes a wrong pattern the model learns later.

## 3. The five checks
```python
key = ["district", "week_start"]

# 1. Duplicates: the key must be unique
df.duplicated(key).sum()

# 2. Spelling: one name per district
df["district"] = df["district"].str.strip().str.title().replace(NAME_MAP)
sorted(df["district"].unique())

# 3. Impossible values
df[(df["cases"] < 0) | (df["rain_mm"] < 0) | (df["rain_mm"] > 1000)]

# 4. Completeness: build the full grid of every district × every week
weeks = pd.date_range(df["week_start"].min(), df["week_start"].max(), freq="7D")
grid = pd.MultiIndex.from_product([df["district"].unique(), weeks], names=key)
full = df.set_index(key).reindex(grid).reset_index()
full["cases"].isna().groupby(full["district"]).sum()      # missing weeks per district

# 5. Unusual periods: flag, do not delete
full["flag_epidemic_2017"] = full["week_start"].dt.year == 2017
full["flag_covid"] = full["week_start"].between("2020-03-01", "2021-12-31")
```

Check 4 matters most. A missing week is usually a **missing row**, not a `NaN`, so you cannot see it until you build the grid.

## 4. Why flag instead of delete?
- Deleting weeks leaves holes, and holes break lag features (two rows back is no longer two weeks back).
- With a flag you can try both: train with or without those weeks, and compare.
- The flag itself documents your decision.

## 5. Ways to handle a missing value
| Method | What it does | Uses the future? | Good for |
|---|---|---|---|
| **Leave as `NaN`** | Nothing | No | The target; long gaps |
| **Drop the row** | Removes it | No | Only after features are built |
| **Forward fill** (`ffill`) | Repeats the last known value | No | Slow-changing values such as population |
| **Interpolate** | Draws a line between the values before and after | **Yes** | Short gaps in weather, for analysis only |
| **Fill with a mean** | Uses an average | Yes, if the mean includes later data | Rarely a good choice in time series |

```python
g = full.groupby("district")
full["population"] = g["population"].ffill()
full["rain_mm"] = g["rain_mm"].transform(lambda s: s.interpolate(limit=2))  # gaps of 1–2 weeks only
full["cases_was_missing"] = full["cases"].isna()         # remember what was missing
```

## 6. Three rules for this project
1. **Never fill the target.** An invented case count teaches the model something that did not happen. Leave it `NaN` and drop those rows at training time.
2. **A feature may be filled only from the past.** Interpolation uses the next real value, which the live system does not have yet. Use forward fill with a limit for anything that feeds the model. See [[03.03 Data Leakage]].
3. **Record what you filled.** A `was_missing` column lets you check later whether filled rows behave differently.

## 7. Why is it missing?
| Type | Meaning | Example here |
|---|---|---|
| Missing completely at random | No pattern | One report was never uploaded |
| Missing at random | Depends on something you can see | A small district reports late more often |
| Missing not at random | Depends on the missing value itself | Reporting collapses *during* a crisis |

The third kind is the dangerous one: the weeks you most need are the ones that vanish.

## 8. Common mistakes
- **Looking only for `NaN`** and never building the full grid.
- **Interpolating the case counts** and then training on them.
- **Deleting 2017 and 2020–21** because they look odd.
- **Treating a missing count as zero.** Zero means "no cases". Missing means "we do not know".
- **Filling without `groupby("district")`,** so one district's value fills another's gap.
- **Fixing the raw file by hand.** Fix it in code, so the fix is repeated on every run.
- **Not writing decisions down.** Put each one in the notebook and in `docs/data.md`.

## 9. Exam and viva focus
- **Name four data-quality problems:** duplicates, missing values, inconsistent names, impossible values (also outliers).
- **Deletion vs imputation:** removing incomplete rows vs filling in values, with one advantage and one risk of each.
- **Forward fill vs interpolation:** only interpolation needs a later value.
- **Why flag an outlier instead of deleting it?** It may be real; deletion breaks the time order; a flag keeps both options.
- **Zero vs missing.**
