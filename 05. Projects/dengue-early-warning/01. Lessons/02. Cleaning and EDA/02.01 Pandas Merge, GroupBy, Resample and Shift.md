# 02.01 · Pandas: Merge, GroupBy, Resample and Shift

> [!info] [[02.00 Cleaning and EDA|Lesson 2]] · Roadmap Phase 2 · Priority 🔴 Core
> **Parent concept:** [[Pandas]]. This note covers only the four operations that build the weekly table and its lags.

## 1. Definitions
| Operation | In one sentence |
|---|---|
| **merge** | Join two tables side by side by matching the values in key columns. |
| **groupby** | Split the rows into groups, do something to each group, and put the results together. |
| **resample** | A groupby where the groups are periods of time (days → weeks). |
| **shift** | Move a column's values down (or up) by a number of rows. |

## 2. Why they are used
| Task in this project | Operation |
|---|---|
| Put cases, weather and population in one table | `merge` |
| Do anything "per district" | `groupby` |
| Turn daily weather into weekly weather | `resample` |
| Get "rainfall 6 weeks ago" next to this week's cases | `shift` |

## 3. Merge
```python
weekly = cases.merge(
    weather,
    on=["district", "week_start"],   # the key columns
    how="left",                      # keep every row of `cases`
    validate="one_to_one",           # raise an error if a key repeats
    indicator=True,                  # add a column saying where each row matched
)
weekly["_merge"].value_counts()      # how many rows found no weather?
```

| `how=` | Keeps |
|---|---|
| `"inner"` | Only keys found in **both** tables |
| `"left"` | Every row of the **left** table; missing right values become `NaN` |
| `"right"` | Every row of the **right** table |
| `"outer"` | Every key from **either** table |

Count the rows before and after every merge. If the number changes and you did not expect it, something is wrong with the keys.

## 4. GroupBy: split, apply, combine
```python
weekly.groupby("district")["cases"].mean()
```
1. **Split** the rows by district.
2. **Apply** `mean` to the `cases` of each group.
3. **Combine** into one result.

| Method | Result size | Use for |
|---|---|---|
| `.agg("mean")` | One row **per group** | Summaries: average cases per district |
| `.transform("mean")` | One row **per original row** | A new column: each row gets its district's average |

```python
weekly["district_mean"] = weekly.groupby("district")["cases"].transform("mean")
weekly["week_of_year"] = weekly["week_start"].dt.isocalendar().week
seasonal = weekly.groupby(["district", "week_of_year"])["cases"].mean()
```

## 5. Resample
```python
daily.set_index("date").groupby("district").resample("W-FRI")["rain_mm"].sum()
```
It needs a date index. The rule (`"W-FRI"`) sets the period. Details and the week rules are in [[01.05 Dates and Epidemiological Weeks]].

## 6. Shift
`shift(k)` moves values **down** by `k` rows, so each row sees the value from `k` rows earlier.

```python
weekly = weekly.sort_values(["district", "week_start"])          # 1. sort by time
weekly["rain_lag2"] = weekly.groupby("district")["rain_mm"].shift(2)   # 2. shift per district
```

| district | week_start | rain_mm | rain_lag2 |
|---|---|---|---|
| Colombo | 6 Jan | 10 | NaN |
| Colombo | 13 Jan | 40 | NaN |
| Colombo | 20 Jan | 5 | 10 |
| Colombo | 27 Jan | 0 | 40 |
| Kandy | 6 Jan | 22 | NaN |
| Kandy | 13 Jan | 8 | NaN |

The first two rows of each district are `NaN`: there is no earlier week to take a value from.

> [!warning] Always shift inside `groupby("district")`
> Without the groupby, Kandy's first row would receive Colombo's last value. The table still looks fine, and the model quietly learns from another district's numbers.

`shift(-4)` moves values **up**: each row sees the value from 4 weeks **later**. That is how the target is made, and it is the only place a negative shift belongs: [[03.01 Forecast Origin, Horizon and Target]].

## 7. Common mistakes
- **Shifting without sorting by date first.** "Two rows earlier" is then not "two weeks earlier".
- **Shifting without grouping by district.** Values leak between districts.
- **Shifting when weeks are missing.** With a gap in the table, two rows back is three weeks back. Fill the grid first: [[02.02 Data Quality Checks and Missing Data]].
- **A merge that multiplies rows.** A repeated key in one table duplicates rows in the result. Use `validate=`.
- **An inner merge that silently drops rows.** Use `how="left"` with `indicator=True` and look at what did not match.
- **Keys that look equal but are not:** `"Colombo "` with a trailing space, or a date stored as text in one table.
- **`agg` where `transform` was needed**, giving a result that does not line up with the original rows.

## 8. Exam and viva focus
- **Join types:** inner, left, right, outer, and what each keeps.
- **Split–apply–combine:** the three steps of a groupby.
- **`agg` vs `transform`:** one row per group vs one row per original row.
- **What does `shift(1)` do?** Each row gets the previous row's value; the first row becomes `NaN`.
- **Primary key of the weekly table:** `(district, week_start)`.
