# 06.06 · Environment Variables and Configuration

> [!info] [[06.00 Database and Flask API|Lesson 6]] · Roadmap Phase 6 · Priority 🔴 Core
> **Used for:** keeping the database password out of GitHub, and letting the same code run on your laptop and on a server.

## 1. Definitions
> [!note] Configuration
> **Configuration** is everything that differs between the places a program runs: database address, passwords, debug mode. The code stays the same; the configuration changes.

> [!note] Environment variable
> An **environment variable** is a named value that the operating system hands to a program when it starts. The program reads it; the value is not written in the code.

> [!note] Secret
> A **secret** is a configuration value that must stay private: a password, an API key, a token.

## 2. Why it is used
- **Security.** A password committed to a public repository is found by automated scanners within minutes, and Git keeps it in the history even after you delete it.
- **Portability.** Your laptop uses `localhost`; the server uses another address. With configuration outside the code, nothing needs editing when you deploy.
- **Safety.** Development and production can use different databases, so a test cannot damage real data.

## 3. How it works
```text
.env file (your laptop, never committed)
        │  load_dotenv() copies its lines into the environment
        ▼
environment variables ──▶ os.environ["DATABASE_URL"] ──▶ your code

On a server there is no .env file. The host's settings page (or Docker, or GitHub Actions)
puts the values into the environment directly. The code does not change.
```

| File | Contains | In Git? |
|---|---|---|
| `.env` | Real values, including secrets | **No.** Listed in `.gitignore`. |
| `.env.example` | The variable names with placeholder values | Yes. It tells others what to set. |

## 4. Syntax
```ini
# .env
DATABASE_URL=mysql+pymysql://dengue_user:the-real-password@localhost:3306/dengue
FLASK_DEBUG=1
```
```python
import os
from dotenv import load_dotenv          # pip install python-dotenv

load_dotenv()                            # reads .env if it exists; does nothing otherwise

DATABASE_URL = os.environ["DATABASE_URL"]         # required: raises KeyError if missing
DEBUG = os.getenv("FLASK_DEBUG", "0") == "1"      # optional: "0" is the default
```

| Form | If the variable is missing | Use for |
|---|---|---|
| `os.environ["X"]` | Raises an error immediately | Values the program cannot run without |
| `os.getenv("X", "default")` | Returns the default | Optional settings |

Setting a variable by hand in PowerShell, for the current terminal only:
```powershell
$env:DATABASE_URL = "mysql+pymysql://dengue_user:...@localhost:3306/dengue"
```

## 5. Example: the same code in three places
| Where | How `DATABASE_URL` gets its value |
|---|---|
| Your laptop | The `.env` file, loaded by `load_dotenv()` |
| Docker Compose | `environment:` or `env_file:` in `docker-compose.yml`: [[08.03 Docker and Docker Compose]] |
| GitHub Actions | A repository **secret**, read as `${{ secrets.DATABASE_URL }}`: [[08.02 Scheduling with cron and GitHub Actions]] |
| A cloud host | The host's environment-variable settings: [[08.04 Cloud Deployment Basics]] |

In all four the Python code is the same line: `os.environ["DATABASE_URL"]`.

## 6. If a secret leaks
1. **Change it at once** (a new password, a new key). This is called **rotating** the secret. The old one must be treated as public.
2. Then remove it from the code.
3. Deleting the line in a new commit is **not enough**: the old commit still contains it.

## 7. Common mistakes
- **Committing `.env`.** Check `git status` before the first commit.
- **Adding `.env` to `.gitignore` after it was already committed.** Git keeps tracking it. Remove it from the index with `git rm --cached .env`, and rotate the secrets.
- **A real password in `.env.example`.**
- **`os.getenv("DATABASE_URL")` with no default** for a required value. It returns `None`, and the error appears later and far from its cause.
- **Printing or logging the whole configuration**, password included.
- **Everything is a string.** `os.getenv("FLASK_DEBUG")` returns `"0"`, and `bool("0")` is `True`. Compare with `== "1"`.
- **Spaces around `=`** or stray quotes in `.env`, which become part of the value.
- **The same password for development and production.**

## 8. Exam and viva focus
- **Define** environment variable and say why configuration is kept out of the code: security, portability, separate environments.
- **What is a secret, and how should it be stored?** Outside the repository; in environment variables or a secrets manager.
- **Purpose of `.gitignore`** and of `.env.example`.
- **Development vs production environment.**
- **What to do when a secret is exposed:** rotate it; removing it from the code is not enough.
- **The twelve-factor principle "store config in the environment".**
