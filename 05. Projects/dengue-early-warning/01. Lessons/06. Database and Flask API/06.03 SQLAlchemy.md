# 06.03 · SQLAlchemy

> [!info] [[06.00 Database and Flask API|Lesson 6]] · Roadmap Phase 6 · Priority 🔴 Core
> **Builds on:** [[13.03 SQL Injection]] · [[06.02 SQL Joins, Aggregation and Indexes]]
> **Used for:** loading the CSV data into MySQL, writing forecasts, and reading data inside the Flask API.

## 1. Definition
> [!note] SQLAlchemy
> **SQLAlchemy** is a Python library for working with SQL databases. It opens the connection, sends your SQL safely, and returns the results as Python objects.

It has two layers:

| Layer | You write | Use |
|---|---|---|
| **Core** | SQL, as text or built from Python objects | This project. You keep full control of the SQL. |
| **ORM** (object-relational mapper) | Python classes; SQLAlchemy writes the SQL | Larger applications |

## 2. Why it is used
- **One interface for many databases.** Change the connection address and the same code talks to MySQL, PostgreSQL or SQLite.
- **Safety.** It passes values separately from the SQL text, which blocks SQL injection.
- **Connection handling.** It reuses connections instead of opening a new one for each query.
- **pandas speaks it.** `to_sql` and `read_sql` accept a SQLAlchemy engine.

## 3. How it works
```text
Your code ──▶ Engine ──▶ Connection ──▶ driver (PyMySQL) ──▶ MySQL
```
- The **engine** is created once per program. It knows the database address and keeps a pool of connections.
- A **connection** is borrowed for a piece of work and returned afterwards.
- A **transaction** groups several statements so they all succeed or all fail together.

The address is one string:
```text
mysql+pymysql://USER:PASSWORD@HOST:3306/DATABASE
└dialect┘└driver┘
```

## 4. Syntax
```python
import os
import pandas as pd
from sqlalchemy import create_engine, text

engine = create_engine(os.environ["DATABASE_URL"])      # once, at start-up

# Read
with engine.connect() as conn:
    result = conn.execute(
        text("SELECT id, name FROM districts WHERE name = :name"),
        {"name": "Colombo"},                             # the value travels separately
    )
    rows = result.mappings().all()                       # list of dict-like rows

# Write, inside a transaction: commits at the end, rolls back if anything fails
with engine.begin() as conn:
    conn.execute(
        text("INSERT INTO weekly_cases (district_id, week_start, cases) "
             "VALUES (:district_id, :week_start, :cases)"),
        [{"district_id": 1, "week_start": "2026-08-15", "cases": 310},
         {"district_id": 2, "week_start": "2026-08-15", "cases": 290}],   # many rows at once
    )

# pandas
df.to_sql("weekly_weather", engine, if_exists="append", index=False)
cases = pd.read_sql(text("SELECT * FROM weekly_cases WHERE district_id = :d"),
                    engine, params={"d": 1})
```
`:name` is a **bound parameter**. The `with` block returns the connection even if an error occurs.

## 5. Example: why parameters matter
```python
# DANGEROUS: the value becomes part of the SQL text
name = request.args["district"]
conn.execute(text(f"SELECT * FROM districts WHERE name = '{name}'"))
```
A visitor sends `x' OR '1'='1` as the district. The query becomes:
```sql
SELECT * FROM districts WHERE name = 'x' OR '1'='1'
```
which returns every row. Other inputs can delete tables. This is **SQL injection**, explained in [[13.03 SQL Injection]].

```python
# SAFE: the database receives the SQL and the value separately
conn.execute(text("SELECT * FROM districts WHERE name = :name"), {"name": name})
```
With a bound parameter the value is always treated as data, never as SQL.

## 6. Writing so the pipeline can be re-run
The weekly pipeline may run twice for the same week. A plain `INSERT` would then fail on the primary key or create duplicates. An **upsert** inserts a new row or updates the existing one:

```sql
INSERT INTO weekly_cases (district_id, week_start, cases)
VALUES (:district_id, :week_start, :cases) AS new
ON DUPLICATE KEY UPDATE cases = new.cases;
```
An operation that gives the same result however many times it runs is called **idempotent**: [[08.01 Pipeline Scripts and Logging]].

## 7. Common mistakes
- **Building SQL with f-strings or `+`.** The one mistake in this note that can destroy the database.
- **Creating a new engine for every request.** Create one and reuse it.
- **Forgetting `text()`.** SQLAlchemy 2 does not accept a plain string as a statement.
- **Using `engine.connect()` for a write and never committing.** Use `engine.begin()` for writes.
- **`to_sql(..., if_exists="replace")`.** It **drops the table** and recreates it without your keys and constraints. Create tables with SQL and use `"append"`.
- **The password written in the code.** Read it from the environment: [[06.06 Environment Variables and Configuration]].
- **Sending 20,000 rows one at a time.** Pass a list of dictionaries, or use `to_sql`.
- **Connecting with the database's root user.** Make a user that can only read and write this project's tables.

## 8. Exam and viva focus
- **What is an ORM?** A layer that maps database tables to classes and rows to objects. One advantage (less SQL to write) and one disadvantage (hides what the database is doing).
- **What is SQL injection, and how is it prevented?** Untrusted input changes the SQL; prevented with parameterised queries (prepared statements).
- **Transaction and ACID:** atomicity, consistency, isolation, durability.
- **Commit vs rollback.**
- **Connection pool:** a set of open connections that are reused.
- **Idempotent operation.**
