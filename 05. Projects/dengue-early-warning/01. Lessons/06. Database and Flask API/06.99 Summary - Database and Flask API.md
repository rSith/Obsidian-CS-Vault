# 06.99 · Lesson Summary: Database and Flask API

> [!abstract] Back to [[06.00 Database and Flask API]] · Progress: [[Phase 06 - Database and Flask API]]

## Must know
- **Three tiers:** dashboard (browser) → Flask API → MySQL database.
- **Normalisation:** store each fact once. It removes the insert, update and delete anomalies.
- **1NF** one value per cell · **2NF** depends on the whole key · **3NF** depends on nothing but the key.
- **Tables:** `districts`; `weekly_cases` and `weekly_weather` keyed by `(district_id, week_start)`; `predictions` with `horizon_weeks`, bounds, `alert_level`, `model_version`, `created_at`.
- **Keep every forecast.** Never overwrite one; you need them to check accuracy later.
- **Joins:** `INNER` keeps matches only; `LEFT` keeps every left row. Forecasts for future weeks need a `LEFT JOIN` to actual cases.
- **`WHERE` filters rows, `HAVING` filters groups.** Order of execution: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`.
- **Index:** faster reads, slower writes. The primary key is indexed automatically.
- **SQLAlchemy:** one engine per program; `text()` with **bound parameters**; `engine.begin()` for writes.
- **Never build SQL from user input with strings.** That is SQL injection.
- **Flask:** a route maps a URL to a view function; a returned dict becomes JSON; `return body, 404` sets the status.
- **REST:** resources are nouns, methods are verbs, the server is stateless. **4xx** client's mistake, **5xx** server's.
- **Environment variables:** secrets in `.env` (ignored by Git), names in `.env.example` (committed). A leaked secret must be **rotated**.

```sql
SELECT p.week_start, p.predicted_cases, c.cases AS actual_cases
FROM predictions p
LEFT JOIN weekly_cases c ON c.district_id = p.district_id AND c.week_start = p.week_start
WHERE p.district_id = 1;
```

## Important comparisons
| `INNER JOIN` | `LEFT JOIN` |
|---|---|
| Matches only | Every left row |

| `WHERE` | `HAVING` |
|---|---|
| Before grouping | After grouping |

| Core | ORM |
|---|---|
| You write SQL | You write classes |

| `GET` | `POST` |
|---|---|
| Reads; safe; idempotent | Creates; neither |

| 400 | 404 | 500 |
|---|---|---|
| Bad request | Not found | Server bug |

| `.env` | `.env.example` |
|---|---|
| Real values, ignored | Names only, committed |
