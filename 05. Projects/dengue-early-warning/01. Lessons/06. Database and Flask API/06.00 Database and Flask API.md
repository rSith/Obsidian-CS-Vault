## What this lesson is about
Until now everything lived in CSV files and notebooks. A dashboard cannot read a notebook. This lesson builds the **back end**: a database that holds the data and forecasts, and a small web service that hands them out as JSON.

```text
CSV files ──▶ MySQL database ◀── src/predict.py writes new forecasts
                    │
                    ▼
               Flask API  ──JSON──▶  dashboard (Lesson 7)
```

1. **Design** the tables so each fact is stored once.
2. **Query** them with SQL joins and aggregation.
3. **Connect** Python to the database safely with SQLAlchemy.
4. **Serve** the data through four Flask endpoints that follow REST conventions.
5. **Keep passwords out of the code** with environment variables.

## The four endpoints to build
| Endpoint | Returns |
|---|---|
| `GET /api/districts` | The list of districts |
| `GET /api/predictions?district=Colombo` | History and forecasts for one district |
| `GET /api/alerts/latest` | The current alert level of every district |
| `GET /api/health` | `{"status": "ok"}`, for monitoring |
