# 00.02 · Python Virtual Environments

> [!info] [[00.00 Setup and Domain Knowledge|Lesson 0]] · Roadmap Phase 0 · Priority 🔴 Core
> **Used for:** keeping this project's packages separate from every other project, and making the setup repeatable on another computer.

## 1. Definition
> [!note] Virtual environment
> A **virtual environment** is a folder that holds its own copy of the Python interpreter and its own installed packages. Packages installed inside it are invisible to other projects.

## 2. Why it is used
- **No clashes.** Project A may need scikit-learn 1.3 and project B 1.6. Without environments only one version can exist on the computer.
- **Reproducible.** `requirements.txt` lists the packages. Anyone can rebuild the same environment from it.
- **Safe to delete.** If the environment breaks, delete the folder and rebuild it. Your code is untouched.
- **A saved model depends on it.** A model saved with one scikit-learn version may not load with another.

## 3. How it works
`python -m venv .venv` creates a folder named `.venv`:

```text
.venv/
├── Scripts/            python.exe, pip.exe, Activate.ps1   (Windows)
└── Lib/site-packages/  the packages you install
```

**Activating** the environment puts `.venv\Scripts` at the front of the `PATH` for that terminal. After that, the words `python` and `pip` mean the copies inside `.venv`. Nothing else on the computer changes.

## 4. Syntax (Windows, PowerShell)
```powershell
python -m venv .venv                 # create (once)
.venv\Scripts\Activate.ps1           # activate (every new terminal)
python -m pip install --upgrade pip
pip install -r requirements.txt      # install everything listed
pip install statsmodels              # add one package
pip freeze > requirements.txt        # record exact versions
deactivate                           # leave the environment
```

| File | What it is | In Git? |
|---|---|---|
| `requirements.txt` | The recipe: package names, optionally with versions | Yes |
| `.venv/` | The result: thousands of installed files | No, list it in `.gitignore` |

`pandas` means "any version". `pandas==2.2.3` pins one exact version. Pin versions before you save a trained model.

## 5. Example: test that the recipe works
The roadmap asks you to rebuild the environment once to prove it is reproducible.

```powershell
deactivate
Remove-Item -Recurse -Force .venv
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -c "import pandas, sklearn; print(pandas.__version__, sklearn.__version__)"
```

If the last line prints two version numbers, the recipe is complete.

## 6. Common mistakes
- **Forgetting to activate.** `pip install` then installs into the global Python. Check that the prompt starts with `(.venv)`.
- **"Running scripts is disabled on this system".** PowerShell blocks `Activate.ps1`. Run this once: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
- **VS Code uses a different interpreter.** Press `Ctrl+Shift+P`, choose *Python: Select Interpreter*, and pick the one inside `.venv`.
- **Jupyter uses a different kernel.** Choose the `.venv` kernel in the notebook's top-right corner.
- **Committing `.venv/`.** It is large and specific to your computer.
- **Installing a package and not adding it to `requirements.txt`.** The project then works only on your machine.

## 7. Exam and viva focus
- **Define** a virtual environment and say what activation changes (the `PATH` of that terminal).
- **Why use one?** Isolation, reproducibility, no version conflicts.
- **`requirements.txt` vs `.venv`:** recipe vs result. Commit the first, never the second.
- **Pinned vs unpinned versions:** pinned is reproducible; unpinned gets the newest version each time.
