# 03.04 · Cyclical and One-Hot Encoding

> [!info] [[03.00 Feature Engineering|Lesson 3]] · Roadmap Phase 3 · Priority 🔴 Core
> **Parent concept:** [[Data Preprocessing]]
> **Used for:** telling the model the time of year (week 52 is next to week 1) and which district a row belongs to.

## 1. Definitions
> [!note] Encoding
> **Encoding** means turning a value into numbers in a form a model can use correctly.

> [!note] Cyclical encoding
> **Cyclical encoding** represents a value that goes round in a circle (week of year, hour of day, month) as a point on a circle, using a **sine** and a **cosine**.

> [!note] One-hot encoding
> **One-hot encoding** represents a category as a set of 0/1 columns, one per category, with a single 1 in each row.

## 2. Why they are used
- **Week of year as a plain number is misleading.** Week 52 and week 1 are one week apart, but $52 - 1 = 51$. A model reading the raw number thinks they are as far apart as possible.
- **District as a number is misleading too.** Coding Colombo = 1, Gampaha = 2, Kandy = 3 tells a linear model that Kandy is "three times Colombo", which means nothing.

## 3. Cyclical encoding: how it works
Place the 52 weeks evenly round a circle and record each week's position.

$$\text{week\_sin} = \sin\left(\frac{2\pi \cdot w}{52}\right) \qquad \text{week\_cos} = \cos\left(\frac{2\pi \cdot w}{52}\right)$$

| Week | sin | cos |
|---|---|---|
| 1 | 0.12 | 0.99 |
| 13 | 1.00 | 0.00 |
| 26 | 0.00 | −1.00 |
| 39 | −1.00 | 0.00 |
| 52 | 0.00 | 1.00 |

Week 52 $(0.00,\ 1.00)$ and week 1 $(0.12,\ 0.99)$ are now close together, as they should be.

**Why both?** One alone cannot tell weeks apart: $\sin$ is the same for week 3 and week 23. The pair (sin, cos) is unique for every week.

## 4. Syntax
```python
import numpy as np

# Simple version: ISO week number
week = df["week_start"].dt.isocalendar().week.astype(int)
df["week_sin"] = np.sin(2 * np.pi * week / 52)
df["week_cos"] = np.cos(2 * np.pi * week / 52)

# Safer version: day of year, which has no "week 53" problem
doy = df["week_start"].dt.dayofyear
df["year_sin"] = np.sin(2 * np.pi * doy / 365.25)
df["year_cos"] = np.cos(2 * np.pi * doy / 365.25)
```
Some years have 53 weeks ([[01.05 Dates and Epidemiological Weeks]]). Dividing week 53 by 52 puts it slightly past the start of the circle. The day-of-year version avoids this.

Dengue in Sri Lanka has **two** peaks a year. One sine/cosine pair describes a pattern with one peak. Adding a second pair with twice the frequency ($4\pi$ instead of $2\pi$) lets a linear model fit two. Tree models can work this out from the first pair alone.

## 5. One-hot encoding: how it works
| district | | district_Colombo | district_Gampaha | district_Kandy |
|---|---|---|---|---|
| Colombo | → | 1 | 0 | 0 |
| Kandy | → | 0 | 0 | 1 |
| Gampaha | → | 0 | 1 | 0 |

```python
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

pd.get_dummies(df, columns=["district"])            # quick, for exploring

encoder = OneHotEncoder(handle_unknown="ignore")     # for the model pipeline
```
Use `OneHotEncoder` inside a pipeline for the real model. It remembers the list of districts from the training data and always produces the same columns, even if a district is missing from a later batch: [[04.04 scikit-learn Pipelines and ColumnTransformer]].

## 6. Example: choosing an encoding
| Variable | Kind | Encoding |
|---|---|---|
| Week of year | Cyclical | Sine and cosine |
| District | Category with no order | One-hot |
| Alert level (Normal < Watch < Warning) | Category with an order | Integers 0, 1, 2 |
| Rainfall | Number | None; scale it for linear models |

## 7. Common mistakes
- **Using the raw week number** in a linear model.
- **Only the sine**, without the cosine.
- **Dividing by 52 in a 53-week year.**
- **Label-encoding districts as 1, 2, 3** for a linear model.
- **Running `get_dummies` on training and test data separately.** If a district is absent from one, the columns do not match and the model fails or mixes columns up.
- **The dummy-variable trap.** For plain linear regression, the one-hot columns always add up to 1, which duplicates the intercept. Drop one column (`drop="first"`). Regularised models and trees do not need this.
- **One-hot encoding a category with thousands of values.** Not a problem here with 25 districts.

## 8. Exam and viva focus
- **Why encode categorical data?** Models need numbers.
- **Label encoding vs one-hot encoding:** label encoding implies an order; one-hot does not.
- **Why sine and cosine for a cyclical feature?** The ends of the cycle meet; a plain number puts them far apart.
- **Why are both needed?** Sine alone gives the same value for two different points of the cycle.
- **Dummy-variable trap:** perfect multicollinearity among one-hot columns; solved by dropping one.
