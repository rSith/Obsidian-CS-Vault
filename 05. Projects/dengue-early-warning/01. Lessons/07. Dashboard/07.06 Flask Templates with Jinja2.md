# 07.06 · Flask Templates with Jinja2

> [!info] [[07.00 Dashboard|Lesson 7]] · Roadmap Phase 7 · Priority 🟡 Supporting
> **Builds on:** [[06.04 Flask Routing and JSON APIs]] · [[00.02 HTML Document Structure]]
> **Used for:** serving the dashboard page from the same Flask app as the API, so front end and back end run together.

## 1. Definitions
> [!note] Template
> A **template** is an HTML file with **placeholders**. The server fills in the placeholders with real values and sends the finished HTML to the browser.

> [!note] Jinja2
> **Jinja2** is the template language that Flask uses.

## 2. Why it is used
- **One app, one address.** The page and the API come from the same server, so the browser's same-origin rule causes no trouble: [[07.02 JavaScript fetch and Promises]].
- **Values from the server go straight into the page**, such as the "last updated" date.
- **Shared layout.** The header and footer are written once and reused by every page.
- **Safe by default.** Jinja2 escapes values, which blocks injected scripts.

## 3. How it works
```text
Browser ──GET /──▶ Flask view ──render_template("index.html", last_updated=…)──▶ Jinja2
                                                                                  │ fills the placeholders
Browser ◀────────────── finished HTML ◀───────────────────────────────────────────┘
```
Flask looks for templates in the `templates/` folder, and for CSS, JavaScript and data files in `static/`.

```text
app/
├── __init__.py
├── templates/
│   ├── base.html
│   └── index.html
└── static/
    ├── css/style.css
    ├── js/dashboard.js
    └── data/districts.geojson
```

## 4. Syntax
| Jinja2 | Meaning |
|---|---|
| `{{ value }}` | Print a value |
| `{% for x in items %} … {% endfor %}` | Loop |
| `{% if cond %} … {% else %} … {% endif %}` | Condition |
| `{# note #}` | Comment, not sent to the browser |
| `{{ value \| upper }}` | A **filter** changes the value before printing |
| `{{ url_for('static', filename='css/style.css') }}` | The correct URL of a static file |
| `{% extends "base.html" %}` and `{% block name %}` | Template inheritance |

```python
# app/__init__.py
from flask import render_template

@app.get("/")
def index():
    return render_template("index.html", last_updated="10 Oct 2026",
                           districts=["Colombo", "Gampaha", "Kandy"])
```

## 5. Example: a base layout and a page
```html
{# templates/base.html #}
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{% block title %}Dengue Early-Warning{% endblock %}</title>
  <link rel="stylesheet" href="{{ url_for('static', filename='css/style.css') }}">
</head>
<body>
  <header class="top">
    <h1>Dengue Early-Warning</h1>
    <p>Data last updated: {{ last_updated }}</p>
  </header>

  <main>{% block content %}{% endblock %}</main>

  <footer>Decision-support tool. Not an official forecast.</footer>
  {% block scripts %}{% endblock %}
</body>
</html>
```
```html
{# templates/index.html #}
{% extends "base.html" %}

{% block content %}
  <section id="map" aria-label="Map of districts by alert level"></section>
  <aside id="panel">
    <h2 id="title">Select a district</h2>
    <label for="district">District</label>
    <select id="district">
      {% for name in districts %}
        <option value="{{ name }}">{{ name }}</option>
      {% else %}
        <option>No districts found</option>
      {% endfor %}
    </select>
  </aside>
{% endblock %}

{% block scripts %}
  <script src="{{ url_for('static', filename='js/dashboard.js') }}" defer></script>
{% endblock %}
```
`index.html` supplies only the parts that differ. Everything else comes from `base.html`.

## 6. Where the page is built: two styles
| | **Server-side rendering** | **Client-side rendering** |
|---|---|---|
| Who builds the HTML | The server (Jinja2) | The browser (JavaScript) |
| Good for | Content that is the same for everyone and rarely changes | Content that changes when the user clicks |
| In this project | Page skeleton, "last updated", district list | Map colours, chart, table |

The dashboard uses both: Jinja2 sends the skeleton, then JavaScript fetches the data and fills it in.

## 7. Escaping
Jinja2 **escapes** every `{{ value }}` automatically: `<` becomes `&lt;`, so a value containing `<script>` is shown as text and never run.

| | Effect |
|---|---|
| `{{ name }}` | Escaped. Safe. |
| `{{ name \| safe }}` | **Not** escaped. Use only for HTML you wrote yourself. |
| `{{ data \| tojson }}` | Turns a Python value into safe JavaScript, for use inside a `<script>` block |

See [[13.07 Cross-Site Scripting (XSS)]].

## 8. Common mistakes
- **`TemplateNotFound`.** The folder must be named exactly `templates`, inside the app package.
- **Hard-coded paths** such as `href="/static/css/style.css"`. They break when the app is hosted under a different address. Use `url_for`.
- **`| safe` on data** that came from a user or an outside source.
- **Queries and calculations inside the template.** Templates only display. Do the work in the view function and pass the result.
- **Mixing up Jinja2 and JavaScript.** `{{ … }}` is filled in **on the server, before the page is sent**. JavaScript runs later, in the browser. A Jinja2 loop cannot use a JavaScript variable.
- **Passing a Python list into a script as `{{ data }}`.** Use `{{ data | tojson }}`.
- **Seeing old CSS or JavaScript** after a change. The browser cached the file. Reload with Ctrl+F5.
- **Copying the header into every page** instead of using `{% extends %}`.

## 9. Exam and viva focus
- **What is a template engine?** It combines a template with data to produce a document.
- **`{{ }}` vs `{% %}`:** output a value vs control logic.
- **Template inheritance:** a base template defines blocks; child templates fill them.
- **Server-side vs client-side rendering,** with one advantage of each.
- **Static vs dynamic content.**
- **Separation of concerns (MVC):** the template is the *view*; the Flask function is the *controller*; the database is the *model*.
- **Why does auto-escaping matter?** It prevents cross-site scripting.
