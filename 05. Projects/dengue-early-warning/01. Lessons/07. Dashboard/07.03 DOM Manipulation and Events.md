# 07.03 · DOM Manipulation and Events

> [!info] [[07.00 Dashboard|Lesson 7]] · Roadmap Phase 7 · Priority 🔴 Core
> **Builds on:** [[00.02 HTML Document Structure]] · [[02.02 Web Languages - HTML CSS JavaScript PHP]]
> **Used for:** updating the detail panel and the table when a district is clicked.

## 1. Definitions
> [!note] DOM
> The **DOM** (Document Object Model) is the browser's model of a web page as a **tree of objects**. Every HTML element is a node in the tree. JavaScript changes the page by changing this tree.

> [!note] Event
> An **event** is something that happens on the page: a click, a key press, the page finishing loading.

> [!note] Event listener
> An **event listener** is a function you register to run when a particular event happens on a particular element.

## 2. Why it is used
HTML alone is fixed. To show Colombo's chart when Colombo is clicked, something must (1) notice the click and (2) change what is on the page. Events do the first; DOM manipulation does the second.

## 3. How it works
```text
HTML text                         DOM tree
<body>                            body
  <h2 id="title">…</h2>     ──▶   ├── h2#title
  <table id="alerts">…            └── table#alerts
</body>                                └── tbody ── tr ── td …
```
The browser reads the HTML once and builds the tree. After that, the **tree** is the page. Change a node and the screen changes at once.

A cycle of interaction: **event → listener runs → fetch data → change the DOM**.

## 4. Syntax
```js
// Find elements (CSS selectors, the same as in a stylesheet)
const title = document.querySelector("#title");        // first match
const rows  = document.querySelectorAll("tbody tr");   // all matches

// Change them
title.textContent = "Colombo — Watch";                 // set text, safely
title.classList.add("alert-watch");                    // add a CSS class
title.classList.toggle("hidden");
title.setAttribute("aria-live", "polite");

// Create and add
const li = document.createElement("li");
li.textContent = "Kandy";
document.querySelector("#list").append(li);

// React
button.addEventListener("click", (event) => {
  console.log("clicked", event.target);
});
```

## 5. Example: build the table, then react to clicks
```js
function renderTable(alerts) {
  const tbody = document.querySelector("#alerts tbody");
  tbody.replaceChildren();                              // empty the table

  for (const a of alerts) {
    const tr = document.createElement("tr");
    tr.dataset.district = a.district;                   // stored as data-district="…"

    for (const value of [a.district, a.alert_level, Math.round(a.predicted_cases)]) {
      const td = document.createElement("td");
      td.textContent = value;
      tr.append(td);
    }
    tbody.append(tr);
  }
}

// ONE listener on the table body handles clicks on every row
document.querySelector("#alerts tbody").addEventListener("click", (event) => {
  const row = event.target.closest("tr");               // the row that was clicked
  if (!row) return;
  showDistrict(row.dataset.district);
});
```
The second part is **event delegation**. A click on a cell **bubbles** up through its parents, so a listener on `tbody` hears it. One listener serves all 25 rows, and it keeps working after the table is rebuilt.

## 6. When the script runs
A script that runs before the page is built finds nothing. Load it with `defer`, which waits until the HTML has been read:
```html
<script src="/static/js/dashboard.js" defer></script>
```

## 7. `textContent` or `innerHTML`?
| | `textContent` | `innerHTML` |
|---|---|---|
| Treats the value as | Plain text | HTML to be run |
| If the value contains `<script>` | Shown as text | **May be executed** |
| Use for | Any data | Fixed markup that you wrote yourself |

> [!warning] Never put data into `innerHTML`
> If a value from an API or a user is inserted with `innerHTML`, any script inside it can run in the visitor's browser. This is **cross-site scripting**: [[13.07 Cross-Site Scripting (XSS)]]. Use `textContent` and `createElement`.

## 8. Common mistakes
- **`querySelector` returns `null`** because the script ran before the element existed, or the selector has a typo. Then `null.textContent` throws an error.
- **Calling the function instead of passing it:** `addEventListener("click", handler())` runs `handler` immediately. Write `handler` without brackets.
- **A listener on every row,** and then the rows are rebuilt and the listeners are gone. Use delegation.
- **Data into `innerHTML`.**
- **Adding the same listener again** each time data loads, so one click fires five times.
- **Changing the DOM inside a long loop,** one piece at a time, when the whole table could be built first and added once.
- **Only mouse events.** Keyboard users cannot click a `div`. Use real `<button>` and `<a>` elements, which work with the keyboard already: [[07.07 Dashboard UX and Accessibility]].

## 9. Exam and viva focus
- **Define the DOM:** a tree-structured, programmable model of the document.
- **Ways to select an element:** `getElementById`, `querySelector`, `querySelectorAll`.
- **What is an event? What is an event listener?**
- **Event bubbling:** an event travels from the target up through its ancestors.
- **Event delegation:** one listener on a parent handles events from its children.
- **`innerHTML` vs `textContent`,** and the security reason to prefer the second.
- **Why place scripts at the end of the body or use `defer`?** So the elements exist before the script looks for them.
