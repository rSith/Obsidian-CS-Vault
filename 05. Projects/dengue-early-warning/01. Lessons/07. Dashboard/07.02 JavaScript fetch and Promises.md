# 07.02 · JavaScript fetch and Promises

> [!info] [[07.00 Dashboard|Lesson 7]] · Roadmap Phase 7 · Priority 🔴 Core
> **Builds on:** [[02.09 SPA, AJAX and Custom Development]] · [[02.04 HTTP Protocol]]
> **Used for:** loading alerts and forecasts from the Flask API without reloading the page.

## 1. Definitions
> [!note] Asynchronous
> **Asynchronous** code starts a slow task (such as a network request) and **carries on without waiting**. The result is handled later, when it arrives.

> [!note] Promise
> A **promise** is an object that stands for a result that is not ready yet. It will either **succeed** with a value or **fail** with an error.

> [!note] fetch
> **`fetch()`** is the browser's built-in function for making HTTP requests. It returns a promise.

## 2. Why it is used
A request to the API takes time. If the browser stopped everything to wait, the page would freeze: no scrolling, no clicking. Asynchronous requests keep the page responsive. This technique of updating part of a page with data fetched in the background is known as **AJAX**: [[02.09 SPA, AJAX and Custom Development]].

## 3. How it works
A promise is always in one of three states:

```text
            ┌──▶ fulfilled (has a value)   → .then(...) runs
pending ────┤
            └──▶ rejected (has an error)   → .catch(...) runs
```
Once it has settled, it never changes again.

`fetch` works in **two steps**, and each is a promise:
1. `fetch(url)` resolves when the **headers** arrive, giving a `Response` object.
2. `response.json()` reads the **body** and converts the JSON text into JavaScript objects.

## 4. Syntax
**With `.then`:**
```js
fetch("/api/alerts/latest")
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));
```
**With `async` / `await`**, which reads from top to bottom like ordinary code:
```js
async function loadAlerts() {
  const response = await fetch("/api/alerts/latest");
  const data = await response.json();
  return data;
}
```
- `await` pauses **that function** until the promise settles. The rest of the page keeps working.
- `await` may be used only inside a function marked `async`.
- An `async` function always returns a promise.

## 5. Example: a loader that handles errors properly
```js
async function getJson(url) {
  const response = await fetch(url);
  if (!response.ok) {                                  // status outside 200–299
    throw new Error(`Request failed (${response.status})`);
  }
  return response.json();
}

async function showDistrict(name) {
  const status = document.querySelector("#status");
  status.textContent = "Loading…";
  try {
    const data = await getJson(`/api/predictions?district=${encodeURIComponent(name)}`);
    drawChart(data);
    status.textContent = "";
  } catch (error) {
    status.textContent = "Could not load the forecast. Please try again.";
    console.error(error);
  }
}
```

> [!warning] `fetch` does not fail on a 404 or a 500
> The promise is rejected only when the **network** fails. A `404 Not Found` reply still counts as a successful request. You must check **`response.ok`** yourself, as `getJson` does.

`encodeURIComponent` makes a value safe to put in a URL. A district name with a space would otherwise break the address.

**Several requests at once:**
```js
const [geo, alerts] = await Promise.all([
  getJson("/static/data/districts.geojson"),
  getJson("/api/alerts/latest"),
]);
```
`Promise.all` starts both together and waits for both. It is faster than one after the other.

## 6. Looking at requests in the browser
Press **F12**:
- **Console** tab: your `console.log` output and error messages.
- **Network** tab: every request, its status code and the JSON it returned.

The roadmap's advice is the right first step: fetch the data and log it to the console before drawing anything.

## 7. Common mistakes
- **Not checking `response.ok`.** The error page is then parsed as data.
- **Forgetting `await`.** You get a `Promise` object instead of the data, and `data.forecasts` is `undefined`.
- **Using the result outside the promise.** Code written after a `fetch(...)` call runs **before** the data arrives.
- **No `catch` or `try`.** An error then fails silently and the user sees an empty page.
- **No loading or error message.** Always tell the user what is happening.
- **Building a URL by joining strings** without `encodeURIComponent`.
- **A CORS error.** Browsers block a page from calling an API on a **different origin** (a different domain or port) unless that API allows it. Serving the page and the API from the same Flask app avoids the problem.
- **`await` in a loop** for requests that could run together. Use `Promise.all`.

## 8. Exam and viva focus
- **Synchronous vs asynchronous code.**
- **Define a promise and name its three states:** pending, fulfilled, rejected.
- **`.then`/`.catch` vs `async`/`await`:** two ways to write the same thing.
- **What is AJAX?** Exchanging data with a server and updating part of a page without a full reload.
- **What does `fetch` return?** A promise that resolves to a `Response`.
- **Why check `response.ok`?** `fetch` rejects only on network failure.
- **Same-origin policy and CORS.**
- **Callback vs promise:** promises avoid deeply nested callbacks ("callback hell").
