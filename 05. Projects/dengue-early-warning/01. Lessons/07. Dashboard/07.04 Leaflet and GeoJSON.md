# 07.04 · Leaflet and GeoJSON

> [!info] [[07.00 Dashboard|Lesson 7]] · Roadmap Phase 7 · Priority 🔴 Core
> **Builds on:** [[01.02 Parsing JSON into Tables]] · [[07.02 JavaScript fetch and Promises]]
> **Used for:** the map of Sri Lanka with each district coloured by its alert level.

## 1. Definitions
> [!note] GeoJSON
> **GeoJSON** is a JSON format for geographic shapes: points, lines and polygons, each with a set of properties such as a name.

> [!note] Leaflet
> **Leaflet** is a JavaScript library for interactive maps in a web page: zooming, dragging, layers, popups.

> [!note] Choropleth map
> A **choropleth map** colours each area according to a value for that area. Here the value is the alert level.

## 2. Why it is used
A table of 25 districts must be read row by row. A coloured map is understood at a glance, and it shows something a table hides: whether the districts at risk are **next to each other**.

## 3. How GeoJSON works
```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": { "name": "Colombo" },
      "geometry": {
        "type": "Polygon",
        "coordinates": [[[79.84, 6.98], [79.99, 6.98], [80.00, 6.80], [79.84, 6.98]]]
      }
    }
  ]
}
```

| Part | Meaning |
|---|---|
| `FeatureCollection` | A list of features: all districts |
| `Feature` | One district |
| `properties` | Anything you like about it: name, code |
| `geometry.type` | `Point`, `LineString`, `Polygon`, or `MultiPolygon` for districts with islands |
| `coordinates` | The outline, as a list of points |

> [!warning] Longitude comes first in GeoJSON
> GeoJSON writes a point as **`[longitude, latitude]`**. Leaflet's own functions take **`[latitude, longitude]`**. Colombo is `[79.86, 6.93]` in GeoJSON and `[6.93, 79.86]` in `setView`. Mixing them up puts the map in the wrong ocean.

## 4. How Leaflet works
A Leaflet map is a stack of **layers**:
1. a **tile layer**: the background map, made of small square images loaded as you move;
2. a **GeoJSON layer**: your district shapes, drawn on top and styled by you;
3. **popups, tooltips and controls** such as a legend.

## 5. Syntax
```html
<link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css">
<script src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js" defer></script>

<div id="map"></div>
```
```css
#map { height: 60vh; }        /* without a height the map is invisible */
```
```js
const map = L.map("map").setView([7.87, 80.77], 7);          // [lat, lng], zoom level

L.tileLayer("https://tile.openstreetmap.org/{z}/{x}/{y}.png", {
  maxZoom: 18,
  attribution: "&copy; OpenStreetMap contributors",          // required by the map provider
}).addTo(map);
```

## 6. Example: colour the districts by alert level
```js
const COLOURS = { Normal: "#2e7d32", Watch: "#f9a825", Warning: "#c62828" };

async function initMap() {
  const [geo, alerts] = await Promise.all([
    getJson("/static/data/districts.geojson"),
    getJson("/api/alerts/latest"),
  ]);
  const byName = Object.fromEntries(alerts.map(a => [a.district, a]));   // look up by name

  const layer = L.geoJSON(geo, {
    style: (feature) => {
      const alert = byName[feature.properties.name];
      return {
        fillColor: alert ? COLOURS[alert.alert_level] : "#bdbdbd",       // grey = no data
        fillOpacity: 0.8,
        color: "#ffffff",                                                 // border
        weight: 1,
      };
    },
    onEachFeature: (feature, districtLayer) => {
      const name = feature.properties.name;
      const alert = byName[name];
      districtLayer.bindTooltip(alert ? `${name}: ${alert.alert_level}` : `${name}: no data`);
      districtLayer.on("click", () => showDistrict(name));
    },
  }).addTo(map);

  map.fitBounds(layer.getBounds());                                       // zoom to the island
}
```
- `style` is called once per district and returns how to draw it.
- `onEachFeature` is called once per district to attach the tooltip and the click.
- `getJson` is from [[07.02 JavaScript fetch and Promises]]; `showDistrict` updates the panel.

Add a **legend** that names each colour in words. Without it the colours mean nothing to a new visitor.

## 7. Getting the boundary file
- You need a GeoJSON file of Sri Lanka's **district** boundaries (administrative level 2). Open sources of administrative boundaries include the Humanitarian Data Exchange and GADM. Check each source's licence and credit it on the page.
- Raw boundary files are very detailed and can be many megabytes. **Simplify** them (for example with mapshaper) to a few hundred kilobytes so the page loads quickly on a phone.
- Check that the district names in the file match the names in your database **exactly**.

## 8. Common mistakes
- **The map `div` has no height.**
- **Latitude and longitude swapped.**
- **The Leaflet CSS file is missing.** The map tiles appear scattered and broken.
- **District names do not match:** "Nuwara Eliya" in one place and "NuwaraEliya" in another. That district stays grey. Log the names that found no match.
- **A huge GeoJSON file** that takes ten seconds to load.
- **No attribution** for the map tiles and the boundary data.
- **Colour as the only signal.** Add the level as text in the tooltip, legend and table: [[07.07 Dashboard UX and Accessibility]].
- **Calling `L.map("map")` twice.** Leaflet reports that the container is already initialised.
- **Heavy use of the public OpenStreetMap tile server.** It is for light use. Read its usage policy.

## 9. Exam and viva focus
- **What is GeoJSON?** Name its geometry types.
- **`Feature` vs `FeatureCollection`.**
- **Coordinate order** in GeoJSON: longitude, then latitude.
- **What is a choropleth map,** and when is it the right choice? When a value belongs to an area.
- **Tile layer vs vector layer:** ready-made background images vs shapes drawn from coordinates.
- **Latitude vs longitude:** north–south position (−90 to 90) vs east–west position (−180 to 180).
- **A weakness of choropleth maps:** large areas draw the eye even when few people live there.
