## What this lesson is about
The goal is **a web page a non-technical health officer can understand in 30 seconds**: which districts are at risk, and how sure the system is.

```text
┌──────────────────────────────────────────────────────────────┐
│ Dengue Early-Warning                 Data last updated: …    │  header
├──────────────────────────────────┬───────────────────────────┤
│                                  │ Colombo — Watch           │
│   Map of districts,              │ chart: actual vs forecast │  detail panel
│   coloured by alert level        │ with band and thresholds  │
│                                  ├───────────────────────────┤
│                                  │ Table of districts        │
├──────────────────────────────────┴───────────────────────────┤
│ How to read this · data sources · "decision support only"    │
└──────────────────────────────────────────────────────────────┘
```

The page is served by Flask. Its JavaScript calls the API from [[06.00 Database and Flask API|Lesson 6]] and draws the map and chart.

## Topic structure
```text
Dashboard
├── Structure and layout
│   ├── HTML page served by a Flask (Jinja2) template
│   └── CSS layout: Flexbox and Grid, responsive
├── Behaviour
│   ├── fetch and promises: get JSON from the API
│   └── DOM and events: update the panel when a district is clicked
├── Visuals
│   ├── Leaflet + GeoJSON: the district map
│   └── Chart.js: actual vs forecast with an uncertainty band
└── People
    └── UX and accessibility: clear in 30 seconds, not colour alone, works on a phone
```

## Suggested order of work
1. Sketch the layout on paper.
2. Flask template with the page skeleton (note 6) and the layout (note 1).
3. Fetch `/api/alerts/latest` and log it to the console (note 2).
4. Draw the map and colour it (note 4).
5. Click a district → fetch its forecasts → draw the chart (notes 3 and 5).
6. Add the table, the "How to read this" box and the sources.
7. Test on a phone and with one non-technical person (note 7).
