# 01.07 · Resumable Downloads: Caching and Rate Limits

> [!info] [[01.00 Data Collection|Lesson 1]] · Roadmap Phase 1 · Priority 🔴 Core
> **Builds on:** [[01.01 HTTP Requests and REST APIs in Python]] · [[01.02 Parsing JSON into Tables]]
> **Used for:** understanding `src/collect_weather.py` well enough to change it, debug it and write it again.
> **Not the same as:** [[06.08 HTTP Caching and ETags]], which is the cache inside a web browser. This note is about files your own script saves.

## 1. Definition
> [!note] Download cache
> A **download cache** is a folder of saved replies. Before asking the server for something, the script checks whether it already has the answer on disk.

> [!note] Rate limit
> A **rate limit** is the most requests a server accepts from one user in a period of time. Past the limit it answers `429 Too Many Requests`.

> [!note] Resumable
> A script is **resumable** if, after it stops halfway, running it again continues from where it stopped and does not start from the beginning.

## 2. Why it is used
The weather collector makes 546 requests: 26 units × 21 years. The first full run stopped at request 388 with a `429` error. Because every reply had been saved as soon as it arrived, the second run only needed the missing files. Without the cache, every run would start at Colombo 2006, stop at the same place and never reach the last units.

## 3. How it works
The collector does two separate jobs.

```text
districts.csv ──▶ download_all ──▶ download_year ──▶ data/raw/weather/Colombo_2024.json   (546 files)
                                                              │
                                                              ▼
                                                        build_table ──▶ data/processed/weather_daily.csv
```

| Job | Uses the network? | Output |
|---|---|---|
| **Download** | Yes | One raw JSON file per unit and year, saved exactly as received |
| **Build** | No | One table made from all the saved files |

They are separate so that a bug in the table code is fixed and re-run in seconds, without one more request.

**The cache rule.** A file can be reused only if it can no longer change:

| File | Saved on | Reuse it? | Why |
|---|---|---|---|
| `Colombo_2024.json` | 11 Oct 2026 | Yes | 2024 is over; the numbers are final |
| `Colombo_2026.json` | 11 Oct 2026 | No | The year is still growing and the last 5 days are provisional |
| `Colombo_2025.json` | 3 Jan 2026 | No | Saved too soon after the year ended; its last days were still provisional |

**The rate limit is weighted.** Open-Meteo's free tier allows 10,000 calls a day and 5,000 an hour, but one long request counts as several calls. The run stopped after 388 requests. If a year of five variables counts as about 13 calls, then 388 × 13 ≈ 5,000, which fits the hourly limit. That weight is an estimate from this one run, not a number read from the documentation.

## 4. Syntax: the parts of `collect_weather.py`
```python
def raw_path(unit, year):
    return RAW_DIR / f"{unit.replace(' ', '_')}_{year}.json"
```
`/` joins a folder and a file name when the left side is a `Path`. `raw_path("Nuwara Eliya", 2024)` gives `data/raw/weather/Nuwara_Eliya_2024.json`.

```python
def is_final(path, year):
    if not path.exists():
        return False
    saved_on = date.fromtimestamp(path.stat().st_mtime)   # when the file was last written
    return saved_on > date(year + 1, 1, 7)
```
This is the cache rule from section 3 in code.

```python
def download_year(unit, latitude, longitude, year):
    path = raw_path(unit, year)
    if is_final(path, year):
        return False                                       # nothing to do, no request made
    ...
    "end_date": min(date(year, 12, 31), yesterday).isoformat(),
    ...
    response.raise_for_status()
    path.write_text(response.text, encoding="utf-8")       # save exactly what arrived
    return True
```
- `min(...)` keeps the end date out of the future. The API answers `400` to a future date.
- The function returns `True` only when it used the network.

```python
def download_all():
    for row in districts.itertuples():
        for year in range(START_YEAR, date.today().year + 1):
            if download_year(row.unit, row.latitude, row.longitude, year):
                time.sleep(DELAY_SECONDS)
```
The sleep is inside the `if`, so the script waits only after a real request. A run with everything cached finishes in about a second.

```python
def build_table():
    for unit in districts["unit"]:
        for path in sorted(RAW_DIR.glob(f"{unit.replace(' ', '_')}_*.json")):
            daily = json.loads(path.read_text(encoding="utf-8"))["daily"]
            frame = pd.DataFrame(daily).rename(columns=COLUMNS)
            frame.insert(0, "unit", unit)                  # the JSON does not say which unit it is
            frames.append(frame)
    table = pd.concat(frames, ignore_index=True)
```
`glob("Colombo_*.json")` finds every year of one unit. `pd.concat` stacks the small tables into one.

```python
if __name__ == "__main__":
    download_all()
    build_table()
```
This block runs only when the file is started directly. When the Phase 8 pipeline imports a function from this file, nothing is downloaded by accident.

```powershell
python -m src.collect_weather     # run from the project root, with .venv active
```
The paths in the file are relative, so they are resolved from the folder the terminal is in.

## 5. Worked example: what one loop step does
The loop reaches `Puttalam`, `2015`, and the file does not exist yet.

1. `raw_path` → `data/raw/weather/Puttalam_2015.json`.
2. `is_final` → `False`, because the file is missing.
3. `end_date` → `min(2015-12-31, yesterday)` = `2015-12-31`.
4. The request is sent; the server answers `200`.
5. The reply text is written to the file.
6. `download_year` returns `True`, so the loop prints `downloaded Puttalam 2015` and sleeps one second.

On the next run the same step stops at point 2: the file exists and was saved long after 7 January 2016, so `is_final` is `True` and the function returns `False` at once.

## 6. Changing the script
| To do this | Change | Watch out |
|---|---|---|
| Add a variable, such as wind speed | Add it to `DAILY` and to `COLUMNS` | The saved files do not contain it. Delete `data/raw/weather/` and download again. |
| Move a unit's weather point | Edit `districts.csv` | Delete that unit's JSON files, or the old point's data stays. |
| Start from an earlier year | `START_YEAR` | Only the new years are downloaded. |
| Rename an output column | `COLUMNS` | No download needed. |
| Wait longer between requests | `DELAY_SECONDS` | Slower run; the hourly limit is unchanged. |

> [!warning] The cache only knows the unit and the year
> The file name is `unit_year.json`. If anything else about the request changes (the variables, the coordinates, the time zone), the cache cannot tell, and it keeps serving the old answer. After such a change, delete the affected files.

## 7. Common mistakes and how to find them
| Symptom | Likely cause | Check |
|---|---|---|
| `429 Too Many Requests` | Rate limit reached | Wait an hour, or until the next day, and run again |
| `400 Bad Request` | A wrong parameter name or date | Open the URL from the error message in a browser and read the reason |
| `FileNotFoundError: data\reference\districts.csv` | The terminal is not in the project root | `pwd` |
| `ModuleNotFoundError: No module named 'src'` | Wrong folder, or run as `python src\collect_weather.py` | Use `python -m src.collect_weather` from the root |
| `KeyError: 'daily'` | A saved file is not weather data | Open that JSON file |
| `ValueError: No objects to concatenate` | No JSON files were found | Check `RAW_DIR` and the file names |
| The table has too few rows | Some unit-years are missing | `table.groupby("unit").size()` |

Other mistakes:
- **Saving the file only at the end of the run.** One error then loses everything. Save each reply as soon as it arrives.
- **Treating the current year as final.** It would never be updated.
- **Sleeping on every loop step,** cached or not. A fully cached run would take nine minutes to do nothing.
- **Cleaning the data before saving it.** The raw file must be what the server sent, so that a cleaning mistake can be undone.

To test one function alone, open `python` in the project root:
```python
from src.collect_weather import raw_path, is_final
is_final(raw_path("Colombo", 2024), 2024)    # True
is_final(raw_path("Colombo", 2026), 2026)    # False
```

## 9. Exam and viva focus
- **Define** cache, rate limit, resumable.
- **Why separate downloading from table-building?** A bug in the table code is fixed without using the network again.
- **Cache validity:** when is a saved file safe to reuse, and what makes it stale?
- **`429` vs `400`:** `429` means "slow down", and the request itself was fine. `400` means the request is wrong, and waiting will not help.
- **Idempotent:** running the script twice gives the same files as running it once. That is what makes a rerun safe.
- **Why `if __name__ == "__main__":`?** So the file can be imported without running the download.
