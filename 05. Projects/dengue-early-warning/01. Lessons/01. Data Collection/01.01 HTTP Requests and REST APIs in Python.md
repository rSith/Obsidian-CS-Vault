# 01.01 · HTTP Requests and REST APIs in Python

> [!info] [[01.00 Data Collection|Lesson 1]] · Roadmap Phase 1 · Priority 🔴 Core
> **Builds on:** [[02.04 HTTP Protocol]] · [[02.07 Web Services, XML and JSON]]
> **Used for:** `src/collect_weather.py`, which downloads daily weather for every district.

## 1. Definition
> [!note] API
> An **API** (Application Programming Interface) is a set of rules that lets one program ask another program for data or a service. A **web API** does this over HTTP.

> [!note] REST API
> A **REST API** is a web API where each piece of data has its own URL (a **resource**), and you use standard HTTP methods such as `GET` to read it. The reply is usually JSON.

## 2. Why it is used
Weather history for 25 places over 15 years cannot be copied by hand. An API gives it in seconds, and the same script can fetch next week's data automatically.

## 3. How it works
Your program sends a **request**; the server sends back a **response**.

```text
GET https://archive-api.open-meteo.com/v1/archive?latitude=6.93&longitude=79.85&start_date=2024-01-01&...
│   └────────────── base URL ──────────────────┘ └────────── query parameters ─────────────────────┘
method
```

| Part of the request | Meaning |
|---|---|
| **Method** | What you want to do. `GET` reads data. |
| **URL** | Which resource. |
| **Query parameters** | The details, after `?`, joined by `&`: place, dates, variables. |
| **Headers** | Extra information, such as an API key. |

| Part of the response | Meaning |
|---|---|
| **Status code** | Did it work? |
| **Body** | The data, usually JSON. |

| Status code | Meaning | What to do |
|---|---|---|
| `200` | OK | Use the data |
| `400` | Bad request | Your parameters are wrong; read the message |
| `404` | Not found | The URL is wrong |
| `429` | Too many requests | Slow down and wait |
| `500`–`503` | Server problem | Try again later |

## 4. Syntax
```python
import requests

url = "https://archive-api.open-meteo.com/v1/archive"
params = {
    "latitude": 6.93,
    "longitude": 79.85,                      # Colombo
    "start_date": "2024-01-01",
    "end_date": "2024-01-31",
    "daily": "precipitation_sum,temperature_2m_mean,relative_humidity_2m_mean",
    "timezone": "Asia/Colombo",
}

response = requests.get(url, params=params, timeout=30)
response.raise_for_status()                  # stop here if the status is 4xx or 5xx
data = response.json()                       # JSON text → Python dict
```

- `params=` builds the query string for you and handles special characters.
- `timeout=30` stops the program waiting for ever.
- `raise_for_status()` turns an error status into a Python error.

> [!tip] Check the names
> Variable names such as `precipitation_sum` come from the API's documentation and can change. Open the URL in a browser first and read what comes back.

## 5. Example: download once, keep the raw file
```python
import json
import time
from pathlib import Path

RAW = Path("data/raw/weather")

def fetch_weather(district: str, lat: float, lon: float, year: int) -> dict:
    path = RAW / f"{district}_{year}.json"
    if path.exists():                        # already downloaded: read the saved copy
        return json.loads(path.read_text())

    params = {"latitude": lat, "longitude": lon,
              "start_date": f"{year}-01-01", "end_date": f"{year}-12-31",
              "daily": "precipitation_sum,temperature_2m_mean",
              "timezone": "Asia/Colombo"}
    response = requests.get(url, params=params, timeout=30)
    response.raise_for_status()

    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(response.text)           # save exactly what the server sent
    time.sleep(1)                            # be polite: wait before the next request
    return response.json()
```
This gives you two things at once: you never download the same file twice, and you keep an untouched copy in `data/raw/`.

## 6. Common mistakes
- **No `timeout`.** One stuck request freezes the whole script.
- **Not checking the status.** You then parse an error page as if it were data.
- **Building the URL by joining strings.** Spaces and commas break it. Use `params=`.
- **Hammering the server in a fast loop.** You get blocked (`429`). Add a delay.
- **Asking for 15 years in one request.** Ask year by year so one failure costs little.
- **Putting an API key in the code.** Keep it in `.env`: [[06.06 Environment Variables and Configuration]].

## 7. Exam and viva focus
- **Define** API, REST, resource, endpoint.
- **Request parts:** method, URL, query parameters, headers, body. **Response parts:** status code, headers, body.
- **Status code families:** 2xx success, 3xx redirect, 4xx client error, 5xx server error.
- **`GET` vs `POST`:** `GET` reads and changes nothing; `POST` sends data to create something.
- **Stateless:** each request carries everything the server needs; the server remembers nothing between requests.
