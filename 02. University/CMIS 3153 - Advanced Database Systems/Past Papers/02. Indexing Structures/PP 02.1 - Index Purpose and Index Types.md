# PP 02.1 · Purpose of Indexes; Primary, Clustering and Secondary Indexes

## 2020/21 · Q6(a) [25 marks] and 2022/23 · Q2(a) [25 marks]
> **Questions:** What is the main purpose of using indexes in a database? (2020/21) · What is indexing in database systems? Discuss the purpose and advantages of indexing for improving query performance. (2022/23)

### Expected answer
**Definition.** An **index** is an **additional access structure (a separate file)** of entries ⟨**key value, pointer**⟩, sorted (or hashed) on an **indexing field**, that provides a **secondary access path** to the records of a data file **without changing the physical placement** of the records. Searching the index yields pointers to the disk blocks (or records) holding the wanted records.

**Main purpose:** to **speed up retrieval** of records that satisfy a search condition on the indexing field by **reducing the number of disk block accesses**.

**Advantages**
1. **Fewer block accesses:** e.g. a 3,000-block file: linear search 1,500 accesses, binary search 12, primary index 7, multilevel index 4 (lecture examples).
2. **Fast search on fields other than the ordering field** (secondary indexes); many indexes can coexist.
3. **Efficient range queries** and **ordered retrieval** with ordered/B+-tree indexes.
4. Faster **joins**, **ORDER BY**, **GROUP BY**, MIN/MAX; possible **covering** queries (no table access).
5. **Enforcing uniqueness** (primary/unique indexes).
6. Gives the **optimizer cheaper access paths** ([[04.07 Indexing in Query Optimization]]).

**Trade-offs (mention briefly):** extra storage; every insert/update/delete must also update the indexes.

### How to approach
Definition (with ⟨key, pointer⟩ and "does not move data") → purpose in one line → 4–6 advantages with a number/example → one line on the cost.

## 2020/21 · Q5(a) [30 marks]
> **Question:** Discuss the difference between a primary index and a secondary index, using a simple example.

### Expected answer
- **Primary index:** an ordered file on the **ordering key field** (unique, and the field the data file is physically sorted by). One entry **per data block**: ⟨key of the block's first record (**block anchor**), block pointer⟩ → **sparse (non-dense)**; **at most one** per file; small.
- **Secondary index:** an ordered file on a **non-ordering field** (key or non-key). The data file is **not** sorted by it, so (for a key field) there is one entry **per record** → **dense**; **many** allowed; larger.

**Example:** `STUDENT(Reg_No, Name, Email)` stored sorted by Reg_No, 3 records per block:
```text
Data:  B1: 1001 1002 1003 | B2: 1004 1005 1006 | B3: 1007 1008 1009
Primary index on Reg_No (sparse):  ⟨1001,B1⟩ ⟨1004,B2⟩ ⟨1007,B3⟩            (3 entries)
Secondary index on Email (dense):  ⟨amal@..,B2⟩ ⟨binu@..,B1⟩ ⟨chamal@..,B3⟩ … (9 entries)
```
To find 1005: largest anchor ≤ 1005 is 1004 → read B2. To find binu@…: look up the email entry → pointer → B1.

Lecture numbers: 30,000 records, 3,000 blocks → primary index 45 blocks → **7** accesses; dense secondary index 442 blocks → **10** accesses (vs 1,500 for linear search).

| | Primary | Secondary |
|---|---|---|
| Field | ordering key | non-ordering field |
| Density | sparse (per block) | dense (per record) |
| Number | ≤ 1 | many |
| Size / speed | smaller, slightly faster | larger |
| Range queries | efficient (data contiguous) | each match may be a separate block |

Definitions → small example drawing → comparison table.

## 2021/22 · Q1(a) [25 marks]
> **Question:** What is a primary index, a clustering index and a secondary index? Discuss when each of these indexes are used in databases.

### Expected answer
- **Primary index:** on the **ordering key** (unique) of an **ordered** file; one entry per block (block anchors); sparse. **Used when** the table is stored sorted on its primary key and is often searched/range-scanned by that key (e.g. Emp_ID, Order_ID).
- **Clustering index:** on an **ordering non-key field** (many records share a value) of an ordered (clustered) file; one entry per **distinct value**, pointing to the first block containing it; sparse; often a separate block (cluster) per value eases inserts. **Used when** queries fetch **groups** of records with the same value or ranges (e.g. all employees of Dept_no 5, orders by date).
- **Secondary index:** on a **non-ordering** field (key or non-key); dense for key fields; uses block or record pointers. **Used when** you need fast access on other columns the file is not sorted by (e.g. Email, Name, Customer_ID foreign key); several can exist.

### How to approach
Three short definitions with "field type / ordered? / density" and a "used when" sentence + example each.

## 2021/22 · Q1(b) [25 marks]
> **Question:** Why do databases can have at most one primary or clustering index on a file, but several secondary indexes? Explain.

### Expected answer
- Primary and clustering indexes **depend on the physical order of the records** in the data file: their entries point to **block anchors** or to the **first block of each value**, which only works because the file is **sorted on that field**.
- A file's records can be **physically sorted in only one order** at a time (like books on a shelf sorted by author *or* title, not both). Therefore there can be **at most one** primary **or** clustering index (one or the other, not both).
- **Secondary indexes do not rely on physical order**: each is a separate, usually **dense** structure with a pointer for every record (or value), wherever the record is stored. So any number can be created on different fields; the only limits are storage and the **maintenance overhead** on inserts, updates and deletes.

### How to approach
State the "physical order" argument clearly, add the bookshelf analogy, contrast with secondary indexes.
