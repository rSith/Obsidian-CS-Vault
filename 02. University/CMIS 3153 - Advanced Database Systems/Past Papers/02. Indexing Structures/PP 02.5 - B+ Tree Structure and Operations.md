# PP 02.5 · B+ Trees: Structure, Insertion, Deletion, Utilization

> [!info] [[PP 02 - Indexing Structures|PP 02 index]] · Lesson: [[02.08 B+ Trees]] · Priority 🔴 (Q3 of both recent papers)
> **Convention used (state it in the exam):** order $d = 2$ → 2–4 entries per non-root node; leaf split: first $d$ entries stay, rest move right, **copy up** the first key of the new leaf; internal split: **push up** the middle key; deletion: **redistribute** with a sibling (same parent) if it has > $d$ entries, otherwise **merge**; search follows $P_i$ with $K_{i-1} \le X < K_i$.

---

## 2023/24 · Q3(a) [25 marks]
> **Question:** Explain the structure and properties of a B+ tree. Discuss how B+ trees maintain balance and why this is important for database indexing.

### Expected answer
**Structure**
- A **dynamic multilevel index**: a balanced tree whose nodes are disk blocks.
- **Internal nodes** hold only **keys and child pointers** $\langle P_1, K_1, P_2, \dots, K_{q-1}, P_q\rangle$ that guide the search.
- **Leaf nodes** hold **all data entries** $\langle K_i, Pr_i\rangle$ (key + pointer to record/block) and a **next-leaf pointer**: leaves form a **linked list** in key order.
**Properties**
1. **Balanced:** all leaves at the same depth.
2. **Occupancy:** every node except the root is at least half full (order $d$: $d$–$2d$ entries).
3. **Sorted** keys within nodes and across leaves.
4. **High fan-out** → height 3–4 for millions of keys.
5. Every key value appears at the leaf level; internal keys are copies used as signposts.
**Maintaining balance**
- **Insert:** a full leaf **splits** (copy up the first key of the new leaf); a full internal node splits (push up the middle key); if the root splits, a **new root** is created → the tree grows **upwards**, so all leaves stay at the same depth.
- **Delete:** an underfull node **redistributes** with a sibling (update the separator) or **merges** with it (remove/pull down the separator); if the root becomes empty it is removed → the tree shrinks from the **top**.
**Why it matters**
- Every search costs **exactly the height** → guaranteed $O(\log N)$ I/Os, predictable response times.
- Minimum occupancy keeps the index **compact** and short even under heavy insert/delete loads; no periodic reorganization (unlike ISAM/sorted files).
- **Linked leaves** give efficient **range queries** and ordered scans.

## 2022/23 · Q3 (Figure 3.1 for a, b, c) [20 marks each]
```text
                                A[50]
                 ┌────────────────┴──────────────────────┐
             B[40|45]                              C[60|78|87|90]
       ┌────────┼────────┐             ┌───────┬───────┼───────┬───────┐
   D[23 32] E[40 41 43 44] F[45 48]  G[50 59] H[60 66] I[78 80 85 86] J[88 89] K[96 99]
```

### (a) Insert a data entry with key 90: list nodes read and nodes updated
- **Read:** **A** (90 ≥ 50 → go to C) → **C** (90 ≥ 90 → rightmost pointer → K) → **K**.
- **Updated:** **K** only: [96 99] → **[90 96 99]** (space available, no split; no parent change).

### (b) Insert 42
- Path A → B (40 ≤ 42 < 45) → **E**. E = [40 41 43 44] is full → 5 entries 40 41 42 43 44 → split: **E = [40 41]**, new **E′ = [42 43 44]**; **copy up 42** into B → **B = [40 42 45]** (room; no further split). Leaf links: D → E → E′ → F.
```text
                    B[40|42|45]
        ┌───────┬───────┴──────┬────────┐
    D[23 32] E[40 41] E′[42 43 44] F[45 48]
```

### (c) Insert 79
- Path A → C (78 ≤ 79 < 87) → **I**. I = [78 80 85 86] full → 78 79 80 85 86 → **I = [78 79]**, **I′ = [80 85 86]**, **copy up 80** into C.
- C becomes [60 78 80 87 90] (5 keys) → overflow → split: **C = [60 78]**, **C′ = [87 90]**, **push up 80** into A → **A = [50 80]**.
```text
                                 A[50|80]
            ┌───────────────────────┼─────────────────────────┐
        B[40|45]                C[60|78]                    C′[87|90]
                           ┌───────┼───────┐          ┌───────┼───────┐
                        G[50 59] H[60 66] I[78 79]  I′[80 85 86] J[88 89] K[96 99]
```
(B and its leaves are unchanged; height stays 3 levels because A had room.)

## 2022/23 · Q3 (Figure 3.2 for d, e) [20 marks each]
```text
                         A[50]
            ┌──────────────┴──────────────┐
        B[40|45]                       C[60|78]
   ┌────────┼────────┐           ┌────────┼────────┐
D[23 32] E[40 41 43 44] F[45 48] G[50 59] H[60 66] I[78 80 85 86]
```

### (d) Delete 23 (redistribute if possible)
- D = [32] has 1 entry < $d$ = 2 → underflow.
- Sibling **E** (same parent B) has 4 entries → **redistribute**: move 40 into D → **D = [32 40]**, **E = [41 43 44]**.
- Update the separator in B: 40 → **41** → **B = [41 45]**.
```text
        B[41|45]
   ┌───────┼────────┐
D[32 40] E[41 43 44] F[45 48]
```

### (e) Delete 50
1. G = [50 59] → [59]: underflow. G's only sibling under C is H = [60 66], which has exactly 2 entries → cannot lend → **merge G and H → G = [59 60 66]**; delete separator **60** from C → **C = [78]**.
2. C now has 1 key < 2 → underflow. Its sibling **B = [40 45]** has exactly 2 keys → cannot lend → **merge B and C**, **pulling down 50** from A: new node **[40 45 50 78]** with children D, E, F, G, I.
3. A has no keys left → removed; the merged node is the **new root** → **height decreases by one**.
```text
                     [40 | 45 | 50 | 78]                      ← new root
     ┌──────────┬─────────┼─────────┬──────────────┐
  D[23 32] E[40 41 43 44] F[45 48] G[59 60 66] I[78 80 85 86]
```
(50 may remain as a separator although the record is deleted; writing 59 instead is also correct.)

### How to approach (all B+ tree drawing questions)
1. State the order and the conventions.
2. Show the **search path** (which keys you compared).
3. Show the overflow/underflow and the action (split/copy-up/push-up, redistribute/merge).
4. Draw only the changed part if allowed, but label nodes as in the question.

## 2023/24 · Q3(c) [40 + 10 marks]
> **Question:** B+ tree of order two ($d = 2$): max 5 pointers and 4 entries per node. (i) Insert one by one the three-letter keys [era, ban, bat, kin, day, log, rye, max, won, ace, ado, bug, cop, gas, let, fax] into an initially empty B+ tree, using lexicographic ordering; show the tree after every 4 insertions. (ii) What is the utilization of the tree? (Utilization = total entries in all nodes, leaf and non-leaf, ÷ the maximum entries those nodes can store.)

### Expected answer
Alphabetical order of all keys: ace < ado < ban < bat < bug < cop < day < era < fax < gas < kin < let < log < max < rye < won.

**After insertions 1–4 (era, ban, bat, kin)**: a single leaf (= root):
```text
[ban bat era kin]
```
**Insertions 5–8 (day, log, rye, max)**
- day: [ban bat day era kin] overflows → [ban bat] | [day era kin], copy up **day** → root [day].
- log: [day era kin log].
- rye: [day era kin log rye] overflows → [day era] | [kin log rye], copy up **kin** → root [day kin].
- max: [kin log max rye].
```text
              [day | kin]
      ┌────────────┼──────────────┐
  [ban bat]   [day era]   [kin log max rye]
```
**Insertions 9–12 (won, ace, ado, bug)**
- won: [kin log max rye won] overflows → [kin log] | [max rye won], copy up **max** → root [day kin max].
- ace: [ace ban bat]; ado: [ace ado ban bat].
- bug: [ace ado ban bat bug] overflows → [ace ado] | [ban bat bug], copy up **ban** → root [ban day kin max] (4 keys: full but valid).
```text
                   [ban | day | kin | max]
     ┌──────────┬──────────┼──────────┬──────────────┐
 [ace ado] [ban bat bug] [day era] [kin log] [max rye won]
```
**Insertions 13–16 (cop, gas, let, fax)**: no splits:
- cop → [ban bat bug cop]; gas → [day era gas]; let → [kin let log]; fax → [day era fax gas].
```text
                        [ban | day | kin | max]
     ┌───────────────┬────────────┼─────────────┬──────────────┐
 [ace ado] [ban bat bug cop] [day era fax gas] [kin let log] [max rye won]
```
**(ii) Utilization**
- Nodes = 1 root + 5 leaves = **6**; capacity = 6 × 4 = **24** entries.
- Entries = root 4 + leaves (2 + 4 + 4 + 3 + 3 = 16) = **20**.
$$\text{utilization} = \frac{20}{24} \approx 0.833 = \mathbf{83.3\%}$$

### Key points to include
Lexicographic order list; every split with the key copied/pushed up; the four required snapshots; utilization with numerator and denominator shown.
