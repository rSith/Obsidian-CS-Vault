# PP 01.3 · Buffering and Placing a Sequentially Scanned File

> [!info] [[PP 01 - Data Storage and File Organization|PP 01 index]] · Lesson: [[01.04 Buffering of Blocks]] · Priority 🔴 (3 papers)

---

## 2022/23 · Q1(b) [25 marks] and 2023/24 · Q1(b) [25 marks]
> **Questions:** Define the concept of buffering in the context of disk I/O operations. Discuss its significance in improving the performance of data retrieval from storage devices. (2022/23) · Explain the role of buffering in disk input/output operations. Why is buffering considered important for efficient interaction between the CPU and storage devices? (2023/24)

### Expected answer
**Definition.** A **buffer** is a reserved area of **main memory** that holds a copy of a disk block. **Buffering** is reading blocks from disk into these buffers (and writing modified buffers back) so that the CPU works on data in memory. When the addresses of several blocks are known, **several buffers** can be reserved to speed up the transfer.

**How it works: double buffering.** Because an independent **disk I/O processor (controller)** can transfer a block between disk and memory **in parallel with CPU processing**, two buffers A and B are used: while the CPU processes the block in buffer A, the controller fills buffer B with the next block; then they swap.
```text
I/O:  fill A(i) | fill B(i+1) | fill A(i+2) | fill B(i+3)
CPU:            | process A(i)| process B(i+1)| process A(i+2)
```

**Significance / why it matters**
1. **Overlaps CPU and I/O**: the CPU does not sit idle waiting for each block; total time ≈ max(CPU, I/O) rather than their sum.
2. **Continuous reading/writing of consecutive blocks**: seek time and rotational delay are paid **only for the first block**, then only transfer time: $s + rd + k \cdot btt$ instead of $k(s + rd + btt)$.
3. **Data is kept ready** for processing → programs wait less.
4. **Bridges the speed gap** between fast CPU/memory (ns) and slow disks (ms).
5. **Reuse/caching**: blocks already in buffers need not be read again (DBMS buffer pool); writes can be grouped and written back later.

Numeric illustration (Tutorial 1 disk): reading 20 consecutive blocks with double buffering ≈ 62.5 ms vs 870 ms for 20 random blocks.

### Key points to include
Definition; independent I/O processor; two-buffer mechanism (diagram); seek + rotation paid once; CPU–I/O parallelism; caching; an example.

### How to approach
Definition → diagram → 4–5 benefits → one numeric example. For 2023/24 emphasise **CPU–storage interaction** (CPU never stalls; I/O processor works independently).

## 2021/22 · Q2(c) [25 marks]
> **Question:** If you have a large file that is frequently scanned sequentially, explain how you would store the pages in the file on a disk.

### Expected answer
1. **Contiguous allocation:** store the file's pages (blocks) in **consecutive blocks on the same track**, then on the **other tracks of the same cylinder** (switching heads is electronic, no seek), then on **adjacent cylinders**. The arm then moves only between neighbouring cylinders, with minimal seek.
2. **Read with double buffering / prefetching:** the controller reads page *i+1* while the CPU processes page *i*; the seek and rotational delay are paid only once per run.
3. Optionally use **large blocks or extents (clusters of contiguous blocks)** to reduce the number of I/O requests; avoid **linked allocation** (each block may be anywhere → a seek per block).
4. Result: scan time ≈ $s + rd + b \times B/btr$ instead of $b \times (s + rd + btt)$; Tutorial 1: 2,500 blocks take ≈ 3.2 s contiguous vs ≈ 109 s scattered.

### Key points to include
Same track → same cylinder → adjacent cylinders; double buffering; contiguous vs linked allocation; formula/number comparison.

### How to approach
Short explanation + formula comparison; 25 marks ≈ half a page.
