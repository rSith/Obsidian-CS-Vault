## 2020/21 · Q3(c) [25 marks]
> **Question:** What are the components of a disk block address?

**Lesson:** [[01.02 Magnetic Disk Structure]] §3 · Priority 🟡

### Expected answer
Every disk block has a unique **hardware (physical) address** that the DBMS passes to the **disk controller**. It has three components:
1. **Cylinder number:** the cylinder is the imaginary collection of tracks with the **same radius on all surfaces** of the disk pack. The cylinder number tells the **actuator** where to move the **arm** (all heads move together), which costs **seek time**.
2. **Track number (= surface number)** within the cylinder: selects **which surface/read-write head** to use. This is done electronically (no movement).
3. **Block number** within the track: identifies which block along the track; the controller waits for it to **rotate under the head** (rotational delay).

$$\text{address} = \langle \text{cylinder no.},\ \text{track (surface) no.},\ \text{block no.} \rangle$$

Small diagram: concentric tracks on several platters, a vertical "cylinder" through same-radius tracks, a block as an arc on one track.

### Key points to include
- Name all three parts and **what each selects** (arm position / head / rotational position).
- Mention that a block is a group of contiguous **sectors** on one track and is the unit of transfer.
- Link to access time: cylinder → seek; block → rotational delay.

List → explain each in one or two sentences → add a quick sketch. 25 marks = about half a page.

## 2021/22 · Q2(a) [25 marks]
> **Question:** Both disks and main memory support direct access to any desired location (page). Discuss the important differences between the two.

**Lesson:** [[01.01 Types of Storage and Memory Hierarchy]] §6 · Priority 🟡

### Expected answer
Although both are **direct (random) access** devices, they differ in:
| Aspect | Main memory | Disk |
|---|---|---|
| Volatility | **volatile**: lost on power failure | **non-volatile**: persistent |
| Access time | ~nanoseconds, **uniform** for every address | ~milliseconds; **depends on position** (seek + rotational delay + transfer) |
| Mechanism | electronic | **mechanical** (moving arm, spinning platters) |
| Transfer unit | byte/word | whole **block (page)**, 512 B–8 KB |
| Sequential vs random | almost no difference | **sequential (contiguous) much faster** than random |
| CPU access | CPU operates on it **directly** | data must be **copied into memory** before processing and written back if changed |
| Cost / capacity | expensive per byte; GB | ~10× cheaper per byte; TB |
| Role in DBMS | buffers, working area | permanent home of the database (too large for memory; persistent; cheap; online) |

**Consequence:** DBMS costs are measured in **block accesses**; designs (buffering, contiguous allocation, indexes, clustering) aim to reduce disk I/O.

### Key points to include
Volatility; speed difference and its **cause**; block-based transfer; position-dependent cost; copy-to-memory requirement; cost/capacity; why DBs still live on disk.

### How to approach
A comparison table plus a closing sentence on why the difference matters to a DBMS.

## 2022/23 · Q7(c) [short note, 25 marks]
> **Question:** The mechanical components of Hard Disk Drives, how they work and their importance.

**Lesson:** [[01.02 Magnetic Disk Structure]] · [[01.03 Disk Access Time and Performance]] · Priority 🟡

### Expected answer
**Components**
- **Platters** (disks), single- or double-sided, stacked in a **disk pack** on a **spindle** turned by a **motor** at constant speed (5,400–15,000 rpm).
- Each surface holds concentric **tracks** (separated by intertrack gaps), divided into **sectors** (typically 512 B; smallest hardware unit). A **block** is a group of contiguous sectors; blocks are separated by **interblock gaps**.
- Tracks of the same radius on all surfaces form a **cylinder**.
- **Read/write heads**, one per surface, on **arms** attached to an **actuator** that moves all heads together across cylinders. (Fixed-head disks: one head per track, no arm movement, expensive.)
- **Disk controller** (e.g. SCSI interface): accepts I/O commands, positions the arm, performs the transfer.

**How they work:** the block address (cylinder, surface, block) is given to the controller → actuator moves the arm to the cylinder (**seek time**, 3–10 ms) → the head for the surface is activated → wait for the block to rotate under the head (**rotational delay**, half a revolution on average, e.g. 4.17 ms at 7,200 rpm) → bits pass under the head and are transferred to a memory buffer (**block transfer time**).

**Importance**
- Access time is dominated by the **mechanical** steps (seek + rotation): milliseconds vs nanoseconds for memory, so disk I/O is the main cost in databases.
- Data on the **same cylinder/track** can be read without re-seeking → contiguous allocation, clustering and double buffering.
- Faster rpm → lower rotational delay and higher transfer rate.
- Moving parts can fail (head crash) → reliability measures such as **RAID**.
- Capacity = surfaces × tracks × blocks × block size.

### Key points to include
List of components with function; the seek → rotate → transfer sequence; importance for DB performance and reliability.

Short note = 4–5 short paragraphs or a labelled diagram + bullets. Cover **what, how, why** as the question asks.
