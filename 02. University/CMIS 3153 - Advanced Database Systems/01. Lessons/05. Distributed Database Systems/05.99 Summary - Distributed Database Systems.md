# 05.99 · Lesson Summary: Distributed Database Systems

> [!info] Hub: [[05.00 Distributed Database Systems]] · Past papers: [[PP 05 - Distributed Database Systems]] · Priority 🔴 (3/4 papers, a whole question since 2022/23)

## Must know
- **DDB:** collection of logically related databases distributed over a network; **DDBMS** manages it and makes distribution **transparent**; **loosely coupled sites**, no shared components; transactions may span sites.
- **Why:** horizontal/elastic scalability, high availability, geographic distribution, parallel performance and load balancing, fault tolerance (replication; eventual consistency), cost (commodity hardware), disaster recovery, big data, no single point of failure, flexible models, multi-tenancy, microservices.
- **Architecture (textbook-level):** global schema → fragmentation schema → allocation schema → local schemas/DBMSs at sites, joined by a network; DDBMS components: global query processor, transaction manager, catalog.
- **CAP:** only two of Consistency, Availability, Partition tolerance; P is unavoidable → choose C or A during partitions. **CP:** HBase, ZooKeeper. **AP:** Cassandra, Couchbase. **CA:** theoretical.
- **Transparency:** location, naming, replication, fragmentation, design, execution. **Autonomy:** design, communication, execution. **Reliability** (up at a point in time) vs **availability** (up over an interval); fault → error → failure.
- **Fragmentation:** horizontal $\sigma_C(R)$ (rebuild with ∪), vertical $\pi_L(R)$ incl. key (rebuild with outer union/join), mixed $\pi_L(\sigma_C(R))$; derived horizontal; complete and disjoint. **Fragmentation schema** vs **allocation schema**.
- **Replication:** full (best availability/reads, worst updates), none, partial; choose by read/write mix and access locality.
- **Homogeneous** (same DBMS, cooperative, less autonomy) vs **heterogeneous** (different DBMS/schemas); **federated** (global schema, minimal autonomy) vs **multidatabase** (no global schema, full autonomy); heterogeneity: data models, constraints, query languages.
- **Distributed query processing:** mapping → localization → global optimization (communication cost dominates) → local optimization → join processing → partial aggregation → result merging. **Ship the smaller relation; semijoin** sends only join columns.
- **Concurrency/recovery problems:** multiple copies, site failure, link failure/partition, distributed commit, distributed deadlock. **Primary site** (+backup), **primary copy**, **voting**; coordinator election; **logs, checkpoints, 2PC, 3PC**.

## Important formulas / numbers
$$
R_i=\sigma_{C_i}(R),\ R=\bigcup R_i \qquad R_j=\pi_{L_j}(R),\ \bigcup L_j=ATTRS(R),\ L_i\cap L_j=PK(R) \qquad R\ltimes S=\pi_{attrs(R)}(R\bowtie S)
$$
Lecture example: EMPLOYEE 1,000,000 B at site 1, DEPARTMENT 3,500 B at site 2, result at site 3 → best = ship DEPARTMENT to site 1: **403,500 B** (Q), **7,500 B** (Q′). Semijoin with result at site 2: **340,400 B** (Q), **4,800 B** (Q′).

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Centralized DB:** one site, simple, single point of failure | **Distributed DB:** many sites, transparency, availability, communication cost |
| **Horizontal fragmentation:** rows, σ, rebuild with ∪ | **Vertical fragmentation:** columns + key, π, rebuild with outer union/join |
| **Full replication:** max availability, slow updates | **No replication:** cheap updates, low availability |
| **Homogeneous:** same DBMS, cooperative | **Heterogeneous:** different DBMS/schemas, limited cooperation |
| **Federated:** global schema, low autonomy | **Multidatabase:** no global schema, full autonomy |
| **CP:** consistent, may refuse requests | **AP:** always answers, may be stale |
| **Primary site:** one coordinator, simple, bottleneck | **Primary copy:** per-item primary, load spread, needs directory |
| **Distinguished copy:** fewer messages | **Voting:** truly distributed, more messages |
| **2PC:** prepare + commit; blocking if coordinator fails | **3PC:** adds pre-commit; non-blocking |
| **Reliability:** up at a time point | **Availability:** up during an interval |
