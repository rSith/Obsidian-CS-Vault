# 07.99 · Lesson Summary: Data Warehousing and OLAP

> [!info] Hub: [[07.00 Data Warehousing and OLAP]] · Past papers: [[PP 07 - Data Warehousing and OLAP]] · Priority 🟡 (1/4 papers, latest)

## Must know
- **Data warehouse:** enterprise system for analysis and reporting of data from multiple sources; core of BI.
- **Inmon:** **subject-oriented, integrated, nonvolatile, time-variant** collection of data in support of management's decisions.
- **OLAP** (complex analysis of warehouse data), **DSS/EIS** (support for top decision makers), **data mining** (discovering unanticipated knowledge).
- **Characteristics:** integrated multidimensional store; historical (time-series, trends); nonvolatile with periodic incremental refresh; ETL acquisition component.
- **Classification:** enterprise-wide DW, virtual DW (materialised views of operational DBs), data mart (department subset).
- **OLTP vs OLAP:** many short read/write transactions on current detailed data, low latency, normalised vs few complex read-only queries on historical summarised data, large scans, star schemas.
- **Cubes/hypercubes;** operations: **roll-up, drill-down, pivot, slice and dice**, sorting, selection, derived attributes.
- **Fact table** (measures + FKs) and **dimension tables**; **star** (one table per dimension), **snowflake** (normalised dimensions), **fact constellation** (shared dimensions); **bitmap indexes** for low cardinality.
- **Building:** acquisition (extract, format, clean (back flushing), fit, load), storage processes, design considerations, **metadata** (technical, business), **distributed vs federated** warehouses.
- **Warehouse vs view:** persistent, multidimensional, indexable, specialised functions, integrated temporal data vs on-demand relational extract of one DB.

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Database:** daily operations, current, one application, smaller | **Data warehouse:** analysis, historical, many sources, very large |
| **OLTP:** short transactions, writes, ms latency, normalised | **OLAP:** complex queries, reads, scans/aggregates, star schema |
| **Operational data:** detailed, frequently updated, short-term | **Analytical data:** summarised, historical, read-only |
| **Star schema:** denormalised dimensions, fewer joins | **Snowflake schema:** normalised dimensions, more joins |
| **Roll-up:** summarise up a hierarchy | **Drill-down:** more detail |
| **Enterprise DW:** whole organisation | **Data mart:** one department |
| **Distributed warehouse:** one replicated metadata repository | **Federated warehouse:** autonomous components, own metadata |
| **Warehouse:** persistent, indexable | **View:** virtual, not independently indexable |
| **Technical metadata** | **Business metadata** |
