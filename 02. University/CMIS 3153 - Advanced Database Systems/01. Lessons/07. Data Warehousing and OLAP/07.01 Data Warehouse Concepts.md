# 07.01 · Data Warehouse Concepts

> [!info] [[07.00 Data Warehousing and OLAP|Lesson 7]] · DW1 intro, §1, §1.1–§1.3; DW2 pp. 3–7, 11–14 · Priority 🟡 Medium

## 1. What is a data warehouse?
A **data warehouse** (enterprise data warehouse) is an enterprise system for the **analysis and reporting** of structured and semi-structured data collected **from multiple sources** (point-of-sale systems, CRM, files …). It supports **ad-hoc analysis and custom reporting** and is a core component of **business intelligence** (DW1 intro).

**W. H. Inmon's definition:** a data warehouse is
> "a **subject-oriented, integrated, nonvolatile, time-variant** collection of data in support of management's decisions."

| Word | Meaning | Example |
|---|---|---|
| **Subject-oriented** | organised around business subjects, not applications | Sales, Customers, Products (not "the billing program") |
| **Integrated** | data from many sources made consistent (names, codes, units) | "M/F", "1/0", "Male/Female" → one coding |
| **Nonvolatile** | data is **loaded and read, not updated** in place; changes rarely, periodic refresh | yesterday's sales are never edited |
| **Time-variant** | keeps **history**; every record relates to a point/period in time | sales per month for 10 years |

> [!tip] Analogy
> A school's **examination archive**: organised by subject (subject-oriented), combining marks from all classes in one format (integrated), never altered after release (nonvolatile), kept year by year (time-variant), used by the principal to plan (decision support).

## 2. Related terms (DW1 §1.1)
- **OLAP (online analytical processing):** analysis of complex data from the warehouse; uses distributed computing for analyses needing more storage/processing than a desktop.
- **DSS (decision-support systems) / EIS (executive information systems):** help an organisation's **leading decision makers** with higher-level data for complex, important decisions.
- **Data mining:** **knowledge discovery**: searching data for **unanticipated new knowledge** (patterns not found by simply querying). A summarized/aggregated warehouse makes data mining more efficient.

## 3. Database vs data warehouse (DW2 p. 5)
| Feature | Database (operational) | Data warehouse |
|---|---|---|
| **Purpose** | supports **daily operations** (insert, update, delete) | supports **analysis and reporting** |
| **Type of data** | **current, operational** | **historical, analytical** |
| **Data source** | usually **one application** | **integrated from many sources** |
| **Data size** | smaller | **very large** (often 10–100× the sources) |
| Updates | frequent, small transactions | periodic bulk loads; read-only for users |
| Optimised for | transaction processing (OLTP) | data retrieval (OLAP) |
| Users | clerks, applications | managers, analysts, executives |

## 4. Characteristics (DW1 §1.2)
- Stores **integrated** data from multiple sources in a **multidimensional model** (unlike multidatabases, which just give access to separate databases).
- Supports **time-series and trend analysis** → needs much more **historical** data than transactional DBs.
- **Nonvolatile:** changes far less often; non-real-time with **periodic** (usually incremental) refresh; information is **coarse-grained**.
- Updates go through the **acquisition component** (ETL: extraction, transformation, loading) that cleans and reformats data.
- A collection of **decision-support technologies** for knowledge workers (executives, managers, analysts).
- Distinctive characteristics listed in DW1: multidimensional conceptual view; generic dimensionality; unlimited dimensions and aggregation levels; unrestricted cross-dimensional operations; dynamic sparse-matrix handling; client-server architecture; multiuser support; accessibility; transparency; intuitive data manipulation; consistent reporting performance; flexible reporting.

## 5. Classification (DW1 §1.3)
| Type | Description |
|---|---|
| **Enterprise-wide data warehouse** | huge projects covering the whole organisation; massive investment of time and resources |
| **Virtual data warehouse** | **views of operational databases** that are **materialized** for efficient access |
| **Data mart** | targeted to a **subset** of the organisation, e.g. one department; more tightly focused |

## 6. Why organisations need data warehouses (DW2 pp. 6–7)
**Need:** huge data volumes; data **scattered** across systems; operational DBs **not optimised for analysis**. A DW **integrates** sources, **stores history**, **improves decision speed and accuracy**.
**Problems without one:** inconsistent data across systems; slow, complex reporting; hard to analyse historical trends; heavy load on operational systems; poor support for management decisions.

## 7. Decision Support Systems and the DW's role (DW2 pp. 11–12)
A **DSS** is a computer-based system that helps managers make informed decisions by analysing data (trends, performance comparison, prediction). The DW provides **clean, integrated, reliable** data and **fast queries**, and supports **reporting, data mining and BI tools**, improving decision quality.

**Applications (DW2 p. 13):** business intelligence, healthcare analysis, government and policy analysis, educational planning, financial analysis, sales and marketing analysis, DSS.
