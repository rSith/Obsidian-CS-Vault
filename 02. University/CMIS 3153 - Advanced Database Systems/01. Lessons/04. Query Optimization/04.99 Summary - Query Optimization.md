# 04.99 · Lesson Summary: Query Optimization

> [!info] Hub: [[04.00 Query Optimization]] · Past papers: [[PP 04 - Query Optimization]] · Tutorial: [[TUT 4 - Selectivity and Index Cost]] · Priority 🔴 (4/4 papers)

## Must know
- **Query optimization** = choosing the most efficient evaluation plan; done by the system, not the user; needs the **cost** of each operation.
- **Two techniques:** heuristic rules (reorder operations in the tree) + systematic **cost estimation**; real optimizers combine them.
- **Execution:** execution plan = indexes, join algorithms, parallelism, order. Scans: table vs index (clustered/non-clustered). Joins: **nested loop** (any condition, small inputs), **index nested loop**, **hash** (equality, large inputs), **sort-merge** (sorted inputs). Phases: fetch → filter → join → project → aggregate/sort.
- **Cost factors:** disk I/O (dominant), CPU, memory, storage of intermediates, communication. **Cost models:** simple, statistical (cardinality, selectivity, histograms), Cascades (dynamic programming), exponential.
- **Catalog statistics:** $r, R, b, bfr$, file organization, indexes and levels $x$, distinct values $d$, selectivity $sl$, selection cardinality $s = sl \cdot r$ (key: $s=1$; non-key: $s = r/d$).
- **Logical plan** = what (RA operators, independent of storage); **physical plan** = how (algorithms, access paths, uses costs).
- **Three steps of optimization:** parse/translate → optimize (with statistics) → evaluate.
- **CBO** (generate → cost → select; accurate but expensive, needs good statistics) vs **RBO/heuristic** (fixed rules; fast, ignores data). Others: hybrid, genetic/ML, dynamic/adaptive.
- **Query tree:** leaves = relations, internal nodes = operators, root = result; order bottom-up. **Query graph:** nodes = relations/constants, edges = conditions; no order; one per query.
- **Heuristics:** cascade σ, push σ down, most restrictive first, avoid ×, × + σ → ⋈, push π down.
- **12 transformation rules** (cascade/commute σ; cascade π; σ↔π; ⋈/× commutative and associative; σ↔⋈; π↔⋈; set ops; σ↔set ops; π↔∪; σ+× → ⋈).
- **Indexes in optimization:** access paths, join methods, avoid sorts, covering; used only when selective enough; write overhead.

## Important formulas
$$
s = sl \times r,\qquad sl_{key} = \tfrac1r,\qquad sl_{nonkey} = \tfrac1d,\qquad \text{selectivity}=\frac{\text{matching}}{\text{total}}
$$
$$
\sigma_{c_1\wedge c_2}(R)=\sigma_{c_1}(\sigma_{c_2}(R)) \qquad \sigma_c(R\bowtie S)=\sigma_c(R)\bowtie S \ (c \text{ on } R) \qquad \sigma_c(R\times S)=R\bowtie_c S
$$

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Logical plan:** what, RA, storage-independent, rewritten by rules | **Physical plan:** how, algorithms/access paths, chosen by cost |
| **Cost-based:** estimates from statistics, many plans, slower to optimize | **Rule-based/heuristic:** fixed rules, one transformed plan, fast |
| **Query tree:** ordered, RA, many per query, used for execution | **Query graph:** unordered, calculus, one per query, shows connections/join options |
| **Table scan:** all blocks, sequential | **Index scan:** selective lookups, random I/O if non-clustered |
| **Nested loop:** any θ, small tables | **Hash join:** equality, large tables, each input read once |
| **Sort-merge:** sorted inputs | **Index nested loop:** small outer + index on inner |
| **Static (rule) optimization:** before execution | **Dynamic optimization:** adjusts during execution |
| **Predicate push-down:** fewer rows | **Projection push-down:** fewer columns |

Role of indexing. 6. Why one physical plan beats another. 7. Reasons for poor performance + remedies.
