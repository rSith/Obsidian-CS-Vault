# 04.04 · Query Optimization Strategies (Cost-Based, Rule-Based, Hybrid, ML, Dynamic)

> [!info] [[04.00 Query Optimization|Lesson 4]] · Lecture L4 §1 (intro), §3.1–§3.5, §5 · Priority 🔴 High
> **Asked as:** "Describe Cost-based and Rule-based query optimisation techniques." (2021/22 Q7(b), 20 marks) · "Discuss the concepts of cost-based optimization and heuristic-based optimization. What is the fundamental difference between these approaches?" (2022/23 Q5(b), 20 marks)

## 1. The two classic techniques (lecture §1)
1. **Heuristic (rule-based):** apply rules that **usually** improve a plan (e.g. "do selections before joins") to reorder operations in the query tree. *A heuristic works well in most cases but is not guaranteed to work well in every case.*
2. **Cost-based:** **systematically estimate the cost** of different execution strategies and choose the one with the **lowest estimated cost**.

Real optimizers **combine** both.

> [!tip] Analogy: choosing a route home
> **Rule-based:** "Always take the highway; never drive through the city centre." Quick to decide, usually right, but wrong on the day the highway is jammed.
> **Cost-based:** check today's live traffic for every possible route, estimate each travel time, take the fastest. Better decisions, but you spend time checking, and it only works if the traffic data is accurate.

## 2. Cost-based optimization (CBO) (lecture §3.1)
**Idea:** evaluate multiple plans; pick the one with the **least estimated cost** (CPU, disk I/O, memory, network).

**Key aspects**
- **Cost model:** estimates resource use from table cardinalities, condition selectivity, available indexes ([[04.02 Query Cost and Cost Models]]).
- **Cardinality estimation:** how many rows each operation will produce.
- **Selectivity estimation:** what fraction of rows a condition keeps.

**Process**
1. **Plan generation:** produce alternative plans by transformations (join reordering, predicate push-down …).
2. **Cost estimation:** cost each plan (index availability, join algorithms, sorting).
3. **Plan selection:** choose the cheapest.

**Pros:** accurate; considers many strategies; adapts to data and hardware **if** statistics are good.
**Cons:** optimization itself can be **computationally expensive** for complex queries (huge search space); depends on **accurate, up-to-date statistics**.

## 3. Rule-based / heuristic optimization (RBO) (lecture §3.2, §4)
**Idea:** apply **predefined rewrite rules** believed always (or usually) to help, regardless of the data.

**Typical rules**
- **Predicate push-down:** move filters as close as possible to the data source.
- **Projection push-down:** drop unneeded columns early.
- **Join reordering:** minimize intermediate results (most restrictive first).
- **Constant folding:** replace `2 + 3` by `5`.
- Replace Cartesian product + selection by a join.
- "Sorting is costly, avoid it if possible."

**Process:** apply rules → result is a transformed, more efficient query/tree.
**Pros:** **fast and simple**: no multiple plans, no cost estimates; works well when simple heuristics apply.
**Cons:** **inflexible**: rules are static and **ignore actual data distribution**, so plans can be suboptimal (e.g. using an index on a column where 90% of rows match).

## 4. Fundamental difference (2022/23 Q5(b))
> **Heuristic optimization decides by fixed rules about the *form* of the query; cost-based optimization decides by *estimated cost* computed from statistics about the actual data.**

| | Heuristic / rule-based | Cost-based |
|---|---|---|
| Basis of decision | general rules ("σ before ⋈") | numerical cost estimates |
| Uses statistics? | **no** | **yes** (cardinality, selectivity, histograms, indexes) |
| Number of plans considered | usually one (transformed) | many alternatives |
| Optimization time | low | can be high |
| Quality of plan | good in typical cases, not guaranteed | usually better, if statistics are accurate |
| Adapts to data distribution | no | yes |
| Typical use | first pass: logical rewriting of the query tree | choosing join order, algorithms, access paths |
| Risk | rule fits badly for unusual data | stale statistics → wrong estimates |

## 5. Other strategies (lecture §3.3–§3.5)
| Strategy | Idea | + | − |
|---|---|---|---|
| **Hybrid** | rules first to simplify / shrink the search space, then cost-based selection among the remaining plans | speed of rules + quality of costing; good for complex queries | more expensive than rules alone; still depends on statistics |
| **Genetic algorithms** | a "population" of plans evolves by mutation and crossover toward the best | handles huge search spaces (many joins) | approximate, complex |
| **Machine-learning-based** | learn from historical queries/plans/run times to predict good plans | adapts to changing workloads; may beat traditional optimizers | needs much historical data; complex; learning overhead |
| **Dynamic (adaptive)** | start with an initial plan; **monitor during execution** and change the plan using intermediate results (feedback loop) | robust when initial estimates are wrong; good for real-time/streaming | adds runtime complexity and overhead |

## 6. Exam-relevant points
- Define both; give **2–3 example rules** for RBO; list the **CBO steps** (generate → cost → select) and the **statistics used**.
- State the **fundamental difference** in one sentence (rules vs estimated costs from statistics).
- Mention that **real DBMSs combine them** (hybrid).
