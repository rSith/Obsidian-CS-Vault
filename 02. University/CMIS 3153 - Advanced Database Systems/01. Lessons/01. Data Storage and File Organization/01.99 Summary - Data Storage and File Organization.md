# 01.99 · Lesson Summary: Data Storage and File Organization

> [!info] Hub: [[01.00 Data Storage and File Organization]] · Past papers: [[PP 01 - Data Storage and File Organization]] · Tutorials: [[TUT 1 - Disk and File Calculations]], [[TUT 2 - Records, File Organization and B-Trees]] · Priority 🔴 (4/4 papers, usually Q1)

## Must know
- **Storage types:** primary (RAM, cache; volatile; CPU works on it directly), secondary (HDD/SSD; non-volatile), tertiary (tape, archive), cloud. Data on disk must be **copied into memory** to be processed.
- **Memory hierarchy:** faster/smaller/dearer near the CPU; slower/larger/cheaper further away.
- **Why databases live on disk:** too big for RAM, non-volatile, ~10× cheaper, online.
- **Disk anatomy:** platters, surfaces, tracks, cylinders, sectors, blocks, interblock gaps, heads, arm/actuator, controller.
- **Block address = cylinder + track (surface) + block number.**
- **Access time $= s + rd + btt$**; $rd = \tfrac12 \cdot 60{,}000/p$ ms; $btt = B/tr$; $btr = \frac{B}{B+G}tr$.
- **Consecutive blocks pay $s + rd$ once** → store sequentially scanned files **contiguously** and use **double buffering**.
- **Records:** fixed vs variable length (4 reasons for variable); **spanned vs unspanned**; $bfr = \lfloor B/R \rfloor$, $b = \lceil r/bfr \rceil$.
- **Allocation:** contiguous, linked, clusters/extents, indexed. **File header** = block addresses + record format.
- **File organization** (how data is arranged) vs **access method** (operations applied).
- **Heap:** cheap insert, $b/2$ search. **Sorted:** binary search $\log_2 b$, fast ranges, expensive insert/delete (overflow file + reorganize).
- **Hashing:** $h(K)$ → bucket; O(1) equality; **no ranges**; collisions via chaining or open addressing (linear, quadratic, double hashing); external hashing uses buckets = blocks + header table; dynamic schemes (extendible with directory and global/local depth; linear hashing without directory).
- **RAID:** objective, striping / mirroring / parity, levels 0, 1, 5, 6, 10.
- **SAN** (block-level, dedicated network) vs **NAS** (file-level, Ethernet).

## Important formulas
$$
rd = \frac{30{,}000}{p}\ \text{ms}\qquad tr = \frac{\text{track bytes}}{60{,}000/p}\qquad btt = \frac{B}{tr}\qquad btr = \frac{B}{B+G}\,tr
$$
$$
bfr = \left\lfloor \frac{B}{R}\right\rfloor\qquad b = \left\lceil\frac{r}{bfr}\right\rceil\qquad T_{\text{random},k} = k(s+rd+btt)\qquad T_{\text{consecutive},k} = s+rd+k\frac{B}{btr}
$$

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Main memory:** volatile, ns access, byte-addressable, CPU works directly, expensive | **Disk:** non-volatile, ms access (seek + rotation), block transfers, must copy to RAM, cheap |
| **Fixed-length records:** same size, fixed field offsets, may waste space | **Variable-length:** varying size, separators/length fields, less waste, harder to update |
| **Unspanned:** record within one block; wastes $B - bfr\cdot R$ | **Spanned:** record may cross blocks via pointer; needed when $R > B$ |
| **Contiguous allocation:** fast full reads, hard to expand | **Linked allocation:** easy expansion, slow full reads |
| **Heap file:** O(1) insert, $b/2$ search | **Sorted file:** $\log_2 b$ search, fast ranges, costly inserts |
| **Hash file:** ~1 block equality lookup, no ranges | **Sorted/B+-tree:** $\log$ lookup, supports ranges and order |
| **Chaining:** linked overflow lists | **Open addressing:** probe other slots in the table |
| **RAID 0:** striping, no redundancy | **RAID 1:** mirroring, 50% capacity |
| **RAID 5:** single distributed parity, survives 1 failure | **RAID 6:** double parity, survives 2 failures |
| **SAN:** block-level, Fibre Channel/iSCSI, databases | **NAS:** file-level, Ethernet, file sharing |
| **File organization:** arrangement of records/blocks | **Access method:** operations applied to a file |
