# 01.02 · Magnetic Disk Structure

> [!info] [[01.00 Data Storage and File Organization|Lesson 1]] · Lecture L1 §5 · Priority 🔴 High
> **Asked as:** "What are the components of a disk block address?" (2020/21 Q3(c), 25 marks) · "Short note: the mechanical components of Hard Disk Drives, how they work and their importance" (2022/23 Q7(c), 25 marks)

## 1. What is it?
A **magnetic disk** (hard disk drive, HDD) stores bits by **magnetizing tiny areas** of a spinning metal platter: one direction means 0, the other means 1. Bits are grouped into **bytes** (one character = one byte in this course).

> [!tip] Analogy: a vinyl record player stack
> Picture a stack of vinyl records on one spindle, all spinning together. Instead of one groove spiralling in, each record surface has many separate **circles** (tracks). A comb of needles (read/write heads), one per surface, moves in and out together on one arm. To play a song you must (1) move the needles to the right circle, then (2) wait for the right part of the circle to spin under the needle, then (3) read it. Those three waits are exactly [[01.03 Disk Access Time and Performance|seek time, rotational delay and transfer time]].

## 2. Components (the vocabulary you must know)
| Component | Simple meaning | Lecture detail |
|---|---|---|
| **Platter / disk** | one round metal plate | **single-sided** (one surface used) or **double-sided** (both surfaces) |
| **Disk pack** | several platters on one spindle | gives many surfaces → more capacity |
| **Spindle + motor** | spins the pack | constant speed, typically **5,400–15,000 rpm** |
| **Track** | one concentric circle on a surface | same width as the head; hundreds to thousands per surface; tens of KB to ~150 KB each |
| **Intertrack gap** | blank band between tracks | separates adjacent tracks |
| **Cylinder** | the set of tracks with the **same diameter** on **all** surfaces | data on one cylinder is read **much faster**: no arm movement is needed |
| **Sector** | an arc (slice) of a track | fixed at formatting; typically **512 bytes**; the **smallest unit read or written** by hardware |
| **Block (page)** | a run of contiguous sectors on one track | size fixed at formatting: **512–8192 bytes**; the **unit of transfer** between disk and memory |
| **Interblock gap** | fixed-size gap between blocks | holds control information so the head knows which block comes next; carries no user data |
| **Read/write head** | the "needle" that senses/sets magnetism | one per surface |
| **Arm + actuator** | moves all heads **together** | positions the heads over the cylinder named in the block address |
| **Disk controller** | electronics inside the drive | takes I/O commands (e.g. via SCSI), moves the arm, starts the read/write |

Because each track holds the same number of bits, **bit density increases from the outer track toward the inner track**.

### Fixed-head vs movable-head disks
- **Movable-head disk:** one head per surface on a moving arm (normal HDD).
- **Fixed-head disk:** one head **per track**, so a track is selected **electronically** with no arm movement: much faster, but the extra heads are very expensive, so they are rare.

## 3. The disk block address (2020/21 Q3(c))
Every block has a unique **hardware (physical) address** made of three parts:

$$
\text{block address} = \langle\ \text{cylinder number},\ \text{track (surface) number},\ \text{block number}\ \rangle
$$

| Part | Meaning | Analogy |
|---|---|---|
| **Cylinder number** | which "ring" (the imaginary collection of same-radius tracks on all surfaces); tells the **arm where to move** | which floor of a building |
| **Track number** (= **surface number** within the cylinder) | which surface/head to use; selected **electronically** | which side of the corridor |
| **Block number** (within the track) | which block along that track; found by **waiting for rotation** | which door |

To read a block, the DBMS gives this address to the **disk controller**, which moves the arm to the cylinder, activates the right head, and waits for the block to rotate underneath.

## 4. How a read works, step by step
1. The DBMS asks for block ⟨c, t, b⟩.
2. The controller moves the actuator arm to **cylinder c** → *seek time*.
3. It switches on the head for **surface t**.
4. It waits until **block b** spins under the head → *rotational delay*.
5. The bytes pass under the head and are copied into a memory buffer → *block transfer time*.

## 5. Why the mechanics matter (importance)
- **Mechanical movement is slow.** Seek and rotation take milliseconds, while CPU and memory work in nanoseconds; the disk is usually the bottleneck of a database.
- **Placement matters.** Putting related blocks on the **same track or cylinder** removes repeated seeks: the basis of contiguous allocation and of reading files sequentially ([[01.04 Buffering of Blocks]]).
- **Reliability:** moving parts wear out and heads can crash; this motivates [[01.10 RAID]].
- **Capacity planning:** capacity = surfaces × tracks × blocks × block size (see [[TUT 1 - Disk and File Calculations|Tutorial 1 Q1]]).

## 6. Capacity formulas
For $n$ blocks per track, block size $B$, interblock gap $G$, $t$ tracks per surface and $f$ surfaces:

$$
\text{track size (total)} = n(B+G) \qquad \text{track size (useful)} = nB
$$
$$
\text{cylinder capacity} = f \times \text{track size} \qquad \text{number of cylinders} = t
$$
$$
\text{disk pack capacity} = t \times \text{cylinder capacity}
$$

> [!example] Tutorial 1 Q1 (also the disk in 2021/22 Q6)
> $B = 512$, $G = 128$, 20 blocks/track, 400 tracks/surface, 15 double-sided disks → $f = 30$ surfaces.
> Track: total $20 \times 640 = 12{,}800$ B, useful $20 \times 512 = 10{,}240$ B. Cylinders: **400**. Cylinder: total $30 \times 12{,}800 = 384{,}000$ B, useful $307{,}200$ B. Pack: total $400 \times 384{,}000 = 153{,}600{,}000$ B, useful $122{,}880{,}000$ B. Full working in [[TUT 1 - Disk and File Calculations]].

## 7. Exam-relevant points
- **Block address = cylinder no. + track (surface) no. + block no.** Say what each one selects (arm position, head, rotational position).
- For the "mechanical components" short note: list **platters, spindle/motor, tracks/sectors/cylinders, read/write heads, arm and actuator, controller**, explain **how a read happens** (seek → rotate → transfer), and explain **importance** (access time dominated by mechanics; cylinder placement; reliability → RAID).
- Know **sector vs block**: a sector is the hardware's smallest unit (fixed at manufacture/format); a block is a group of contiguous sectors chosen at formatting and is the unit of transfer.
