# 01.01 · Types of Storage and the Memory Hierarchy

> [!info] [[01.00 Data Storage and File Organization|Lesson 1]] · Lecture L1 §1–§4 · Priority 🟡 Medium
> **Asked as:** "Both disks and main memory support direct access to any desired location (page). Discuss the important differences between the two." (2021/22 Q2(a), 25 marks)

## 1. What is data storage?
**Data storage** is the process of saving and managing digital information so it can be found, read and changed later. Its goal (lecture §1) is that information is **available and secure**, with suitable **retrieval speed, redundancy and backup**.

A computer has several *kinds* of storage. They differ in **speed**, **size**, **cost** and whether they **forget everything when the power goes off** (this property is called *volatility*).

> [!tip] Analogy
> - **Cache / RAM** = your desk: tiny, but whatever is on it you can grab instantly. Clear the desk (power off) and it is empty.
> - **Hard disk / SSD** = the bookshelves in your room: much bigger, a few steps away, and the books stay there overnight.
> - **Tape / archive / cloud archive** = a storage unit across town: enormous and cheap, but you only go there for old boxes.

## 2. The four types of storage (lecture §2)
| Type | Also called | Volatile? | Examples | Speed | Capacity / cost |
|---|---|---|---|---|---|
| **Primary** | main memory, RAM | **Yes** (lost at power-off) | CPU cache (SRAM), main memory (DRAM) | fastest; the CPU works on it **directly** | small, expensive per byte |
| **Secondary** | online storage | **No** (persistent) | HDD, SSD, optical disc, USB flash drive | slower | large, cheaper |
| **Tertiary** | archival / offline | **No** | magnetic tape drives, cloud archives, optical jukeboxes | slowest | huge, cheapest |
| **Cloud** | remote storage | No | storage on internet servers | depends on network | very scalable, pay as you go |

Key rule from the lecture: **data in secondary or tertiary storage cannot be processed directly by the CPU**. It must first be **copied into primary storage** (RAM), processed there, and written back if it changed.

## 3. The memory hierarchy (lecture §3)
A **memory hierarchy** arranges storage by speed, size and cost: **faster, smaller, more expensive** memory sits **closer to the CPU**; **slower, larger, cheaper** memory sits further away.

```text
        fastest, smallest, most expensive per byte
                 ┌──────────────┐
                 │ CPU registers│
                 ├──────────────┤
                 │ Cache (SRAM) │   primary storage, volatile
                 ├──────────────┤
                 │ Main memory  │   (DRAM)
                 ├──────────────┤
                 │ Flash / SSD  │
                 ├──────────────┤
                 │ Magnetic disk│   secondary storage, non-volatile, direct access
                 ├──────────────┤
                 │ Optical disk │   tertiary
                 ├──────────────┤
                 │ Magnetic tape│   tertiary, sequential access, offline
                 └──────────────┘
        slowest, largest, cheapest per byte
```

| Device (lecture §3) | Level | Key facts |
|---|---|---|
| **Cache memory** | primary | static RAM; used by the CPU to speed up instructions (prefetching, pipelining); volatile; random access |
| **Main memory** | primary | DRAM; the CPU's main work area; cheap compared with SRAM but volatile and slower than cache; random access |
| **Hard disks** | secondary | magnetic; non-volatile; GB–TB; **direct access** |
| **Optical disks** | tertiary | CD-ROM, DVD; non-volatile; MB–GB |
| **Magnetic tapes** | tertiary | archiving and backup; cheapest; non-volatile; **sequential access** |
| **Flash memory** | (between) | EEPROM, floating-gate transistors; non-volatile; fast, durable, low power; USB drives, phones, SSDs |

### Trade-offs (lecture §3.1)
- **Speed vs capacity:** faster memory is smaller and dearer; bigger storage is slower and cheaper.
- **Cost vs performance:** put expensive fast memory near the CPU, cheap slow memory for long-term storage.
- **Data access:** frequently needed data is kept in fast memory; rarely used data in slower memory.

### Emerging technologies (lecture §3.2)
3D NAND (stacked flash layers in SSDs), Intel Optane / 3D XPoint (non-volatile memory between DRAM and storage), quantum storage (research stage).

## 4. Why databases live on disk (lecture §3.3)
Data that must last a long time is called **persistent data**. Most databases are stored on **magnetic disk** because:
1. Databases are usually **too large to fit in main memory**.
2. Disk is **non-volatile**; main memory is volatile.
3. Disk storage **costs an order of magnitude less per unit** than primary storage.
4. Disks are **online** (directly accessible at any time), unlike tapes, which are offline.

Whenever data is needed it is **located on disk → copied to main memory → processed → written back to disk if changed**. That round trip is why the rest of the course obsesses over *how many disk blocks* an operation reads.

The lecture also names three storage styles used by DBMSs: **file storage** (files in a file system, DB keeps metadata; weak for big data), **block storage** (fixed-size blocks, used in [[01.11 SAN and NAS|SANs]]; fast and flexible) and **object storage** (objects + metadata in cloud systems; very scalable).

### Primary file organization vs secondary access structure
- A **primary file organization** decides **where records physically go** on disk: [[01.07 Heap and Sorted Files|heap, sorted]], [[01.08 Hash Files and Collision Handling|hashed]], or B-tree.
- A **secondary organization / auxiliary access structure** (an [[02.01 What Is an Index|index]]) gives a fast path to records using **other fields**, without moving the records.

## 5. Key considerations in data storage (lecture §4)
| Consideration | Question it answers |
|---|---|
| Capacity | How much can be stored (petabytes, exabytes for big data / IoT / ML)? |
| Speed | How fast can data be read or written? |
| Reliability and durability | Is the data correct and consistent? Does it survive time and hardware failure? |
| Scalability | Can storage grow as data grows? |
| Security | Is it protected from unauthorized access, corruption and loss (encryption, backup)? |
| Cost | What is the cost per unit stored? |

## 6. Important distinction: main memory vs disk (exam favourite)
Both support **direct (random) access** to any location, but:

| Aspect | Main memory (RAM) | Magnetic disk |
|---|---|---|
| Volatility | **volatile**: contents lost on power failure | **non-volatile**: persistent |
| Access time | nanoseconds; same for every address | milliseconds; **depends on where the head is** (seek + rotation) |
| Unit of transfer | a byte or word | a whole **block / page** (512 B–8 KB) |
| How access works | purely electronic | **mechanical**: arm moves, platter spins ([[01.02 Magnetic Disk Structure]]) |
| Cost per byte | high | about 10× lower or more |
| Capacity | GB | TB |
| CPU access | CPU operates on it directly | data must be **copied into memory** first |
| Role in a DBMS | buffer pool, working area | permanent home of the database |
| Sequential vs random | little difference | **sequential reads are far cheaper** than random reads |

> [!example] Why this matters
> Reading one random disk block costs about 10 ms. In the same 10 ms, RAM can serve tens of millions of reads. That gap is why a DBMS counts **block accesses** as its main cost ([[04.02 Query Cost and Cost Models]]) and why [[01.04 Buffering of Blocks|buffering]] and [[02.01 What Is an Index|indexes]] exist.
