# 01.10 · RAID (Redundant Array of Independent Disks)

> [!info] [[01.00 Data Storage and File Organization|Lesson 1]] · Lecture L1 §8, §8.1 · Priority 🟡 Medium
> **Asked as:** "Discuss RAID architecture. Your answer should cover the objective of RAID, the key techniques used, and a brief description of the types of RAID." (2021/22 Q2(d), 25 marks)

## 1. What is RAID?
**RAID** combines **several physical disks into one logical disk** to improve **performance**, **reliability (redundancy)**, or both. It is standard in servers and enterprise storage.

> [!tip] Analogy: a team of photocopiers
> One photocopier copying a 1,000-page book is slow. **Four photocopiers each copying every fourth page** finish 4× faster (striping). Making **two identical copies** means losing one copy is no disaster (mirroring). Keeping a **checksum sheet** lets you recreate any one lost page from the others (parity).

## 2. Objective of RAID (lecture §8)
Processors and memory have become faster much more quickly than disks. RAID's main goal is to **even out this gap**: use **a large array of small independent disks acting as a single higher-performance logical disk**, while also providing **fault tolerance** so that a disk failure does not lose data.

## 3. Key techniques
| Technique | How it works | Gives |
|---|---|---|
| **Data striping** | split data into equal-sized blocks and spread them across disks (block 1 → disk 1, block 2 → disk 2 …) | **parallel I/O** → higher throughput; capacity = sum of disks |
| **Mirroring (shadowing)** | write identical copies of the data to two or more disks | **redundancy**; reads can use either copy |
| **Parity** | store extra computed information (e.g. XOR of the data blocks) | the data on **one failed disk can be rebuilt** from the others, at lower cost than mirroring |

```text
Striping (RAID 0)          Mirroring (RAID 1)         Striping + distributed parity (RAID 5)
Disk1 Disk2 Disk3 Disk4    Disk1   Disk2              Disk1 Disk2 Disk3 Disk4

```

## 4. RAID levels (lecture §8.1)
| Level | Technique | Fault tolerance | Read / write performance | Usable capacity | Use case (lecture) |
|---|---|---|---|---|---|
| **RAID 0** | striping, **no redundancy** | **none**: one disk fails → all data lost | very high read and write | 100% (sum of all disks) | temporary storage, video editing |
| **RAID 1** | mirroring | survives loss of a disk (as long as one copy remains) | reads improved (either disk); writes ≈ single disk | 50% (one disk's worth for a pair) | critical databases, OS drives |
| **RAID 5** | striping with **distributed parity** | survives **1** disk failure | good reads; slower writes (parity computation) | total − 1 disk | file and web servers |
| **RAID 6** | striping with **double parity** | survives **2** disk failures | good reads; writes slower than RAID 5 | total − 2 disks | enterprise high-availability storage |
| **RAID 10** (1+0) | mirror pairs, then stripe across pairs | one disk per mirrored pair | high reads **and** writes | 50% | high-performance databases, critical systems |

> [!warning] Small inconsistency in the lecture (RAID 5)
> The lecture first says parity is "stored on a separate disk" and later says "parity is distributed across all disks". **RAID 5 distributes parity across all disks** (storing it on one dedicated disk is RAID 4). Use the distributed version in exams.

### Advantages and disadvantages (lecture)
- RAID 0: + highest performance, full capacity · − no fault tolerance.
- RAID 1: + excellent fault tolerance, better reads · − half the capacity, writes not faster.
- RAID 5: + fault tolerance with lower overhead than RAID 1, good reads, good compromise · − slower writes, two failures lose data.
- RAID 6: + survives two failures · − slower writes than RAID 5, more capacity lost.
- RAID 10: + excellent fault tolerance and high read/write · − only 50% capacity, needs more disks (at least 4).

## 5. Why RAID matters to databases
- **Performance:** striping lets a big table scan read from several disks in parallel.
- **Availability:** a failed disk does not stop the DBMS (RAID 1/5/6/10).
- **Choice depends on workload:** write-heavy OLTP logs → RAID 10 (no parity penalty); read-mostly warehouses → RAID 5/6 for capacity.
