# 01.12 · Worked File and Disk Calculations

> [!info] [[01.00 Data Storage and File Organization|Lesson 1]] · Lecture L1 §5.1, §5.3.3, §7.1–7.2 · Priority 🔴 High
> **Asked as:** 2021/22 Q6(a)–(e) (100 marks, **identical to [[TUT 1 - Disk and File Calculations|Tutorial 1 Q2]]**), 2022/23 Q1(c), 2023/24 Q1(c).
> This note collects **every formula** and a method you can follow line by line.

## 1. The formula sheet
| Quantity | Formula | Notes |
|---|---|---|
| Record size | $R = \sum \text{field sizes} \ (+1 \text{ deletion marker})$ | include every byte the question lists |
| Blocking factor | $bfr = \lfloor B/R \rfloor$ | unspanned, fixed-length; round **down** |
| Wasted space per block | $B - bfr \cdot R$ | unspanned only |
| Number of blocks | $b = \lceil r / bfr \rceil$ | round **up** |
| One revolution | $60{,}000/p$ ms | $p$ = rpm |
| Rotational delay | $rd = \tfrac12 \cdot 60{,}000/p$ ms | average = half a revolution |
| Transfer rate | $tr = \text{track size}/\text{revolution time}$ | bytes/ms; track size includes gaps if the track is described as $n(B+G)$ |
| Block transfer time | $btt = B/tr$ | ms |
| Bulk transfer rate | $btr = \frac{B}{B+G} \cdot tr$ | useful bytes/ms for consecutive blocks |
| One random block | $s + rd + btt$ | |
| $k$ random blocks | $k(s + rd + btt)$ | non-contiguous file |
| $k$ consecutive blocks (double buffering) | $s + rd + k \cdot (B/btr)$ | less accurate: $s + rd + k \cdot btt$ |
| Linear search, average | $b/2$ blocks (record found); $b$ (not found / several) | heap or unsorted search |
| Binary search | $\lceil \log_2 b \rceil$ blocks, each a random access | sorted on the search field |

## 2. Method for any "file on disk" question
1. **Disk parameters first:** $rd$, $tr$, $btt$, $btr$ (if not given).
2. **File:** $R$ → $bfr$ → $b$.
3. **Search:** how many blocks? Are they contiguous (pay $s + rd$ once) or scattered (pay it every block)?
4. **Multiply** and state the answer in ms and seconds.

## 3. Full worked example: 2021/22 Q6 / Tutorial 1 Q2
**Given:** $r = 20{,}000$ STUDENT records; fields Name 30, Ssn 9, Address 40, PHONE 10, Birthdate 8, Sex 1, Major_dept_code 4, Minor_dept_code 4, Class_code 4, Degree_program 3; deletion marker 1 byte. Disk: $B = 512$, $G = 128$, 20 blocks/track, 400 tracks/surface, 15 double-sided disks.

> [!warning] Missing parameters in the 2021/22 paper
> The paper does **not** print the rpm or seek time; it says "the disk whose parameters are …" and lists only $B$, $G$, blocks/track, tracks/surface. Tutorial 1 (the same question) uses **2400 rpm** and **average seek 30 ms** from Q1(e)–(f). In the exam, **state these as assumptions** taken from the tutorial disk.

**Disk parameters (from Tutorial 1 Q1):**
- Revolution $= 60{,}000/2400 = 25$ ms → $rd = 12.5$ ms
- Track size $= 20 \times (512 + 128) = 12{,}800$ bytes → $tr = 12{,}800/25 = 512$ bytes/ms
- $btt = 512/512 = 1$ ms
- $btr = \frac{512}{640} \times 512 = 409.6$ bytes/ms → $B/btr = 1.25$ ms
- $s = 30$ ms → random block access $= 30 + 12.5 + 1 = 43.5$ ms

**(a) Record size**
$$R = 30+9+40+10+8+1+4+4+4+3+1 = 114 \text{ bytes}$$

**(b) Blocking factor and blocks (unspanned)**
$$bfr = \lfloor 512/114 \rfloor = \lfloor 4.49 \rfloor = 4 \qquad b = \lceil 20{,}000/4 \rceil = 5{,}000 \text{ blocks}$$

**(c) Linear search, blocks contiguous, double buffering**
On average half the blocks are read: $b/2 = 2{,}500$. Contiguous + double buffering means one seek and one rotational delay, then a stream of blocks:
$$s + rd + 2500 \times \frac{B}{btr} = 30 + 12.5 + 2500 \times 1.25 = 3{,}167.5 \text{ ms} \approx 3.17 \text{ s}$$
(Less accurate version with $btt$: $30 + 12.5 + 2500 \times 1 = 2{,}542.5$ ms.)

**(d) Linear search, blocks not contiguous**
Every block is a separate random access:
$$2500 \times (s + rd + btt) = 2500 \times 43.5 = 108{,}750 \text{ ms} \approx 108.75 \text{ s}$$

**(e) Binary search on Ssn (file ordered by Ssn)**
$$\lceil \log_2 5000 \rceil = \lceil 12.29 \rceil = 13 \text{ block accesses}$$
Each access is random: $13 \times 43.5 = 565.5$ ms.

**Interpretation:** binary search (0.57 s) ≪ contiguous linear scan (3.2 s) ≪ scattered linear scan (109 s). Placement and ordering matter enormously.

## 4. Second worked example: Tutorial 1 Q3–Q4 (EMPLOYEE file)
$s = 20$ ms, $rd = 10$ ms, $btt = 1$ ms, $B = 2400$, $G = 600$, $r = 30{,}000$. Fields: Ssn 9, Last_name 20, First_name 20, Middle_init 1, Birth_date 10, Address 35, Phone 12, Supervisor_ssn 9, Department 4, Job_code 4, deletion marker 1.
- $R = 125$ bytes; $bfr = \lfloor 2400/125 \rfloor = 19$; $b = \lceil 30{,}000/19 \rceil = 1{,}579$ blocks.
- Wasted space per block $= 2400 - 19 \times 125 = 25$ bytes.
- $tr = B/btt = 2400$ bytes/ms; $btr = \frac{2400}{3000}\times 2400 = 1920$ bytes/ms → $B/btr = 1.25$ ms.
- Linear search average: $b/2 = 789.5$ block accesses.
- Contiguous + double buffering: $20 + 10 + 789.5 \times 1.25 \approx 1{,}016.9$ ms.
- Not contiguous: $789.5 \times (20 + 10 + 1) \approx 24{,}474.5$ ms.
- Binary search: $\lceil \log_2 1579 \rceil = 11$ accesses → $11 \times 31 = 341$ ms.

## 5. Index calculations (preview of Lesson 2)
| Quantity | Formula |
|---|---|
| Index entry size | $R_i = V + P$ (key size + pointer size) |
| Index blocking factor (= fan-out $fo$) | $bfr_i = \lfloor B / R_i \rfloor$ |
| Primary index entries | $r_i = b$ (one per data block; sparse) |
| Dense secondary index entries | $r_i = r$ (one per record) |
| Binary search on index + data | $\lceil \log_2 b_i \rceil + 1$ |
| Multilevel index levels | $t = \lceil \log_{fo} r_1 \rceil$ → $t + 1$ block accesses |

## 6. Common mistakes
- Forgetting the **deletion-marker byte**.
- Rounding $bfr$ **up** (wrong) or $b$ **down** (wrong).
- Using $b$ instead of $b/2$ for an average successful linear search.
- Charging $s + rd$ for **every** block when the file is contiguous with double buffering.
- Mixing seconds and milliseconds; always convert rpm to **ms per revolution**.
