# 01.06 · File Operations, File Organization and Access Methods

> [!info] [[01.00 Data Storage and File Organization|Lesson 1]] · Lecture L1 §6, §7 (intro) · Priority 🟢 Low (no direct exam question; [[TUT 2 - Records, File Organization and B-Trees|Tutorial 2]] Q11 asks it; useful for 2022/23 Q7(d))

## 1. What are file operations?
Programs (including the DBMS) work on files through a small set of operations. They fall into two groups:
- **Retrieval operations** only *find and read* records; they change nothing.
- **Update operations** change the file: **insert**, **delete** or **modify** records.

Searches are usually based on a **selection condition**, e.g. `Ssn = '123456789'` or `Salary > 30000`.

> [!tip] Analogy: a music playlist app
> *Open* loads the playlist; *Reset* jumps back to song 1; *Find* jumps to the first song matching "rock"; *Read* plays the current song; *FindNext* goes to the next rock song; *Insert / Delete / Modify* change the playlist; *Close* exits.

## 2. Typical operations (lecture §6)
| Operation | What it does |
|---|---|
| **Open** | prepares the file; allocates buffers (at least two) and reads the **file header**; sets the file pointer to the start |
| **Reset** | moves the file pointer back to the beginning |
| **Find (Locate)** | finds the **first** record satisfying a condition; brings its block into a buffer; that record becomes the **current record** |
| **Read (Get)** | copies the current record from the buffer to a program variable; may advance to the next record (possibly reading the next block) |
| **FindNext** | finds the **next** record satisfying the condition |
| **Delete** | deletes the current record and (eventually) updates the file on disk |
| **Modify** | changes field values of the current record and (eventually) writes it to disk |
| **Insert** | finds the right block, brings it into a buffer, writes the new record, and (eventually) writes the buffer to disk |
| **Close** | releases buffers and finishes clean-up |
| **FindOrdered** | retrieves all records in a specified order |
| **Reorganize** | starts reorganization, e.g. re-sorting records or reclaiming space of deleted records |

## 3. File organization vs access method
| | File organization | Access method |
|---|---|---|
| Meaning | **how the data of a file is arranged**: into records and blocks, plus access structures; how records/blocks are **placed on the medium and linked** | **a group of operations** (like those above) that can be **applied** to a file |
| Question it answers | "How is the file stored?" | "How do programs get at the records?" |
| Examples | heap, sorted, hashed, B-tree | sequential scan, binary search, hashed lookup, indexed access |
| Relationship | one organization can support **several** access methods | some access methods need a particular organization: e.g. an **indexed** access method cannot be used on a file that has **no index** |

## 4. Factors for choosing a file organization (lecture §7)
- Fast data retrieval and throughput
- Efficient use of storage space
- Protection from failure and data loss
- Minimizing the need for reorganization
- Accommodating growth
- Security from unauthorized use

**Types:** Heap, Sorted (Sequential), Hashed, B-tree and B+-tree. Each makes some operations efficient and others expensive. See [[01.07 Heap and Sorted Files]], [[01.08 Hash Files and Collision Handling]], [[02.08 B+ Trees]].

### Effect of file size on the choice of organization ([[TUT 2 - Records, File Organization and B-Trees|Tutorial 2 Q6]])
- **Small files** (a few blocks): a **heap** is fine; a full scan is cheap and indexes add overhead.
- **Large files:** a linear scan is expensive ($b/2$ block reads on average), so use a **sorted file with a primary index**, a **hash file** (equality lookups) or a **B+-tree** (ranges and growth).
- **Very large, growing files:** static structures (sorted files, static hashing) need costly reorganization; **dynamic** structures (B+-trees, extendible/linear hashing) grow gracefully.
