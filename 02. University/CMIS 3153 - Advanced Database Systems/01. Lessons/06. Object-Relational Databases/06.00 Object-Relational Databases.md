## Why this lesson matters
Programmers think in **objects** (a `Customer` with a list of `Orders`, an `Address`, methods like `getTotal()`), but relational databases store **flat tables**. Translating between the two is painful (the **impedance mismatch**). **Object-relational databases** add object features (user-defined types, inheritance, references, methods, collections) **on top of** the relational model and SQL, and **ORM frameworks** do the translation in application code.

> [!tip] Analogy
> A relational DB is a spreadsheet: every cell holds one simple value. An object-oriented program is a set of Russian dolls and linked cards: things contain things and point to things. An **ORDBMS** is a spreadsheet that also allows a cell to hold a small structured card or a list, lets one sheet "inherit" columns from another, and gives each row a permanent identity tag.
