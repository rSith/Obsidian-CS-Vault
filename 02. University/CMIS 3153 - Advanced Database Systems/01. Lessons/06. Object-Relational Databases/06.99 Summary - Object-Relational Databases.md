# 06.99 · Lesson Summary: Object-Relational Databases

> [!info] Hub: [[06.00 Object-Relational Databases]] · Past papers: [[PP 06 - Object-Relational Databases]] · Priority 🔴 (4/4 papers, ~1 question)

## Must know
- **RDB:** data model (tables), high-level operations, normalization. **Issues:** flat tables, no nested sets/arrays, weak complex types, no OO.
- **OODB:** DBMS functionality added to an OO language; objects with state (attributes, relationships) and behaviour (operations).
- **Why OODBs failed:** new vs mature RDBMS; scale ($10^7$ vs $>10^{10}$ records); suited only to complex data; market <5%; encapsulation hinders querying/indexing/transactions; RDBMS vendors added OR extensions.
- **ORDBMS:** relational model + OO features; still SQL; treats the RDB as an object store.
- **Features:** object types/UDTs, complex types, methods, inheritance, nested tables, varrays, object views. SQL: UDTs, table inheritance, OIDs, arrays/JSON/XML, methods/stored procedures, encapsulation via views/triggers, FKs, polymorphism via joins, triggers/rules.
- **SQL-99 syntax:** `CREATE TYPE … AS (…)`, `ARRAY[n]`, dot notation, `CREATE TABLE … OF type (REF IS oid SYSTEM GENERATED | DERIVED)`, `REF(type) SCOPE (table)`, `->`, `METHOD name() RETURNS type`, `UNDER`, `NOT FINAL`/`FINAL`.
- **Typed-table hierarchy:** subtable rows also appear in the supertable (projected to its columns); `ONLY` excludes them.
- **ORM:** class→table, object→row, attribute→column, method→SQL; transparent persistence; declarative mapping; sessions/unit of work; lazy loading; CRUD; techniques: call-level APIs (JDBC/ODBC/ADO.NET), SQL query mapping (iBATIS), proprietary (LINQ), full ORM (JPA: Hibernate, EclipseLink, OpenJPA).
- **Impedance mismatch** and its factors.
- **OID vs PK:** existence-based, system-generated, immutable, hidden, system-wide, referenced by pointers vs value-based, user-chosen, changeable, visible, per-table, referenced by FKs.

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Primary key:** value-based, user-defined, mutable, FK references | **OID:** system-generated, immutable, independent of values, REF pointers |
| **Relational table:** column list, tuples | **Object table:** `OF type`, rows are objects with OIDs, methods, inheritance |
| **Relational model:** flat tables, SQL | **OO model:** objects, classes, OQL/navigation |
| **OR model:** tables + UDTs, REFs, UNDER, SQL3 | |
| **OODBMS:** complex data, niche | **RDBMS:** mature, scalable, dominant |
| **Lazy loading:** load on access | **Eager loading:** load with parent |
| **Entity class:** own identity, own table | **Value type:** no identity, embedded in owner |
| **One-to-many:** collection in the "one" side | **Many-to-one:** single reference in the "many" side |
| **Directional OO association** | **Non-directional FK** |
| **FINAL type:** no subtypes | **NOT FINAL type:** can have subtypes |

## Typical exam tasks
1. OIDs vs PKs (two differences). 2. Object tables vs relational tables. 3. `UNDER`/typed tables: result columns and rows. 4. Relational vs OO vs OR models (representation, DDL, DML, query languages). 5. UML class vs entity type vs table. 6. Short note: ORDBs bridging OOP and RDBs; key features.
