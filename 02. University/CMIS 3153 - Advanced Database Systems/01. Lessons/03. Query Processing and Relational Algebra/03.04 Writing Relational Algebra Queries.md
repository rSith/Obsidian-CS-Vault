# 03.04 · Writing Relational Algebra Queries (Method and Patterns)

> [!info] [[03.00 Query Processing and Relational Algebra|Lesson 3]] · Lecture L3 §3.1–§3.3, Exercise 1 · [[TUT 3 - Relational Model and Relational Algebra|Tutorial 3 Q4]], [[TUT 5 - Relational Algebra Practice|Tutorial 5]] · Priority 🔴 High (**every paper**, 20–40 marks)
> **Asked as:** lives/works/located-in/manages (2020/21 Q7(d) = Tutorial 3 Q4) · Suppliers/Parts/Catalog using only σ, π, ×, ⋈ (2021/22 Q5(b)) · employee/works/company/manages, First Bank Corporation (2022/23 Q4(c)) · Sailors/Boats/Reserves (2023/24 Q4(c)) · SQL → RA (2020/21 Q1(a)(b))

## 1. The method: Filter → Join → Reduce (Tutorial 5's memory rule)
> [!tip] Think like cooking
> **Filter** = pick the ingredients you need (σ on each table), **Join** = combine them (⋈ on matching keys), **Reduce** = serve only what was asked (π the requested columns).

1. **Read the question; underline the output columns** ("find the *names* …") → these go in the final π.
2. **Find the tables** that hold the conditions and the outputs.
3. **Filter** each table early with σ (constants such as `= 'City Bank'`, `colour = 'red'`).
4. **Join** the tables along their key/foreign-key paths (natural join when column names match; otherwise give the condition).
5. **Reduce** with π to the requested columns.
6. **Special words:**
   - "**or**" → ∪ (or ∨ inside one σ if same table);
   - "**and** (two different facts about the same entity)" → ∩ or a join on the key;
   - "**not / never / no / do not**" → **difference** (all − those that do);
   - "**all / every**" → **division** ÷ (or the double-difference form);
   - "**at least two different**" → **self-join with ρ** and a $\ne$ condition;
   - "**same as their manager / same city as …**" → rename (ρ) and join the table with itself.
7. **Check the result columns are union-compatible** before ∪ / ∩ / −.

## 2. The patterns, with templates
| Pattern | Template |
|---|---|
| Simple filter + project | $\pi_{out}(\sigma_{cond}(R))$ |
| Condition in one table, output in another | $\pi_{out}(\sigma_{cond}(R) \bowtie S)$ |
| OR on different tables | $\pi_{x}(\ldots) \cup \pi_{x}(\ldots)$ |
| AND across two facts | $\pi_{x}(\ldots) \cap \pi_{x}(\ldots)$ or join on $x$ |
| NOT | $\pi_x(\text{All}) - \pi_x(\text{those who do})$ |
| ALL | $\pi_{x,y}(R) \div \pi_y(\ldots)$ |
| at least two | $\pi_{R1.x}(\sigma_{R1.x = R2.x \wedge R1.y \ne R2.y}(\rho_{R1}(R) \times \rho_{R2}(R)))$ |
| same attribute as related row | $\rho$ + join on both the relationship and the attribute |

## 3. Worked example from the lecture (Exercise 1)
Employee(EmpID, Name, Age, DeptID), Department(DeptID, DeptName), Project(ProjectID, DeptID, ProjectName), Assignment(EmpID, ProjectID). *Names of employees who work on a project in the "IT" department and are older than 30.*

1. Output: Name. 2. Tables: Employee (Age, Name), Assignment (links), Project (DeptID), Department (DeptName).
3. Filter: $\sigma_{Age>30}(Employee)$, $\sigma_{DeptName='IT'}(Department)$.
4. Join: Employee ⋈ Assignment (EmpID) ⋈ Project (ProjectID) ⋈ Department (on Project.DeptID).
$$
\pi_{Name}\Big(\sigma_{Age>30}(Employee) \bowtie Assignment \bowtie \pi_{ProjectID,\,DeptID}(Project) \bowtie_{Project.DeptID = Department.DeptID} \sigma_{DeptName='IT'}(Department)\Big)
$$
> [!warning] Natural-join trap
> Employee **and** Project both have a `DeptID`. A plain natural join of Employee ⋈ Assignment ⋈ Project would also force *the employee's own department* = *the project's department*, which the question did not ask. Projecting Project down first (or using explicit equi-join conditions) avoids it.

## 4. Worked example: Sailors (2023/24 Q4(c)(i))
S(sid, sname, rating, age), B(bid, bname, colour), R(sid, bid, date).
1. Colours of boats reserved by Albert:
$$\pi_{colour}(\sigma_{sname='Albert'}(S) \bowtie R \bowtie B)$$
2. IDs of sailors with rating ≥ 8 **or** who reserved boat 103:
$$\pi_{sid}(\sigma_{rating \ge 8}(S)) \cup \pi_{sid}(\sigma_{bid=103}(R))$$
3. Names of sailors who have **not** reserved a red boat:
$$\pi_{sname}\Big(\big(\pi_{sid}(S) - \pi_{sid}(\sigma_{colour='red'}(B) \bowtie R)\big) \bowtie S\Big)$$

## 5. Interpreting a given RA expression ("describe what is queried")
Read **inside-out**, translate each operator into English, then summarise.
> [!example] 2023/24 Q4(c)(ii)(2)
> $\pi_{S.sname}\big[(\sigma_{R.sid=R2.sid \wedge R.bid \ne R2.bid}(R \times \rho_{R2}(R))) \bowtie S\big]$
> - $R \times \rho_{R2}(R)$: every pair of reservations.
> - σ keeps pairs by the **same sailor** for **different boats**.
> - ⋈ S attaches the sailor; π gives the name.
> → **Names of sailors who have reserved at least two different boats.**

## 6. SQL → RA translation rules
| SQL | RA |
|---|---|
| `FROM R, S` | $R \times S$ |
| `FROM R JOIN S ON c` | $R \bowtie_c S$ |
| `WHERE c` | $\sigma_c$ |
| `SELECT DISTINCT a, b` | $\pi_{a,b}$ |
| `GROUP BY g` + aggregates | ${}_g\gamma_{f(x) \to N}$ |
| `HAVING c` | $\sigma_c$ **after** γ |
| `UNION / INTERSECT / EXCEPT` | $\cup / \cap / -$ |
| `x NOT IN (subquery)` | difference on $x$ (anti-join) |
| `x IN (subquery)` | join / semi-join on $x$ |
| `AS alias` | $\rho$ |

> [!example] 2020/21 Q1(b): NOT IN
> ```sql
> SELECT R.b FROM R, S
> WHERE  R.a = S.d
>   AND  R.b NOT IN (SELECT R2.b FROM R AS R2, T WHERE R2.b = T.g);
> ```
> $$\pi_{R.b}(R \bowtie_{R.a = S.d} S)\ -\ \pi_{R2.b}(\rho_{R2}(R) \bowtie_{R2.b = T.g} T)$$
> The subquery's values are subtracted from the outer query's values. (Because only `b` is output, subtracting on `b` is equivalent; under SQL's bag semantics duplicates of `b` would be kept, a detail worth one sentence.)
