# 03.03 · Set Operations, Joins, Division and Aggregation

> [!info] [[03.00 Query Processing and Relational Algebra|Lesson 3]] · Lecture L3 §3.1.1, §3.1.2, Exercises 2–4 · Priority 🔴 High
> **Asked as:** "Is $\pi_A(E_1 - E_2)$ equal to $\pi_A(E_1) - \pi_A(E_2)$? Discuss." (2020/21 Q7(c)) · GROUP BY/HAVING translated with γ (2020/21 Q1(a)) · lecture exercises: union vs intersection, join vs theta join; nulls, aggregate functions, division; multiset RA.

## 1. Set operations
Relations are **sets of tuples**, so the usual set operations apply to **union-compatible** relations (same number of attributes, compatible domains).

| Operation | Symbol | Result | SQL | Commutative? |
|---|---|---|---|---|
| Union | $R \cup S$ | rows in R **or** S | UNION | yes |
| Intersection | $R \cap S$ | rows in **both** | INTERSECT | yes |
| Difference | $R - S$ | rows in R **not** in S | EXCEPT | **no** |

### Union vs intersection (lecture exercise)
| | Union ∪ | Intersection ∩ |
|---|---|---|
| Keeps | everything in either input | only common rows |
| Size | ≥ larger input | ≤ smaller input |
| Logical meaning | OR | AND |
| Fundamental? | yes | no: $R \cap S = R - (R - S)$ |

## 2. Joins (lecture §3.1.2)
A **join** combines rows from two relations **that match on a condition**: like a Cartesian product followed by a selection, but computed efficiently.

> [!tip] Analogy
> A school dance: × pairs every student with every other student; a join only pairs students who share a class (the join condition).

| Join | Notation | Condition | Notes |
|---|---|---|---|
| **Theta join** | $R \bowtie_\theta S$ | any comparison $\theta$ ($=, <, >, \le, \ge, \ne$) between attributes | $= \sigma_\theta(R \times S)$ |
| **Equi-join** | $R \bowtie_{R.A = S.B} S$ | only **equality** | both join columns kept |
| **Natural join** | $R \bowtie S$ | equality on **all attributes with the same name** | duplicate columns kept once; no common names → behaves like × |
| **Left outer join** | R ⟕ S | as join | keeps **all R rows**; unmatched S side filled with NULL |
| **Right outer join** | R ⟖ S | as join | keeps all S rows |
| **Full outer join** | R ⟗ S | as join | keeps unmatched rows of both |

### Join vs theta join (lecture exercise)
"Join" usually means an **equi-/natural join** on matching key values; a **theta join** allows **any comparison**, e.g. $Emp \bowtie_{Emp.Salary > Mgr.Salary} Mgr$ (employees earning more than some manager). Every equi-join is a theta join with $\theta$ being "=".

> [!example] Natural join
> `Employees(EmpID, Name, Salary, DeptID)` ⋈ `Departments(DeptID, DeptName)` matches on **DeptID** (the shared name) and gives `(EmpID, Name, Salary, DeptID, DeptName)`.
> Danger: if two tables accidentally share another column name (e.g. both have `Name`), the natural join also requires those to be equal.

## 3. Division ÷ ("for all" queries)
$R(A, B) \div S(B)$ returns the values of $A$ that are paired in $R$ with **every** value of $B$ in $S$.

> [!example] Students enrolled in *all* IT courses (Tutorial 5 (viii))
> $$\pi_{SID,CID}(ENROLL) \div \pi_{CID}(\sigma_{Dept='IT'}(COURSE))$$
> Using only fundamental operators:
> $$
> \pi_{SID}(ENROLL) - \pi_{SID}\big((\pi_{SID}(ENROLL) \times \pi_{CID}(\sigma_{Dept='IT'}(COURSE))) - \pi_{SID,CID}(ENROLL)\big)
> $$
> Read it as: all students, minus those for whom some (student, IT course) pair is **missing** from ENROLL.

## 4. Aggregation and grouping γ (extended RA)
$$
{}_{G_1, \dots, G_k}\gamma_{F_1(A_1) \to N_1, \dots}(R)
$$
(the 2020/21 paper writes $\gamma_{R.b,\ count(*) \to TOTAL}$). It **groups** the rows of $R$ by $G_1 \dots G_k$ and computes aggregate functions (COUNT, SUM, AVG, MIN, MAX) per group. The output contains **only the grouping attributes and the aggregates**.

SQL mapping:
```sql
SELECT   R.b
FROM     R, S, T
WHERE    R.a = S.d AND S.e = T.g AND T.h > 21 AND S.f < 50
GROUP BY R.b
HAVING   count(*) > 2;
```
$$
\pi_{R.b}\Big(\sigma_{TOTAL > 2}\big(\gamma_{R.b,\ count(*) \to TOTAL}(\sigma_{T.h>21 \wedge S.f<50}(R \bowtie_{R.a=S.d}(S \bowtie_{S.e=T.g} T)))\big)\Big)
$$
**Order:** FROM/joins → WHERE (σ) → GROUP BY (γ) → HAVING (σ on the aggregate) → SELECT (π).
A WHERE condition **must be applied before γ**: after grouping, columns like `T.h` no longer exist and the counts would be different. This is exactly 2020/21 Q1(a) ([[PP 03.2 - SQL to Relational Algebra]]).

## 5. Null values in RA (lecture exercise 2)
A NULL means "unknown/missing". In a selection, a comparison with NULL is **unknown**, so the row is **not** selected ($\sigma_{Salary > 50000}$ drops rows with NULL salary). Joins do not match NULLs (NULL = NULL is not true). Outer joins **produce** NULLs for unmatched rows. Aggregates (except COUNT(*)) ignore NULLs.

## 6. Multiset (bag) relational algebra (lecture exercise 3)
Classical RA treats relations as **sets** (no duplicates). **Multiset (bag) RA** allows duplicate tuples, which is how **SQL actually behaves** (SELECT without DISTINCT, UNION ALL).
- π does **not** remove duplicates; ∪ adds multiplicities (bag union); ∩ takes the minimum multiplicity; − subtracts multiplicities.
- **Use:** models SQL precisely; avoids the cost of duplicate elimination; aggregates such as COUNT and SUM need duplicates to give correct answers (e.g. summing salaries where two people earn the same amount).

## 7. Is $\pi_A(E_1 - E_2) = \pi_A(E_1) - \pi_A(E_2)$? (2020/21 Q7(c))
**No, not in general.** Projection **commutes with union** (lecture transformation rule 11) but **not with difference**.

> [!example] Counter-example
> $E_1 = \{(a_1, b_1)\}$, $E_2 = \{(a_1, b_2)\}$ (attributes A, B).
> Left: $E_1 - E_2 = \{(a_1, b_1)\}$ → $\pi_A = \{a_1\}$.
> Right: $\pi_A(E_1) = \{a_1\}$, $\pi_A(E_2) = \{a_1\}$ → difference $= \emptyset$.
> $\{a_1\} \ne \emptyset$.

Why: projection can make **different** tuples look **identical**; subtracting after projecting removes too much. In general $\pi_A(E_1) - \pi_A(E_2) \subseteq \pi_A(E_1 - E_2)$. Equality holds if $A$ contains a **key** of both relations (then projection does not merge distinct tuples).
