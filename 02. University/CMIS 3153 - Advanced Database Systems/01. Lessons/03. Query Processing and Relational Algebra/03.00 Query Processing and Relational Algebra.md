## Why this lesson matters
When you type an SQL query, you say **what** you want, not **how** to get it. The DBMS must turn your text into a step-by-step plan. Lesson 3 explains:
1. the **stages** a query passes through (parse → check → optimize → plan → execute), and
2. **relational algebra (RA)**: the small "math language" of table operations (σ, π, ⋈, ∪, −, …) into which SQL is translated, and on which the optimizer works.

> [!tip] Analogy
> SQL is a customer's order at a restaurant ("a vegetarian pizza, no onions"). Relational algebra is the kitchen's recipe card (take dough → add sauce → add vegetables → remove onions → bake). The kitchen can reorder some steps to cook faster, as long as the pizza comes out the same. That reordering is query optimization ([[04.00 Query Optimization|Lesson 4]]).
