# 03.99 · Lesson Summary: Query Processing and Relational Algebra

> [!info] Hub: [[03.00 Query Processing and Relational Algebra]] · Past papers: [[PP 03 - Query Processing and Relational Algebra]] · Tutorials: [[TUT 3 - Relational Model and Relational Algebra]], [[TUT 5 - Relational Algebra Practice]] · Priority 🔴 (4/4 papers)

## Must know
- **Query processing goal:** correct result with minimum resources.
- **Stages in order:** (1) **parsing** (tokens, syntax, parse tree) → (2) **semantic analysis** (schema/type checks; translate to RA/query tree) → (3) **optimization** (alternative plans, cost estimates, heuristics) → (4) **execution plan generation** (algorithms, access paths) → (5) **execution** (scans, filters, joins, aggregates, sorts) → (6) **results**.
- **RA operators:** σ (rows), π (columns, removes duplicates), ∪, −, × (fundamental), ρ (rename); derived: ∩, ⋈ (theta, equi, natural, outer), ÷ (for all), γ (grouping/aggregation).
- **Writing queries:** Filter → Join → Reduce; "not" = difference; "all" = division; "at least two" = self-join with ρ and ≠; "or" = ∪; "and" (two facts) = ∩ / join.
- **SQL mapping:** SELECT→π, WHERE→σ, JOIN→⋈, UNION→∪, GROUP BY→γ, HAVING→σ after γ, NOT IN→−.
- **WHERE conditions go below γ; HAVING above γ.**
- $\pi_A(E_1 - E_2) \ne \pi_A(E_1) - \pi_A(E_2)$ in general; π commutes with ∪ only.
- **Relation** = set of tuples (distinct, atomic values); **schema** = structure.
- **Referential integrity:** $\pi_B(r_1) - \pi_B(r_2) = \emptyset$.
- **Pipelining** (stream tuples, "on the fly") vs **materialization** (store intermediate results).

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Selection σ:** rows, WHERE | **Projection π:** columns, SELECT list |
| **Union:** rows in either (OR) | **Intersection:** rows in both (AND) |
| **Join (equi/natural):** equality on keys | **Theta join:** any comparison |
| **Natural join:** all same-named columns, one copy kept | **Equi-join:** stated equality, both columns kept |
| **Inner join:** matches only | **Outer join:** keeps unmatched rows with NULLs |
| **Set RA:** no duplicates | **Multiset (bag) RA:** duplicates kept, models SQL |
| **Relation schema:** structure | **Relation instance:** current tuples |
| **Pipelining:** no temp results, early output | **Materialization:** stores intermediate results |
| **Parsing:** syntax | **Semantic analysis:** meaning against schema |
