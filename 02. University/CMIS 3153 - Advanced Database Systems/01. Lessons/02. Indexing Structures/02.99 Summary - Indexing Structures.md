# 02.99 · Lesson Summary: Indexing Structures

> [!info] Hub: [[02.00 Indexing Structures]] · Past papers: [[PP 02 - Indexing Structures]] · Tutorials: [[TUT 2 - Records, File Organization and B-Trees]] (Q13–15), [[TUT 4 - Selectivity and Index Cost]] · Priority 🔴 (4/4 papers; Q2 + Q3 recently)

## Must know
- **Index** = separate file of ⟨key, pointer⟩ giving a **secondary access path** without moving data. Purpose: fewer block accesses; search on non-ordering fields; ranges; joins; uniqueness. Cost: space + maintenance.
- **Primary index:** on the ordering **key**; one entry per **block** (block anchor); **sparse**; ≤ 1 per file. Search $\lceil\log_2 b_i\rceil + 1$.
- **Clustering index:** on an ordering **non-key**; one entry per **distinct value**; sparse; block clusters ease insertion.
- **Secondary index:** on a **non-ordering** field; **dense** for keys; many per file.
- **At most one primary/clustering index** because a file has one physical order.
- **Clustered** (rows stored in index order; ranges = sequential I/O) vs **non-clustered** (pointers; ranges = random I/O).
- **Hash vs tree:** hash = equality only; B+-tree = equality + ranges + order.
- **Multilevel index:** index on index; fan-out $fo = bfr_i$; $t = \lceil\log_{fo} r_1\rceil$; cost $t+1$. Static (ISAM) vs dynamic (B/B+-tree).
- **B-tree:** order $p$; keys + data pointers in all nodes; nodes ≥ half full; insert = split + push middle up; delete = borrow or merge; root split/merge changes height.
- **B+-tree:** data entries only in **leaves**, **linked leaves**, internal nodes are signposts; insert: leaf split **copy up**, internal split **push up**; delete: **redistribute** else **merge**; utilization = entries/capacity.
- **Maintenance:** each INSERT/DELETE touches every index; UPDATE of an indexed column = delete + insert; clustered key updates move rows.
- **Composite indexes** (column order, leftmost prefix) and **covering indexes** (no table access).

## Important formulas
$$
R_i = V + P \qquad fo = bfr_i = \left\lfloor\frac{B}{R_i}\right\rfloor \qquad b_i = \left\lceil\frac{r_i}{fo}\right\rceil
$$
$$
\text{single-level: } \lceil\log_2 b_i\rceil + 1 \qquad \text{multilevel: } t = \lceil\log_{fo} r_1\rceil,\ \ t+1 \text{ accesses}
$$
$$
\text{selectivity} = \frac{\text{matching rows}}{\text{total rows}}\qquad \text{utilization} = \frac{\text{entries stored}}{\text{nodes} \times \text{max entries per node}}
$$

## Important comparisons
| Concept A | Concept B |
|---|---|
| **Dense:** entry per record | **Sparse:** entry per block/value; needs sorted file |
| **Primary:** ordering key, sparse, 1 per file | **Secondary:** non-ordering field, dense, many |
| **Primary:** unique ordering field | **Clustering:** non-unique ordering field |
| **Clustered:** rows in index order, great for ranges, 1 per table | **Non-clustered:** pointers, good for selective lookups, many |
| **Hash index:** equality ~1 I/O, no ranges | **B+-tree:** equality + ranges, height + 1 I/Os |
| **Single-level:** binary search $\log_2 b_i$ | **Multilevel:** $\log_{fo} r_1$, one block per level |
| **Static (ISAM):** fixed, overflow chains, no locking, read-mostly | **Dynamic (B+-tree):** split/merge, always balanced |
| **B-tree:** data pointers everywhere, no leaf links | **B+-tree:** data only in leaves, linked leaves, higher fan-out |
| **Leaf split:** copy up | **Internal split:** push up |
| **Redistribute:** borrow from sibling, update separator | **Merge:** combine nodes, remove/pull down separator |
| **Covering index:** query answered from index | **Non-covering:** extra row fetch per match |
