## 2023/24 · Q4(b) (2 marks)
> **Question:** How does user experience (UX) design differ from user interface (UI) design?

**Lesson:** [[05.01 UI vs UX]]

### Expected answer
| UX design | UI design |
|---|---|
| The **whole user journey and how it feels**: emotions, satisfaction, solving users' pain points | The **look and the interactive elements** of the screens: visual appeal |
| Research: user analysis, **usability testing, information architecture, wireframes and prototypes** | Implementation: **colours, typography, buttons, layout, mockups**, consistency, responsiveness |
| **User-centred**, holistic | **Interface-centred**, focused on individual elements |

In one line: **UX decides what the product should do and how it flows and feels; UI decides how it looks and presents that experience.**

## 2023/24 · Q4(d) (6 marks)
> **Question:** Describe how web designers can utilize Cognitive load theory principles to minimize excessive mental effort that can lead to user frustration and poor engagement.

**Lesson:** [[05.09 Cognitive Load Theory]]

### Expected answer
**Cognitive load** is the mental effort users must spend to navigate a site, process information and complete tasks. Because **working memory is small**, designers should **reduce extraneous load** (clutter, confusing layouts), **simplify intrinsic load**, and **maximise germane load** (linking new information to what users already know). The four CLT principles guide this:

1. **Information store principle.** The brain holds primary (innate) and secondary (learned) knowledge. Use **familiar, consistent design patterns** and **simple interfaces** to rely on what users already know, and support new learning with **tooltips, short videos, guided onboarding and personalisation**.
2. **Borrowing and reorganising principle.** Well-organised information is easier to retrieve. Keep **layouts consistent**, **break complex information into small chunks**, and **disclose it gradually**.
3. **Randomness as genesis principle.** New features create tension with understanding. Introduce them with **onboarding and contextual help**, use **progressive disclosure**, add only features that serve **real user goals** (no novelty for novelty's sake), and present them with **familiar UI patterns and terms**.
4. **Narrow limits of change principle.** The brain can process only a limited amount at once. **Split tasks into small steps** (e.g. a 3-step checkout with a progress bar instead of one long form), reveal information gradually, use **familiar categories and labels**, and use only **recognisable UI elements**.

### Key points to include
- Definition + three load types
- **All four principles, each with 2+ UX techniques**
- At least one concrete example

## 2023/24 · Q8(a) (5 marks)
> **Question:** What is usability in web design? Describe two (02) usability testing methods.

**Lesson:** [[04.04 Functional and Usable Design]] · [[05.10 Usability Testing Methods]]

### Expected answer
**Usability** assesses **how easy a user interface is to use**. It measures the quality of a person's experience with a website, through **learnability, efficiency, memorability, errors and satisfaction**. *(For example, users can quickly find information, and an FAQ anticipates their needs.)*

**Method 1: In-person (in-house) testing.** Conducted on-site and **moderated by researchers** who give each participant tasks and observe them. *Pro:* gives **in-depth information** about how users interact and what usability issues arise. *Con:* needs **more resources and qualified researchers**, and only a **small group** can take part per session.

**Method 2: Unmoderated remote testing.** There is **no moderator or controlled environment**; participants complete the tasks **anywhere on their own devices**. *Pro:* **less costly** and reflects **real-world usage**. *Con:* less control, and the researcher cannot ask follow-up questions.

*(Other valid choices: moderated remote, guerrilla, phone interview, card sorting, session recording with Hotjar.)*

### How to approach this question
About 1 mark for the definition and about 2 per method: **what happens + one pro + one con**.
