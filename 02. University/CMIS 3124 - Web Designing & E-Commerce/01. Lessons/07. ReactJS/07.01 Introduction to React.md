# 07.01 · Introduction to React: Virtual DOM, Features, Installing, JSX

> [!info] [[07.00 ReactJS|Lesson 7]] · Lecture ref L7.1–L7.4 · Priority 🟡 Watch (not examined yet)

## 1. What is React? (lecture)
- **"A simple, feature-rich, component-based JavaScript UI library."**
- **Created by Facebook software engineer Jordan Walke.**
- **First used in 2011 for Facebook's News Feed** feature.
- **Latest version (in the slides): React.js 19.0.0 (December 2024).**

**Key terms:**
- **Library:** a collection of reusable code you call from your own program. React handles only the **UI (view)** part.
- **Component-based:** the UI is built from small, independent pieces (components) that you combine.

## 2. The virtual DOM
- The **DOM (Document Object Model)** is the browser's in-memory tree of the page's elements. Changing it is **slow** because the browser must recalculate layout and repaint.
- **React creates a virtual DOM in memory**, a lightweight copy of the DOM.
- **"All the necessary manipulation is first done in the virtual DOM, before making the changes in the browser DOM."**
- **"React only changes what needs to be changed."**

### How it works, step by step
1. State or props change.
2. React re-renders the component into a **new virtual DOM**.
3. React **compares (diffs)** the new virtual DOM with the previous one.
4. React updates **only the changed nodes** in the real browser DOM.

```text
state changes → new virtual DOM → diff with old virtual DOM → patch only the differences → real DOM
```

**Why it is efficient:** real DOM updates are expensive; fewer updates mean faster, smoother UIs.

## 3. Features (lecture)
Solid base architecture · **Extensible** architecture · **Component-based** library · **JSX-based** design architecture · **Declarative** UI library

**Declarative** means you describe **what** the UI should look like for a given state, and React works out **how** to update the DOM. (The opposite, *imperative*, means writing every DOM change step by step yourself.)

## 4. Advantages (lecture)
Easy to learn · Easy to adopt in **modern as well as legacy** applications · **Faster way to code** functionality · **Large number of ready-made components** · **Large and active community**

## 5. Installing React (lecture)

### Option A: as a project (5 steps)
1. **Install Node.js**
2. **Choose a project setup tool** (e.g. Vite)
3. **Navigate to your project directory**
4. **Install dependencies**
5. **Start the development server**

```bash
npm create vite@latest my-app -- --template react   # step 2 (Vite: example tool)
cd my-app                                           # step 3
npm install                                         # step 4
npm run dev                                         # step 5
```
> [!note]
> The commands are an illustration with Vite. The slide lists the five steps without commands.

### Option B: via a CDN (lecture code)
```html
<head>
  <script src="https://unpkg.com/react@18/umd/react.development.js" crossorigin></script>
  <script src="https://unpkg.com/react-dom@18/umd/react-dom.development.js" crossorigin></script>
  <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
</head>
```
- **React** and **ReactDOM** let you write React code in your JavaScript.
- **Babel** lets you write **JSX (JavaScript XML) syntax and ES6 in older browsers**.

## 6. JSX (JavaScript XML)
JSX lets you write **HTML-like markup inside JavaScript**. Babel compiles it into normal JavaScript.

```jsx
const name = "Kevin";
const element = <h2 className="title">My name is {name}</h2>;
```

| JSX rule | Example |
|---|---|
| JavaScript **expressions go inside `{ }`** | `{name}`, `{2 + 3}` |
| Return **one parent element** (or a fragment `<>…</>`) | `<><h1/><p/></>` |
| Use **`className`**, not `class` | `<div className="box">` |
| **Close every tag** | `<img />`, `<br />` |
| Inline styles are **objects** with camelCase names | `style={{backgroundColor: "lightblue"}}` |

> [!warning]
> The deck has no separate JSX slide. JSX is named as a feature and used in every example. The rules in this table come from the study guide and standard React; you can see them in the slide code (e.g. fragments `<>…</>`, `{this.state.name}`).
