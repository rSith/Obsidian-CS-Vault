# 07.02 · React Components and Props

> [!info] [[07.00 ReactJS|Lesson 7]] · Lecture ref L7.5–L7.6 · Priority 🟡 Watch

## Part A: Components

### 1. What is a component? (lecture)
- **Independent and reusable bits of code** that return a piece of UI.
- **Two types:** **class components** and **function components**.
- **The component name must start with an uppercase letter** (e.g. `Employee`, not `employee`).

### 2. Rendering a component
Use it like an HTML tag, `<Employee />`, and render it into the page's `root` element:

```jsx
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<Employee />);
```
The HTML page contains an empty `<div id="root"></div>`, and React fills it.

### 3. Class component: constructor and super() (lecture)
```jsx
class Employee extends React.Component {
  constructor() {
    super();                          // run React.Component's constructor
    this.state = {name: "Kevin"};     // component properties live in "state"
  }
  render() {
    return <h2>I am an Employee and my name is {this.state.name}</h2>;
  }
}
```
- **`constructor()`** is **called when the component is initiated**. The component's **properties are initiated** there and **should be kept in an object called `state`**.
- **`super()`** **executes the parent component's constructor**, so the child has **access to all the functions of the parent (`React.Component`)**.
- **`render()`** returns the JSX to display.
- `extends React.Component` makes `Employee` a React class component.

### 4. Function component
```jsx
function Employee() {
  return <h2>I am an employee</h2>;
}
```
A plain JavaScript function that returns JSX. It is shorter, and it gets state through **hooks** ([[07.07 Hooks]]).

### 5. A component inside another (lecture)
```jsx
function Employee() {
  return <h2>I am an employee</h2>;
}

function Department() {
  return (
    <>
      <Employee />
    </>
  );
}

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<Department />);
```
`<>…</>` is a **fragment**: an invisible wrapper, because JSX must return one parent element.

### Class vs function components
| Class component | Function component |
|---|---|
| `class X extends React.Component` | `function X() { … }` |
| Has a `render()` method | Returns JSX directly |
| State: `this.state` + `this.setState()` | State: `useState` hook |
| Lifecycle **methods** (componentDidMount…) | Lifecycle through **hooks** (useEffect) |

## Part B: Props

### 1. What are props? (lecture)
- **Props (properties)** handle component properties.
- **"Props are like function arguments, and they are sent as attributes into the component."**
- Props are **read-only** inside the component; the parent decides them.

### 2. Lecture example: passing a name
```jsx
function Employee(props) {
  return <h2>My name is {props.name}</h2>;
}

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<Employee name="Kevin" />);   // → "My name is Kevin"
```
`name="Kevin"` looks like an HTML attribute. Inside the component it arrives as `props.name`.

### 3. Props in the constructor (class components)
*"Props should always be passed to the constructor and also to `React.Component` via the `super()` method."*
```jsx
class Employee extends React.Component {
  constructor(props) {
    super(props);
  }
  render() {
    return <h2>I am {this.props.name}!</h2>;
  }
}
root.render(<Employee name="Kevin" />);
```

### 4. Reusability example (illustration)
```jsx
function ProductCard(props) {
  return (
    <div className="card">
      <h3>{props.title}</h3>
      <p>Rs. {props.price}</p>
    </div>
  );
}

function Shop() {
  return (
    <>
      <ProductCard title="Shoes" price={12500} />
      <ProductCard title="Bag" price={8000} />
    </>
  );
}
```
One component is written once and reused with different props.
