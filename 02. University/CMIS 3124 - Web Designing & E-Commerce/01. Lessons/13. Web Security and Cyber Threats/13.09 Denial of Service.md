# 13.09 · Denial of Service (DoS)

> [!info] [[13.00 Web Security and Cyber Threats|Lesson 13]] · Lecture ref L13.9 · Priority 🔴 High
> **Asked as:** short note on DoS: definition, how it happens, prevention (2023/24 Q6(d)(iv), 2 marks); "Describe: Denial-of-Service" (2019/20 Q8(a)(v), 3 marks).

## 1. What is it? (lecture)
A **cyber-attack on an individual computer or website with the intent to deny services to intended users**.

**How the attacker generates overwhelming traffic or requests:**
1. **Flooding the target with a massive amount of data**;
2. **Sending repeated requests to a specific part of the system**;
3. **Exploiting software vulnerabilities to crash the system**.

**DDoS (Distributed DoS)** uses **many machines at once**, usually a **botnet** of infected computers or IoT devices, which makes the attack much bigger and harder to block. *(Beyond the slides, but standard.)*

Recall: client–server architecture is **vulnerable to DoS** because *"the number of servers is considerably smaller than the number of clients"* ([[02.06 Client-Server and Three-Tier Architecture]]).

## 2. Examples (lecture)

### Ping of Death
*Works by generating and sending special network messages.* The slide shows:
```text
ping ip_address –t -65500
```
| Part | Meaning (lecture) |
|---|---|
| `ping` | Sends data packets to the victim |
| `ip_address` | The victim's IP address |
| `-t` | Packets should be sent **until the program is stopped** |
| `65500` | The **data load** (bytes) to be sent with each packet |

> [!note]
> On Windows the size option is written `-l 65500`. The slide omits the `l`. Modern systems are no longer vulnerable to the classic ping of death, but the idea of oversized or endless packets remains a good example.

### Smurf attack (lecture's version)
- A variant of DoS that **involves emails with automatic responses**.
- Someone sends **hundreds of emails with a fake return address** to hundreds of people in an organisation who have an **autoresponder** turned on.
- The sent messages turn into **thousands of automatic replies sent to the fake address**.
- If the fake address **belongs to someone**, their account is **overwhelmed**.

> [!note] Beyond the slides
> In networking textbooks, a "smurf attack" usually refers to spoofed **ICMP broadcast** pings, where every host on a network replies to the victim. The lecture's email version shows the same principle: **amplification + a spoofed return address**.

## 3. Prevention (lecture: 8 measures)
| Measure | How it helps |
|---|---|
| **Network segmentation** | Prevents the attack spreading through the whole network; **limits impact** and **isolates** affected systems |
| **Firewalls** | **Block traffic from known malicious IPs** or **limit traffic from a single source** |
| **Intrusion Detection and Prevention Systems (IDS/IPS)** | **Analyse network traffic** and **block malicious traffic** |
| **Limit bandwidth** | Bandwidth limits on **incoming traffic** |
| **Content Delivery Network (CDN)** | **Distributes traffic across multiple servers** and reduces the impact ([[02.08 Web Application Architecture Components]]) |
| **Anti-malware software** | Detects and prevents malware used in DoS attacks, **such as botnets** |
| **Regular network scans** | Find vulnerabilities and misconfigurations before attackers do |
| **A response plan** | Steps for **identifying** the attack, **isolating** affected systems and **restoring** normal operations |

## 4. Short note for 2023/24 Q6(d)(iv) (2 marks)
- **Definition:** an attack that makes a website or server **unavailable to legitimate users** by overwhelming it.
- **How:** flooding it with huge traffic, repeated requests to one resource, or exploiting a vulnerability to crash it (Ping of Death, smurf attack; DDoS through botnets).
- **Prevention:** firewalls and rate limiting, IDS/IPS, bandwidth limits, a CDN to distribute load, network segmentation, anti-malware, a response plan.
