# 13.11 · AI and ML in Web Security

> [!info] [[13.00 Web Security and Cyber Threats|Lesson 13]] · Lecture ref L13.11 (+ L14.5) · Priority 🔴 High
> **Asked as:** "Concisely explain how Artificial Intelligence (AI) and Machine Learning (ML) could be utilized to enhance web security." (2023/24 Q3(e), 5 marks)

## 1. Big idea
Traditional security uses **fixed rules and known signatures**. **Machine learning** learns what **"normal"** looks like from data and flags what is **abnormal**, so it can catch **new, unknown** attacks and respond **faster** than humans.

## 2. The three areas (lecture)

### A. Automated threat detection and analysis
| Use | Lecture explanation |
|---|---|
| **Anomaly detection** | Train algorithms to **recognise unusual patterns in network traffic, user behaviour and system activity** that might indicate an attack |
| **Malware detection** | ML models **analyse characteristics of malware samples** to identify **new and emerging threats** |
| **Phishing detection** | Analyse email content: **suspicious language, sender information** and other indicators |
| **Intrusion detection** | Analyse **network traffic and system logs** to spot intrusions and unauthorised access |

### B. Incident response
| Use | Lecture explanation |
|---|---|
| **Automated response** | Automate tasks such as **isolating compromised systems, blocking malicious traffic, triggering alerts**, giving **faster, more efficient** responses |
| **Threat intelligence** | Analyse threat data from many sources to understand attackers' **tactics, techniques and procedures (TTPs)** |
| **Vulnerability management** | **Identify vulnerabilities** and **prioritise fixes by risk severity** |

### C. Prevention
| Use | Lecture explanation |
|---|---|
| **Predictive analytics** | Analyse **historical data** to **predict future attacks**, enabling **proactive** measures |
| **Behavioural analysis** | Analyse **user and entity behaviour** for anomalies (e.g. **unusual login attempts or data-access patterns**) |
| **Security automation** | Automate routine security tasks, **freeing professionals for complex threats** |

## 3. Challenges (lecture)
1. **Quantity and quality of training data.**
2. **Biases in the data.**
3. **Adversarial attacks:** attackers **craft malicious inputs designed to fool the AI** and bypass security.
4. **Explainability and transparency:** it is **hard to understand the root cause** of an AI decision.
5. **Integration with existing systems.**

## 4. Web-specific examples (from Lesson 14, AI-enhanced cybersecurity)
Real-time **DDoS detection**; **fraud prevention** (fake accounts, payment fraud); **bot detection** (smarter CAPTCHAs); stronger encryption. See [[14.04 Emerging AI Trends]].

## 5. Model answer for 2023/24 Q3(e) (5 marks)
1. **Threat detection:** ML learns normal patterns and flags **anomalies** in traffic and user behaviour; it detects **new malware, phishing emails and intrusions** from logs.
2. **Incident response:** automatically **isolates compromised systems, blocks malicious traffic, raises alerts**; threat intelligence on attackers' TTPs; prioritises vulnerabilities.
3. **Prevention:** **predictive analytics** from historical attacks; **behavioural analysis** of logins and data access; **security automation**.
4. **Web examples:** real-time DDoS detection, payment-fraud and fake-account detection, bot detection.
5. **Balance:** limitations such as adversarial attacks, biased or poor training data, and explainability.
