# 13.02 · Related Threat Terms from Older Papers (Sniffers, Backdoors, Spoofing, MITM, CAPTCHA…)

> [!warning] Mostly not in the current slides
> The 2017/18–2019/20 papers asked about terms that the **current lecture does not define**: sniffer programs, backdoors, cyber vandalism, masquerading/spoofing, man-in-the-middle, ActiveX, CAPTCHA. The explanations below use standard security knowledge and the study guide, and they point to the **nearest current lecture topic**. Use them for older-style questions. They are probably **low priority** for the current syllabus.

| Term | Meaning | Nearest current lecture topic |
|---|---|---|
| **Sniffer programs** | A **packet sniffer** captures and inspects data packets travelling across a network. It is legitimate for troubleshooting, but harmful when used by attackers. **Impacts:** steals **unencrypted** passwords, emails, card numbers and session cookies; enables identity theft, session hijacking and MITM attacks. **Protection:** HTTPS/TLS, VPN on public Wi-Fi, network segmentation, intrusion detection. | [[13.06 Spyware]] (keyloggers, data harvesters); [[12.04 Tools for Ethical Web Development]] (HTTPS/TLS) |
| **Backdoors** | A **hidden way into a system that bypasses normal authentication**, left by developers or installed by malware. It gives attackers remote control to steal data, install more malware or join a **botnet** (used for DDoS). **Prevention:** code review/SAST, patching, anti-malware, least privilege, monitoring. | [[13.06 Spyware]] (Remote Access Trojans); [[13.13 DevSecOps]] (SAST) |
| **Cyber vandalism** | Deliberately **damaging, defacing or destroying** websites or data for fun, protest or spite (e.g. replacing a homepage with offensive content, deleting files), often through XSS, injection or stolen credentials. **Prevention:** patching, input validation, access control, backups, monitoring. | [[13.07 Cross-Site Scripting (XSS)]], [[13.10 Best Practices for Securing a Website]] |
| **Masquerading / spoofing** | **Pretending to be a trusted user, device or website** by **faking an identity**: email spoofing (fake sender), **caller-ID spoofing (vishing)**, IP/DNS spoofing, fake look-alike websites (phishing). **Prevention:** verify senders and URLs, HTTPS certificates, email authentication, MFA, user awareness. | [[13.04 Phishing]] (vishing uses caller-ID spoofing); [[13.06 Spyware]] (enters through spoofing) |
| **Man-in-the-middle (MITM) exploit** | An attacker **secretly positions themself between two communicating parties** (e.g. a user and a bank on public Wi-Fi) to **intercept, read or alter** traffic; steals credentials and session cookies; often uses spoofing or sniffing. **Prevention:** HTTPS/TLS with valid certificates, avoid public Wi-Fi or use a VPN, MFA, heed certificate warnings. | [[12.04 Tools for Ethical Web Development]] (HTTPS/TLS) |
| **ActiveX controls** (2017/18 Q6(c)) | Old Microsoft Internet Explorer plug-in components that run with **full access to the user's computer**. **Effects:** a malicious or vulnerable ActiveX control could install malware, read files or take control. This is why modern browsers dropped them. | [[13.01 Web Security and Major Threats]] (client-side threats) |
| **CAPTCHA, "confirm you're not a robot"** (2017/18 Q6(d)) | A test that **tells humans from automated bots**. It stops bots from creating fake accounts, spamming, **brute-forcing passwords**, scraping, and **flooding forms** (DoS-style abuse); it protects server resources and data quality. Modern checks analyse behaviour with AI. | [[13.09 Denial of Service]], [[14.03 AI for Performance and Security]] |
