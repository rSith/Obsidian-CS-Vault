# 13.99 · Lesson Summary: Web Security and Cyber Threats

> [!abstract] Back to [[13.00 Web Security and Cyber Threats]] · Practice: [[PP 13 - Web Security and Cyber Threats]]

## Must know
- **Web security** = protecting data in transit + safeguarding sites, apps and servers from attacks, breaches and unauthorised access. **85%+ of sites are vulnerable.**
- **8 threats:** ransomware, SQLi, phishing, viruses and worms, spyware, XSS, code injection, DoS.
- **SQLi:** via inputs, poisoned cookies, server variables. **Types:** in-band (`OR 1=1`), error-based, blind (`1=1` vs `1=0`), out-of-band (DNS/HTTP), time-based blind (`SLEEP(5)`). **Prevent:** prepared statements, stored procedures, whitelist validation, ORM, least DB privilege, generic errors.
- **Phishing:** pose as trusted entities. Email, spear (a target), whaling (head of company), smishing (SMS), vishing (calls, caller-ID spoofing), clone (copied email + bad link).
- **Virus** (needs execution and a host; modifies programs) vs **worm** (self-spreading, no user action; scans IPs/ports).
- **Spyware:** enters via unknown links, phishing, spoofing, free software. Keyloggers, adware, Trojans, tracking cookies, system monitors, data harvesters, browser hijackers, RATs.
- **XSS:** a third party runs script in the user's browser on behalf of the app. Reflected (search field), stored (comment thread), DOM-based (unsanitised data into the DOM). **Prevent:** sanitise input, encode output, CSP, HttpOnly.
- **Code injection:** injected code interpreted by the app; poor input/output validation; PHP `eval($_GET…)`.
- **DoS:** deny service by flooding, repeated requests, or crashing via vulnerabilities; Ping of Death; smurf (autoresponder emails). **Prevent:** segmentation, firewalls, IDS/IPS, bandwidth limits, CDN, anti-malware, network scans, response plan.
- **11 best practices:** update, beware SQLi, prevent XSS, limit error messages, validate input, access control, strong passwords, HTTPS, 2FA, monitor and log, modern tech stack.
- **AI/ML:** detection (anomaly, malware, phishing, intrusion) · response (automated, threat intelligence on TTPs, vulnerability management) · prevention (predictive, behavioural, automation) · challenges (data quantity/quality, bias, adversarial attacks, explainability, integration).
- **Zero Trust:** "never trust, always verify". **3 principles:** continuous validation, least privilege, assume breach. **5 pillars:** identity (IAM, SSO, MFA), devices, networks (micro-segmentation), applications/workloads, data. **ZTNA.** Use cases: multicloud, supply chain, remote employees, IoT visibility.
- **DevSecOps:** security integrated throughout CI/CD; a shared responsibility; shift left/right; components (code analysis, change management, compliance, threat modelling, training); tools **SAST/SCA/IAST/DAST**; challenges (culture, tool integration).
- **IoT security:** no built-in security, unencrypted; challenges (default passwords, no encryption, firmware flaws, insecure communications such as the 2022 Bluetooth car locks, patching); **Learn → Segment → Protect**.

## Important comparisons
| SQLi | XSS | Code injection |
|---|---|---|
| SQL → database | Script → victim's browser | Code → app server |
| Prepared statements | Output encoding | No `eval()`, validation |

| DevOps | DevSecOps |
|---|---|
| Dev + Ops, speed | Dev + Sec + Ops, security in every stage |
| Security at the end | Shift left and right |

| Perimeter model | Zero Trust |
|---|---|
| Trust inside the network | Trust no one; verify every request |
