# 13.12 · The Zero Trust Security Model

> [!info] [[13.00 Web Security and Cyber Threats|Lesson 13]] · Lecture ref L13.12 · Priority 🔴 High
> **Asked as:** "Briefly explain the Zero Trust Security Model." (2023/24 Q6(c), 4 marks)

## 1. What is it? (lecture)
- **A security strategy for modern multicloud networks.**
- Operates on the principle **"never trust, always verify."**

### Why it was needed: perimeter model vs Zero Trust
| Traditional perimeter ("castle and moat") | Zero Trust |
|---|---|
| Protected **the perimeter of the network** with firewalls and other controls | **No perimeter** is assumed |
| **Users inside were considered trustworthy** and got free access to apps, data and resources | **No one is trusted by default**, inside or outside |
| Works when everything is in one office | Works for **cloud, remote work, mobile, IoT** |

*"**Digital transformation eliminated the traditional concept of a network perimeter**. Corporate networks extend beyond on-premises locations and network segments."*

## 2. The three principles (lecture)
| Principle | Lecture explanation |
|---|---|
| **1. Continuous monitoring and validation** | Users, devices and workloads must pass **continuous, contextual authentication and validation** to access any resource **every time they request a connection**. Requests are approved based on data such as the user's **privileges, physical location, device health, threat intelligence and unusual behaviour**. |
| **2. Least privilege** | Users and devices receive the **minimum level of permission required** for a task. **Permissions are revoked when the session is over.** |
| **3. Breach assumption** | Security teams **assume hackers have already breached** network resources. Actions used to mitigate an ongoing attack become **standard operating procedure**: **network segmentation** to limit scope; **monitoring every asset, user, device and process**; responding to unusual behaviour **in real time**. |

## 3. The five pillars (lecture)
| Pillar | Lecture explanation |
|---|---|
| **1. Identity** | **Authenticate user identities** and grant access only to **approved** resources. **Tools: IAM** (identity and access management), **SSO** (single sign-on), **MFA** |
| **2. Devices** | **Every device** (workstations, phones, servers, laptops, IoT devices, printers…) must be **fully compliant** with zero trust policies and controls |
| **3. Networks** | **Micro-segmentation:** resources separated into **smaller, more secure zones**; **contains breaches** and prevents **lateral movement**; attackers **can't even see** unauthorised resources; plus **encrypted traffic** and **behaviour monitoring** |
| **4. Applications and workloads** | **Dynamic authorisation** with **continual revalidation** for persistent access; monitor applications that **talk to each other** for unusual behaviour |
| **5. Data** | **Categorise data**; apply **targeted access control** and security policies; **encrypt data in transit, in use and at rest**; continuously monitor data processing |

**Key terms:**
- **Lateral movement:** an attacker who breaks into one machine moving sideways to others on the network.
- **SSO:** log in once and access many apps.
- **IAM:** systems that manage who has which identity and permissions.

## 4. ZTNA: Zero Trust Network Access (lecture)
- **The primary technology** for implementing Zero Trust.
- Provides **remote access** to applications and services.
- **Connects users only to the resources they have permission to access**, **rather than to the whole network** (unlike a traditional VPN, which typically puts you "inside").

## 5. Use cases (lecture)
- **Multicloud security**
- **Supply-chain security**
- **Remote access for employees**
- **IoT visibility:** hackers target IoT devices to introduce malware. Zero Trust **continuously tracks the location, status and health of every IoT device**; IoT devices are subject to **access controls, authentication and encrypted communications** ([[13.14 IoT Security]]).

## 6. Model answer for 2023/24 Q6(c) (4 marks)
- **Definition:** a security model based on **"never trust, always verify"**: no user or device is trusted by default, even inside the network. It replaces the perimeter model, which cloud computing and remote work made obsolete.
- **Three principles:** continuous monitoring and validation of every request; least-privilege access revoked after the session; assume breach.
- **Five pillars:** identity (IAM, SSO, MFA), devices, networks (micro-segmentation), applications/workloads, data (encryption, classification).
- **Implemented with ZTNA**, which connects users only to permitted resources.
