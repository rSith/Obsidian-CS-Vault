# 03.01 · Web Engineering vs Software Engineering

> [!info] [[03.00 Web Engineering|Lesson 3]] · Lecture ref L3.1–L3.2 · Priority 🟡 Medium. This is the evidence you need to answer *why* WebE must be agile (2023/24 Q4(a)).

## 1. What is web engineering?
**Web engineering (WebE)** is the use of systematic, engineering-style methods to **build and maintain web-based systems (WebApps)**.

The lecture says: *"Developing web-based systems is **significantly different** from traditional software development and causes **many additional challenges**. There are slight differences in the **nature and life cycle**."*

## 2. A multidisciplinary field
*"Building a complex web-based system needs knowledge and expertise from **many different disciplines** and requires a **team of various people** with expertise in different areas."*

The lecture diagram shows web engineering drawing on four fields:

```text
        Hypermedia        Information systems
               \             /
                Web Engineering
               /             \
  Software Engineering     Network Engineering
```

| Discipline | What it contributes |
|---|---|
| **Hypermedia** | Linked content: pages, links, multimedia |
| **Information systems** | Organising and managing business data |
| **Software engineering** | Processes, modelling, coding and testing methods |
| **Network engineering** | Servers, protocols, performance, security over the Internet |

## 3. Comparison table (from the lecture slide)

| Software Engineering | Web Engineering |
|---|---|
| Software system has a **small user range** | WebApps have a **large user range** |
| User requirements are **specific** | User requirements **change with time** |
| Growth and change is **small** | **Rapidly changing** |
| Development budgets **vary widely** with the size of the company | Development budgets are **small** |
| Development time is **longer** | Development time is **small (short)** |
| Hardware and software constraints are **specific** | Hardware/software constraints are **not specific** (any browser, any device) |
| Design and development expertise is **scarce** ("few") | Expertise is **available in a wide range** |
| Security and legal issues are **not much important** | Security and legal issues are **much important** |
| **Less** emphasis on user interfaces | **More** emphasis on user interfaces |

### Why each WebE characteristic makes sense
- **Large user range:** anyone on the Internet can visit, so you cannot know every user.
- **Requirements change with time, rapid change:** businesses update products, content and features constantly, and new devices appear.
- **Small budgets, short time:** online businesses want to launch fast before competitors.
- **Non-specific constraints:** the app must run on unknown browsers and devices.
- **Security and legal issues very important:** the app is exposed to the public Internet and handles personal data and payments ([[13.00 Web Security and Cyber Threats]], [[12.07 Web Compliance and Copyright]]).
- **More UI emphasis:** users leave immediately if a site is hard to use ([[05.00 HCI in Web Design]]).

## 4. Exam-relevant points
- This table is the **evidence** for "why WebE must be agile, adaptable and incremental": **changing requirements, rapid change, short time, small budgets, large diverse users**. See [[03.02 WebE Process Framework]].
- If asked to compare, use a **table with at least 4–5 rows**.
