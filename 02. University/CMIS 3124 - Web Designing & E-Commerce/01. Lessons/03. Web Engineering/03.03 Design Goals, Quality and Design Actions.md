## Part A: Design goals (7, lecture)

The slide lists only the names. The explanations come from the study guide.

| Goal | Meaning |
|---|---|
| **Simplicity** | Moderation: don't overload the site with content, animation or features |
| **Consistency** | Same layout, colours, navigation and wording on every page |
| **Identity** | The look and feel match the **brand and purpose** of the business |
| **Robustness** | Users can rely on functions working and recovering from errors |
| **Navigability** | Simple, consistent navigation, so users always know how to move |
| **Visual appeal** | Attractive layout, colour, typography and images ([[04.00 Web Design Principles]]) |
| **Compatibility** | Works across **browsers, devices, screen sizes and connection speeds** |

> [!tip] Mnemonic
> **"Simple, Consistent Identity: Robust, Navigable, Visual, Compatible"** (S-C-I-R-N-V-C).

## Part B: Quality requirement tree (lecture diagram)

**WebApp quality** breaks into **five attributes**, each with sub-attributes:

```text
Web application quality
├── Usability ........ global site understandability · online feedback & help features
│                      · interface & aesthetic features · special features
├── Functionality .... searching & retrieving capability · navigation & browsing features
│                      · application-domain-related features
├── Reliability ...... correct link processing · error recovery · user input validation & recovery
├── Efficiency ....... response time performance · page generation speed · graphics generation speed
└── Maintainability .. ease of correction · adaptability · extensibility
```

> [!tip] Mnemonic (from the study guide)
> **U-F-R-E-M:** "**U**sers **F**ind **R**eliable, **E**fficient, **M**aintainable apps."

### Applying it: an e-commerce example
- **Usability:** clear help pages and a live chat (online feedback and help).
- **Functionality:** product search and filters (searching and retrieving).
- **Reliability:** no broken links; the form tells you clearly if your card number is wrong (input validation and recovery).
- **Efficiency:** pages load in under 2 seconds (response time).
- **Maintainability:** new product categories are easy to add (extensibility).

## Part C: Design actions (the design pyramid)

WebApp design is shown as a **pyramid**. The **top is closest to the user** and the **base is closest to the technology**.

```text
                user
               /    \
         Interface design
        Aesthetic design
       Content design
      Navigation design
     Architecture design
    Component design
             technology
```

| Layer | What is designed |
|---|---|
| **Interface design** | How the user interacts: screens, controls, feedback ([[05.05 UI Design and Layout]]) |
| **Aesthetic design** | Look and feel: layout, colour, typography, graphics ([[04.01 Aesthetic Layout and CARP Principles]]) |
| **Content design** | The text, images and media, and how they are organised |
| **Navigation design** | The paths users take between content ([[05.07 Navigation Design]]) |
| **Architecture design** | The overall structure of the WebApp (content architecture + technical architecture: [[02.06 Client-Server and Three-Tier Architecture]]) |
| **Component design** | The detailed functional components (modules, functions) |

> [!note]
> The right-hand descriptions are added explanations. The slide shows only the layer names.
