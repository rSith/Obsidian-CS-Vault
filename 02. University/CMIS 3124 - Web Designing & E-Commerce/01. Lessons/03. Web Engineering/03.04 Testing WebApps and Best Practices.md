# 03.04 · Testing WebApps and WebE Best Practices

> [!info] [[03.00 Web Engineering|Lesson 3]] · Lecture ref L3.7–L3.8 · Priority 🟡 Medium. Supports "things to consider before planning a website" (2017/18 Q2(a), 2018/19 Q4(a)).

## Part A: Testing WebApps (7 types, lecture diagram)

| Testing type | What it checks | Example (e-commerce) |
|---|---|---|
| **Content testing** | Errors in text, images, facts, spelling | Wrong price or a typo in a product description |
| **Interface testing** | Buttons, forms, menus and layout behave correctly | "Add to cart" button works; the checkout form submits |
| **Navigation testing** | Every link and path works; no dead ends | Category → product → cart → checkout path works |
| **Component testing** | Each function or module works in isolation | The shipping-cost calculator gives correct totals |
| **Configuration testing** | Different browsers, OSs, devices, servers | The site works on Chrome, Safari, Android, iPhone |
| **Performance testing** | Speed and behaviour under heavy load | 10,000 users during a sale |
| **Security testing** | Vulnerabilities such as SQLi, XSS, weak authentication | Login form resists SQL injection ([[13.03 SQL Injection]]) |

> [!note]
> The slide is a diagram of the seven names. The "what it checks" column comes from the study guide.

## Part B: WebE best practices (lecture list)
1. **Take the time to understand business needs and product objectives.**
2. **Describe how users will interact with the WebApp.**
3. **Always develop a project plan.**
4. **Spend some time modelling** what you are going to build.
5. **Review the models** for consistency and quality.
6. **Use tools and technology** that let you build the system with **as many reusable components as possible**.
7. **Don't reinvent when you can reuse.**
8. **Don't rely on early users to debug the WebApp.** Design and use **comprehensive tests before releasing** the system.

## Part C: Applying Lesson 3: "things to consider before planning a website"
For an online store selling many kinds of items (2017/18 Q2(a), 2018/19 Q4(a)), organise your answer around the process and best practices:
- **Communication:** formulate business goals and target customers; elicit requirements (categories, search, cart, payment, delivery, returns); negotiate scope and budget.
- **Planning:** estimate cost and time, analyse risks, schedule increments.
- **Information architecture / navigation:** a clear category hierarchy, search and filters ([[05.07 Navigation Design]]).
- **Platform choice:** open-source, SaaS or headless ([[10.05 E-Commerce Platforms]]).
- **Design goals and quality:** simplicity, consistency, identity, navigability, compatibility; responsive design; usability; accessibility.
- **Security and legal:** HTTPS, secure payment gateway, PCI DSS, privacy policy/GDPR, consumer rights ([[10.10 GDPR]], [[10.11 PCI DSS and Consumer Rights]]).
- **Operations:** inventory, shipping, customer support; marketing and SEO; **testing before launch**.
