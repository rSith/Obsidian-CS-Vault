# 03.99 · Lesson Summary: Web Engineering

> [!abstract] Back to [[03.00 Web Engineering]] · Practice: [[PP 03 - Web Engineering]]

## Must know
- WebE is **multidisciplinary**: hypermedia + information systems + software engineering + network engineering.
- **WebE vs SE:** large user range, requirements change with time, rapid change, small budgets, short development time, non-specific HW/SW constraints, widely available expertise, security and legal issues very important, more UI emphasis.
- **Process framework (incremental):** **Communication** (formulation, elicitation, negotiation) → **Planning** (estimation, risk analysis, scheduling, monitoring) → **Modelling** (analysis, design) → **Construction** (coding, testing) → **Deployment** (delivery, evaluation). Each increment starts at communication and is delivered at deployment.
- **7 design goals:** simplicity, consistency, identity, robustness, navigability, visual appeal, compatibility.
- **Quality tree (U-F-R-E-M):** usability, functionality, reliability, efficiency, maintainability.
- **Design pyramid (user → technology):** interface, aesthetic, content, navigation, architecture, component design.
- **7 testing types:** content, interface, navigation, component, configuration, performance, security.
- **Best practices:** understand the business, describe user interaction, plan, model, review, reuse, test before release (don't rely on early users to debug).

## Important comparison

| Software engineering | Web engineering |
|---|---|
| Small user range | Large user range |
| Specific requirements | Requirements change with time |
| Longer development time, varied budgets | Short time, small budgets |
| Security/legal less important | Security/legal very important |
| Less UI emphasis | More UI emphasis |

## Exam focus
- 🟡 **Why agile, adaptable, incremental (2 marks):** changing requirements + rapid change + short time/small budget + large users → release in increments and adapt from feedback.
- 🟡 **Before planning an e-commerce site:** goals and requirements, planning, information architecture, platform, design goals, security and legal, operations, testing.
