# 03.02 · The WebE Process Framework

> [!info] [[03.00 Web Engineering|Lesson 3]] · Lecture ref L3.3 · Priority 🟡 Medium
> **Asked as:** "WebE process must be agile, adaptable, and incremental. Why?" (2023/24 Q4(a), 2 marks). Also used for "things to consider before planning a website" (2017/18 Q2(a), 2018/19 Q4(a)).

## 1. What is it?
The **WebE process framework** is an **incremental, cyclic** process made of **five framework activities**. The app is built in **increments** (small working pieces). The lecture diagram labels it:
- **"Each increment starts here"** → at **Communication**
- **"Each increment delivered here"** → at **Deployment**

After each delivery, feedback is gathered and the cycle repeats for the next increment.

```text
      ┌──► Communication ──► Planning ──► Modelling ──┐
      │   (increment starts)                          ▼
  Deployment ◄──────────────────────────── Construction
 (increment delivered → evaluation → next increment)
```

## 2. Activities and actions (from the lecture diagram)

| Activity | Actions | Plain-English meaning |
|---|---|---|
| **Communication** | **Formulation**, **Elicitation**, **Negotiation** | Define the business goals (formulation); gather requirements from stakeholders (elicitation); agree on the scope, priorities and cost (negotiation) |
| **Planning** | **Estimation**, **Risk analysis**, **Scheduling**, **Monitoring** | Estimate effort and cost; identify what could go wrong; set a timeline; track progress |
| **Modelling** | **Analysis**, **Design** | Analyse content, functions and users; design the interface, navigation and architecture |
| **Construction** | **Coding**, **Testing** | Build the increment and test it ([[03.04 Testing WebApps and Best Practices]]) |
| **Deployment** | **Delivery**, **Evaluation** | Release the increment to users; collect their feedback for the next cycle |

## 3. Why must the WebE process be agile, adaptable and incremental? (2023/24 Q4(a))

**Key terms:**
- **Agile:** able to respond quickly to change; works in short cycles.
- **Adaptable:** the process and plan can be adjusted as conditions change.
- **Incremental:** the system is delivered in small working pieces, not all at once.

**Reasons (taken from [[03.01 Web Engineering vs Software Engineering]]):**
1. **Requirements change with time** and the web environment changes **rapidly** (new content, features, devices), so a fixed, one-time plan would soon be out of date.
2. **Development time is short and budgets are small**, so the team must **release working parts quickly** rather than wait for one big release.
3. The **user range is large and diverse**, so **feedback after each release** is needed to adapt the next increment.
4. That is why each increment goes **communication → planning → modelling → construction → deployment**, is **evaluated** by users, and the next increment **adapts** to that feedback.

## 4. Practical example
An online shop launches **increment 1** with a product catalogue and cart (deployment). Users say search is weak (evaluation). **Increment 2** starts at communication again: formulate better search, plan it, model it, build it, deploy it. Then increment 3 adds loyalty points, and so on.

- Name all **5 activities in order** and their **actions**.
- For "why agile": link to **changing requirements, rapid change, short time, small budget, large user range, feedback per increment**.
