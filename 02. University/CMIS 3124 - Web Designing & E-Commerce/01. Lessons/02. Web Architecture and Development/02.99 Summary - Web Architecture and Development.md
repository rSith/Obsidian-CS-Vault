# 02.99 · Lesson Summary: Web Architecture and Development

> [!abstract] Back to [[02.00 Web Architecture and Development]] · Practice: [[PP 02 - Web Architecture and Development]]

## Must know
- **Web app:** software that works in a browser, hosted on a remote server, built with client- and server-side scripting.
- **Languages:** HTML = structure · CSS = design · JavaScript = behaviour (events, event handlers) · PHP = open-source, server-side, returns **plain HTML**.
- **URL parts:** scheme, subdomain, domain, TLD, port, path, `?`, query string, fragment. **TLD types:** gTLD, geoTLD, grTLD, sTLD, ccTLD, tTLD.
- **HTTP:** request = version, URL, method, headers, body. There are 8 methods. Status codes: 2xx success, 3xx redirect, 4xx client error, 5xx server error. HTTP is **stateless** → cookies, sessions, hidden variables, URL parameters.
- **Client–server:** 7-step flow; negatives (centralised failure, DoS, cost); supports scalability, availability, dependability, heterogeneity; inhibits robustness and transparency.
- **Three-tier:** presentation / application (logic) / data; 6-step request flow; 6 benefits; "new view" with a web services server.
- **Ten architecture components:** DNS, load balancer, web app servers, databases, caching, job queue, full-text search, services, data warehouse (firehose → cloud storage → warehouse), CDN.
- **CMS:** CMA (edit) + CDA (deliver); features and benefits.

## Important definitions
- **Session:** a series of related browser requests from the same client during a certain time period. **Timeout** discards all session data.
- **Cookie:** a small piece of text stored by the browser; name–value pairs; sent as an HTTP header and returned unchanged; used for authentication, session tracking and preferences.
- **Web service:** a software system for machine-to-machine interaction over a network; platform- and language-independent (XML); uses HTTP; styles RPC/SOAP/REST.
- **XML:** information interchange; elements (tree) + attributes. **JSON:** lightweight, subset of JavaScript, language-independent alternative to XML.
- **SPA:** loads and updates content dynamically without full-page reloads (CSR, SSR, SSG).
- **AJAX:** XHTML + CSS, DOM, XML, XMLHttpRequest, JavaScript. Drawbacks: back button, bookmarks, attack vector.
- **CMS:** software that helps users create, manage, store and modify digital content without coding.

## Important comparisons

| GET | POST |
|---|---|
| Data in the URL query string | Data in the request body |
| Visible, bookmarkable, cached | Hidden from the URL, not cached |
| Length-limited | No practical limit; file uploads |
| Search / retrieve | Login, payment, change data |

| Session | Cookie |
|---|---|
| Stored on the server | Stored in the browser |
| Ends at logout or timeout | Ends at browser close or expiry date |

| Database approach | Web services approach |
|---|---|
| The application accesses the DB directly and decides | The service validates, authenticates and decides |

## Important examples
- PHP form → `welcome.php` → `$_POST["name"]` → plain HTML.
- Doctor-channelling 3-tier: UI (search, book, pay) / logic (availability, fees, payment, SMS) / data (doctors, schedules, appointments).
