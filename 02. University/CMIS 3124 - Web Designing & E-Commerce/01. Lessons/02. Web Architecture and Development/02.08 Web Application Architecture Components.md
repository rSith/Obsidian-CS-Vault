# 02.08 · Web Application Architecture Components

> [!info] [[02.00 Web Architecture and Development|Lesson 2]] · Lecture ref L2.12 · Priority 🔴 High
> **Asked as:** "Write the functionality of the load balancer, web app server, caching service, and Content Delivery Network (CDN) in the web application architecture." (2023/24 Q1(b), 4 marks)

## 1. What is it?
A large web application is not one program on one computer. It is made of **many cooperating components**, each with one job. The lecture lists ten.

```text
            User's browser
                 │  (1) DNS: name → IP
                 ▼
   CDN ◄── static files (HTML/CSS/JS/images) from a nearby server
                 │
                 ▼
          Load balancer ──► Web app server 1 ─┐
                       └──► Web app server 2 ─┼─► Caching service
                                              ├─► Database(s)
                                              ├─► Job queue → job servers
                                              ├─► Full-text search service
                                              └─► Services (e.g. payment)
                     Data → "firehose" → cloud storage → data warehouse
```

## 2. The components (lecture definitions + explanation)

| Component | Lecture definition | In plain English |
|---|---|---|
| **DNS** (Domain Name System) | *A fundamental system that helps search a domain name and IP address* | The Internet's **phone book**: turns `shop.lk` into an IP address |
| **Load balancer** | *Directing incoming requests to one of the multiple servers so they will not be overcharged* (i.e. overloaded) | A **traffic officer** that spreads users across servers |
| **Web app servers** | *Process a user's request and send documents (JSON, XML, etc.) back to a browser* | Run the **application code** (business logic) |
| **Databases** | *Give instruments for organising, adding, searching, updating, deleting and performing computations* | **Permanent storage** of data |
| **Caching service** | *Provides storage for data …; results go to cache whenever a user gets information from the server; caching lets you refer to the previous result to make a computation much faster* | **Short-term memory** for answers you have already worked out |
| **Job queue** (optional) | *A job goes to the job queue and is operated according to a schedule*; two components: **job queue and servers** | A **to-do list** for slow background work (e.g. sending emails) |
| **Full-text search service** (optional) | *With the help of keywords, it searches the needed data among a vast number of documents* | The **search box** engine |
| **Services** | *When a web application reaches a specific level, services are created in the form of separate apps* | Big features split into their own apps (e.g. a payment service) |
| **Data warehouse** | *Works with data: collecting, storing and analysing*, in **three stages** (below) | Where data goes for **analytics and reports** |
| **CDN** (Content Delivery Network) | *Deals with sending HTML files, CSS files, JavaScript files and images* | Copies of static files on servers **close to each user** |

### Data warehouse: three stages (lecture)
1. Data is sent to the data **"firehose"** (the slide says "firehouse"), which provides a **streaming interface** for taking in and processing data.
2. **Raw, processed and additional data** is sent to **cloud storage**.
3. **Processed and additional data** also goes to the **data warehouse**.

## 3. The four examined components (2023/24 Q1(b) model answer)

| Component | Functionality |
|---|---|
| **Load balancer** | Receives incoming requests and **distributes them across multiple web app servers** so that no server is overloaded. This improves **availability and scalability**, and traffic is rerouted if a server fails. |
| **Web app server** | **Runs the application code**: processes the user's request (business logic, database access) and **returns documents such as HTML, JSON or XML** to the browser. |
| **Caching service** | **Stores the results of previous requests or computations** in fast storage. Repeated requests are answered from the cache, which makes responses **faster** and **reduces database load**. |
| **CDN** | A geographically distributed network that **delivers static files (HTML, CSS, JavaScript, images)** from the **server nearest the user**. This lowers **latency** (delay) and helps absorb traffic spikes and DDoS attacks. |

> [!note] Beyond the slides
> "Nearest server", "latency" and "absorbs DDoS" for the CDN are standard points, and the course itself mentions CDNs for DDoS protection in [[02.10 Content Management Systems]] and [[13.09 Denial of Service]]. The slide's own definition of a CDN is only "sending HTML, CSS, JS files and images".

## 4. Practical example: a big e-commerce sale
- Thousands of users → the **load balancer** shares them across 10 app servers.
- The product images load quickly from a **CDN** node in Colombo instead of a server in the USA.
- "Top deals" are computed once and kept in the **cache**.
- Order-confirmation emails go into a **job queue**.
- Sales data flows to a **data warehouse** for tomorrow's reports.
