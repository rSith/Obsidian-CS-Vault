# 02.01 · Web Applications and Web Technologies

> [!info] [[02.00 Web Architecture and Development|Lesson 2]] · Lecture ref L2.1 · Priority 🔴 High
> **Asked as:** "List two advantages and two disadvantages of web applications" (2023/24 Q1(a), 2 marks).

## 1. What is a web application?

The lecture defines **web applications** as:
- **Software programs that work on a web browser**;
- **Hosted on a remote server** and **distributed to the intended users over the Internet**;
- **Developed using server-side and client-side scripting languages**.

### Key terms in simple English
- **Client-side scripting:** code that runs **in the user's browser**, e.g. JavaScript (and HTML/CSS for display).
- **Server-side scripting:** code that runs **on the web server**, e.g. PHP, before the result is sent to the browser.
- **Remote server:** a computer somewhere else on the Internet that stores and runs the application.

### Website vs web application

> [!note] Beyond the slides
> This distinction is not on the slide, but it is useful when answering.

| Website (static) | Web application |
|---|---|
| Mainly displays information | Lets users **do tasks** (send email, bank, shop) |
| Same content for everyone | Content depends on the user and their data |
| Often only HTML/CSS | Client-side **and** server-side code + a database |
| e.g. a brochure page | e.g. **Gmail, online banking, an e-commerce store** |

## 2. What are web technologies?

**Web technologies** are *"related to the interface between web servers and their clients."* They include:
- **markup languages** (HTML, XML);
- **programming interfaces and languages** (JavaScript, PHP, APIs);
- **standards for document identification and display** (URLs, HTTP, CSS).

## 3. Advantages and disadvantages of web applications

> [!warning]
> The lecture does **not** list advantages and disadvantages directly. The 2023/24 question is therefore marked "partial" in the mapping. The points below come from the study guide and follow from the definition (browser-based, remotely hosted).

| Advantages | Disadvantages |
|---|---|
| Run on **any device with a browser**, no installation | Need an **Internet connection** |
| **One central copy**, so updates reach everyone at once | Speed depends on the **network and server** |
| Accessible **anywhere, any time** | Data on a remote server → **security and privacy risks** (SQLi, XSS, DoS: see [[13.00 Web Security and Cyber Threats]]) |
| **Cross-platform** (Windows, macOS, Android) | **Browser compatibility** issues |
| Low demands on the client machine | A central server can be a **single point of failure** |
| Easy to **scale** on the server side | **Limited access to device hardware** compared with native apps |

### Why each point follows from the definition
- *Hosted on a remote server* → updates are central (advantage), but you depend on the network and the server (disadvantage).
- *Works in a web browser* → any device and OS (advantage), but browsers differ (disadvantage).
