# 02.04 · HTTP: Requests, Methods, Status Codes, GET vs POST

> [!info] [[02.00 Web Architecture and Development|Lesson 2]] · Lecture ref L2.6 · Priority 🔴 High
> **Asked as:** "Compare and contrast PHP's GET and POST methods" (2023/24 Q7(c), 2 marks).

## 1. What is HTTP?

**HTTP (HyperText Transfer Protocol)** is the **communication protocol used by a web browser (client) and a web server to exchange information**. The browser sends a **request**, and the server sends back a **response**.

**HTTPS** is HTTP made secure with **TLS encryption**. See [[12.04 Tools for Ethical Web Development]].

## 2. The HTTP request message

According to the lecture, an HTTP request message contains:

| Part | Meaning |
|---|---|
| **HTTP version** | e.g. HTTP/1.1 |
| **URL** | Which resource is wanted |
| **HTTP method** | What to do (GET, POST, …) |
| **Request headers** | Extra information (browser type, cookies, accepted formats) |
| **Body** | Data sent to the server (used by POST) |

Example of a raw request:

```http
POST /login.php HTTP/1.1
Host: shop.example.lk
Content-Type: application/x-www-form-urlencoded
Cookie: theme=dark

username=kasun&password=secret123
```

## 3. HTTP request methods

Methods **"indicate the desired action to be performed on the identified resource."** The lecture lists eight:

| Method | Purpose |
|---|---|
| **GET** | **Retrieve** a resource; data goes in the URL query string |
| **POST** | **Send data to be processed** (e.g. form submission); data goes in the body |
| **HEAD** | Like GET but returns **headers only** (no body) |
| **PUT** | Replace / upload a resource |
| **DELETE** | Delete a resource |
| **TRACE** | Loop-back test: echoes the request |
| **OPTIONS** | Asks which methods the server supports |
| **CONNECT** | Opens a tunnel (used for HTTPS through proxies) |

> [!note] Beyond the slides
> The slide lists only the eight names. The purposes come from the study guide and the HTTP standard.

## 4. The HTTP response and status codes

- The **first line of the HTTP response is the status line**, e.g. `HTTP/1.1 200 OK`.
- *"The way the user agents handle the response depends **primarily on the status code** and **secondarily on the response headers**."* (A **user agent** is the browser.)

| Code range | Meaning | Common examples (beyond the slides) |
|---|---|---|
| **2xx** | **Success** | 200 OK |
| **3xx** | **Redirection** | 301 Moved Permanently |
| **4xx** | **Client-side error** | 404 Not Found, 403 Forbidden |
| **5xx** | **Server-side error** | 500 Internal Server Error, 503 Service Unavailable |

## 5. HTTP is stateless

- **Stateless** means **"hosts do not need to retain information about users between requests."** Each request is independent: the server forgets you after it responds.
- So when a site needs to **customise content for a user** (keep you logged in, remember your cart), it must use:
  - **cookies**,
  - **sessions**,
  - **hidden variables** (hidden form fields),
  - **URL-encoded parameters**.

See [[02.05 Sessions and Cookies]].

## 6. GET vs POST (2023/24 Q7(c))

In PHP, a form chooses its method with `<form method="get">` or `<form method="post">`, and the script reads the values with `$_GET[...]` or `$_POST[...]`.

```html
<!-- GET: data appears in the URL -->
<form action="search.php" method="get">
  <input type="text" name="q">
  <input type="submit" value="Search">
</form>
<!-- submitting "shoes" requests: search.php?q=shoes -->
```

```php
<?php echo "You searched for " . $_GET["q"]; ?>
```

| | **GET** | **POST** |
|---|---|---|
| Where data goes | **Appended to the URL** as a query string | **Inside the HTTP request body** |
| Visibility | **Visible** in the address bar, history, server logs | **Not shown** in the URL |
| Size | **Limited** by URL length | **No practical limit**; can upload files |
| Bookmark / cache | **Can** be bookmarked and cached | **Not** bookmarked or cached |
| Security | **Not for passwords** or sensitive data | Better for sensitive data (still needs HTTPS) |
| Typical use | Search, filters, **retrieving** data | Login, registration, payments, **changing** data |
| In PHP | `$_GET["name"]` | `$_POST["name"]` |

**Similarities (the "compare" half):** both are HTTP methods that send form data from the browser to a server-side (PHP) script; both are set with the form's `method` attribute; both send name–value pairs.

> [!warning]
> The lecture only lists GET and POST as methods. **Practical 2** confirms the core difference: "With GET, form data is generally added to the URL as a query string… commonly used for search. With POST, form data is sent inside the request body… commonly used when sending larger or more sensitive form information." The other rows (bookmarking, caching, size limits) come from the study guide and general HTTP knowledge (the mapping marks this question "partial").
