# 02.07 · Web Services, XML and JSON

> [!info] [[02.00 Web Architecture and Development|Lesson 2]] · Lecture ref L2.11 · Priority 🟢 Low. Not examined directly, but it underpins mashups ([[01.06 Mashups]]) and social-media APIs ([[11.04 Integrating Social Media APIs]]).

## 1. What is a web service?
A **web service** is **"a software system designed to support machine-to-machine interaction over a network."**

Lecture properties:
- It **allows data on the Web to be accessed using a remote procedure call (RPC) mechanism**. A **remote procedure call** means calling a function that runs on *another* computer as if it were local.
- Web services are **platform-independent and language-independent**, **because they use XML**.
- They **use HTTP for transmitting messages**.
- **Styles of use:** **RPC**, **SOAP**, **REST**.

## 2. How web services function
- They **accept requests** and **provide information**.
- **PHP example:** *"you can treat any website as a web service with the `file()` function, which places the result of the HTTP GET in a variable. This is called a 'mashup'."*
- **Enabling technology: XML**. This is *how data coming from web services is usually structured*.
- **Problem: the "battle of the standards"**. Several competing standards exist, and **SOAP is the most common**.

### What web services add (from the three-tier slides)
A database server only gets and updates data on command. A web service **adds processing**, e.g. **credit-card transactions**, or **real-time data such as stock quotes or weather information**.

> [!note] Beyond the slides
> **SOAP** (Simple Object Access Protocol) sends strict XML "envelopes". **REST** (Representational State Transfer) uses ordinary HTTP methods (GET, POST, PUT, DELETE) on URLs and often returns JSON. The slide only names the three styles.

## 3. XML (eXtensible Markup Language)
- **Used for information interchange** (sending data between systems).
- **Two primary building blocks:**
  - **Elements:** tags with values, **structured as a tree**;
  - **Attributes:** *give more meaning and describe elements efficiently and clearly.*

Lecture example:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<note>
  <date>
    <year>2008</year>
    <month>01</month>
    <day>10</day>
  </date>
  <to>Sam</to>
  <from>Jane</from>
</note>
```

`<note>` is the **root** element. `<date>` is a child that contains `<year>`, `<month>` and `<day>`, so the data forms a **tree**. (This example has no attributes. An attribute would look like `<note priority="high">`.)

## 4. JSON (JavaScript Object Notation)
- A **lightweight data-interchange format**.
- **Based on a subset of the JavaScript language**, but **language-independent**.
- **Serves as an alternative to XML.**

The same data in JSON (lecture example):

```json
{
  "date": {
    "year": "2008",
    "month": "01",
    "day": "10"
  },
  "to": "Sam",
  "from": "Jane"
}
```

`{ }` is an **object** made of **key–value pairs** (`"to": "Sam"`). Objects can be nested (`"date"`). JSON also has arrays `[ ]`.

## 5. XML vs JSON

| | XML | JSON |
|---|---|---|
| Full name | eXtensible Markup Language | JavaScript Object Notation |
| Purpose | Information interchange | Lightweight data interchange |
| Building blocks | **Elements** (tree) + **attributes** | **Objects** `{}`, **arrays** `[]`, key–value pairs |
| Size | More verbose (opening + closing tags) | Shorter, lighter |
| Origin | Markup language family (like HTML) | Subset of JavaScript; language-independent |
| Typical use | SOAP web services, RSS feeds | REST APIs, social-media APIs |
