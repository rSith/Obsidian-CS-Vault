## Part A: Single-page application (SPA) architecture

### 1. What is it?
A **single-page application (SPA)** is a **"web application that loads and updates content dynamically without refreshing the entire page."**
- Unlike traditional websites, SPAs **minimise interruptions** and give a **smoother interface**.
- The key benefit is the **elimination of full-page reloads**, which gives a **more responsive and engaging** experience.
- *Examples (beyond the slides):* Gmail, Google Maps.

### 2. Three ways to render an SPA (lecture)

**(a) Client-side rendering (CSR)**
1. The browser requests HTML from the server.
2. The server swiftly responds with a **basic HTML file** and linked styles/scripts.
3. The user sees a **blank page or loader** while JavaScript executes.
4. The app **fetches data, creates views, and injects them into the DOM**.
- ⚠️ *"Can be slower for basic websites because it uses a lot of device resources."*

**(b) Server-side rendering (SSR)**
1. The browser asks the server for an HTML file.
2. The server **gathers the necessary data, builds the SPA and creates an HTML file** instantly.
3. The user sees the **content ready to go**.
4. The SPA structure then **adds events, makes a virtual DOM**, and gets ready.
5. The application is set for use.

**(c) Static site generator (SSG)**
1. Browsers ask for HTML, and the SSG quickly provides **pre-made static pages**.
2. The server shows users the static page for **fast loading**.
3. SPAs in the page **fetch data and make dynamic changes**.
4. The SPA is ready for smooth interaction once the data is added.
- ⚠️ *"SSGs are great for fast static pages but may not be ideal for highly dynamic websites."*

| | CSR | SSR | SSG |
|---|---|---|---|
| Where HTML is built | In the **browser** (JavaScript) | On the **server, per request** | **In advance** (build time) |
| First thing the user sees | Blank page / loader | Ready content | Ready static page |
| Strength | Rich interactivity after loading | Fast first view | Fastest loading |
| Weakness | Slow for basic sites; uses device resources | Server work on every request | Not ideal for highly dynamic sites |

**Key term: DOM (Document Object Model).** The browser's tree-shaped, in-memory representation of the page, which JavaScript can change. A **virtual DOM** is a lightweight copy used by libraries such as React ([[07.01 Introduction to React]]).

## Part B: AJAX (Asynchronous JavaScript and XML)

### 1. What is it?
AJAX lets a page **talk to the server in the background** and **update only part of the page**, without reloading. *Asynchronous* means the user can keep working while the request is in progress.
*Example (beyond the slides):* search suggestions that appear as you type.

### 2. Technologies it incorporates (lecture)
AJAX is not one technology. It combines:
- **XHTML and CSS** (presentation),
- the **Document Object Model (DOM)** (dynamic display),
- **XML** (data interchange),
- the **XMLHttpRequest** object (background communication with the server),
- **JavaScript** (which ties everything together).

```javascript
// Minimal AJAX request (illustration)
const xhr = new XMLHttpRequest();
xhr.open("GET", "suggest.php?q=sho");
xhr.onload = function () {
  document.getElementById("suggestions").innerHTML = xhr.responseText; // update part of page
};
xhr.send();
```

### 3. Drawbacks (lecture)
1. **Breaks the browser history engine** (the **back button** does not return to the previous state).
2. **No bookmark** of a particular page state.
3. **Opens up another attack vector** for malicious code that web developers might not fully test for.

## Part C: Custom web-app development

- **Definition:** *the process of creating a **unique software application** that solves a **specific set of challenges**.*
- **Steps:** **requirement analysis → design → development → testing → maintenance and support**.
- **Who builds it:** **in-house** (hire developers to build and support it) **or outsourced** (partner with an outside organisation that specialises in software development).
- **Range:** from full-scale application development to **application customisation (e.g. ERP or CRM)**, **modernisation**, **mobile applications**, and management.

| In-house | Outsourced |
|---|---|
| Full control, deep business knowledge | Specialist expertise, faster start |
| Higher fixed cost (salaries) | Less control, communication overhead |

> [!note]
> The in-house vs outsourced table is a short synthesis. The slide only names the two options.
