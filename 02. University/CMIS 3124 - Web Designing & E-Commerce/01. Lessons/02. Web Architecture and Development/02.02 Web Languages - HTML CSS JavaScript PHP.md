# 02.02 · Web Languages: HTML, CSS, JavaScript and PHP

> [!info] [[02.00 Web Architecture and Development|Lesson 2]] · Lecture ref L2.2 · Priority 🔴 High
> **Asked as:** "How does PHP work? Briefly describe." (2023/24 Q7(b), 3 marks). GET vs POST is in [[02.04 HTTP Protocol]].

## 1. The four languages and their jobs

| Language | Job | Lecture definition |
|---|---|---|
| **HTML** (HyperText Markup Language) | **Structure** | Describes the structure of a web page, *"i.e. which part of page is a heading, a paragraph, a list, a table, etc."* |
| **CSS** (Cascading Style Sheets) | **Design / presentation** | Specifies the design of a web page, *"the fonts, colors, positions of different parts of the page"* |
| **JavaScript** | **Behaviour** (client-side) | *"Used to manage the behavior of web pages"*: dynamic elements such as **animated graphics, interactive maps, clickable buttons** |
| **PHP** (PHP: Hypertext Preprocessor) | **Server-side processing** | *"An open-source, server-side scripting language used to generate dynamic web pages"* |

> [!tip] Memory hook
> HTML = the **skeleton**, CSS = the **clothes**, JavaScript = the **muscles** (movement), PHP = the **kitchen behind the restaurant** (work the customer never sees).

## 2. JavaScript: reacting to events

When JavaScript is used in HTML pages, it can **"react" to events**. **Event handlers** handle and verify **user input, user actions and browser actions**.

An **event** is something that happens, such as a click, a key press or the page finishing loading. An **event handler** is the code that runs when that event happens.

Lecture example:

```html
<!DOCTYPE html>
<html>
<body>
  <button onclick="document.getElementById('demo').innerHTML=Date()">
    The time is?
  </button>
  <p id="demo"></p>
</body>
</html>
```

**What it does:**
- `onclick` is the **event handler attribute**: it runs when the button is clicked.
- `document.getElementById('demo')` finds the `<p>` element with `id="demo"`.
- `.innerHTML = Date()` puts the current date and time inside it.
- So clicking the button shows the time, **without reloading the page**.

## 3. PHP in detail

### What is it?
- **PHP: Hypertext Preprocessor** (a recursive acronym).
- **Open-source** (free) and **server-side** (runs on the server, not in the browser).
- Used to **generate dynamic web pages**: for **form handling, file processing and database access**.

### How does PHP work? (answer to 2023/24 Q7(b))
The key lecture sentence: **"PHP codes are executed on the server and the result is returned to the browser as plain HTML."**

Step by step:
1. **Request:** the user opens `welcome.php` or submits a form to it. The browser sends an **HTTP request**.
2. **Server hands over:** the web server sees the `.php` file and passes it to the **PHP interpreter (engine)**.
3. **Execute:** PHP runs the code on the server. It reads form data (`$_POST` / `$_GET`), queries the **database**, processes files.
4. **Output:** PHP **generates plain HTML**.
5. **Response:** the server sends that HTML back, and the browser renders it. **The user never sees the PHP source code.**

```text
Browser ──HTTP request──► Web server ──► PHP engine (runs code, uses DB)
   ▲                                          │
   └────────── plain HTML response ◄──────────┘
```

### The lecture's form example (HTML file + welcome.php)

```html
<!-- form.html -->
<form action="welcome.php" method="post">
  Name: <input type="text" name="name">
  <input type="submit">
</form>
```

```php
<!-- welcome.php (runs on the server) -->
<html>
<body>
  Welcome <?php echo $_POST["name"]; ?>
</body>
</html>
```

**Explanation:**
- `action="welcome.php"` tells the browser **where to send** the form data.
- `method="post"` sends the data **in the HTTP request body**. See [[02.04 HTTP Protocol]].
- In `welcome.php`, `$_POST["name"]` reads the value typed into the input called `name`.
- `echo` writes it into the HTML. If the user typed *Kasun*, the browser receives only `<html><body>Welcome Kasun</body></html>`.

> The two lecture slides with the HTML file and welcome.php are images. The code above is a reconstruction of the standard example they show (it is also in the study guide).

## 4. Client-side vs server-side scripting

| Client-side (JavaScript) | Server-side (PHP) |
|---|---|
| Runs **in the browser** | Runs **on the web server** |
| Code is visible to the user | Code is **hidden**; only HTML output is sent |
| Fast UI reactions, no round trip | Can access **databases and files** securely |
| e.g. form checks, animations | e.g. login, storing orders, reading MySQL |

## 5. Exam-relevant points
- **How PHP works (3 marks):** definition (open-source, server-side) → the server passes the `.php` file to the PHP engine → it executes (form data, database, files) → **returns plain HTML** → the browser never sees the PHP code.
- Know each language's **one-word job**: structure / design / behaviour / server-side.
