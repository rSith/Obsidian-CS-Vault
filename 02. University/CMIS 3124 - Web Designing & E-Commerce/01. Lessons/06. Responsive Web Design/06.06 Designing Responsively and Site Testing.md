# 06.06 · Designing Responsively and Site Testing

> [!info] [[06.00 Responsive Web Design|Lesson 6]] · Lecture ref L6.10–L6.11 · Priority 🟡 Medium (good supporting points for Q2(d) "how to make pages responsive")

## 1. Aspects to pay attention to (lecture)
Content hierarchy · Layout · Typography · Navigation · Images · Special content (tables, forms)

## 2. Content hierarchy
- **Biggest challenge:** deciding **what is visible in the first screen on small devices**.
- **Content parity across devices:** *everyone should have access to the **same content**, even if it is **not in exactly the same place**.* (This matches the One Web idea.)

## 3. Layout
- **RWD is based on fluid layouts.**
- **Most common approach:** start with **one column on small devices** and **add columns as space is available**.
- **Optimum width of a text element:** a line length of **45 to 75 characters**. **If lines get longer, introduce a breakpoint.**

```css
article { max-width: 65ch; }   /* "ch" ≈ one character width: keeps lines in the 45–75 range */
```

### Responsive layout patterns (lecture diagram, from Jennifer Robbins)

> [!note]
> The slide is an image. These are the standard pattern names it shows (study-guide reading).

| Pattern | Behaviour |
|---|---|
| **Mostly fluid** | A fluid grid that gets margins on large screens and stacks columns on small ones |
| **Column drop** | Columns **stack one below another** as the width shrinks |
| **Layout shifter** | The layout **changes significantly** at different breakpoints |
| **Off-canvas** | Less-used content (e.g. a menu) sits **off-screen** and **slides in** when needed |

## 4. Typography (lecture)
- **Optimise for different screen sizes.**
- **Avoid complicated font styles on small screens.**
- Set the font size to keep line length at **45–75 characters**.
- **Line height should be larger on larger screens.**
- **Left and right margins can increase on larger screens.**

## 5. Navigation options (lecture diagrams)
The slides show image examples. Common responsive navigation patterns:
- **Top navigation** links that wrap onto several lines;
- a **"Menu" (hamburger) toggle** that shows or hides the links;
- an **off-canvas drawer** that slides in;
- a **select (drop-down) menu**;
- a **footer menu anchor** (a "Menu" link that jumps to links at the bottom).

## 6. Images (lecture)
- Use **responsive image markup techniques**.
- **Serve the smallest file-size version by default.**
- Make sure **important image details are not lost** at small sizes: **allow zooming or provide a cropped version**.
- **Avoid text in graphics**, or provide alternative versions with larger type for small screens.

```html
<!-- Responsive image markup: the browser picks the best size (illustration) -->
<img src="shoe-480.jpg"
     srcset="shoe-480.jpg 480w, shoe-960.jpg 960w, shoe-1600.jpg 1600w"
     sizes="(min-width: 768px) 33vw, 100vw"
     alt="Red running shoe">
```

## 7. Special content (lecture)
| Content | Advice |
|---|---|
| **Forms** | Design for **efficiency and flexibility** (use **Flexbox**) |
| **Tables** | Research **responsive table patterns** (e.g. horizontal scroll, stacking rows) |
| **Interactive elements** | **Scale videos proportionally**; explore alternatives that work better on small screens, e.g. **linking to a map app instead of a small embedded map** |

## 8. Site testing (lecture)
*Testing the site in a wide variety of browser environments is critical.*

| Method | Description |
|---|---|
| **Real devices** | **The best way to test** |
| **Emulators** | A **desktop application that simulates a device's hardware and software** |
| **Browser testing services** | **Subscription-based** services that show how the site looks on a **wide variety of browsers** |
