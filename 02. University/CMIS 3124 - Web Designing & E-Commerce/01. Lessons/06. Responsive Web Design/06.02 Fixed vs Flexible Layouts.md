# 06.02 · Fixed vs Flexible (Fluid / Elastic) Layouts

> [!info] [[06.00 Responsive Web Design|Lesson 6]] · Lecture ref L6.2 · Priority 🔴 High
> **Asked as:** "Briefly explain the pros and cons of fixed-width layout." (2023/24 Q2(c), 4 marks)

## 1. The debate (lecture)
*"A debate about how website layouts should be constructed."* Two views:
1. **Fixed-width layouts:** *the **designer should be in control** of the layout, as they knew what looked and worked best.*
2. **Flexible (fluid or elastic) layouts:** *the **user should be able to choose** what width they wanted the web page to be.*

Reference: **John Allsopp, *A Dao of Web Design*** (A List Apart, April 2000).

## 2. The three layout types

| Layout | How widths are set | Behaviour when the window changes |
|---|---|---|
| **Fixed** | A fixed number of **pixels** (e.g. `960px`) | Stays the same: horizontal scroll on small screens, empty space on large ones |
| **Fluid (liquid)** | **Percentages** (e.g. `width: 70%`) | Columns **resize proportionally** with the window |
| **Elastic** | **em** units (relative to font size) | Scales when the user **changes the text size** |

> [!note]
> The lecture names fluid and elastic. The definition "elastic = em units" comes from the study guide and the Smashing Magazine article the slide cites.

```css
/* Fixed */
.container { width: 960px; margin: 0 auto; }

/* Fluid */
.container { width: 90%; }
.main { width: 66.66%; float: left; }
.side { width: 33.33%; float: left; }

/* Elastic */
.container { width: 60em; }   /* grows if the user enlarges the font */
```

## 3. Pros and cons of fixed-width layout (2023/24 Q2(c))

| ✅ Pros | ❌ Cons |
|---|---|
| The **designer has full control**; the layout looks **the same** in every browser and screen | On **small screens/phones**, users must **scroll horizontally or zoom**; content may be cut off |
| **Easier to design and code**; image sizes, columns and **line lengths are predictable** | On **large screens** it leaves **wasted white space** at the sides |
| Consistent visual design, good for pixel-precise layouts | **Ignores user choice** and does **not adapt**: it is **not responsive** |
| | **Text resizing** by the user can break the layout |

> [!warning]
> The lecture gives the debate but does not list the pros and cons. They follow directly from "the designer is in control" vs "the user chooses the width" (study-guide answer).

### Pros and cons of fluid layout (for comparison)
- ✅ Uses the available space; adapts to the window; respects user choice.
- ❌ Lines can become **too long** on wide screens (beyond the 45–75 characters per line limit) and too cramped on narrow ones, unless combined with media queries.

## 4. Exam-relevant points
- 4 marks → **2 pros + 2 cons**, each explained in a sentence.
- Mention that RWD (fluid grid + media queries) is the modern answer to this debate.
