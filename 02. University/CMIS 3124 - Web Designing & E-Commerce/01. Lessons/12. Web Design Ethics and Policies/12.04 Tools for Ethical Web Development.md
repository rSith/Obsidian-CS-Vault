# 12.04 · Tools and Technologies for Ethical Web Development

> [!info] [[12.00 Web Design Ethics and Policies|Lesson 12]] · Lecture ref L12.4 · Priority 🟡 Medium. HTTPS/TLS answers the old "use of Secure Sockets Layer" question (2019/20 Q8(b)) and the man-in-the-middle question.

## The four tool categories (lecture)

| Category | Lecture description | Examples |
|---|---|---|
| **Privacy management platforms** | Help businesses **manage user consent, data privacy and compliance** with regulations like **GDPR and CCPA** | **OneTrust, TrustArc** (cookie banners, consent records, data maps) |
| **Secure communication protocols** | **HTTPS with TLS (Transport Layer Security)** ensures that data transmitted **between the browser and the web server is encrypted and secure** | The padlock 🔒 in the address bar |
| **Data encryption tools** | **AES (Advanced Encryption Standard)** for data encryption, plus secure storage, safeguard user data **at rest and in transit** | Encrypted customer database |
| **Anonymisation and pseudonymisation tools** | Minimise risk in processing and storage, so that **personal information cannot easily be linked back to an individual** | Replacing names with random IDs in analytics |

**CCPA** = California Consumer Privacy Act, the US (California) counterpart of GDPR.

## Key terms explained

### HTTPS, TLS and SSL
- **HTTP** sends data as plain text, so anyone on the network can read it.
- **HTTPS** = HTTP **+ encryption** using **TLS**.
- **SSL (Secure Sockets Layer)** is the **older predecessor of TLS**. People still say "SSL certificate".
- **What SSL/TLS does:**
  1. **Encryption:** data in transit can't be read if intercepted (protects passwords and card numbers).
  2. **Authentication:** the site's **digital certificate** proves the server is genuine, which defeats fake sites and **man-in-the-middle** attacks.
  3. **Integrity:** data can't be altered in transit without detection.

> [!note] Beyond the slides
> The three functions and the SSL → TLS history are standard knowledge used to answer the old SSL question. The slide says only that HTTPS with TLS encrypts data between browser and server.

```text
Browser ──"hello, I want HTTPS"──► Server
Browser ◄──certificate (public key, signed by a CA)── Server
Browser verifies certificate → both agree a secret session key
All further traffic encrypted (e.g. with AES)
```

### Data at rest vs in transit
| At rest | In transit |
|---|---|
| Stored data (databases, backups) | Data moving across the network |
| Protected by **AES** encryption, secure storage | Protected by **HTTPS/TLS** |

### Anonymisation vs pseudonymisation
| Anonymisation | Pseudonymisation |
|---|---|
| Identifiers **removed permanently**; data can't be linked back | Identifiers **replaced** with codes; can be re-linked with a separate key |
| `Age 24, Kurunegala` | `User #A93F, age 24, Kurunegala` (key held separately) |
