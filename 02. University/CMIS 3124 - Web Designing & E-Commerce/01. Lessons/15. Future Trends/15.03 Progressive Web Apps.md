# 15.03 · Progressive Web Apps (PWAs)

> [!info] [[15.00 Future Trends|Lesson 15]] · Lecture ref L15.3 · Priority 🔴 High
> **Asked as:** "What is a Progressive Web App (PWA)? How is it different from Platform-specific apps?" (2023/24 Q3(a), 3 marks)

## 1. What is a PWA? (lecture)
- **"An app that's built using web platform technologies, but that provides a user experience like that of a platform-specific app."**
- **Combines the best features of traditional websites and platform-specific apps.**

*Examples (beyond the slides):* Twitter/X Lite, Starbucks, Spotify web player.

## 2. Benefits (lecture)
1. Runs on **multiple OSs and device classes from a single codebase**.
2. Can be **accessed directly from the web**.
3. Can be **installed** on the device.
4. Can operate **in the background and offline**: work without network connectivity, **update content in the background**, **respond to push messages** from the server, **display notifications** using the OS notification system.
5. Can use the **whole screen** rather than running in the browser UI.
6. Can be **integrated into the device**.
7. Can be **distributed in app stores**.

## 3. PWAs and the browser (lecture)
| Website in the browser | Installed PWA |
|---|---|
| The **browser UI** gives a visible frame (back/forward buttons, page title) | **Displayed without the browser UI** around it |
| Web APIs are implemented by the browser engine | The **browser engine still works in the background** |

## 4. Technical features (lecture)
| Feature | What it does |
|---|---|
| **At least one HTML page** | Usually loads some CSS and JavaScript |
| **Web app manifest file** | Provides the information **the browser needs to install the PWA**; defines its **appearance** (theme colour, background colour…) and **behaviour** (e.g. acting as a **share target**, handling particular **file types**) |
| **Service worker** | **Implements a back-end** that supports **offline and background operations** |

### Code example (beyond the slides)
```json
// manifest.json
{
  "name": "Ceylon Artefacts",
  "short_name": "Artefacts",
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#2150C8",
  "background_color": "#ffffff",
  "icons": [{ "src": "icon-192.png", "sizes": "192x192", "type": "image/png" }]
}
```
```html
<!-- In index.html -->
<link rel="manifest" href="manifest.json">
<script>
  if ("serviceWorker" in navigator) {            // feature detection
    navigator.serviceWorker.register("/sw.js");  // register the service worker
  }
</script>
```
```javascript
// sw.js – a minimal service worker that serves cached files when offline
self.addEventListener("install", e => {
  e.waitUntil(caches.open("v1").then(c => c.addAll(["/", "/index.html", "/style.css"])));
});
self.addEventListener("fetch", e => {
  e.respondWith(caches.match(e.request).then(r => r || fetch(e.request)));
});
```
- `"display": "standalone"` → opens **without browser UI**.
- The service worker **intercepts network requests** (`fetch`) and answers from the **cache** when offline.

## 5. PWAs and single-page apps (lecture)
- A traditional website is a **collection of interlinked pages**.
- A **single-page app** is **one HTML page**; internal links are handled by **JavaScript**, which fetches new content and updates parts of the page, giving a UX **closer to platform-specific apps**.
- **PWAs don't necessarily have to be single-page apps.**

## 6. Progressive enhancement (lecture)
- **Important for PWAs**, because they run on **many devices** and use **advanced Web APIs** that **not all browsers support**.
- Visit by URL → it works **like a normal website**. If the browser **can install** it, the user is **prompted to install**, and it appears as an app on the device.
- PWAs should perform **feature detection** and provide **acceptable fallbacks**.
  - *Lecture example:* the user writes a message while **offline**. The **Background Sync API** sends it **once the device reconnects**. **If Background Sync isn't supported**, the app should **tell the user the message couldn't be sent**.

**Progressive enhancement** = start with a basic version that works everywhere, then **add advanced features where the browser supports them** (the same idea as mobile-first CSS: [[06.03 Mobile Web, One Web and Mobile First]]).

## 7. Model answer for 2023/24 Q3(a) (3 marks)
**PWA:** an app built with **web technologies (HTML, CSS, JavaScript)** that gives a **native-app-like experience**. It is **installable**, works **offline and in the background** through a **service worker**, is described by a **web app manifest**, runs **full screen** without the browser UI, and supports push notifications.

**Different from platform-specific apps:**
| PWA | Platform-specific app |
|---|---|
| **One codebase** for all OSs and devices | Built **per OS** with the vendor's **SDK** |
| Accessed by **URL** (can also be listed in stores) | Distributed through the **app store** |
| Updates instantly through the web; progressive enhancement | Store distribution and approval; deeper OS and hardware integration, dedicated UI |
