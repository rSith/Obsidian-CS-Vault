# 15.02 · Platform-Specific Apps vs Traditional Websites

> [!info] [[15.00 Future Trends|Lesson 15]] · Lecture ref L15.2 · Priority 🔴 High (the second half of 2023/24 Q3(a): "How is a PWA different from platform-specific apps?")

## 1. Platform-specific (native) apps (lecture)
- **Developed for a specific operating system and/or class of device** (e.g. **iOS or Android**), generally using an **SDK provided by the platform vendor**.
- **Usually distributed through the vendor's app store**, where users find and install them.

**SDK (Software Development Kit):** the vendor's tools and libraries for building apps for its platform (e.g. Apple's iOS SDK, Google's Android SDK).

**Benefits (lecture):**
| Benefit | Example |
|---|---|
| **Easy for users to access** | An icon on the home screen |
| **Offline and background operation** | A chat app **receives messages when it is not open** and **displays a notification** |
| **Dedicated UI** | The app's own full-screen interface |
| **OS integration** | A messaging app can **register as a share target**, so users can pick an image in the photo app and send it with the messaging app |
| **Distribution through the app store** | Users find it in the store |

## 2. Traditional websites (lecture)
- **No presence on the user's device** when the user is not using it.
- Can only be accessed by **opening a browser and navigating** to the site.
- **Highly dependent on network connectivity.**

**Benefits (lecture):**
- **Run on different operating systems and device classes from a single codebase.**
- **Distributed via the web** (just share the URL).

## 3. Comparison (including PWAs)

| | Traditional website | **PWA** | Platform-specific app |
|---|---|---|---|
| Built with | HTML, CSS, JS | **HTML, CSS, JS** (web tech) | Vendor **SDK**, per platform |
| Codebase | **One** for all | **One** for all | **Separate** per OS |
| How users get it | Type a URL | URL **and/or install**; can be in app stores | **App store** |
| Presence on device | None | **Installed icon** | Installed icon |
| Offline / background | ✗ (needs network) | ✓ (**service worker**) | ✓ |
| Push notifications | ✗ | ✓ | ✓ |
| Full screen, no browser UI | ✗ | ✓ | ✓ |
| OS integration | Minimal | **Can be integrated** (e.g. share target) | **Deepest** |
| Updates | Instant | **Instant (via the web)** | Through the store, after approval |

> [!note]
> The table combines the lecture's three lists. The "updates" row is an added inference from web vs store distribution.

> [!tip]
> A **PWA combines the best features** of both: web reach (one codebase, a URL) **plus** app-like features (install, offline, notifications, full screen). See [[15.03 Progressive Web Apps]].
