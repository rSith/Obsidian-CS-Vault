# 09.02 · Components of Web Accessibility and the W3C Guidelines

> [!info] [[09.00 Web Accessibility|Lesson 9]] · Lecture ref L9.2–L9.3 · Priority 🟡 Medium (a strong opening for 2023/24 Q8(b))

## 1. Components that work together (lecture)
*"Web accessibility relies on several components that work together."*

| Component | Lecture definition | Examples |
|---|---|---|
| **Web content** | **Any part of a website**, including text, images, forms and multimedia, **as well as any markup code, scripts, applications** | Your HTML page, its images, its JavaScript |
| **User agents** | **Software that people use to access web content** | **Desktop graphical browsers, voice browsers, mobile phone browsers, multimedia players, plug-ins**, and some **assistive technologies (e.g. screen readers)** |
| **Authoring tools** | **Software or services that people use to produce web content** | **Code editors, document conversion tools, content management systems, blogs, database scripts** |

**Assistive technology** means hardware or software that helps people with disabilities use computers: **screen readers** (read the page aloud, e.g. **JAWS**), screen magnifiers, voice control, switch devices.

## 2. W3C Web Accessibility Initiative (WAI)
The **W3C WAI** *develops technical specifications, guidelines, techniques and supporting resources that describe accessibility solutions.* It publishes **one guideline per component**:

| Guideline | Full name | Applies to (component) |
|---|---|---|
| **WCAG** | **Web Content Accessibility Guidelines** | **Web content** (what developers build) |
| **UAAG** | **User Agent Accessibility Guidelines** | **User agents** (browsers, media players, assistive technologies) |
| **ATAG** | **Authoring Tool Accessibility Guidelines** | **Authoring tools** (editors, CMSs): the tools themselves are accessible *and* help authors create accessible content |

- The lecture references **WCAG 2.2, W3C Recommendation, 12 December 2024**.

> [!note] Beyond the slides
> WCAG is organised by four principles, **POUR**: content must be **Perceivable, Operable, Understandable and Robust**. It has three conformance levels: **A** (minimum), **AA** (the usual legal target) and **AAA** (highest). These come from WCAG itself, not the lecture slides.

## 3. How the pieces fit
```text
Author ──uses──► Authoring tool (ATAG) ──produces──► Web content (WCAG)
                                                            │
User ◄──────── User agent / assistive technology (UAAG) ◄───┘
```
All three must be accessible for a disabled user to succeed.
