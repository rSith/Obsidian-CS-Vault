# 09.03 · Applying Accessible Web Design

> [!info] [[09.00 Web Accessibility|Lesson 9]] · Lecture ref L9.4 (+ L4.8) · Priority 🔴 High
> **Asked as:** "Describe how you can make web content accessible to everyone despite their disabilities." (2023/24 Q8(b), 5 marks)

## 1. The lecture's techniques
The slide lists the technique names. The "how" column combines Lesson 4's accessibility basics with the study guide.

| Technique | How to apply it | Helps |
|---|---|---|
| **Alt text** | Describe every meaningful image in `alt`; decorative images get `alt=""` | Blind users (screen readers), SEO |
| **Provide captions** | Captions for video; **transcripts** for audio | Deaf / hard-of-hearing |
| **Utilise screen readers (JAWS)** | Test your site with a screen reader to hear what blind users hear | Blind users |
| **Be mindful of contrast** | Enough contrast between text and background; **don't use colour alone** to convey meaning | Low vision, colour blind |
| **Simple navigation** | Consistent menus, headings in logical order, skip links | Everyone, especially cognitive and screen-reader users |
| **Minimal content** | Clear, concise, uncluttered pages | Cognitive disabilities |
| **Tab through your site** | Everything must work with the **keyboard alone**, with a **visible focus** | Motor impairments, screen-reader users |
| **Offer accessible PDF options** for images/flyers | Don't publish information only as an image | Blind users |
| **Utilise web forms** properly | Every input has a visible `<label>`; clear error messages | Everyone |
| **Test your site** | Automated checkers + manual + user testing | Everyone |

### Code examples
```html
<!-- Alt text -->
<img src="campus.jpg" alt="Students walking in front of the Wayamba library">
<img src="divider.png" alt="">                       <!-- decorative: screen reader skips it -->

<!-- Labelled form field with a clear, not-colour-only error -->
<label for="email">Email address</label>
<input id="email" type="email" required aria-describedby="email-err">
<p id="email-err">⚠ Please enter a valid email address.</p>

<!-- Captions for video -->
<video controls>
  <source src="intro.mp4" type="video/mp4">
  <track kind="captions" src="intro-en.vtt" srclang="en" label="English">
</video>

<!-- Skip link for keyboard users -->
<a href="#main" class="skip-link">Skip to main content</a>
```

## 2. The flyer example (lecture)
**Problem:** flyers are often uploaded **as images** because they are easy to design, but **these images are not accessible**. *Screen readers can only read the image alt text, which is usually just a few words.*

**Solution: Optimise → Upload → Utilise**
| Step | Action |
|---|---|
| **Optimise** | Edit the photo to **reduce file size**, or **create an accessible PDF**. Save it with a **clear, concise title**. |
| **Upload** | Upload the optimised file to the **correct folder** and add **alt text or captions**. |
| **Utilise** | Add the images or **link the PDFs** from the uploaded files. Add **alt text** and provide **clear instructions**. |

### Using images and PDFs together (lecture)
- **If your flyer is a PDF:** convert the PDF to an image and place it in the body → add alt text → **link the image to the accessible PDF**.
- **If your flyer is an image:** add **descriptive text in the body** → add a **"printable" PDF version** below the image (or link the image to an accessible PDF) → be **descriptive in alt tags and captions**.

## 3. Model answer for 2023/24 Q8(b) (5 marks): organise by disability
1. **Follow the W3C WAI's WCAG**, and make sure content, user agents (assistive technologies) and authoring tools work together.
2. **Visual impairments:** alt text; semantic HTML and correct headings for screen readers; high contrast; no colour-only meaning; resizable real text; accessible PDFs instead of image-only flyers.
3. **Hearing impairments:** captions for video, transcripts for audio.
4. **Motor impairments:** full keyboard access (tab through the site), visible focus, large click targets; ARIA/`tabindex` for custom widgets.
5. **Cognitive impairments:** simple navigation, minimal and clear content, labelled forms with helpful error messages.
6. **Test** with screen readers (JAWS), keyboard-only use and accessibility checkers.

Five distinct, explained techniques = 5 marks.
