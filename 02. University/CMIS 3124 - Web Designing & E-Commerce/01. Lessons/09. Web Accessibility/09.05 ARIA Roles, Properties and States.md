# 09.05 · ARIA Roles, Properties and States

> [!info] [[09.00 Web Accessibility|Lesson 9]] · Lecture ref L9.7 · Priority 🔴 High. These three categories structure the 6-mark tab-widget question (2023/24 Q8(d)).

## Overview

| Category | Answers the question… | Changes? | Examples |
|---|---|---|---|
| **Roles** | **What is this element / what does it do?** | Fixed | `role="navigation"`, `role="search"`, `role="tablist"`, `role="tab"`, `role="tabpanel"` |
| **Properties** | **What extra meaning does it have?** | Rarely change | `aria-required`, `aria-labelledby`, `aria-label`, `aria-controls` |
| **States** | **What condition is it in right now?** | **Change** with user interaction | `aria-expanded`, `aria-selected`, `aria-checked`, `aria-hidden` |

## 1. Roles (lecture)
- **"Roles define what an element is or does."**
- Many are **landmark roles**, which *replicate the semantics of HTML5 sectioning elements*:
  - `role="navigation"` ⇔ `<nav>`
  - `role="contentinfo"` ⇔ `<footer>`
- Some describe page components **without a native HTML counterpart**: `role="search"`, `role="tablist"`, `role="tab"`.

```html
<div role="navigation">…</div>    <!-- same meaning as <nav> (prefer <nav>!) -->
<div role="search">…</div>        <!-- no native HTML equivalent at the time -->
```

| Native HTML landmark | ARIA landmark role (beyond the slides) |
|---|---|
| `<header>` (page level) | `role="banner"` |
| `<nav>` | `role="navigation"` |
| `<main>` | `role="main"` |
| `<aside>` | `role="complementary"` |
| `<footer>` (page level) | `role="contentinfo"` |
| `<form>` with a name | `role="form"` |
| (none) | `role="search"` |

> [!note]
> The lecture shows this comparison as an image ("Native HTML Landmarks vs ARIA landmark roles"). The mapping above is the standard WAI-ARIA one.

## 2. Properties (lecture)
- **"Properties are used to give elements extra semantics."**
- **`aria-required="true"`** specifies that a **form input must be filled in** to be valid.
- **`aria-labelledby="some-id"`** lets authors **reference other elements on the page** to define an **accessible name**.

```html
<label id="lbl-phone">Phone number</label>
<input aria-labelledby="lbl-phone" aria-required="true">
```

## 3. States (lecture)
- **"States define the current conditions of elements."**
- **`aria-expanded="true"`** tells a screen reader that a **collapsible element (like an accordion) is currently active/expanded/visible**.
- **`aria-expanded="false"`** means it is **inactive/collapsed/hidden**.

```html
<button aria-expanded="false" aria-controls="faq1">What is your return policy?</button>
<div id="faq1" hidden>You can return items within 14 days.</div>

<script>
  const btn = document.querySelector('[aria-controls="faq1"]');
  btn.addEventListener('click', () => {
    const open = btn.getAttribute('aria-expanded') === 'true';
    btn.setAttribute('aria-expanded', String(!open));      // update the STATE
    document.getElementById('faq1').hidden = open;
  });
</script>
```
JavaScript must **update states** whenever the UI changes, or the screen reader will announce the wrong condition.
