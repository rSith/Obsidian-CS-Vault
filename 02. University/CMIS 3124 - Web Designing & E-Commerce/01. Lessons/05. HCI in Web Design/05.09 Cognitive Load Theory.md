# 05.09 · Cognitive Load Theory in Web Design

> [!info] [[05.00 HCI in Web Design|Lesson 5]] · Lecture ref L5.11 · Priority 🔴 High
> **Asked as:** "Describe how web designers can utilize Cognitive load theory principles to minimize excessive mental effort that can lead to user frustration and poor engagement." (2023/24 Q4(d), **6 marks**)

## 1. What is cognitive load?
**Cognitive load** is **"the amount of mental effort users need to expend to navigate a website, process information and complete tasks."**

Too much cognitive load → users feel **frustrated**, make mistakes and **leave** (poor engagement).

## 2. Three types of cognitive load (lecture diagram)

| Type | Meaning | What the designer should do |
|---|---|---|
| **Intrinsic** | The **complexity of the new information itself** | **[SIMPLICITY]**: you can't remove it, but you can simplify and sequence it |
| **Extraneous** | Effort that **distracts working memory** from processing new information (clutter, confusing layouts, unfamiliar controls) | **[REDUCE]** it |
| **Germane** | **Deep processing** of new information by **integrating it with previous learning** (real understanding) | **[MAXIMISE]** it |

## 3. Working memory vs long-term memory (lecture)

| Working memory | Long-term memory |
|---|---|
| **Small capacity** | **Huge capacity** |
| Where we **hold and process new information** | Where we **store what we have learnt** |
| Information **not transferred to long-term memory is forgotten** | New things are learnt by **connecting** working-memory information to long-term memory |

**Why this matters:** a web page that shows too much at once overflows the small working memory. Familiar patterns use what is already in long-term memory, so they cost less effort.

## 4. The four cognitive load theory (CLT) principles and their UX techniques

### Principle 1: Information Store
- The **brain stores two types of knowledge**: **innate (primary)** and **learned (secondary)**.
- **Primary knowledge and UX:**
  - **Familiarity:** consistent design patterns and intuitive interfaces;
  - **Simplicity:** avoid unnecessary complexity and distractions.
- **Supporting secondary knowledge:**
  - **Contextual learning:** **tooltips, informational videos, guided onboarding** help users grasp new features;
  - **Personalisation.**

### Principle 2: Borrowing and Reorganising
- *How we acquire and organise information from the external world*, building a vast knowledge store.
- **Properly organised information makes access and retrieval easier.**
- **In UX design:**
  - **maintain consistent design patterns and layouts**;
  - **break complex information into smaller, digestible chunks** (chunking);
  - **gradual disclosure** of information.

### Principle 3: Randomness as Genesis
- **True novelty arises from experimentation and testing.** This creates **tension between introducing new features and ensuring user comprehension**.
- **In UX design:**
  - provide **onboarding, tooltips and contextual help** to explain new features and their benefits;
  - use **progressive disclosure** to unveil new features **incrementally**;
  - introduce features that **directly address user goals**; **avoid novelty for novelty's sake**;
  - use **familiar UI patterns and terminology** with new features.

### Principle 4: Narrow Limits of Change
- **Our brains have a finite capacity** for processing information at any one time.
- **In UX design:**
  - **break complex tasks into smaller, manageable steps**;
  - **reveal information gradually** (progressive disclosure);
  - **organise information logically** using **familiar categories and labels**;
  - **only use recognisable UI elements**;
  - provide **clear onboarding** for new information, features and concepts.

## 5. Key techniques explained
- **Progressive disclosure:** show only the essential options first, and reveal advanced ones when the user asks (e.g. an "Advanced settings ▾" link).
- **Chunking:** group information into small units (e.g. a phone number shown as `077 123 4567`, not `0771234567`).
- **Onboarding:** a short guided tour for first-time users.

### Example: a long sign-up form → a 3-step form

```html
<!-- Step 1 of 3 – only a few fields at a time (narrow limits of change) -->
<p>Step 1 of 3: Account</p>                    <!-- progress indicator -->
<form>
  <label for="email">Email</label>
  <input id="email" type="email" required>
  <label for="pw">Password</label>
  <input id="pw" type="password" required
         title="At least 8 characters">           <!-- tooltip = contextual help -->
  <button>Next</button>                           <!-- familiar UI element -->
</form>
<!-- Step 2: Address · Step 3: Payment (revealed gradually) -->
```
