# 05.08 · User Interface Design Principles (17)

> [!info] [[05.00 HCI in Web Design|Lesson 5]] · Lecture ref L5.10 · Priority 🟡 Medium (not asked yet; a likely "explain any N principles" question)

## The principles (lecture definitions + example)

| # | Principle | Lecture meaning | Web example |
|---|---|---|---|
| 1 | **User familiarity** | Based on **user-oriented terms and concepts** | "Cart" and "Checkout", not "Order buffer" |
| 2 | **Consistency** | An appropriate level of consistency: commands and menus have the **same format**, similar punctuation | Same menu position and button style on every page |
| 3 | **Minimal surprise** | If a command works in a known way, users can **predict comparable commands** | Every "×" closes its window |
| 4 | **Recoverability** (undo, redo) | **Resilience to user errors**: an undo facility, **confirmation of destructive actions**, **"soft" deletes** | "Are you sure you want to delete?"; "Undo" after removing a cart item |
| 5 | **User diversity** | Support **different types of user** | **Larger text** option for users with seeing difficulties |
| 6 | **Anticipation** | Anticipate the **user's next move** | After adding to cart, show "Proceed to checkout" |
| 7 | **Communication** | **Communicate the status** of any activity the user started | Progress bar while uploading; "Order placed ✓" |
| 8 | **Controlled autonomy** | Free movement through the WebApp, but **enforcing established navigation conventions** | Users can jump around, but checkout must go in order |
| 9 | **Efficiency** | **Optimise the user's work efficiency** | Saved addresses, one-click reorder |
| 10 | **Focus** | Stay **focused on the user's task(s)** at hand | No pop-up ads during checkout |
| 11 | **Human interface objects** | Reuse the **vast library of reusable interface objects** | Standard date pickers, drop-downs, checkboxes |
| 12 | **Latency reduction** | Use **multi-tasking** so the user **proceeds as if the operation has completed** | Keep browsing while a file uploads in the background |
| 13 | **Learnability** | **Minimise learning time**, and **minimise relearning** on revisits | Familiar layout patterns |
| 14 | **Maintain work-product integrity** | A work product (a completed form, a user's list) is **automatically saved** so it is not lost if an error occurs | Gmail auto-saves drafts |
| 15 | **Readability** | **All information** presented must be **readable** | Good font size and contrast |
| 16 | **Track state** | **Track and store the interaction state** so a user can **log off and return later** to pick up where they left off | The cart is still there tomorrow |
| 17 | **Visible navigation** | Provides **"the illusion that users are in the same place, with the work brought to them"** | Single-page app with a fixed menu ([[02.09 SPA, AJAX and Custom Development]]) |

> [!note]
> The "web example" column is illustrative. The middle column paraphrases the slides closely.

## Grouping to help memory
- **Predictability:** familiarity, consistency, minimal surprise, learnability, human interface objects
- **Error safety:** recoverability, work-product integrity, track state
- **Feedback and speed:** communication, latency reduction, efficiency, anticipation
- **Clarity and inclusion:** readability, user diversity, focus, visible navigation, controlled autonomy

## Exam-relevant points
- If asked for *N* principles: **name + lecture meaning + a web example** for each.
- Several overlap with cognitive-load techniques (consistency, familiarity, focus): see [[05.09 Cognitive Load Theory]].
