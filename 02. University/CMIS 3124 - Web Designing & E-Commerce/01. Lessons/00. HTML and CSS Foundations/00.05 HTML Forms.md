# 00.05 · HTML Forms

> [!info] [[00.00 HTML and CSS Foundations|Foundations]] · Source: Practical 2 (section 3) · Priority 🟡 Medium (GET/POST was examined in 2023/24 Q7(c); forms appear in PHP, ARIA and React questions)

## 1. What are forms for? (Practical 2)
HTML forms **collect information from users** and let them **interact with a website**: **login pages, registration forms, search bars, contact forms, feedback forms, bookings and checkout pages**. A form is created with `<form>`.

## 2. `action` and `method`
```html
<form action="process.php" method="post"> … </form>
```
| Attribute | Meaning (Practical 2) |
|---|---|
| `action` | **Where** the form data is sent (the server-side file) |
| `method` | **How** it is sent: **GET** (data added to the **URL as a query string**, e.g. search) or **POST** (data sent **in the request body**, for larger or more sensitive data) |

Submission flow (Practical 2): *User completes the form → clicks Submit → browser collects the data → data is sent → a server-side file processes it.* See [[02.04 HTTP Protocol]] and [[02.02 Web Languages - HTML CSS JavaScript PHP]].

## 3. Labels, `id`, `name` and `for`
```html
<label for="email">Email:</label>
<input type="email" id="email" name="email">
```
| Attribute | Purpose (Practical 2) |
|---|---|
| `id` | **Identifies** the input element on the page |
| `name` | The **name used when the form data is submitted**, i.e. the key PHP reads: `$_POST["email"]` |
| `for` (on `<label>`) | **Connects the label** to the input; **must match the input's `id`** |

Clicking a connected label focuses its input, and screen readers read the label, so this is an **accessibility** essential ([[09.03 Applying Accessible Design]]).

## 4. Input types (Practical 2)
`text` · `email` · `password` · `number` · `date` · `time` · `url` · `tel` · `file` · `range` · `color` (plus `checkbox`, `radio`, `submit`, `reset`, `button`).
*The same `<input>` element behaves differently depending on its `type`.* Mobile phones show suitable keyboards, e.g. a numeric pad for `tel`.

## 5. Radio buttons vs checkboxes
```html
<!-- Radio: choose ONE from the group (same name) -->
<input type="radio" id="contact-email" name="contact_method" value="email">
<label for="contact-email">Email</label>
<input type="radio" id="contact-phone" name="contact_method" value="phone">
<label for="contact-phone">Phone</label>

<!-- Checkbox: choose zero, one or many -->
<input type="checkbox" id="technology" name="interests" value="technology">
<label for="technology">Technology</label>
<input type="checkbox" id="travel" name="interests" value="travel">
<label for="travel">Travel</label>
```
| Radio buttons | Checkboxes |
|---|---|
| **Only one** option from a group | **Zero, one or many** options |
| Grouped by the **same `name`** | Each can be ticked independently |
| `value` = what is submitted | `value` = what is submitted (use `name="interests[]"` so PHP receives an array *(study-guide tip)*) |

## 6. Drop-down list and text area
```html
<label for="subject">Subject:</label>
<select id="subject" name="subject">
  <option value="">Select a subject</option>
  <option value="general">General Inquiry</option>
  <option value="feedback">Feedback</option>
</select>

<label for="message">Message:</label>
<textarea id="message" name="message" rows="6" cols="40"></textarea>
```
- `<select>` + `<option>`: the **selected option's value** is submitted.
- `<textarea>`: **longer text**; `rows` = visible height, `cols` = visible width. Use `<input type="text">` for short data such as a name.

## 7. Grouping: `<fieldset>` and `<legend>`
```html
<fieldset>
  <legend>Personal Information</legend>
  <label for="name">Name:</label>
  <input type="text" id="name" name="name">
</fieldset>
```
`<fieldset>` **groups related controls**; `<legend>` gives the group a **title**. Large forms become easier to understand (lower cognitive load: [[05.09 Cognitive Load Theory]]).

## 8. Buttons
| Button | Effect |
|---|---|
| `<button type="submit">` | **Sends** the form data |
| `<button type="reset">` | **Clears** the values |
| `<button type="button">` | Does **nothing automatically**; used with JavaScript |

## 9. HTML5 form validation (client-side)
| Attribute | Effect |
|---|---|
| `required` | The field is **compulsory** |
| `min` / `max` | Number range, e.g. `min="18" max="100"` |
| `minlength` / `maxlength` | Number of characters |
| `pattern` | Must match a regular expression, e.g. `pattern="[A-Za-z ]+"` |
| `placeholder` | A **hint** inside the field (not a label!) |
| `type="email"` etc. | Built-in format checks |

> [!warning] Client-side validation is not security
> Browser validation improves UX, but attackers can bypass it. The **server must validate again** ([[13.10 Best Practices for Securing a Website]]: "validate user input").

**File uploads** need `method="post"` and `enctype="multipart/form-data"`; `accept=".pdf,.jpg"` limits the file types.

## 10. Practice: a login form (study-guide practice question)
```html
<form action="login.php" method="post">
  <label for="email">Email:</label>
  <input type="email" id="email" name="email" required>

  <label for="pw">Password:</label>
  <input type="password" id="pw" name="password" minlength="6" required>

  <button type="submit">Log in</button>
</form>
```
POST is used because a **password** is sent.
