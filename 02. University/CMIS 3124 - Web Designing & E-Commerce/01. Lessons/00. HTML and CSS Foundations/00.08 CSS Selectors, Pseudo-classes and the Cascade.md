# 00.08 · CSS Selectors, Pseudo-classes, Pseudo-elements and the Cascade

> [!info] [[00.00 HTML and CSS Foundations|Foundations]] · Source: Practical 3 (Part 1) Steps 6–8, 18, 33; Practical 3 Part 2 exercises 34–37 · Priority 🟡 Medium (a possible short question: "pseudo-class vs pseudo-element")

## 1. Selectors used in the practicals
| Selector | Example | Selects |
|---|---|---|
| **Type (element)** | `p`, `button` | Every `<p>` / `<button>` |
| **Class** | `.button` | Every element with `class="button"` (reusable) |
| **ID** | `#myself` | The **one** element with `id="myself"` |
| **Descendant** (space) | `#latest_blogs article img` | Any `img` inside an `article` inside `#latest_blogs` |
| **Child** (`>`) | `body > header`, `section > h2` | Only **direct children** |
| **Grouping** (`,`) | `input[type="text"], select, textarea` | All of them with one rule |
| **Attribute** | `input[type="email"]` | **Every** email input (vs `#email` = **one** specific element) |
| **Multiple classes** | `.button.button-primary` | Elements with both classes |

**Practical 3 Part 2, Exercise 34:** `#email` → selects **one specific element**; `input[type="email"]` → selects **every email input**.
**Exercise 35:** `button {}` styles every button, but **reusable classes** (`.button`, `.button-primary`) make styling easier as the project grows.
**Exercise 36, multiple classes:** `<button class="button button-primary">` receives styles from **both** `.button` and `.button-primary`. This is a "base + variant" component.

## 2. Pseudo-classes: an element in a particular **state** or **position**
*"Keywords added to selectors to style an element when it is in a particular state, such as when the mouse is over it, it has keyboard focus, or it is being clicked."* (Practical 3, Step 8)

| Pseudo-class | When it applies (Practical 3 table) | Example |
|---|---|---|
| `:hover` | The **mouse pointer is over** the element | Mouse over a link |
| `:focus` | The element **has focus** (clicked or keyboard) | An input field currently selected |
| `:focus-visible` | Has focus **and** the browser decides a visible indicator is needed (commonly **keyboard navigation**) | Tab to a nav link |
| `:active` | **While being activated** (mouse button pressed) | Pressing a button |
| `:visited` | A link to a page **already visited** | A previously opened link |
| `:nth-child(even)` | **Position**: every even child | Zebra table rows |
| `:required`, `:valid`, `:invalid`, `:checked`, `:disabled`, `:placeholder-shown` | **Form states** | [[00.09 Styling Forms with CSS]] |

```css
nav a:hover { background-color: var(--color-primary); color: white; }
nav a:focus-visible { outline: 3px solid var(--color-primary); outline-offset: 3px; }
```
*Keyboard focus is important for users who navigate with the **Tab** key* ([[09.03 Applying Accessible Design]], "tab through your site").

## 3. Pseudo-elements: style a **part** of an element, or insert generated content
```css
article > a::after { content: " →"; }   /* Practical 3, Step 18: arrow after "Read more" */
li::marker { color: var(--color-primary); }
input::placeholder { color: var(--color-muted); }
p::first-line { font-weight: bold; }
```

### Pseudo-class vs pseudo-element (likely short question)
| Pseudo-class | Pseudo-element |
|---|---|
| **Single colon** `:` | **Double colon** `::` |
| Selects an element in a **state or position** | Styles a **part** of an element or **inserts content** |
| `a:hover`, `input:focus`, `tr:nth-child(even)` | `a::after { content: "→" }`, `p::first-line`, `::placeholder` |

## 4. The cascade: which rule wins?
**Cascading** means that when several rules target the same element, the browser decides which one applies by:
1. **Importance** (`!important` beats normal rules; avoid using it);
2. **Specificity**: more specific selectors win;
3. **Source order**: if specificity is equal, the **later** rule wins.

**Specificity, simplified:** count the selector's parts as (IDs, classes/attributes/pseudo-classes, elements):
| Selector | Specificity |
|---|---|
| `p` | (0, 0, 1) |
| `section p` | (0, 0, 2) |
| `.button` | (0, 1, 0) |
| `#myself p` | (1, 0, 1) |
| Inline `style="…"` | beats all of the above |

> [!note]
> The specificity rules are standard CSS knowledge. The practicals demonstrate the cascade with exercises but don't state the rules.

### Practical 3, Step 33: demonstrate the cascade
```css
p           { color: black; }                    /* (0,0,1) */
section p   { color: var(--color-text); }        /* (0,0,2) wins over p */
#myself p   { color: var(--color-secondary); }   /* (1,0,1) wins inside #myself */
```
➡ A paragraph inside `<section id="myself">` is **secondary colour**; a paragraph in another section is **text colour**; a paragraph outside any section is **black**.

### Practical 3 Part 2, Exercise 37
```css
button          { background-color: gray; }   /* (0,0,1) */
.button         { background-color: blue; }   /* (0,1,0) */
.button-primary { background-color: green; }  /* (0,1,0), later in the file */
```
➡ `<button class="button button-primary">` is **green**: classes beat the type selector, and between the two equal classes the **later** rule wins.
