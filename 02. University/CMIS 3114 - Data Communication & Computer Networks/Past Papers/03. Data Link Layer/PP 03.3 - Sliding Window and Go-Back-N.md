## A. Sliding window protocol

> **2019/20 Q6(d):** Explain the Sliding Window Protocol used in the Data Link Layer from the initial state of the sender and receiver to the receipt of an acknowledgement message. Indicate the sequence numbers for Data and Acknowledgment messages.
> **2022/23 Q5(b):** Using diagrams, explain the Sliding Window Protocol used in the Data Link Layer. The messages will be exchanged from the initial state of the sender and receiver to the receipt of an acknowledgement message. Indicate the sequence numbers for Data and Acknowledgment messages.

### Expected answer
Each frame carries an **n-bit sequence number** (lecture: **3 bits → 0–7**, drawn as a dial). The **sender window** holds the sequence numbers of frames sent but not yet acknowledged; the **receiver window** holds the numbers it may accept. Window size **1**:

```text
          Sender window            Receiver window
 (a)      empty, next = 0          expects 0         ← initial state
 (b)      {0}  (frame 0 sent)      expects 0         DATA(seq=0) →
 (c)      {0}  (waiting)           expects 1         ← ACK(ack=0)   frame 0 delivered
 (d)      empty, next = 1          expects 1         ACK 0 received; window slides
```
Draw two circles (0–7) per step with the window shaded: sender shading appears at 0 in (b), clears in (d); receiver shading moves from 0 to 1 in (c).

**Step by step:**
1. **(a) Initially:** sender has nothing outstanding, next sequence number **0**; receiver's window is at **0**.
2. **(b)** Sender transmits **DATA frame seq = 0**, starts a **timer**; its window now contains 0.
3. **(c)** Receiver gets frame 0, checks it, passes it to the network layer, **slides its window to 1**, and sends **ACK 0**.
4. **(d)** Sender receives **ACK 0**, stops the timer, removes frame 0 from its window (window slides); it may now send **frame 1**. Sequence numbers wrap 7 → 0.
If the frame or ACK is lost, the timer expires and frame 0 is resent; the receiver discards a duplicate (it expects 1) and re-acknowledges.

## B. Go-Back-N

> **2020/21 Q6(a):** Data link layer uses protocols such as Go back – N. describe its behavior when the window size is 1. What happens if the receiver's window size is large?
> **2023/24 Q7(c):** Go back-N is a Data link layer protocol. Describe its behavior when the window size is 1. What happens if the receiver's window size is large?

### Expected answer
Go-Back-N uses **pipelining**: the sender may send several frames before waiting for ACKs, keeping a timer for each.

**Receiver window size = 1 (Go-Back-N):**
1. Frames 0, 1 arrive and are acknowledged.
2. Frame 2 is **lost/damaged**.
3. The receiver accepts **only the next expected frame (2)**, so it **discards frames 3, 4, 5, …** even though they are correct, and sends no new ACKs.
4. The sender's **timer for frame 2 expires**; it **goes back** and **retransmits frame 2 and all following frames** (2, 3, 4, …).
5. Simple receiver (no buffering), but **wastes bandwidth** when errors are frequent.

**Receiver window size large (Selective Repeat):**
1. Frame 2 is lost; frames 3–8 arrive correctly.
2. The receiver **buffers** 3–8 and sends a **NAK for frame 2** (while ACKs stay at 1).
3. The sender **retransmits only frame 2**.
4. When 2 arrives, the receiver delivers **2–8 in order** to the network layer and sends a cumulative **ACK 8**.
5. Efficient (only the bad frame resent) but needs **buffer memory** at the receiver and more complex logic.

```text
(a) receiver window 1      0 1 2 3 4 5 6 7 8 |timeout| 2 3 4 5 6 …
                           0 1 E D D D D D D           2 3 4 5 6 …   (D = discarded)
(b) receiver window large  0 1 2 3 4 5 2 6 7 8 …
                           0 1 E 3 4 5 2 6 7 8 …     (3–5 buffered, NAK 2)
```

> [!note] Wording
> The question's "window size is 1" refers to the **receiver's** window (as in the lecture figure). With a sender window of 1 as well, the protocol reduces to stop-and-wait.
