## A. What is a protocol and why is it needed?

> **2018/19 Q2(a):** Describe the role of protocols in computer networks.
> **2019/20 Q3(a):** Describe what is a network protocol and why they are needed in computer networks.
> **2020/21 Q3(a) (first part):** Define what is a network protocol…
> **2021/22 Q3(a):** Define what is a network protocol and why they are needed in computer networks
> **2022/23 Q3(a):** Describe the need for network protocols and why multiple protocols are used in a computer network.
> **2023/24 Q3(a):** Explain what a Network Protocol is and why they are needed in computer networks.

### Expected answer
A **protocol** is *"an agreement, standard or a set of rules on the conversation"*: *"a set of rules that specify the **format and meaning of messages** exchanged between computers across a network."* A set of related, compatible protocols is a **protocol suite (protocol hierarchy)**.

**Why needed / role:**
- Computers from **different vendors** with different hardware/software must understand each other → agreed **message format (syntax)** and **meaning (semantics)**.
- Define **order and timing**: who sends first, what reply to expect (like the human "Hi / Hi / Got the time? / 2:00" example vs the web client "connection request / OK / GET / file").
- Provide **addressing**, **error detection and recovery** (corruption, loss, duplication, reordering), **flow control**, and **routing**.
- Without protocols there is no **interoperability**; hence standards bodies (ISO, IEEE, IAB).

**Why multiple protocols (2022/23):** the communication problem is split into **layers**, each solving one part with its **own protocol** (e.g. HTTP, TCP, IP, Ethernet), forming a **protocol stack**. Different applications also need different services at the same layer (TCP for reliability, UDP for speed). Each protocol can be changed independently.

## B. Why layering? Advantages and disadvantage

> **2018/19 Q3(a):** Explain why network protocols are designed with a layered approach.
> **2020/21 Q3(a) (second part):** …why they are designed with a layered approach.
> **2019/20 Q3(b), 2023/24 Q3(b):** List two reasons for using layered protocols. Describe one possible disadvantage of using layered protocols.
> **2021/22 Q3(b):** List reasons for using layered protocols? Describe one possible disadvantage of using layered protocols

### Expected answer
Networks are complex (hosts, routers, links, applications, hardware, software). Layering applies **"divide and conquer"**: the problem is split into layers, each built on the one below, each **offering services to the layer above** while **hiding how they are implemented**.

**Reasons/advantages:**
1. **Reduces design complexity / easier to design**: each layer solves one well-defined part.
2. **Modularity / independence**: a layer's implementation can change without affecting others (the secretary switching from fax to e-mail doesn't affect the philosophers).
3. **Easier maintenance and updating**; easier to **extend and add new services** (flexibility).
4. **Standardisation and interoperability**: clean interfaces between layers.

**Disadvantage:** **performance overhead**: each layer adds its own header and processing, consuming bandwidth and CPU time; some functions (e.g. error control) are duplicated across layers.

## C. Effect of changes at layer k

> **2018/19 Q3(b):** What are the impacts on the operations at layers k − 1 and k + 1 when, i. The algorithms used to implement the operations at layer k is changed. ii. The service (set of operations) provided by layer k is changed.

### Expected answer
(i) **No impact** on layers k−1 or k+1. Layers interact only through **services and interfaces**; the algorithm is a hidden internal detail of layer k, so as long as layer k provides the same service, neighbouring layers are unaffected.
(ii) **Layer k+1 is affected**: it uses layer k's service, so it must be changed to use the new set of operations. **Layer k−1 is normally not affected**, because it only provides services to layer k (unless the new service requires new operations from k−1).

## D. Message through five layers

> **2018/19 Q3(c):** Describe how a message from a sender machine would travel through the multiple layers to a receiver machine assuming that the protocol consists of five layers. Write any reasonable assumptions made regarding the limitations of each layer.
> **2021/22 Q3(c):** Using a diagram, describe how a message from a sender machine would travel through the multiple layers to a receiver machine assuming that the protocol consists of five layers. Write any reasonable assumptions made regarding the limitations of each layers.

**Related topic:** [[01.11 Protocol Hierarchies and Encapsulation]]

### Expected answer
```text
 Layer 5:  M                                  →  M
 Layer 4:  H4 M                               →  H4 M
 Layer 3:  H3 H4 M1      H3 M2                →  H3 H4 M1   H3 M2
 Layer 2:  H2 H3 H4 M1 T2   H2 H3 M2 T2       →  (same)
 Layer 1:  ─────────── bits over the physical medium ───────────►
           Source machine                         Destination machine
```
1. An application process in **layer 5** produces message **M** and passes it to layer 4.
2. **Layer 4** adds header **H4** (e.g. **sequence numbers**, size, time) and passes it to layer 3.
3. **Layer 3** must **split** the message into packets **M1, M2** because of its size limit, adds **H3** to each, chooses the outgoing line, passes them to layer 2.
4. **Layer 2** adds header **H2** and trailer **T2** (e.g. checksum) to each piece and passes the frames to layer 1.
5. **Layer 1** transmits the bits.
6. At the receiver, the message moves **up**; each layer **strips its own header** and passes the rest up; layer 3 reassembles, layer 4 reorders, layer 5 gets M. Headers of lower layers are never passed up.

**Assumptions:** layer 4 has no message-size limit but layer 3 does; lower layers may not preserve order (hence sequence numbers in H4); layer 2 adds a trailer for error detection; layer 1 adds no header; peers communicate **virtually**, only layer 1 communicates **physically**.

## E. Host–router–router–host: physical and virtual communication

> **2020/21 Q3(c):** A host is communicating with another host via two routers in between them. Consider that the hosts and the routers are using the ISO reference model. Draw a diagram clearly indicating the physical and virtual communication between the layers of the above four components.
> **2020/21 Q3(d):** Describe how a message would travel from one host to the other through the routers in the above network in part 'c)'.
> **2021/22 Q3(d):** Consider that in the above scenario in part "c)", the addressing is done in layer 2. A host is communicating with another host via two routers in between them. Draw a diagram clearly indicating the physical and virtual communication between the layers of the above four components.

### Expected answer (2020/21, ISO 7-layer)
```text
   Host A          Router 1        Router 2          Host B
 ┌─────────┐                                       ┌─────────┐
 │7 Appl.  │ · · · · · · · · · · · · · · · · · · · │7 Appl.  │
 │6 Pres.  │ · · · · · · · · · · · · · · · · · · · │6 Pres.  │
 │5 Session│ · · · · · · · · · · · · · · · · · · · │5 Session│
 │4 Transp.│ · · · · · · · · · · · · · · · · · · · │4 Transp.│
 │3 Network│ · ·│3 Network│ · · │3 Network│ · · · ·│3 Network│
 │2 DataLnk│ · ·│2 DataLnk│ · · │2 DataLnk│ · · · ·│2 DataLnk│
 │1 Phys.  │────│1 Phys.  │─────│1 Phys.  │────────│1 Phys.  │
 └─────────┘    └─────────┘     └─────────┘        └─────────┘
  · · · virtual (peer-to-peer) communication   ─── physical communication
```
- Routers implement only layers **1–3** (they forward packets); hosts implement all 7.
- **Virtual communication:** layers 4–7 talk **end to end** between the two hosts; layers 1–3 talk **hop by hop** between neighbours.
- **Physical communication:** only through layer 1 over each link.

**Message travel (Q3d):** Host A's data passes down 7→1 with a header added at each layer (plus a DLL trailer) → bits cross the link → **Router 1** passes it up to layer 3, checks the frame, reads the **destination network address**, looks up its **routing table**, chooses the next link, builds a **new frame** and sends it (**store-and-forward**) → **Router 2** does the same → Host B passes the data up 1→7, each layer removing its header, until the application receives the message.

### Expected answer (2021/22, 5-layer model, addressing at layer 2)
Draw both hosts with **layers 1–5**, and the two intermediate devices with **layers 1–2 only**, because forwarding decisions are made using **layer-2 addresses** (they act like switches/bridges). Virtual communication: layer-2 peers on each hop; layers 3–5 end to end between the hosts. Physical communication: layer 1 links Host A – device 1 – device 2 – Host B.

## F. Four design issues of layers

> **2020/21 Q3(b):** List and describe four design issues of protocol layers.

**Related topic:** [[01.12 Design Issues for the Layers]]

### Expected answer (any four)
1. **Addressing:** identify senders and receivers among many destinations.
2. **Error control:** detect and correct errors and reorder messages over an imperfect medium.
3. **Flow control:** stop a fast sender swamping a slow receiver (feedback or agreed rate).
4. **Routing:** select a path between source and destination.
5. **Multiplexing:** many connections share one channel.
6. **QoS:** real-time traffic delay and quality.
7. **Message size:** disassemble long messages and reassemble; combine tiny ones.

## G. Connection-oriented client–server interaction

> **2019/20 Q2(d):** Describe, step-by-step, the interactions between two computers using connection oriented services in a Client-Server setting.
> **2021/22 Q2(d):** Client-Server system is a popular network model. Describe, step-by-step, the interactions between a client and a server that uses connection oriented service.
> **2023/24 Q2(d):** Describe, step-by-step, the interactions between two computers using **connection-oriented services** in a Client-Server setting.

**Related topic:** [[01.14 Service Primitives]]

### Expected answer
Primitives: **LISTEN, CONNECT, ACCEPT, RECEIVE, SEND, DISCONNECT**.
1. **Server executes LISTEN** → blocked until a connection request arrives.
2. **Client executes CONNECT** → sends a connection request **(packet 1)**; client suspended.
3. The server's OS sees the request, finds the listener, **unblocks it (ACCEPT)** and sends an **acknowledgement (packet 2)**.
4. The acknowledgement **releases the client** → connection **established**.
5. **Server executes RECEIVE** → blocked waiting for a request.
6. **Client executes SEND** with its **request (packet 3)**, then RECEIVE to wait for the reply.
7. The request **unblocks the server**, which processes it and uses **SEND** to return the **reply (packet 4)**. More requests may follow.
8. **Client executes DISCONNECT** (blocking) → **packet 5** tells the server the connection is no longer needed.
9. **Server executes DISCONNECT**, acknowledging (**packet 6**); when it reaches the client, the client is released and the **connection is released**.

Draw the sequence diagram with packets (1)–(6) between client and server machines.
