## A. TCP vs UDP

> **2019/20 Q3(c), 2023/24 Q3(c):** Compare and Contrast TCP and UDP protocols.
> **2022/23 Q3(b):** State the similarities and differences of TCP and UDP protocols.

### Expected answer
**TCP (Transmission Control Protocol)** provides a **reliable, connection-oriented** service that delivers a **byte stream** from one machine to another without error; it **guarantees delivery** and provides **flow control**; it fragments the byte stream into messages and the receiving TCP reassembles them.
**UDP (User Datagram Protocol)** provides an **unreliable, connectionless** service for applications that provide their own reliability or don't want TCP's sequencing and flow control; used for **one-shot request–reply queries** and where **prompt delivery matters more than accurate delivery** (speech, video).

| Feature | TCP | UDP |
|---|---|---|
| Connection | Connection-oriented (setup first) | Connectionless |
| Reliability | Reliable: ACKs, retransmission | Unreliable, no ACKs |
| Order | In-order delivery | No ordering |
| Flow / congestion control | Yes | No |
| Data | Byte stream | Independent datagrams |
| Overhead / speed | Higher, slower | Low, faster |
| Header | ≥ 20 bytes | 8 bytes |
| Examples | HTTP, SMTP, FTP, Telnet | DNS queries, VoIP, video streaming, games |

**Similarities:** both are **transport-layer** protocols in TCP/IP; both run over **IP**; both provide **end-to-end, process-to-process** delivery between hosts (using **port numbers**); both include a **checksum**; both are used by application-layer protocols.

### Exam approach
One-sentence definition of each (lecture words) → table of 6+ rows → similarities → one application example each.

## B. OSI vs TCP/IP

> **2019/20 Q3(d):** Contrast the OSI reference model with the TCP/IP reference model using a diagram to show the correspondence between relevant protocol layers in the two models.
> **2022/23 Q3(c):** Compare and differentiate the OSI and the TCP/IP reference models, using a diagram to illustrate the relationship and correspondence between their respective protocol layers.
> **2023/24 Q3(d):** Using illustrations compare ISO-OSI with TCP/IP reference model.

### Expected answer
```text
      OSI                       TCP/IP
 7 Application  ┐
 6 Presentation ├──────────►  Application   (HTTP, FTP, Telnet, SMTP, DNS)
 5 Session      ┘
 4 Transport    ───────────►  Transport     (TCP, UDP)
 3 Network      ───────────►  Internet      (IP)
 2 Data link    ┐
 1 Physical     ┘──────────►  Host-to-network (not defined)
```

| OSI | TCP/IP |
|---|---|
| **7 layers** | **4 layers** |
| Model designed **first**, protocols later → general, not biased to any protocols | Protocols came **first**; the model only describes them → fits TCP/IP only |
| Clearly distinguishes **services, interfaces and protocols** | Does not clearly distinguish them |
| Protocols better hidden, easy to replace | Minor protocols entrenched |
| Network layer: **connectionless and connection-oriented**; transport: **connection-oriented only** | Network (internet) layer: **connectionless only**; transport: **both** (TCP, UDP) |
| Has session and presentation layers (nearly empty) | No session/presentation layers |
| Physical and data link layers defined | Host-to-network layer not really defined |
| Protocols rarely used; model used for teaching | Protocols used everywhere (Internet) |

**Similarities:** both are **stacks of independent protocols**; both have **network/internet, transport and application** layers; the functions of corresponding layers are **roughly similar** (transport is end-to-end in both).

## C. Which OSI layer? (2023/24 Q3(d))

> **Question:** Which (OSI) layer is used for the following? i. to route packets ii. to convert packets to frame iii. to detect and correct errors iv. to run services like HTTP, FTP, Telnet etc.

### Expected answer
| | Task | OSI layer | Why |
|---|---|---|---|
| (i) | Route packets | **Network layer (3)** | Chooses the path from source to destination (routing) |
| (ii) | Convert packets to frames | **Data link layer (2)** | Framing: encapsulates packets into frames |
| (iii) | Detect and correct errors | **Data link layer (2)** | Handles damaged/lost/duplicate frames (transport also ensures end-to-end reliability) |
| (iv) | Run HTTP, FTP, Telnet | **Application layer (7)** | Application-specific protocols |
