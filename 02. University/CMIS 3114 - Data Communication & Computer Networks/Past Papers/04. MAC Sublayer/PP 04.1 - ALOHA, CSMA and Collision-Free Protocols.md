## A. ALOHA vs CSMA (a different pair each year)

> **2019/20 Q7(a):** Compare and contrast Slotted Aloha and p-persistent CSMA techniques for wireless medium access.
> **2020/21 Q6(b):** Compare and contrast Pure Aloha and 1-persistent CSMA techniques for wireless medium access.
> **2021/22 Q7(a):** Compare and contrast *Slotted Aloha* and *p-Persistent CSMA* wireless transmission protocols.
> **2022/23 Q6(b):** Using diagrams, describe the similarities and differences in Pure Aloha and p-persistent CSMA techniques for wireless medium access.
> **2023/24 Q6(a):** Using diagrams, describe the similarities and differences in *Slotted Aloha* and *1-persistent CSMA* techniques for wireless medium access.

### Building blocks (learn all four)
- **Pure ALOHA:** transmit **whenever** there is data (no listening); the central station rebroadcasts so the sender knows if it succeeded; after a collision wait a **random time** and resend. Vulnerable period 2 frame times; max throughput ≈ **18%**.
- **Slotted ALOHA:** time divided into **slots** of one frame; transmit **only at the start of a slot**; collisions only within a slot; vulnerable period 1 frame time; max ≈ **37%**; needs synchronisation.
- **1-persistent CSMA:** **listen first**; if idle, send **immediately (probability 1)**; if busy, keep listening and send as soon as it becomes idle; on collision wait a random time. Problem: stations waiting for the same idle moment collide.
- **p-persistent CSMA** (slotted): listen; if idle, send **with probability p**, otherwise (q = 1 − p) **defer to the next slot** and repeat. Small p → few collisions, high throughput, more delay.

### Diagrams to draw
```text
Pure ALOHA (any time; overlaps destroy both)       Slotted ALOHA (slot boundaries)
A ▭      ▭                                         |  ▭  |     |  ▭  |     |
B    ▭▭  ← overlap = collision                     |     |  ▭▭ ← both in slot 2 collide
C        ▭       ▭                                 |     |     |     |  ▭  |
──────────────────► time                           ───────────────────────► time

1-persistent CSMA                                  p-persistent CSMA (slotted)
channel busy ████████│send at once                  busy █████│ slot: send with prob p
B, C both waiting → both send → collision           else defer to next slot, sense again
```

**Similarities (all pairs):** all are **random-access contention protocols** for a **shared broadcast channel**; all are **decentralised**; collisions can occur in all; all use a **random waiting time** before retransmitting after a collision; none needs a central controller.

## B. CSMA/CD states

> **2019/20 Q7(b):** The CSMA with Collision Detection (CD) is used for wireless data transmission. At a given time, the channel can be in any three of the following states, Transmission/Contention/Idle. Show the channel using a diagram and explain how this technique is implemented.
> **2023/24 Q6(b):** The CSMA/CD (Collision Detection) is used for wireless data transmission. At a given time, the channel can be in any three of the following states, Transmission/Contention/Idle. Show the channel using a diagram and explain how this technique is implemented.

### Expected answer
```text
        t0     contention slots
         ↓      ↓ ↓ ↓
 [ Frame ]  [][][]  [ Frame ]  [][][][]  [ Frame ]          [] [ Frame ]
 └Transmission┘└Contention┘                         └─Idle─┘
                                                          time →
```
1. **Idle:** no station has data; channel silent.
2. A station with data **senses** the channel; when idle it starts transmitting (time t₀).
3. While transmitting it **listens**; if the signal read back equals what it sends, there is no collision → **transmission period** until the frame ends.
4. If two stations start together, each detects that the signal is **different** (collision), **both stop immediately** (saving time), and the channel enters the **contention period**, divided into short **contention slots** (each ≥ the round-trip propagation time).
5. Each station waits a **random number of slots** (binary exponential backoff) and retries; the first to transmit alone wins and the channel returns to a **transmission period**.
6. When no station has data, the channel is **idle**.
*(Note: in practice CSMA/CD is used on wired Ethernet; wireless LANs use CSMA/CA with RTS/CTS because radios cannot detect collisions at the receiver.)*

## C. Collision detection vs collision-free

> **2021/22 Q7(b):** Describe the operation of collision detection in wireless protocols and collision free wireless protocols with their advantages and disadvantages.

### Expected answer
**Collision detection (CSMA/CD):** listen before and while transmitting; stop as soon as a collision is detected; random backoff; retry.
✅ simple, fully distributed, little overhead, low delay at light load. ❌ collisions still **waste bandwidth**; **variable delay** (bad for real-time voice); performance falls at heavy load; hard to detect collisions on wireless.

**Collision-free protocols:** decide **who transmits before** sending data, so data frames never collide:
- **Bit-map:** N contention slots, a station with data sets its bit; then stations send in order.
- **Token passing:** only the token holder may send (token ring/bus).
- **Binary countdown:** stations broadcast addresses bit by bit (ORed); highest address wins.
✅ **no collisions**, predictable delay, efficient at **heavy load**, fair (bit-map, token). ❌ **overhead** (1 bit/station for bit-map; token circulation; address bits), delay even at light load, token loss/duplication problems, binary countdown favours high addresses.

## D. Basic bit-map protocol

> **2022/23 Q6(c):** What is meant by a Collision free protocol? Explain the Basic bit-map protocol used for wireless communications.

### Expected answer
A **collision-free protocol** resolves contention **before** data transmission (reservation, token or address contest), so **no data frames collide**: collisions reduce bandwidth and make frame time variable, bad for real-time traffic such as VoIP.
**Basic bit-map:** N stations, addresses 0 … N−1. Each **contention period has N slots**; if station j has a frame, it transmits a **1 bit in slot j** (no one else may use that slot). After N slots **every station knows who wants to send**, and they transmit their frames **in numerical order**. Then a new contention period begins.
```text
 slots 0 1 2 3 4 5 6 7        frames
       - 1 - 1 - - - 1   →    [1] [3] [7]   → next contention period …
```
✅ no collisions, fair ❌ **1 bit/station overhead**; inefficient with many idle stations.

## E. Binary countdown

> **2019/20 Q7(c), 2022/23 Q6(d):** Consider that four wireless stations want to transmit data using the Binary countdown technique. The codes given to each station are 0001, 0101, 1000 and 1001. Using the given station codes, explain how this technique is implemented.

### Expected answer
Each station wanting the channel broadcasts its **address bit by bit, high-order bit first**; the channel **ORs** bits sent at the same time; a station that sends **0** but sees **1** gives up.

| Bit time | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 0001 | 0 | – | – | – |
| 0101 | 0 | – | – | – |
| 1000 | 1 | 0 | 0 | – |
| 1001 | 1 | 0 | 0 | 1 |
| **OR result** | **1** | **0** | **0** | **1** |

1. Bit 0: OR = 1 → **0001 and 0101 give up**.
2. Bit 1: 0 and 0 → OR = 0.
3. Bit 2: 0 and 0 → OR = 0.
4. Bit 3: 1000 sends 0, 1001 sends 1 → OR = 1 → **1000 gives up**.
5. **Station 1001 wins** (result 1001 = its address) and transmits. Losers try again in the next round (1000 next, then 0101, then 0001). Higher addresses have **priority**.
