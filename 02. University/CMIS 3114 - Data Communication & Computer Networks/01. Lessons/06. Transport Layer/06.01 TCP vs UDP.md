# 06.01 · TCP vs UDP

> [!info] [[06.00 Transport Layer|Lesson 6]] · Priority 🔴 High (asked 3/6 papers: 2019/20 Q3c, 2022/23 Q3b, 2023/24 Q3c)
> The **lecture definitions** are in [[01.16 TCP-IP Reference Model]] (Chapter 1 slides). This note adds textbook detail, clearly marked.

## 1. Lecture definitions (Chapter 1)
- **TCP:** *"a reliable connection oriented protocol that delivers a byte stream from one node to another. Guarantees delivery and provides flow control."* Fragments the byte stream into messages and reassembles them at the destination.
- **UDP:** *"an unreliable connection-less protocol for applications that provide their own connection establishment/reliability"*; used for *"one-shot, client-server-type request-reply queries and applications in which prompt delivery is more important than accurate delivery, such as transmitting speech or video."*

## 2. Ports *(additional explanation from the reference textbook)*
An IP address identifies a **host**; a **port number** (16 bits) identifies a **process** on that host. A connection is identified by (source IP, source port, destination IP, destination port). Well-known ports: HTTP 80, HTTPS 443, SMTP 25, DNS 53, FTP 21, Telnet 23.

## 3. Headers *(additional explanation)*

```text
 └──────────────┴──────────────┘         ├──────────────────────────────┤

                                         └──────────────────────────────┘
```

## 4. The comparison (exam answer)

| Feature | TCP | UDP |
|---|---|---|
| Connection | **Connection-oriented**: three-way handshake first | **Connectionless**: just send |
| Reliability | **Reliable**: ACKs, timeouts, retransmission | **Unreliable**: best effort, no ACKs |
| Ordering | **In-order** delivery using sequence numbers | No ordering |
| Data unit | **Byte stream** (no message boundaries); unit = segment | **Messages/datagrams** (boundaries preserved) |
| Flow control | **Yes** (receiver window) | No |
| Congestion control | **Yes** (slows down when the network is congested) | No |
| Header | 20 bytes minimum | **8 bytes** |
| Speed / overhead | Slower, more overhead | **Faster**, low overhead |
| Broadcast/multicast | No (one-to-one) | **Yes** |
| Used by | HTTP/HTTPS, SMTP, FTP, SSH/Telnet | **DNS**, DHCP, VoIP, video streaming, online games, SNMP |

**Similarities:** both are **transport-layer** protocols of the TCP/IP suite, both run **on top of IP**, both provide **process-to-process** delivery using **port numbers**, and both carry a **checksum** for error detection.

**When to use which:** choose **TCP** when every byte must arrive correctly and in order (web pages, e-mail, file downloads); choose **UDP** when **speed matters more than perfection** (a late voice sample is useless, so retransmitting it is pointless) or for one-shot queries (DNS).
