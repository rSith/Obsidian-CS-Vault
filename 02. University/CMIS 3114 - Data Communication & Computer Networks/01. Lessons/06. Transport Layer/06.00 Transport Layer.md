## What the transport layer does
- Provides **end-to-end (process-to-process)** communication between applications on two hosts. From the Ch1 OSI slides: it is *"a true end-to-end layer"*; it accepts data from above, splits it if needed, passes it to the network layer, and ensures the pieces **arrive correctly at the other end**; it hides the network from higher layers; it does **flow control**.
- Uses **port numbers** to deliver data to the right process (multiplexing many applications over one IP address).
- Offers two services in TCP/IP: **TCP** (reliable, connection-oriented byte stream) and **UDP** (unreliable connectionless datagrams).

## Quick revision
- **TCP:** connection-oriented, reliable, in-order byte stream; 3-way handshake (SYN, SYN-ACK, ACK); sequence numbers + ACKs + retransmission; **flow control** (receiver window); **congestion control** (slow start, AIMD).
- **UDP:** connectionless, no ACKs, no ordering, 8-byte header; fast; DNS, VoIP, streaming, games.
- **Flow control** protects the receiver; **congestion control** protects the network.
