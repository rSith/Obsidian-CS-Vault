# 07.02 · HTTP and the Web

> [!warning] Not in the available CMIS 3114 slides
> The Ch1 slides name **HTTP (the Web)** as an application-layer protocol and describe the Web as a **distributed system on top of the Internet**. Detail below is additional explanation from the reference textbook (Tanenbaum 6e §7.3). For more on HTTP methods and status codes, see your CMIS 3124 note [[02.04 HTTP Protocol]].

## 1. What is it?
**HTTP (HyperText Transfer Protocol)** is the **request–response** protocol between a **web browser (client)** and a **web server**. It follows the **client–server model** ([[01.04 Client-Server and Peer-to-Peer Models]]) and runs over **TCP** (port 80; **HTTPS** = HTTP over TLS on port 443). HTTP is **stateless**: each request is independent (cookies add state, see [[01.06 Social Issues of Computer Networks]]).

## 2. Request / response
```http
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256

<html> … </html>
```
Methods: **GET** (fetch), **POST** (send data), PUT, DELETE, HEAD… Status code families: **2xx** success (200 OK), **3xx** redirect (301), **4xx** client error (404 Not Found), **5xx** server error (500).

## 3. What happens when you open a web page (the whole stack)
1. **DNS:** the browser resolves `www.example.com` to an IP address ([[07.01 DNS]]).
2. **ARP / gateway:** the PC finds its default gateway's MAC address ([[05.10 ARP and DHCP (Beyond the Slides)]]).
3. **TCP connection:** three-way handshake to port 80/443 ([[06.02 TCP Connection Management]]).
4. **HTTP request** (GET) is sent: Application → Transport (TCP segment) → Network (IP packet) → Data link (frame) → Physical (bits) ([[01.17 OSI vs TCP-IP and the Hybrid Model]]).
5. **Routers** forward the packets hop by hop (store-and-forward, routing tables) ([[05.01 Network Layer Design Issues]]).
6. The **server** decapsulates, processes the GET, and returns an **HTTP response** with the HTML.
7. The browser **renders** the page, making further requests for images/CSS/JS (often on the same TCP connection).
8. The TCP connection is **closed** (FIN/ACK) or kept alive for reuse.
