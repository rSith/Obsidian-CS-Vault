# 05.02 · Datagram vs Virtual-Circuit Networks, Label Switching and MPLS

> [!info] [[05.00 Network Layer|Lesson 5]] · Lecture ref Ch5-L1 slides 5–10 · Priority 🟡 Medium (2/6 papers, same structure both times)
> **Asked as:** five routers A–E with hosts H1, H2: "To implement connectionless services in the network, describe how the routers build their routing tables and state the routing table for each router" · "If the link between routers A and D are broken, state the routing table entry changes" · "It is required to establish a virtual circuit between H1 and H2. ## 1. Two ways to implement the network service (lecture)

| | Connectionless | Connection-oriented |
|---|---|---|
| Setup | *"No advance setup is needed"* | *"A path from the source router to the destination router must be established **before** any data packets can be sent"* |
| Packets called | **Datagrams** | — |
| Network called | **Datagram network** | **Virtual-circuit (VC) network** |
| Example | **IP** | **MPLS** |

## 2. Datagram network (connectionless)
- Each packet carries the **full destination address** and is **routed independently**.
- Lecture figure: packets 1, 2, 3 follow the **same route**, but **packet 4 is sent on another route** (e.g. because A's table changed after congestion).
- Each router has a **routing table**: *destination → outgoing line*. Tables are built and updated by the **routing algorithm** ([[05.03 Routing Algorithms and the Sink Tree]]).

### How routers build their tables (exam explanation)
1. Each router knows its **directly connected neighbours** (and the cost of each link, e.g. 1 hop).
2. Using a routing algorithm (shortest path / distance vector), each router finds the **best (fewest hops) path** to every destination.
3. It stores only the **first hop (outgoing line)** for each destination: *"for destination X, send on line Y."*
4. When a packet arrives, the router does **forwarding**: look up the destination, send it out on that line.
5. If the topology changes (a link breaks), **adaptive** algorithms recompute and update the tables.

## 3. Virtual-circuit network (connection-oriented)
- Purpose: *"Avoid having to choose a **new route for every packet** sent."*
- *"When a connection is established, a route from the source machine to the destination machine is chosen as part of the **connection setup** and **stored in tables inside the routers**."* All packets of that connection then follow this route.
- Each packet carries a short **connection identifier (VC number / label)** instead of the full address.

### Lecture example: H1 and H3 both connect to H2
Network: H1 and H3 attach to router A; H2 is beyond router F. Route chosen: A → C → E → F.

| A's table: In | Out | C's table: In | Out | E's table: In | Out |
|---|---|---|---|---|---|
| H1, 1 | C, 1 | A, 1 | E, 1 | C, 1 | F, 1 |
| H3, 1 | C, **2** | A, 2 | E, 2 | C, 2 | F, 2 |

1. **H1 establishes connection 1 with H2.** This is remembered as the **first entry** in each router's table: at A, *"arriving from H1 with identifier 1 → send to C with identifier 1"*; C and E have matching entries.
2. **H3 also wants a connection to H2.** H3 also chooses identifier **1** (it doesn't know H1 used 1). Router A would now see two connections both labelled 1 going to C, so **A assigns a different connection identifier (2)** to the outgoing traffic of the second connection.
3. *"This process is called **label switching**."* Each router **replaces the incoming label with the outgoing label** when forwarding.

### MPLS (Multi-Protocol Label Switching)
- *"An example of a connection-oriented network service is **MPLS**."*
- Used **within ISP networks** in the Internet: IP packets are **wrapped in an MPLS header** with a **20-bit connection identifier (label)**.
- Often **hidden from customers**. The ISP sets up **long-term connections for large amounts of traffic**; also used when **quality of service** matters.

## 4. Comparison (lecture table, slide 9)

| Issue | Datagram network | Virtual-circuit network |
|---|---|---|
| Circuit setup | **Not needed** | **Required** |
| Addressing | Each packet contains the **full source and destination address** | Each packet contains a **short VC number** |
| State information | Routers **do not hold state** about connections | **Each VC requires router table space** per connection |
| Routing | **Each packet routed independently** | Route chosen when the VC is set up; **all packets follow it** |
| Effect of router failures | **None**, except packets lost during the crash | **All VCs that passed through the failed router are terminated** |
| Quality of service | **Difficult** | **Easy** if enough resources can be allocated in advance for each VC |
| Congestion control | **Difficult** | **Easy** if enough resources can be allocated in advance for each VC |
