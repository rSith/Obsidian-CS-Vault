## 1. What is subnetting?
**Lecture:** subnets *"allow the block of addresses to be **split into several parts for internal use as multiple networks**, while still **acting like a single network to the outside world**."* Example: a **campus network with LANs for various departments** (Art, English, French, Music, CS, EE, Math, Physics), each department LAN connected to a **main router** that connects to the ISP.

**Why:** separate LANs per department (less broadcast traffic, better security and management) while the ISP/Internet still sees one prefix (small routing tables).

## 2. How a subnet is formed
Borrow bits from the **host part** to make a **subnet part**:
```text
 Class B example (lecture: a class B network subnetted into 64 subnets)
 ┌────┬──────────────────────┬──────────┬────────────────┐
 │ 10 │   Network (14 bits)  │ Subnet 6 │   Host 10 bits │
 └────┴──────────────────────┴──────────┴────────────────┘
 Mask: 11111111.11111111.11111100.00000000 = 255.255.252.0 (/22)
 6 subnet bits → 2⁶ = 64 subnets; 10 host bits → 1024 addresses each (1022 hosts)
```

## 3. The method (largest block first)

**Inputs:** the address block (e.g. /24) and each subnet's requirement.

1. **Total available** addresses $= 2^{32-n}$ (e.g. /24 → 256).
2. For each requirement find the **block size** = the **smallest power of 2 that is large enough**:
   - if the question gives **addresses**, block ≥ addresses;
   - if it gives **hosts/computers/devices**, block ≥ hosts **+ 2** (network address + broadcast address). Count printers, servers and the router interface as hosts too.
3. **Sort the subnets from largest to smallest** (*"start with largest block first and so on"*).
4. **Prefix length** for each: $\text{prefix} = 32 - \log_2(\text{block size})$.
5. **Allocate** from the first address upward. Each block must **start at a multiple of its own size** (alignment); if it doesn't, skip to the next multiple.
6. For each subnet write:
   - **Network ID** = first address
   - **Broadcast address** = first address + block − 1
   - **Usable range** = network ID + 1 → broadcast − 1
   - **Subnet mask** (dotted decimal) from the prefix.
7. Check the total does not exceed the block; note any **unused** addresses.

$$
\text{block} = 2^{\lceil \log_2(\text{hosts}+2)\rceil}\qquad
\text{prefix} = 32 - \log_2(\text{block})\qquad
\text{usable hosts} = \text{block} - 2
$$

## 4. Lecture worked example
*"A university has a **14.24.74.0/24** IP address block which needs to be split into **10, 60 and 120** address blocks."*
- Available: $2^{32-24} = 256$; first 14.24.74.0, last 14.24.74.255.

| Order | Need | Allocate | Range | Prefix | Mask |
|---|---|---|---|---|---|
| 1 | 120 | **128** (not a power of 2 → round up) | 14.24.74.**0 – 127** | $32-\log_2 128 = $ **/25** | 255.255.255.**128** |
| 2 | 60 | **64** | 14.24.74.**128 – 191** | $32-\log_2 64 = $ **/26** | 255.255.255.**192** |
| 3 | 10 | **16** | 14.24.74.**192 – 207** | $32-\log_2 16 = $ **/28** | 255.255.255.**240** |

**208 addresses allocated; 48 still available (14.24.74.208 – 255).**

> [!warning] Typo on the lecture slide
> For the third block the slide writes *"Subnet mask /26 = 11111111.11111111.11111111.11110000 = 255.255.255.208"*. The binary shown is correct for **/28**, and 11110000 = **240**, so the mask is **/28 = 255.255.255.240**. (208 is the next free address, not the mask.)

## 5. Quick recipe for a /24 split (most past papers)
Block sizes in the last octet and where they can start:
| Block | Prefix | Mask (last octet) | Valid start values |
|---|---|---|---|
| 128 | /25 | 128 | 0, 128 |
| 64 | /26 | 192 | 0, 64, 128, 192 |
| 32 | /27 | 224 | 0, 32, 64, 96, 128, 160, 192, 224 |
| 16 | /28 | 240 | multiples of 16 |
| 8 | /29 | 248 | multiples of 8 |

> [!example] 192.168.1.0 into 100, 60, 30, 30 hosts (2021/22, 2023/24)
> 100+2 → 128 (/25) · 60+2 → 64 (/26) · 30+2 → 32 (/27) · 30+2 → 32 (/27). Total 256 = exactly the /24.
>
> | Hosts | Mask | Network | Usable range | Broadcast |
> |---|---|---|---|---|
> | 100 | 255.255.255.128 (/25) | 192.168.1.0 | .1 – .126 | 192.168.1.127 |
> | 60 | 255.255.255.192 (/26) | 192.168.1.128 | .129 – .190 | 192.168.1.191 |
> | 30 | 255.255.255.224 (/27) | 192.168.1.192 | .193 – .222 | 192.168.1.223 |
> | 30 | 255.255.255.224 (/27) | 192.168.1.224 | .225 – .254 | 192.168.1.255 |

## 6. Common mistakes
- Forgetting **+2** for hosts (30 hosts needs 32, not 30 → still /27; but 31 hosts needs 64).
- Allocating smallest first, which leaves misaligned gaps.
- Starting a block at a non-multiple of its size (e.g. a /26 at .32).
- Writing the broadcast as a usable host.
- Mask arithmetic: /26 → 192, /27 → 224, /28 → 240 (add 128, 64, 32, 16… left to right).
