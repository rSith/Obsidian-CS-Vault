# 05.06 · Distance Vector Routing

> [!info] [[05.00 Network Layer|Lesson 5]] · Lecture ref Ch5-L1 slide 18 · Priority 🟡 Medium (2/6 papers)
> **Asked as:** short note "Distance Vector Routing" (2020/21 Q8b(iv)) · "Distance Vector Routing is a popular routing protocol. Calculate the new estimated delays and the output line for the router J in the following network" (2023/24 Q8d), the lecture's own example.

## 1. What is it?
**Lecture:** *"Operates by having each router maintain a **table (i.e., a vector)** giving the **best known distance to each destination** and **which link to use** to get there."* Each entry has **two parts**: the **preferred outgoing line** for that destination and an **estimate of the distance (delay)** to it.

It is an **adaptive (dynamic)** algorithm (also called **Bellman-Ford**; used in the original ARPANET and in RIP: *textbook*).

## 2. How it works (step by step)
1. Each router knows the **cost (delay) to each directly connected neighbour** (e.g. by measuring with ECHO packets).
2. Periodically, every router **sends its whole distance vector to its neighbours** (not to the whole network).
3. When router J receives vectors from its neighbours, it computes, for **each destination D**:
$$
\boxed{\;D_J(\text{dest}) = \min_{\text{neighbour } X}\Big(\,\text{delay}(J \to X) + D_X(\text{dest})\Big)\;}
$$
4. The neighbour X giving the minimum becomes the **outgoing line** for D.
5. J **ignores its own old table** in the calculation and builds a completely new one; the process repeats so changes propagate through the network.

## 4. Advantages and disadvantages
| Advantages | Disadvantages |
|---|---|
| **Simple**; each router talks only to neighbours | **Slow convergence**: bad news (a link failure) spreads slowly |
| Adapts to topology and traffic changes | **Count-to-infinity problem** *(textbook)*: after a failure, routers can keep increasing distances via each other |
| Little memory: one vector per neighbour | Whole vectors exchanged periodically → overhead in big networks |

For **Distance Vector vs Link State**, see [[05.04 Shortest Path Routing]].

## 5. Common mistakes
- Adding the **neighbour's distance to J** instead of J's measured delay to the neighbour.
- Forgetting the **J → J = 0, line "–"** entry.
- Using J's old table.
