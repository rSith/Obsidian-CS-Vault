# 05.03 · Routing Algorithms, the Optimality Principle and the Sink Tree

## 1. What is a routing algorithm?
*"Part of the network layer software responsible for **deciding which output line** an incoming packet should be transmitted on."*

A router has **two main tasks**:
| Task | What it does |
|---|---|
| **Forwarding** | Handles **each packet as it arrives**, looking up the outgoing line in the **routing table** |
| **Routing (the algorithm)** | **Filling in and updating** the routing tables |

**Desirable properties:** **correctness, simplicity, robustness** (cope with failures and topology changes without rebooting), **stability** (converge to fixed routes), **fairness, efficiency**.

## 2. Two classes

| | Non-adaptive / static | Adaptive / dynamic |
|---|---|---|
| Based on measurements? | **No**: decisions *"do not base their routing decisions on any measurements or estimates of the current topology and traffic"* | **Yes**: change decisions to reflect **changes in topology** and sometimes **traffic** |
| When computed | *"Computed in advance, offline, and downloaded to the routers when the network is booted"* | Continuously, while running |
| Example | Static routes configured by an administrator | **Distance vector**, link state |
| Pros / cons | Simple, no overhead; cannot react to failures | Robust; adds control traffic and complexity |

## 3. The optimality principle
> [!warning] Slide wording
> The slide's sentence under "Optimality principle" reads *"Routes are set up without regard to network topology or traffic,"* which actually describes static routing. The **textbook statement** of the principle is:
> *"If router J is on the optimal path from router I to router K, then the optimal path from J to K also falls along the same route."*
> (If there were a better route from J to K, you could use it to improve the I→K path, contradicting that the I→K path was optimal.)

## 4. The sink tree
- *"As a direct consequence of the optimality principle, the **set of optimal routes from all sources to a given destination form a tree rooted at the destination**."* This is the **sink tree**.
- *"Distance metric is the number of hops."*
- *"The goal of all routing algorithms is to **discover and use the sink trees** for all routers."*
- A sink tree has **no loops**, so each packet reaches the destination in a finite number of hops.
- It is **not necessarily unique**: when two routes have the same hop count, either may be chosen.

### How to draw a sink tree (algorithm = breadth-first search from the destination)
1. Put the **destination router** (e.g. B) at the root: level 0.
2. Level 1 = all routers **directly connected** to it.
3. Level 2 = routers connected to a level-1 router that are not yet in the tree; draw an edge to **one** level-1 parent.
4. Continue level by level until every router is included.
5. **Keep only one parent per router** (the tree must not have loops). Where two parents give the same hop count, pick either and say "equal-cost alternative".
6. Write the hop count next to each router (optional but helpful).

### Lecture example: (a) a subnet, (b) a sink tree for router B
The slide shows a 15-router subnet (A–O) and its sink tree rooted at **B**: every other router's optimal (fewest-hop) path to B is drawn, and the result has no cycles.

### Mini example
```text

                                           E (0)
```
