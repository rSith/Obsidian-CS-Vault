# 01.12 · Design Issues for the Layers

> [!info] [[01.00 Introduction|Lesson 1]] · Lecture ref Ch1 §1.3 (slides 97–100) · Priority 🟢 Low (1/6 papers)
> **Asked as:** "List and describe four design issues of protocol layers" (2020/21 Q3b)

## 1. What is it?
Every layer must solve some common problems. The lecture lists **seven design issues**. Each later chapter shows *how* a particular layer solves them, so this note is a map of the whole course.

## 2. The seven issues

| # | Issue | Lecture explanation | Where you meet it later |
|---|---|---|---|
| 1 | **Addressing** | Multiple destinations ⇒ some form of addressing is needed to **identify senders/receivers**, so a process on one machine can talk to a process on another | MAC address ([[04.01 Channel Allocation Problem]]), IP address ([[05.08 IP Addresses and Classful Addressing]]) |
| 2 | **Error control** | Needed because the physical medium is **not perfect**: **error detection, error correction, message reordering** | [[03.04 Error Detection - Parity, Interleaving and Checksum]], [[03.07 Hamming Code]] |
| 3 | **Quality of Service (QoS)** | Dealing with **real-time traffic** (video call, live score): how much delay, what video resolution? | 802.11 QoS scheduling ([[04.06 IEEE 802.11 WiFi]]), virtual circuits ([[05.02 Datagram and Virtual-Circuit Networks]]) |
| 4 | **Flow control** | *"Sender shouldn't overwhelm (swamp) the receiver."* Solutions: number the pieces with **feedback** from the receiver, or limit the sender to an **agreed transmission rate** | [[03.03 Error Control and Flow Control]] |
| 5 | **Multiplexing** | Multiplexing/de-multiplexing: **several connections use one logical channel**; allocate bandwidth based on demand (**statistical muxing**) | [[02.06 Multiplexing - FDM, OFDM, WDM and TDM]] |
| 6 | **Routing** | **Select a path** between source and destination | [[05.03 Routing Algorithms and the Sink Tree]] |
| 7 | **Message size** | Processes cannot accept arbitrarily long messages ⇒ **disassemble, transmit, reassemble**; very small messages are inefficient ⇒ **gather several small messages** to the same destination into one large message and split it at the other side | IP fragmentation ([[05.07 IPv4 Header]]), layer 3 splitting M into M1/M2 ([[01.11 Protocol Hierarchies and Encapsulation]]) |

> [!note] Slide wording
> On the slide the sentence about *"number the pieces, feedback from the receiver… agreed-on transmission rate"* is printed under **Addressing**, but it describes **flow control** (the textbook places it there). It is listed under flow control above.

## 3. Exam relevance
- 🟢 Asked once. If asked for four: **addressing, error control, flow control, routing** are the easiest to explain with examples.
