# 01.11 · Protocol Hierarchies, Message Flow and Encapsulation

> [!info] [[01.00 Introduction|Lesson 1]] · Lecture ref Ch1 §1.3 (slides 84–96) · Priority 🟡 Medium (3/6 papers)
> **Asked as:** "Describe how a message from a sender machine would travel through the multiple layers to a receiver machine assuming that the protocol consists of five layers. Write any reasonable assumptions…" (2018/19 Q3c, 2021/22 Q3c) · "A host is communicating with another host via two routers… using the ISO reference model. Draw a diagram clearly indicating the physical and virtual communication…" (2020/21 Q3c, 2021/22 Q3d) · "Describe how a message would travel from one host to the other through the routers" (2020/21 Q3d)

## 1. Key vocabulary (lecture)

| Term | Lecture meaning |
|---|---|
| **Layer** | Performs specific actions; **implements a service** to the layer above, **relying on services** of the layers below |
| **Peers** | *"The entities comprising the corresponding layers on different machines."* **It is the peers that communicate using the protocol.** |
| **Protocol** | Each layer has its own; a level on one host talks to the **same level on another host** (its peer) |
| **Interface** | *"Defines the services that one layer offers another."* Must be **simple and clean** |
| **Service** | *"A set of primitives (operations) that a layer provides to the layer above it."* |
| **Physical medium** | Underneath layer 1: the wire, fibre, etc. where **actual** communication happens |
| **Virtual communication** | Layer n ↔ layer n on another machine (drawn **dotted**) |
| **Physical communication** | Down through the layers, across the medium, up the other side (drawn **solid**) |
| **Network architecture** | *"A set of layers and protocols."* Specifies what each layer does and says to its peer; **implementation details and interfaces are not part of the spec** |
| **Protocol stack** | *"A list of protocols used by a system, one protocol per layer."* |

*"In reality, no data are directly transferred from layer n on one machine to layer n on another machine. Instead, each layer passes data and control information to the layer immediately below it, until the lowest layer is reached."*

**Advantages of clean interfaces:** minimise the information passed between layers, and make it simpler to **replace the implementation of one layer** with a completely different one.

Information flow is thought of as *"Send_to_peer" rather than "call_next_layer_down"*.

## 2. Message through the layers (the 5-layer example)

```text
Layer 5   M                                        M
Layer 4   H4 M                                     H4 M
Layer 3   H3 H4 M1 │ H3 M2                       H3 H4 M1 │ H3 M2
Layer 2   H2 H3 H4 M1 T2 │ H2 H3 M2 T2            (same)
Layer 1   ──────── bits on the physical medium ────────►
          Source machine                           Destination machine
```

### Step by step at the sender (encapsulation)
1. **Layer 5** (application process) produces message **M** and gives it to layer 4.
2. **Layer 4** puts a **header H4** in front of M to identify the message (e.g. **sequence numbers** so the destination's layer 4 can deliver messages **in order** if the lower layers do not maintain sequence; headers may also carry sizes, times and other control fields). Passes **H4 + M** to layer 3.
3. **Layer 3** has a **size limit** (layer 4 usually has none), so it **breaks the message into smaller packets M1 and M2**, prepending a **layer-3 header H3** to each. Layer 3 **decides which outgoing line to use** and passes the packets to layer 2.
4. **Layer 2** adds a **header H2 and a trailer T2** to each piece and gives the resulting unit (frame) to layer 1.
5. **Layer 1** physically transmits the bits.

### At the receiver (decapsulation)
The message moves **upward**, layer by layer, with **headers stripped off** as it goes. *"None of the headers for layers below n are passed up to layer n."* Layer 3 reassembles M1 and M2, layer 4 checks the sequence number, and layer 5 receives the original M.

### Sender vs receiver (lecture slide 94)
| On the sender, each layer | On the receiver, each layer |
|---|---|
| Accepts an outgoing message from the layer above | Receives an incoming message from the layer below |
| **Adds a header** for that layer and does other processing | **Removes the header** for that layer and does other processing |
| Passes the result to the next **lower** layer | Passes the result to the next **higher** layer |

### "Reasonable assumptions" to write (2018/19, 2021/22)
- Layer 4 has **no size limit**; layer 3 has a **maximum packet size**, so it fragments M.
- Lower layers **may not keep order**, so layer 4 adds sequence numbers.
- Layer 2 adds a **trailer** (e.g. checksum for error detection, see [[03.02 Framing]]).
- Layer 1 has **no header**; it just transmits bits.

## 3. Encapsulation with real PDU names (additional explanation)

| Layer (hybrid model) | Adds | Data unit (PDU) |
|---|---|---|
| Application | Application data (e.g. HTTP request) | **Message / data** |
| Transport | TCP/UDP header (ports, sequence numbers) | **Segment** (TCP) / datagram (UDP) |
| Network | IP header (source/destination IP) | **Packet / datagram** |
| Data link | Frame header (MAC addresses) + **trailer** (CRC) | **Frame** |
| Physical | — | **Bits** |

The lecture names the TCP/IP transport unit a **segment** and the network unit a **datagram**; the DLL unit a **frame** ([[03.01 Functions and Services of the Data Link Layer]]).

## 4. Host → router → router → host (2020/21 Q3c/d, ISO model)

Routers only need the **lower three OSI layers** (physical, data link, network), because they forward packets; **hosts** run all **seven** layers.

```text
    Host A            Router 1          Router 2            Host B
 ┌─────────────┐                                        ┌─────────────┐
 │7 Application│ · · · · · · · · · · · · · · · · · · · ·│7 Application│
 │6 Presentation · · · · · · · · · · · · · · · · · · · ·│6 Presentation
 │5 Session    │ · · · · · · · · · · · · · · · · · · · ·│5 Session    │
 │4 Transport  │ · · · · · · · · · · · · · · · · · · · ·│4 Transport  │
 │3 Network    │ · · ·│3 Network │ · · │3 Network │ · · ·│3 Network    │
 │2 Data link  │ · · ·│2 Data link · · │2 Data link · · ·│2 Data link  │
 │1 Physical   │──────│1 Physical│─────│1 Physical│──────│1 Physical   │
 └─────────────┘      └──────────┘     └──────────┘      └─────────────┘
   · · ·  virtual (peer) communication       ───  physical communication
```

- **Layers 4–7 are end-to-end:** the transport, session, presentation and application peers are on the two **hosts** only (*"the transport layer is a true end-to-end layer"*).
- **Layers 1–3 are hop-by-hop:** each host or router talks to its **immediate neighbour**.
- **Physical path:** Host A goes down 7→1, across the link to Router 1, **up to layer 3** (which decides the next hop), back down to layer 1, across to Router 2, up to 3 and down, across to Host B, and **up 1→7**.

**How a message travels (2020/21 Q3d), step by step:**
1. Host A's application creates the message; each layer 7→2 adds its header (layer 2 also a trailer); layer 1 sends the bits.
2. **Router 1** receives the bits, its layer 2 checks the frame (error check), strips the frame header, and passes the packet to layer 3.
3. Router 1's network layer reads the **destination address**, looks up its **routing table**, chooses the outgoing line, and passes the packet down; layer 2 builds a **new frame** for the next link (**store-and-forward**).
4. **Router 2** repeats steps 2–3.
5. **Host B** receives the frame, and each layer 1→7 strips its own header and passes the data up until the application receives the original message.

**2021/22 Q3(d) variant: "addressing is done in layer 2" (5-layer model).** If forwarding decisions use **layer-2 addresses**, the intermediate devices only need **layers 1 and 2** (they behave like **switches/bridges**). Draw hosts with layers 1–5, intermediate devices with layers 1–2; virtual links between layer-2 peers on each hop, and layers 3–5 virtual end-to-end between the hosts.
