# 01.17 · OSI vs TCP/IP, Critiques, and the Hybrid 5-Layer Model

> [!info] [[01.00 Introduction|Lesson 1]] · Lecture ref Ch1 §1.4 (slides 146–157) · Priority 🔴 High (3/6 incl. 2023/24)
> **Asked as:** "Contrast the OSI reference model with the TCP/IP reference model using a diagram to show the correspondence between relevant protocol layers" (2019/20 Q3d) · "Compare and differentiate the OSI and the TCP/IP reference models, using a diagram…" (2022/23 Q3c) · "Using illustrations compare ISO-OSI with TCP/IP reference model" (2023/24 Q3d)

## 1. Correspondence diagram (draw this)

```text
        OSI (7)                     TCP/IP (4)           Hybrid (5, used in this course)
 ┌──────────────────┐        ┌────────────────────┐     ┌──────────────────┐
 │ 7 Application    │        │                    │     │ 5 Application    │
 │ 6 Presentation   │ ─────► │   Application      │ ──► │                  │
 │ 5 Session        │        │                    │     │                  │
 ├──────────────────┤        ├────────────────────┤     ├──────────────────┤
 │ 4 Transport      │ ─────► │   Transport        │ ──► │ 4 Transport      │
 ├──────────────────┤        ├────────────────────┤     ├──────────────────┤
 │ 3 Network        │ ─────► │   Internet         │ ──► │ 3 Network        │
 ├──────────────────┤        ├────────────────────┤     ├──────────────────┤
 │ 2 Data link      │ ─────► │   Host-to-network  │ ──► │ 2 Link           │
 │ 1 Physical       │        │   (not defined)    │     │ 1 Physical       │
 └──────────────────┘        └────────────────────┘     └──────────────────┘
```
**Explanation:** OSI's top three layers collapse into TCP/IP's single application layer (TCP/IP has **no session or presentation** layers). Transport ↔ transport, network ↔ internet. OSI's data link and physical layers sit inside TCP/IP's **undefined host-to-network** layer.

## 2. Comparison table

| Point | OSI | TCP/IP |
|---|---|---|
| Number of layers | **7** | **4** |
| Common layers | Both have **(inter)network, transport and application** layers; the others differ | |
| Basis | Both are a **stack of independent protocols**; functionality of layers is **roughly similar** | |
| Service / interface / protocol | **Clearly distinguished**: services = what a layer does; interfaces = how processes above access it; protocols = hidden internals (fits **object-oriented** ideas) | Did **not originally clearly distinguish** them |
| Protocol replacement | Protocols **better hidden**, can be **replaced relatively easily** as technology changes | Minor protocols deeply entrenched, **hard to replace** |
| Order of creation | **Model first**, protocols later → model **general**, not biased to one protocol set | **Protocols first**; the model was **just a description** of existing protocols → fits TCP/IP perfectly but **no other stacks** |
| Network layer modes | **Connectionless and connection-oriented** | **Connectionless only** (IP) |
| Transport layer modes | **Connection-oriented only** | **Both** (TCP and UDP), *"giving the users a choice"* |
| Lower layers | Physical and data link defined | Host-to-network **"not really a layer"**; physical/data link not mentioned |
| Use today | Model still valid for teaching; **protocols rarely used** | **Protocols used everywhere** (the Internet); model of little use |

## 3. Why OSI did not take over the world (lecture)
1. **Bad timing**: TCP/IP was already in use when OSI arrived.
2. **Bad technology**: the choice of seven layers was *"more political than technical"*; **session and presentation are nearly empty**, **data link and network are overfull**; functions like addressing, flow control and error control **reappear in every layer**.
3. **Bad implementations**: *"huge, unwieldy, and slow."*
4. **Bad politics.**

## 4. Problems with the TCP/IP model (lecture)
- Service, interface and protocol **not distinguished**.
- **Not a general model**: only good for describing TCP/IP.
- **Host-to-network "layer" is not really a layer**.
- **No mention of physical and data link layers**.
- Minor protocols **deeply entrenched**, hard to replace.
- Good software engineering separates specification from implementation; *"OSI does very carefully, and TCP/IP does not."* So TCP/IP is *"not much of a guide for designing new networks using new technologies."*

## 5. The hybrid model (lecture slide 157)

| Layer | Job | Example protocols |
|---|---|---|
| **Application** | Supporting network applications | FTP, SMTP (HTTP, DNS) |
| **Transport** | Host-to-host data transfer | TCP, UDP |
| **Network** | Routing of datagrams from source to destination | IP, routing protocols |
| **Link** | Data transfer between **neighbouring** network elements | PPP, Ethernet |
| **Physical** | Bits "on the wire" | Cables, signals |

The rest of the course follows this model: Physical (Ch 2) → Data link + MAC (Ch 3–4) → Network (Ch 5) → Transport (Ch 6) → Application (Ch 7).

## 6. Data flowing down and up the stack (encapsulation example)

> [!example] You open `www.example.com` (additional explanation)
> **Down at your PC:** Application builds an HTTP GET → Transport adds a **TCP header** (port 80, sequence number) = segment → Network adds an **IP header** (your IP, server IP) = packet → Link adds an **Ethernet/WiFi header + CRC trailer** = frame → Physical sends **bits**.
> **Across the Internet:** each router strips the frame, reads the IP header, chooses the next hop, re-frames and forwards.
> **Up at the server:** Physical → Link (check CRC, strip frame) → Network (check IP address, strip) → Transport (reorder, ACK, strip) → Application receives the GET and returns the page.
