# 03.01 · Functions and Services of the Data Link Layer

> [!info] [[03.00 Data Link Layer|Lesson 3]] · Lecture ref Ch3-L1 slides 2–10 · Priority 🔴 High (5/6 papers)
> **Asked as:** "Describe two main functions of the Data Link Layer of the OSI reference model" (2019/20 Q6a, 2022/23 Q5a) · "Describe two main responsibilities…" (2023/24 Q5a) · "Describe two services provided to the Network layer by the Data link layer" (2020/21 Q5a, 2021/22 Q5a)

## 1. Main functions (lecture)
*"The data link layer uses the services of the physical layer to send and receive bits over communication channels."* Its main functions:
1. **Provide a service interface to the network layer**: well-defined services so the network layer can hand over packets.
2. **Deal with transmission errors**: detect (and possibly correct) damaged, lost and duplicated frames.
3. **Regulate data flow**: *"slow receivers not swamped by fast senders"* (**flow control**).

The tools used for these:
- **Framing:** *"The data link layer takes the packets it gets from the network layer and **encapsulates them into frames** for transmission."* (header + payload + trailer) → [[03.02 Framing]]
- **Error control** and **flow control** → [[03.03 Error Control and Flow Control]]

Note from the lecture: errors are also handled by transport and other protocols. *"Reliability is an overall goal, and it is achieved when all the layers work together."* The DLL does *"the minimal job that is 'good enough'"* ⇒ a **best-effort** service.

## 2. Services provided to the network layer
*"The principal service is transferring data from the network layer on the **source** machine to the network layer on the **destination** machine."* The lecture figure shows (a) **virtual communication** (network layer ↔ network layer, dotted) and (b) **actual communication** (down through the DLL and physical layer, across the wire, and up).

### 1. Unacknowledged connectionless service (e.g. **Ethernet**)
- **No logical connection** is established beforehand or released afterwards.
- **No acknowledgements**: if a frame is lost due to noise, **no attempt is made to detect or recover** in the DLL.
- Appropriate when the **error rate is very low** (recovery is left to higher layers), and for **real-time traffic such as voice**, *"in which late data are worse than bad data."*

### 2. Acknowledged connectionless service (e.g. **802.11 WiFi**)
- No logical connection, but **each frame is individually acknowledged**.
- The sender knows whether a frame arrived or was lost; if it has not arrived within a specified time, it is **sent again**.
- Useful over **unreliable channels such as wireless**.

### 3. Acknowledged connection-oriented service (e.g. **satellite channels, long-distance telephone circuits**)
Three distinct **phases**:
1. **Connection established**: both sides initialise variables and counters to track which frames have been received.
2. **Frames transmitted**: each frame is **numbered**, and the DLL guarantees each frame is **received exactly once** and **in the right order**.
3. **Connection released**: variables, buffers and other resources are freed.

Appropriate over **long, unreliable links**. Without numbering, **lost acknowledgements** *"could cause a frame to be sent and received several times, wasting bandwidth."*

### Comparison

| Service | Connection? | ACKs? | Order / exactly once | Best for | Example |
|---|---|---|---|---|---|
| Unacknowledged connectionless | No | No | No | Low-error links, real-time voice | **Ethernet** |
| Acknowledged connectionless | No | **Yes**, per frame | No guarantee of order | Unreliable (wireless) links | **802.11 WiFi** |
| Acknowledged connection-oriented | **Yes** (3 phases) | Yes | **Yes**: each frame exactly once, in order | Long, unreliable links | **Satellite**, long-distance telephone circuits |

**Placement:** the data link protocol runs **between two DLL processes** in the routers on each link (the lecture shows the DLL protocol between routers along a path).
