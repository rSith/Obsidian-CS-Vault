# 03.04 · Error Types, Detection vs Correction, Parity, Interleaving and Checksum

(2018/19 Q5a) · "Using a suitable example, describe a technique that uses the Parity to detect burst errors… What is the maximum detectable burst error length?" (2020/21 Q5c) · "…how a parity bit can be used to detect 1-bit transmission errors. Also explain how parity bit can be used to detect burst errors" (2022/23 Q5c)

## 1. Types of transmission errors (lecture)
| Type | Cause | Handling |
|---|---|---|
| **Single-bit errors** (isolated) | *"Extreme values of thermal noise that overwhelm the signal briefly and occasionally"* | Easy to **detect and correct** without retransmission |
| **Burst errors** | Errors *"come in bursts rather than singly"* (e.g. a lightning spike, fading) | May **only be detected** and will **require retransmission** |

Error rates differ: **fibre** has tiny error rates; **wireless links and aging local loops** have rates orders of magnitude larger. *"Transmission errors are here to stay."*

## 2. Two strategies: detection vs correction

| | Error detection | Error correction (FEC) |
|---|---|---|
| Idea | Include **only enough redundancy** for the receiver to deduce **that** an error occurred (not which) and **request retransmission** | Include **enough redundancy** for the receiver to deduce **what the data must have been** |
| Codes | Error-**detecting** codes: parity, checksum, CRC | Error-**correcting** codes: Hamming code (**forward error correction, FEC**) |
| Overhead | **Low** (few redundant bits) | **High** (many check bits) |
| Best for | Reliable channels with **occasional** errors (fibre) | Noisy channels where retransmission is costly (wireless, satellite, memory) |
| Needs return channel? | Yes (to ask for resend) | No |

*"Error detection is more efficient for dealing with the occasional errors… the receiver may request a retransmission."*

**Codeword (definition):** *"An n-bit unit containing data and check bits is referred to as an n-bit codeword."* → [[03.06 Codewords and Hamming Distance]]

## 3. Parity
- *"A single **parity bit** is appended to the data. The parity bit is chosen so that the **number of 1 bits in the codeword is even (or odd)**."*
- **Lecture example:** `1011010` (four 1s)
  - **Even parity** → append **0** → `10110100`
  - **Odd parity** → append **1** → `10110101`
- *"Any single-bit error produces a codeword with the wrong parity"* → **detects single-bit errors** (in fact any **odd** number of errors).
- **Limitation:** two errors (any even number) cancel out and go **undetected**; with a long burst, detection probability is only about **½**.

### 1-bit error detection example (2022/23 Q5c)
Send `1011010` with even parity → `10110100`. Bit 3 flips in transit → received `10010100` (three 1s = odd) → the receiver's even-parity check **fails** → error detected, ask for retransmission.

## 4. Parity for burst errors: interleaving (2018/19, 2020/21, 2022/23)
**Lecture:** regard each block as a **rectangular matrix n bits wide and k bits high**. *"Send one parity bit for each row; up to k bit errors will be reliably detected as long as there is **at most one error per row**."* **Interleaving:** *"compute the parity bits over the data in a **different order** than the order in which the data bits are transmitted. Attach the parity bits as a trailer."*

### How it works (step by step)
1. Arrange the data in a matrix of **k rows × n columns**.
2. Compute **one parity bit per column** (n parity bits), giving a parity row.
3. **Transmit the data row by row** (in the normal order), then the **parity row as a trailer**.
4. A burst of length ≤ n consecutive bits hits each column **at most once**, so **every affected column's parity fails** → the burst is detected.

### Worked example (even parity, k = 4 rows, n = 7 columns)
```text
            c1 c2 c3 c4 c5 c6 c7
 Row 1:      1  0  0  1  1  0  1
 Row 2:      1  1  0  0  1  0  1
 Row 3:      0  1  1  1  0  0  0
 Row 4:      1  0  1  0  1  1  0
 Parity:     1  0  0  0  1  1  0      ← sent as a trailer after the data
 Transmitted order: row1 row2 row3 row4 parity  (7 bits at a time)
```
A noise burst of **7 bits** starting at row 2, column 4 flips row 2 c4–c7 and row 3 c1–c3: **each column is hit exactly once**, so all seven column parities fail → error **detected**.

### Maximum detectable burst length
$$
\text{Max burst length reliably detected} = n = \text{number of parity bits (columns)}
$$
A burst longer than n can hit the same column twice (two flips cancel), so it might pass. For bursts longer than n (or several bursts), each column has about a ½ chance of catching it, so detection probability is $1 - 2^{-n}$. The lecture's equivalent statement: with one parity bit per row, **up to k errors** are detected if at most one error falls in each row (i.e. bits are sent column by column).

**Answer pattern:** *matrix → parity per column → transmit row by row → burst ≤ n changes at most one bit per column → detected; max burst = n (the width / number of parity bits).*

## 5. Checksum
- *"A group of check bits associated with a message, regardless of how they are calculated."* Usually placed at the **end** of the message.
- Errors are detected by **summing the entire received codeword** (data + checksum); **if the result is zero, no error** is detected.

### 16-bit Internet checksum: lecture worked example
Data to send: `0x3456, 0xABCC, 0x02BC, 0xEEEE`

**Sender:**
1. Add all 16-bit words: `3456 + ABCC + 02BC + EEEE = 1 D1CC` (a carry out of 16 bits).
2. **Wrap around** the carry: `D1CC + 1 = D1CD` (one's complement addition).
3. **Complement**: `FFFF − D1CD = 2E32` → **checksum = 0x2E32**.
4. Send the data **and** the checksum.

**Receiver:**
1. Add all words **including the checksum**: `3456 + ABCC + 02BC + EEEE + 2E32 → FFFF` (after wrap-around).
2. Complement: `FFFF − FFFF = 0000` → **zero ⇒ no error detected**.

**Why it is weak** *(textbook):* it cannot detect reordered words or two errors that cancel; CRC is stronger.
