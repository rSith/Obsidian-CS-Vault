# 03.06 · Codewords and Hamming Distance

> [!info] [[03.00 Data Link Layer|Lesson 3]] · Lecture ref Ch3-L2 slides 13–19 · Priority 🔴 High (3/6 papers incl. 2023/24)
> **Asked as:** "Describe with an example, the concept of Hamming Distance" (2021/22 Q5c, 2023/24 Q5d) · "Assume that datawords the size of two bits are sent using Hamming code technique. Show that the following list of codewords can correct one bit errors: 00→00000, 01→01011, 10→10101, 11→11110" (2021/22 Q5d)

## 1. Codewords and code rate
- A frame has **m data (message) bits** and **r redundant (check) bits**; total length **n = m + r**.
- *"An n-bit unit containing data and check bits is referred to as an **n-bit codeword** or **(n, m) codeword**."*
- **Code rate** = fraction of the codeword that is useful information:
$$\text{code rate} = \frac{m}{n}$$
- Rates vary: about **½ for a noisy channel** (half the bits are redundant), **close to 1 for a high-quality channel**.

## 2. Hamming distance
**Lecture:** *"The number of bit positions in which two codewords differ is called the **Hamming distance**."* To find it, **XOR the two codewords and count the 1s**.

> [!example] Example
> ```text
>   10001001
> ⊕ 10110001
>   --------
>   00111000   → three 1s → Hamming distance d = 3
> ```
> Significance: *"if two codewords are a Hamming distance d apart, it will require **d single-bit errors to convert one into the other**."*

**High or low distance — which is better?** **Higher.** The further apart the legal codewords are, the more bit errors are needed to turn one legal codeword into another, so more errors can be detected/corrected.

## 3. Distance of a complete code
Given the rule for computing check bits, list all **legal codewords**; the **smallest** Hamming distance between any two of them is the **Hamming distance of the code**.

**Sparseness:** all $2^m$ data messages are legal, but only $2^m$ of the $2^n$ possible n-bit words are legal codewords, i.e. a fraction $2^m/2^n = 1/2^r$. *"It is the **sparseness** with which the message is embedded in the space of codewords that allows the receiver to detect and correct errors."*

## 4. Detection and correction rules

$$
\boxed{\text{To detect } d \text{ errors: distance } d+1}
\qquad
\boxed{\text{To correct } d \text{ errors: distance } 2d+1}
$$

- **Detect d:** with distance d + 1, *"there is no way that d single-bit errors can change a valid codeword into another valid codeword"*, so the receiver sees an **illegal** codeword.
- **Correct d:** with distance 2d + 1, *"the legal codewords are so far apart that even with d changes the original codeword is still **closer than any other** codeword"*, so the receiver picks the **nearest** legal codeword (assuming fewer errors are more likely).

| Code distance D | Detects up to | Corrects up to |
|---|---|---|
| 2 | 1 | 0 |
| 3 | 2 | **1** |
| 4 | 3 | 1 |
| 5 | 4 | **2** |

$$\text{detect} = D - 1,\qquad \text{correct} = \left\lfloor \tfrac{D-1}{2} \right\rfloor$$

### Lecture example: four valid codewords
`0000000000, 1111100000, 0000011111, 1111111111` → minimum distance **5**.
- **Detects up to 4** errors (5 = 4 + 1). **Corrects up to 2** errors (5 = 2·2 + 1).
- Received `0000000111`, expecting at most double errors → nearest codeword is **`0000011111`** (distance 2).
- *"It is not possible to both detect 4-bit errors and correct 2-bit errors"* at the same time.

## 5. Worked: 2021/22 Q5(d)
Codewords: 00→`00000`, 01→`01011`, 10→`10101`, 11→`11110`. Compute every pairwise distance (XOR and count 1s):

| Pair | XOR | Distance |
|---|---|---|
| 00000 – 01011 | 01011 | 3 |
| 00000 – 10101 | 10101 | 3 |
| 00000 – 11110 | 11110 | 4 |
| 01011 – 10101 | 11110 | 4 |
| 01011 – 11110 | 10101 | 3 |
| 10101 – 11110 | 01011 | 3 |

**Minimum distance of the code = 3.** To correct d errors needs $2d + 1 \le 3 \Rightarrow d = 1$. **So the code can correct any single-bit error** (and detect up to 2).

*Demonstration:* send `01011`; bit 1 flips → received `11011`. Distances: to `00000` = 4, to `01011` = **1**, to `10101` = 3, to `11110` = 2. Nearest is `01011` → corrected to data **01**.
