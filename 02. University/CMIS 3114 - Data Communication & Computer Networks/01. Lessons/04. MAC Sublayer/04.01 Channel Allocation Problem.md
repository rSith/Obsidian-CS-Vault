# 04.01 · DLL = LLC + MAC, and the Channel Allocation Problem

> [!info] [[04.00 MAC Sublayer|Lesson 4]] · Lecture ref Ch4 slides 2–7 · Priority 🟢 Low (foundation for all MAC questions)

## 1. DLL = LLC + MAC
- *"The Data Link Layer is divided into two sublayers: the **LLC (Logical Link Control)** sublayer and the **MAC (Media Access Control)** sublayer. **LLC deals with the Network Layer** while **MAC has access to the Physical Layer**."*
- *"The MAC sublayer (IEEE 802.3) specifies the physical **MAC address** that identifies a device on a network."* (A 48-bit hardware address such as `00:1A:2B:3C:4D:5E`; used by switches; see [[05.10 ARP and DHCP (Beyond the Slides)]].)
- Technically, *"the MAC sublayer is the **bottom part** of the data link layer."*

```text
 Network layer
 ┌──────────────── Data link layer ────────────────┐
 │ LLC  (interface to network layer, flow/error)    │
 │ MAC  (who may use the shared medium; MAC address)│
 └──────────────────────────────────────────────────┘
 Physical layer
```

## 2. Broadcast / multi-access channels
- The MAC sublayer deals with **broadcast links** and their protocols. Broadcast channels are also called **multi-access** or **random access** channels.
- Especially important in **wireless LANs**.
- **Main problem:** *"how to allocate a **single broadcast channel among competing users**."* The channel may be a portion of the wireless spectrum, or a single wire/fibre with many nodes.

## 3. Static channel allocation
- **Total bandwidth divided into equal parts** among the users (**TDM/FDM/WDM**, see [[02.06 Multiplexing - FDM, OFDM, WDM and TDM]]).
- ✅ **No interference** among users; good for **constant data flow** (e.g. a fixed number of radio stations).
- ❌ **Not useful for dynamic load and a changing number of users**: if a user is idle its share is wasted; if more users arrive than slots, they are refused. Computer traffic is **bursty**, so static allocation is inefficient.

## 4. Dynamic channel allocation: five key assumptions
1. **Independent traffic:** N independent stations each generate frames for transmission.
2. **Single channel:** one channel is available for all communication.
3. **Observable collisions:** if two frames overlap in time the result is garbled (a **collision**), and **all stations can detect** that a collision occurred.
4. **Continuous or slotted time:** transmission can begin at any instant (continuous), or only at the start of discrete slots (slotted).
5. **Carrier sense or no carrier sense:** stations may or may not be able to tell whether the channel is busy before trying to use it.

These assumptions define the protocols that follow: ALOHA (no carrier sense; continuous or slotted) → CSMA (carrier sense) → CSMA/CD (observable collisions).

**Contention system:** *"Systems in which multiple users share a common channel in a way that can lead to conflicts."*
