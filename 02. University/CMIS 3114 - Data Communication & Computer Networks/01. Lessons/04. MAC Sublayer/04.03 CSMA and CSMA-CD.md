# 04.03 · CSMA (1-, Non-, p-Persistent) and CSMA/CD

> [!info] [[04.00 MAC Sublayer|Lesson 4]] · Lecture ref Ch4 slides 11–15 · Priority 🔴 High
> **Asked as:** ALOHA vs a CSMA variant (5/6 papers) · "The CSMA with Collision Detection (CD) is used for wireless data transmission. At a given time, the channel can be in any three of the following states, Transmission/Contention/Idle. Show the channel using a diagram and explain how this technique is implemented" (2019/20 Q7b, 2023/24 Q6b) · "Describe the operation of collision detection in wireless protocols and collision free wireless protocols with their advantages and disadvantages" (2021/22 Q7b)

## 1. Carrier sense
*"Protocols in which stations **listen for a carrier** (i.e., a transmission) and act accordingly are called **carrier sense protocols**."* CSMA = **Carrier Sense Multiple Access**: listen before you talk.

## 2. The three CSMA variants (lecture)

### 1-persistent CSMA
1. Listen to the channel.
2. If **idle**, send **with probability 1** (immediately).
3. If **busy**, **keep listening (persist)** until it becomes idle, then send immediately.
4. If a **collision** occurs, wait a **random time** and start over.
- ❌ If two stations are waiting for the same busy period to end, **both send at once → collision** guaranteed.

### Non-persistent CSMA
1. Sense the channel.
2. If **idle**, transmit.
3. If **busy**, **do not keep listening**: wait a **random time**, then sense again.
- ✅ *"Better channel utilization"*; ❌ *"longer delays than 1-persistent CSMA."*

### p-persistent CSMA (used on **slotted** channels)
1. When ready, sense the channel.
2. If **idle**, transmit **with probability p**; with probability **q = 1 − p** **defer to the next slot**.
3. In the next slot, if still idle, repeat (transmit with probability p, defer with q).
4. If the channel becomes busy, act as if a collision occurred (wait random time, start again) *(textbook detail)*.
- Small p (e.g. 0.01) → **fewer collisions, high throughput** at heavy load, but more delay at light load.

### Utilisation (lecture graph)
At high load: **0.01-persistent CSMA ≈ 1.0**, non-persistent ≈ 0.9, 0.1-persistent ≈ 0.8, 0.5-persistent and 1-persistent lower (peak ~0.5–0.55), slotted ALOHA ~0.37, pure ALOHA ~0.18.

## 3. CSMA/CD: CSMA with Collision Detection
**Lecture:**
- *"The station's hardware must **listen to the channel while it is transmitting**."*
- *"If the signal it reads back is **different from the signal it is putting out**, it knows that a **collision** is occurring, then **both stations will stop transmission**,"* and **repeat after a random period of time**.
- CSMA/CD can be in one of **three states: contention, transmission, or idle.**

### The channel-states diagram (draw this)
```text
            t0          contention slots
            ↓            ↓ ↓ ↓ ↓
 ┌───────┐ ┌─┐┌─┐┌─┐ ┌───────┐ ┌─┐┌─┐┌─┐┌─┐ ┌───────┐           ┌─┐ ┌───────┐
 │ Frame │ │ ││ ││ │ │ Frame │ │ ││ ││ ││ │ │ Frame │           │ │ │ Frame │
 └───────┘ └─┘└─┘└─┘ └───────┘ └─┘└─┘└─┘└─┘ └───────┘           └─┘ └───────┘
 └Transmission┘└Contention┘                                └─Idle period─┘
   period         period                                                  time →
```

### How it is implemented (step by step)
1. **Idle:** no station has data; the channel is quiet.
2. A station with a frame **senses** the channel (carrier sense). If idle, it starts transmitting at $t_0$.
3. While sending it **listens** to the channel. If what it reads back equals what it sends → no collision → the **transmission period** continues until the frame ends.
4. If two or more stations start together, they **detect the collision** within a short time, **abort immediately** (saving the rest of the frame time), and the channel enters the **contention period**: a series of short **contention slots**.
5. Each colliding station waits a **random** number of slots (textbook: **binary exponential backoff**, doubling the range after each collision) and tries again.
6. Eventually one station wins a contention slot and starts its **transmission period**; when all are done, the channel returns to **idle**.

The **minimum contention slot** must be long enough for a signal to travel to the farthest station and back ($2\tau$, twice the propagation delay) so that a collision is always noticed *(textbook)*.

> [!warning] Exam wording vs reality
> The past papers say "CSMA/CD is used for **wireless** data transmission". In practice **CSMA/CD is used on wired Ethernet**: a radio cannot easily listen while it transmits (its own signal drowns the receiver), and collisions happen **at the receiver**, which the sender may not hear (hidden terminals). Wireless LANs use **CSMA/CA** with RTS/CTS ([[04.05 Hidden and Exposed Terminals and MACA]]). Answer the question as asked (the three-state diagram), and you may add this one-line note.

## 4. Comparisons asked in the papers

### Slotted ALOHA vs p-persistent CSMA (2019/20, 2021/22)
| | Slotted ALOHA | p-persistent CSMA |
|---|---|---|
| Carrier sense | **No**: sends at the next slot regardless | **Yes**: listens first |
| Time | Slotted | Slotted |
| Decision | Send at slot start if you have a frame | If idle, send with prob. **p**, else defer to next slot |
| Collisions | Frequent at high load | Fewer (only stations that sense idle together and both "win" p) |
| Max throughput | ~37% | Much higher (close to 100% for small p) |
| Delay at light load | Low | Higher for small p (stations defer) |
**Similarities:** both are **contention** protocols for a shared broadcast channel; both use **slotted time**; both use **random retransmission** after a collision; neither prevents collisions completely.

### Pure ALOHA vs 1-persistent CSMA (2020/21)
| | Pure ALOHA | 1-persistent CSMA |
|---|---|---|
| Listen first | No | **Yes** |
| When to send | Any time | When the channel goes idle, **immediately** (prob. 1) |
| Collisions | Any overlap | Mainly when several stations wait for the same idle moment, or due to propagation delay |
| Throughput | ~18% | Better (~50% peak) |

### Pure ALOHA vs p-persistent CSMA (2022/23)
Pure ALOHA: no sensing, continuous time, ~18%. p-persistent: sensing + probability p per slot, slotted, high throughput. Both random-access contention protocols with random backoff.

### Slotted ALOHA vs 1-persistent CSMA (2023/24)
Slotted ALOHA: no sensing, transmit at slot start, ~37%. 1-persistent: sense, send at once when idle (greedy) → collisions when several wait. Similarities: contention, random retry, shared channel.

**Diagrams to draw:** an ALOHA timeline with overlapping frames (see [[04.02 ALOHA]]) and a CSMA timeline where a station waits for the busy frame to end, then sends.

### Collision detection vs collision-free protocols (2021/22 Q7b)
| | Collision detection (CSMA/CD) | Collision-free (bit-map, token, binary countdown) |
|---|---|---|
| Idea | Allow collisions, **detect** and abort quickly, retry randomly | **Prevent** collisions by reserving or ordering access |
| ✅ | Simple, decentralised, low delay at **light load** | **No wasted collisions**, predictable delay (good for **real-time**/VoIP), high efficiency at **heavy load** |
| ❌ | Collisions **waste bandwidth**, delay **variable**, poor at heavy load; hard on wireless | **Overhead** (bit-map: 1 bit/station; token management; contention bits), delay even at light load; token loss problems |
See [[04.04 Collision-Free Protocols]].

### CSMA/CD vs CSMA/CA *(textbook)*
| CSMA/CD | CSMA/CA |
|---|---|
| Wired Ethernet (802.3) | Wireless LAN (802.11) |
| **Detects** collisions during transmission, aborts | **Avoids** collisions: random backoff before sending, optional **RTS/CTS** reservation, ACK for every frame |
| Sender can listen while sending | Radio can't detect collisions at the receiver |
