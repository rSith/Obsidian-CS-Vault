# 04.04 · Collision-Free Protocols: Bit-Map, Token Passing, Binary Countdown

> [!info] [[04.00 MAC Sublayer|Lesson 4]] · Lecture ref Ch4 slides 17–20 · Priority 🟡 Medium (3/6 papers; binary countdown **identical** in 2019/20 and 2022/23)
> **Asked as:** "Consider that four wireless stations want to transmit data using the Binary countdown technique. The codes given to each station are 0001, 0101, 1000 and 1001. Using the given station codes, explain how this technique is implemented" (2019/20 Q7c, 2022/23 Q6d) · "What is meant by a Collision free protocol? Explain the Basic bit-map protocol used for wireless communications" (2022/23 Q6c) · collision detection vs collision-free (2021/22 Q7b)

## 1. Why collision-free?
Lecture: collisions **adversely affect system performance**: they **reduce bandwidth** and make the **time to send a frame variable**, *"which is not good for real-time traffic such as voice over IP."* A **collision-free protocol** resolves who sends **before** anyone transmits data, so data frames never collide.

## 2. The basic bit-map protocol
**Lecture:**
- Exactly **N stations**, each with a unique address **0 to N − 1**.
- Each **contention period has exactly N slots**. If station j has a frame to send, it transmits a **1 bit during slot j**. *"No other station is allowed to transmit during this slot."*
- After all N slots, **every station knows which stations want to send**. They then send their frames **in numerical order**.
- **Disadvantage: 1 bit per station overhead** (wasteful with many idle stations).

```text
 Contention period 1         Data frames      Contention period 2        Data frames
 slot: 0 1 2 3 4 5 6 7                        slot: 0 1 2 3 4 5 6 7
 bit:  - 1 - 1 - - - 1   →   [1] [3] [7]      bit:  - 1 - - - 1 - -   →  [1] [5]
 (1 = "I have a frame"; - = empty slot)
```
*(Lecture example: in the first period stations 1, 3 and 7 set their bits, then send frames 1, 3, 7 in order; in the next period stations 1 and 5; then 2.)* This is a **reservation** protocol.

## 3. Token passing
- *"Pass a small message called a **token** from one station to the next in the **same predefined order**."*
- *"If a station has a frame queued for transmission when it receives the token, it can send that frame **before it passes the token** to the next station. If it has no queued frame, it simply passes the token."*
- **Token ring** (stations in a physical ring; IEEE 802.5, [[01.09 Network Classification by Scale]]) and **token bus** (logical ring on a bus).

## 4. Binary countdown
**Lecture:**
- A station wanting the channel **broadcasts its address as a binary bit string, starting with the high-order bit**. All addresses have the **same length**.
- Bits sent at the same time by different stations are **Boolean ORed** together by the channel.
- *"As soon as a station sees that a high-order bit position that is **0 in its address has been overwritten with a 1**, it **gives up**."*
- Result: the station with the **highest address wins**. (Lecture example: 0010, 0100, 1001, 1010 → result **1010**; 0010 and 0100 give up at bit 0, 1001 gives up at bit 2.)

### Worked: stations 0001, 0101, 1000, 1001 (2019/20, 2022/23)

| Bit time | 0 (MSB) | 1 | 2 | 3 (LSB) |
|---|---|---|---|---|
| Station **0001** | 0 | — | — | — |
| Station **0101** | 0 | — | — | — |
| Station **1000** | 1 | 0 | 0 | — |
| Station **1001** | 1 | 0 | 0 | 1 |
| **Channel (OR)** | **1** | **0** | **0** | **1** |

Step by step:
1. **Bit 0:** stations send 0, 0, 1, 1 → OR = **1**. Stations **0001** and **0101** had 0 but see 1 → **give up** (dash = silence afterwards).
2. **Bit 1:** remaining 1000 and 1001 send 0, 0 → OR = **0**. Nobody gives up.
3. **Bit 2:** both send 0 → OR = **0**. Nobody gives up.
4. **Bit 3:** 1000 sends 0, 1001 sends 1 → OR = **1**. Station **1000** sees its 0 overwritten → **gives up**.
5. **Winner: station 1001** (the highest address). Result string = **1001**. It transmits its frame; then a new countdown starts and the losers compete again (next 1000, then 0101, then 0001 if all keep wanting to send).

**Property:** higher-numbered stations get **priority**; efficiency is good because only $\log_2 N$ bits of overhead are used per contention (vs N for the bit-map).

## 5. Comparison
| | Bit-map | Token passing | Binary countdown |
|---|---|---|---|
| How the sender is chosen | Reservation bit in its own slot | Whoever holds the token | Highest address in the OR contest |
| Overhead per round | **N bits** | Token circulation | **$\log_2 N$ bits** |
| Fairness | Fair (numerical order) | Fair (round robin) | **Unfair**: high addresses favoured |
| Weakness | Overhead with many stations | Lost/duplicate token, adding stations | Priority bias |
