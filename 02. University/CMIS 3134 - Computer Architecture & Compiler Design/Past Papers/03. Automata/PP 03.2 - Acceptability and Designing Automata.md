## 2019/20 · Q3(d) and 2020/21 · Q3(d) (40 marks)
> **Question:** Consider the following finite automaton and check whether the following strings are acceptable or not. Show each step. i. bba ii. bab iii. abbabcba iv. cbacabab v. cababbabaacc

**The automaton (from the diagram):** start **A**, final **D**.

| State | a | b | c |
|---|---|---|---|
| → A | {A} | **{A, B}** | {A} |
| B | {C} | {A} | {A} |
| C | {C} | {D} | {A} |
| \* D | {D} | {D} | {D} |

> [!important] This machine is an NDFA
> A has a self-loop on a, b, c **and** an arrow A –b→ B, so on input b, A can go to A **or** B. Say this in your answer and trace with **sets of states** (or show an accepting path).
> Reaching D requires the path **B –a→ C (–a→ C)\* –b→ D**, entered from A on b. So **a string is accepted iff it contains a substring "b a…a b" (b, one or more a's, b)**. Use this to check your work.

> [!warning] Correction to the earlier study guide
> The earlier Exam Lab traced `bba` as accepted (δ(B,b) = C, δ(C,a) = D). Those transitions are not in this diagram (B on b goes back to A; C on a loops to C). **bba is rejected.**
> Also note the fifth string: the paper prints **cababbabaacc** (your earlier topic map wrote "cabbbabaacc"). Both are accepted.

### Expected answer
Acceptance rule: S is accepted iff $\delta^*(A, S)$ contains the final state D.

| String | Set-of-states trace | Result |
|---|---|---|
| `bba` | {A} -b→ {A,B} -b→ {A,B} -a→ {A,C} | ❌ Rejected (D never reached) |
| `bab` | {A} -b→ {A,B} -a→ {A,C} -b→ {A,B,D} | ✅ Accepted |
| `abbabcba` | {A} -a→ {A} -b→ {A,B} -b→ {A,B} -a→ {A,C} -b→ {A,B,D} -c→ {A,D} -b→ {A,B,D} -a→ {A,C,D} | ✅ Accepted |
| `cbacabab` | {A} -c→ {A} -b→ {A,B} -a→ {A,C} -c→ {A} -a→ {A} -b→ {A,B} -a→ {A,C} -b→ {A,B,D} | ✅ Accepted |
| `cababbabaacc` | {A} -c→ {A} -a→ {A} -b→ {A,B} -a→ {A,C} -b→ {A,B,D} -b→ {A,B,D} -a→ {A,C,D} -b→ {A,B,D} -a→ {A,C,D} -a→ {A,C,D} -c→ {A,D} -c→ {A,D} | ✅ Accepted |

**Accepting paths:**
- bab: A –b→ B –a→ C –b→ **D**
- abbabcba: A –a→ A –b→ A –b→ B –a→ C –b→ **D** –c→ D –b→ D –a→ D
- cbacabab: A –c→ A –b→ A –a→ A –c→ A –a→ A –b→ B –a→ C –b→ **D**
- cababbabaacc: A –c→ A –a→ A –b→ B –a→ C –b→ **D** –b→ D –a→ D –b→ D –a→ D –a→ D –c→ D –c→ D

**Why bba is rejected:** after "bb" the machine can be only in A or B; reading a from B gives C and from A gives A; the string ends in {A, C}, which contains no final state.

### Key points to include
- Transition table first · state that the machine is non-deterministic · full step-by-step trace for each string · explicit verdict with the reason.

### How to approach this question
At 40 marks (≈8 per string), presentation and completeness matter: one line per symbol, verdict on its own line.

## 2021/22 · Q4(d) (40 marks)
> **Question:** Consider the following finite automaton and check whether the following strings are acceptable. Show each step of your workout. i. bba ii. aababbbbcba iii. cbacabbb iv. cababbaba

**The automaton (changed from earlier years: B –b→ C):**

| State | a | b | c |
|---|---|---|---|
| → A | {A} | {A, B} | {A} |
| B | ∅ | **{A, C}** | {A} |
| C | {C} | {D} | {A} |
| \* D | {D} | {D} | {D} |

Both A (on b) and B (on b) are non-deterministic. D is reached only via B –b→ C (–a→ C)\* –b→ D, so a string is accepted iff it contains **"b b a…a b"** with zero or more a's in the gap (i.e. bb a\* b).

### Expected answer
| String | Set-of-states trace | Result |
|---|---|---|
| `bba` | {A} -b→ {A,B} -b→ {A,B,C} -a→ {A,C} | ❌ Rejected |
| `aababbbbcba` | {A} -a→ {A} -a→ {A} -b→ {A,B} -a→ {A} -b→ {A,B} -b→ {A,B,C} -b→ {A,B,C,D} -b→ {A,B,C,D} -c→ {A,D} -b→ {A,B,D} -a→ {A,D} | ✅ Accepted |
| `cbacabbb` | {A} -c→ {A} -b→ {A,B} -a→ {A} -c→ {A} -a→ {A} -b→ {A,B} -b→ {A,B,C} -b→ {A,B,C,D} | ✅ Accepted |
| `cababbaba` | {A} -c→ {A} -a→ {A} -b→ {A,B} -a→ {A} -b→ {A,B} -b→ {A,B,C} -a→ {A,C} -b→ {A,B,D} -a→ {A,D} | ✅ Accepted |

Accepting paths:
- aababbbbcba: A –a→ A –a→ A –b→ A –a→ A –b→ A –b→ B –b→ C –b→ **D** –c→ D –b→ D –a→ D
- cbacabbb: A –c→ A –b→ A –a→ A –c→ A –a→ A –b→ B –b→ C –b→ **D**
- cababbaba: A –c→ A –a→ A –b→ A –a→ A –b→ B –b→ C –a→ C –b→ **D** –a→ D

### How to approach this question
Notice the changed arrow (B –b→ C instead of B –a→ C). Re-draw the table before tracing.

## 2022/23 · Q4(d) (40 marks)
> **Question:** Consider the following finite automaton and check whether the following strings are acceptable. Show each step of your workout. i. abaaab ii. babbbba iii. bbbaaabab iv. abababbba

**The automaton (a DFA):** start A, final C.

| State | a | b |
|---|---|---|
| → A | B | A |
| B | B | C |
| \* C | B | A |

(This DFA accepts exactly the strings ending with "ab"; it is the same machine as 2019/20 Q5(c), see [[08.03 Finite Automaton to Regular Expression]].)

### Expected answer
| String | Trace | Result |
|---|---|---|
| `abaaab` | A -a→ B -b→ C -a→ B -a→ B -a→ B -b→ C | ✅ Accepted (C ∈ F) |
| `babbbba` | A -b→ A -a→ B -b→ C -b→ A -b→ A -b→ A -a→ B | ❌ Rejected (B ∉ F) |
| `bbbaaabab` | A -b→ A -b→ A -b→ A -a→ B -a→ B -a→ B -b→ C -a→ B -b→ C | ✅ Accepted |
| `abababbba` | A -a→ B -b→ C -a→ B -b→ C -a→ B -b→ C -b→ A -b→ A -a→ B | ❌ Rejected |

### Key points to include
- Table · δ\*(A, S) ∈ F rule · full traces · verdict with final state named.

## 2019/20 · Q4(b) (20 marks)
> **Question:** Design an NDFA that recognizes the language of all strings containing only a's and b's where there are at least 4 a's and begin with b.

**Lesson:** [[03.06 Non-deterministic Finite Automaton (NDFA)]]

### Expected answer
| State | a | b | Meaning |
|---|---|---|---|
| → q0 | ∅ | {q1} | must start with b |
| q1 | {q2} | {q1} | 0 a's seen |
| q2 | {q3} | {q2} | 1 a |
| q3 | {q4} | {q3} | 2 a's |
| q4 | {q5} | {q4} | 3 a's |
| \* q5 | {q5} | {q5} | ≥ 4 a's |

5-tuple: Q = {q0,…,q5}, Σ = {a,b}, q0, F = {q5}. Tests: baaaa ✅, bbabaaba ✅ (4 a's), aaaab ❌ (starts with a: no move from q0), baaab ❌ (3 a's).

## 2020/21 · Q4(c) (20 marks)
> **Question:** Design a NDFA that recognizes the language of all strings over {a, b}, in which the second last symbol is always 'a'.

### Expected answer
| State | a | b |
|---|---|---|
| → q0 | {q0, q1} | {q0} |
| q1 | {q2} | {q2} |
| \* q2 | ∅ | ∅ |

q0 reads any prefix; on an a it may "guess" that this is the second-last symbol and go to q1; exactly one more symbol reaches q2. Accepted if at least one path ends in q2. Tests: ab ✅, aa ✅, bbab ✅, ba ❌, abb ❌.

## 2019/20 · Q4(c) (20 marks)
> **Question:** Construct a DFA that accepts any strings over {0, 1} that does not contain the string "01011" anywhere in it.

### Expected answer
Build "contains 01011", then make q5 a dead state and all other states final:

| State (prefix matched) | 0 | 1 | Final |
|---|---|---|---|
| → q0 (ε) | q1 | q0 | ✔ |
| q1 (0) | q1 | q2 | ✔ |
| q2 (01) | q3 | q0 | ✔ |
| q3 (010) | q1 | q4 | ✔ |
| q4 (0101) | q3 | q5 | ✔ |
| q5 (dead) | q5 | q5 | ✘ |

Tests: ε ✅, 0101 ✅, 1010 ✅, 01011 ❌, 0010110 ❌.

## 2020/21 · Q4(d) (40 marks)
> **Question:** Construct a DFA, i. that accepts any strings over {x, y} that do not contain the string "xyxyy" anywhere in it. ii. that accepts any strings over {0, 1} with an even number of 1's. iii. that accepts any strings over {a, b, c} that contain the string "acb" anywhere in it. iv. that accepts any strings over {a, b} that contain the string "aababb" as a substring

### Expected answer
**(i) Not containing xyxyy** (q5 = dead; q0–q4 final)

| State | x | y |
|---|---|---|
| → q0 (ε) | q1 | q0 |
| q1 (x) | q1 | q2 |
| q2 (xy) | q3 | q0 |
| q3 (xyx) | q1 | q4 |
| q4 (xyxy) | q3 | q5 |
| q5 (dead) | q5 | q5 |

**(ii) Even number of 1s**

| State | 0 | 1 |
|---|---|---|
| → \*E (even) | E | O |
| O (odd) | O | E |

**(iii) Contains acb**

| State | a | b | c |
|---|---|---|---|
| → q0 | q1 | q0 | q0 |
| q1 (a) | q1 | q0 | q2 |
| q2 (ac) | q1 | q3 | q0 |
| \* q3 (acb) | q3 | q3 | q3 |

**(iv) Contains aababb**

| State | a | b |
|---|---|---|
| → q0 (ε) | q1 | q0 |
| q1 (a) | q2 | q0 |
| q2 (aa) | q2 | q3 |
| q3 (aab) | q4 | q0 |
| q4 (aaba) | q2 | q5 |
| q5 (aabab) | q1 | q6 |
| \* q6 (aababb) | q6 | q6 |

Key fall-backs: q2 on a stays q2 ("aaa" ends in "aa"); q4 on a → q2 ("aabaa" ends in "aa"); q5 on a → q1 ("aababa" ends in "a").

### Key points to include
- Diagram + table for each · label state meanings · two test strings each.

## 2022/23 · Q5(d) (40 marks)
> **Question:** Construct a DFA that, i. Accepts all strings over {a, b, c} that start with "abc". ii. Accepts all strings over {p, q} that do not contain the substring "pqp" anywhere. iii. Accepts all strings over {0, 1} with an even number of 0s and an odd number of 1s. iv. Accepts all strings over {0, 1} ending with "111" with at least four symbols.

### Expected answer
**(i) Starts with abc** (D = dead)

| State | a | b | c |
|---|---|---|---|
| → q0 | q1 | D | D |
| q1 (a) | D | q2 | D |
| q2 (ab) | D | D | q3 |
| \* q3 (abc…) | q3 | q3 | q3 |
| D | D | D | D |

**(ii) Not containing pqp** (q3 dead; q0, q1, q2 final)

| State | p | q |
|---|---|---|
| → q0 (ε) | q1 | q0 |
| q1 (p) | q1 | q2 |
| q2 (pq) | q3 | q0 |
| q3 (dead) | q3 | q3 |

**(iii) Even 0s and odd 1s** (state = parity of 0s, parity of 1s)

| State | 0 | 1 |
|---|---|---|
| → EE | OE | EO |
| \* EO | OO | EE |
| OE | EE | OO |
| OO | EO | OE |

**(iv) Ends with 111, at least four symbols**

| State | 0 | 1 | Meaning |
|---|---|---|---|
| → q0 | q1 | q1 | nothing read |
| q1 | q1 | q2 | ≥1 symbol read, no trailing 1s counted |
| q2 | q1 | q3 | ≥2 symbols, ends in 1 |
| q3 | q1 | q4 | ≥3 symbols, ends in 11 |
| \* q4 | q1 | q4 | ≥4 symbols, ends in 111 |

The first symbol (q0 → q1) is "spent" so that 111 alone is rejected and 1111 is accepted. Tests: 0111 ✅, 1111 ✅, 111 ❌, 01110 ❌.

## 2023/24 · Q4(d) (40 marks)
> **Question:** An ATM accepts a PIN that: contains only digits {0,1}; must start with 1; must end with 0; must contain an even number of 1s; can be of any length greater than or equal to 3 digits. i. Construct a DFA that accepts only valid PINs. ii. Test whether the following strings are accepted. Show all steps. 1. 10 2. 110110 3. 110 4. 11011

**Lesson:** [[03.10 Designing DFAs]]

### Expected answer
States record (parity of 1s, last symbol); length ≥ 3 is automatically satisfied by any string that starts with 1, ends with 0 and has an even (so ≥ 2) number of 1s.

| State (meaning) | 0 | 1 |
|---|---|---|
| → q0 (start) | qD | qO1 |
| qO1 (odd 1s, last 1) | qO0 | qE1 |
| qO0 (odd 1s, last 0) | qO0 | qE1 |
| qE1 (even 1s, last 1) | qE0 | qO1 |
| \* qE0 (even 1s, last 0) | qE0 | qO1 |
| qD (dead) | qD | qD |

**(ii) Tests:**
1. `10`: q0 –1→ qO1 –0→ qO0. **Rejected** (odd number of 1s; also only 2 digits).
2. `110110`: q0 –1→ qO1 –1→ qE1 –0→ qE0 –1→ qO1 –1→ qE1 –0→ qE0. **Accepted**.
3. `110`: q0 –1→ qO1 –1→ qE1 –0→ qE0. **Accepted**.
4. `11011`: q0 –1→ qO1 –1→ qE1 –0→ qE0 –1→ qO1 –1→ qE1. **Rejected** (ends with 1).

### Key points to include
- State meanings · full table/diagram · the four traces with the failing condition named.

## 2023/24 · Q5(d) (40 marks)
> **Question:** An online registration system allows usernames consisting of {a, b}. Conditions: Must contain exactly two 'a's. Any number of 'b's allowed. Order does not matter. i. Construct a DFA. ii. Modify the DFA in part i to accept usernames with at least two 'a's instead of exactly two. Explain the changes made to accommodate the new condition.

### Expected answer
**(i) Exactly two a's:** a state counts the a's; b never changes the count.

| State | a | b |
|---|---|---|
| → q0 (0 a's) | q1 | q0 |
| q1 (1 a) | q2 | q1 |
| \* q2 (2 a's) | q3 | q2 |
| q3 (≥3 a's, dead) | q3 | q3 |

Tests: aa ✅, babba ✅, a ❌, aaba ❌.

**(ii) At least two a's:**

| State | a | b |
|---|---|---|
| → q0 | q1 | q0 |
| q1 | q2 | q1 |
| \* q2 | **q2** | q2 |

**Change:** the transition q2 –a→ q3 becomes **q2 –a→ q2**, and the dead state q3 is removed. "Exactly two" must reject a third a (a trap state is needed), while "at least two" accepts any further a's, so q2 becomes an accepting sink. The DFA shrinks from 4 to 3 states. Tests: aaa ✅, abaab ✅, ab ❌.
