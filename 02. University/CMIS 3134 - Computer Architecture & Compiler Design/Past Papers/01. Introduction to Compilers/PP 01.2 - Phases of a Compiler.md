## 2019/20 · Q1(c) (20 marks)
> **Question:** Briefly explain the use of having a **Symbol Table** in compilers.

**Lesson:** [[01.10 Symbol Table and Error Handler]]

### Expected answer
- A symbol table is a **data structure maintained throughout all the phases** of a compiler (Theory Notes 1).
- It stores **all identifier names along with their types** (and other attributes such as scope and memory location).
- **Uses:**
  - lets the compiler **quickly search and retrieve** an identifier's record;
  - **scope management**: tells which declaration a name refers to in each block;
  - supports **semantic analysis**: type checking, checking that identifiers are declared before use;
  - supports **code generation**: memory and register allocation for identifiers.
- It is not a phase itself; it is shared by all phases (drawn beside the phase diagram, like the error handler).

### Key points to include
- Data structure across all phases · names + types · fast search/retrieval · scope management · one example use.

### How to approach this question
Definition plus 3–4 uses. A tiny example table (name | type | scope) helps.

## 2019/20 · Q2(a), 2021/22 · Q2(b), 2022/23 · Q2(b) (20 marks) and 2020/21 · Q1(d) (40 marks)
> **Questions:** "List down the main steps of the **compilation process**." (2019/20) · "What are the main phases of the **compilation process**?" (2021/22, 2022/23) · "Explain the phases of a **compiler** with a suitable diagram." (2020/21, 40 marks)

**Lesson:** [[01.07 Phases of a Compiler]]

### Expected answer
The compilation process is a sequence of phases; each phase takes input from the previous phase and feeds its output to the next.

```text
Source code
   ↓  1. Lexical Analysis         (characters → tokens <token-name, attribute-value>)
   ↓  2. Syntax Analysis          (tokens → parse tree; checks grammar)
   ↓  3. Semantic Analysis        (parse tree → annotated syntax tree; types, declarations)
   ↓  4. Intermediate Code Gen.   (code for an abstract machine)
   ↓  5. Code Optimization        (remove unnecessary code, reorder statements)
   ↓  6. Code Generation          (→ re-locatable target machine code)
Target code
Symbol Table and Error Handler: connected to ALL phases
```

For the 40-mark version, explain each phase:
1. **Lexical analysis:** text scanner; converts the character stream into lexemes and represents them as tokens; removes whitespace/comments; detects invalid tokens.
2. **Syntax analysis (parsing):** checks token arrangements against the source-code grammar and builds a parse tree.
3. **Semantic analysis:** checks the parse tree follows the language rules (type compatibility, declaration before use); produces an annotated syntax tree.
4. **Intermediate code generation:** produces code for an abstract machine, between high-level and machine language, easy to translate to the target.
5. **Code optimization:** removes unnecessary lines and rearranges statements to speed up execution without wasting CPU/memory.
6. **Code generation:** maps optimized intermediate code to re-locatable target machine code.
- **Symbol table:** data structure used by all phases (names, types, scope).
- **Error handler:** receives and reports errors from all phases and enables recovery.
- Phases 1–3 = **front end** (analysis); 4–6 = **back end** (synthesis).

### Key points to include
- Six phases in the **correct order** · input/output of each · symbol table + error handler spanning the phases · diagram (compulsory for 2020/21).

### How to approach this question
20 marks: diagram + one line per phase. 40 marks: diagram + 2–3 lines per phase + front/back end.

**Lesson:** [[01.08 Front-End Phases and Error Detection]]

### Expected answer

|---|---|

## 2021/22 · Q2(c) (20 marks)
> **Question:** *"Syntax Analysis checks whether the constructed parse tree follows the rules of language and Semantic Analysis checks whether the token arrangements follow the source code grammar or not."* Do you agree with the above statement? Justify your answer.

**Lesson:** [[01.08 Front-End Phases and Error Detection]]

### Expected answer
**No, I do not agree.** The two definitions are swapped.
- **Syntax analysis** checks whether the **token arrangements follow the source-code grammar**, and generates the **parse tree**.
- **Semantic analysis** checks whether the **constructed parse tree follows the rules of the language**, such as type compatibility and declaration before use, and outputs an **annotated syntax tree**.
- **Justification:** syntax analysis is the phase that *creates* the parse tree, so it cannot check a tree that does not exist yet; semantic analysis comes after and works on that tree.
- Examples: `int x = 5` (missing `;`) is a **syntax** error; `int x = "10" + 5;` is a **semantic** error.

### Key points to include
- "No" · both corrected definitions · ordering argument · one example of each.

### How to approach this question
Verdict → correct both → justify with phase order → examples.

## 2021/22 · Q2(d) (40 marks)
> **Question:** Explain the following things with their uses. (i) Intermediate Code Generation (ii) Code Optimization (iii) Code Generation (iv) Symbol Table

**Lesson:** [[01.09 Back-End Phases - Intermediate Code, Optimization, Code Generation]] · [[01.10 Symbol Table and Error Handler]]

### Expected answer
**(i) Intermediate Code Generation:** after semantic analysis, the compiler generates intermediate code for an **abstract machine**, between high-level and machine language.
*Uses:* easier translation to the target machine code; machine-independent (portability, one front end, many back ends); a clean form for optimization. Example: `a = b + c * d` → `t1 = c * d; t2 = b + t1; a = t2`.

**(ii) Code Optimization:** improves the intermediate code by **removing unnecessary code lines** and **rearranging statements**.
*Uses:* faster execution; less CPU and memory used; the program's meaning is unchanged. Example: `x = 4 * 2` → `x = 8`.

**(iii) Code Generation:** maps the optimized intermediate code to the **target machine language**, producing a sequence of **re-locatable machine code**.
*Uses:* produces the actual executable instructions; selects instructions and allocates registers/memory.

**(iv) Symbol Table:** data structure maintained throughout all phases, storing identifier names and types.
*Uses:* quick search and retrieval of identifiers; scope management; type checking and declaration checks; memory allocation during code generation.

### Key points to include
- Definition + use + small example for each (≈10 marks each) · where each sits in the phase sequence.

### How to approach this question
Four headed sections; a mini diagram showing phases 4–6 with the symbol table beside them ties it together.

## 2022/23 · Q1(b) (20 marks)
> **Question:** List the **three** analyses performed at the **front end** of a compiler and briefly explain how they contribute to the translation process.

**Lesson:** [[01.01 What is a Compiler]] · [[01.08 Front-End Phases and Error Detection]]

### Expected answer
1. **Lexical analysis:** scans the source as a character stream, groups characters into lexemes and produces **tokens**; removes whitespace/comments; detects invalid tokens. *Contribution:* turns raw text into meaningful units.
2. **Syntax analysis:** takes tokens and checks their arrangement against the grammar, producing a **parse tree**. *Contribution:* gives the program a verified structure.
3. **Semantic analysis:** checks that the parse tree follows the language rules (types compatible, identifiers declared before use), producing an **annotated syntax tree**. *Contribution:* ensures the program is meaningful.

Together they convert the source into a checked internal representation that the back end (intermediate code, optimization, code generation) can safely translate. The front end depends on the **source language**, not the target machine.

### Key points to include
- Exactly these three, in order · input/output of each · how each helps translation.

### How to approach this question
Three numbered paragraphs plus one concluding sentence on the front end's overall role.

## 2022/23 · Q2(a) (20 marks)
> **Question:** Why is **optimization** considered a critical task for compilers?

**Lesson:** [[01.09 Back-End Phases - Intermediate Code, Optimization, Code Generation]]

### Expected answer
- A compiler is expected to make the target code **efficient and optimized in terms of time and space**; correct code alone is not enough.
- Optimization **removes unnecessary code lines** and **rearranges statements** to **speed up execution** without **wasting resources (CPU, memory)**.
- Benefits: faster programs; smaller memory use; lower power consumption; important for limited hardware (embedded/mobile) and large-scale software.
- It lets programmers write clear, readable code while the compiler produces efficient code.
- It must **preserve the meaning** of the program.
- Example: constant folding (`x = 4*2` → `x = 8`), dead-code removal.

### Key points to include
- Link to the compiler definition · what optimization does · benefits · meaning preserved.

### How to approach this question
Definition + 3–4 reasons + an example.

## 2023/24 · Q1(b) (20 marks)
> **Question:** Briefly explain **Lexical Analysis, Syntax Analysis, Semantic Analysis,** and **Symbol Table**, highlighting how each phase contributes to the detection and reporting of errors during compilation.

**Lesson:** [[01.08 Front-End Phases and Error Detection]] · [[01.10 Symbol Table and Error Handler]]

### Expected answer
| Component | What it does | Error contribution |
|---|---|---|
| **Lexical analysis** | Scans characters, forms lexemes, produces tokens; removes whitespace/comments | Reports **invalid tokens** / illegal characters that match no pattern |
| **Syntax analysis** | Checks token arrangement against the grammar; builds the parse tree | Reports **structural errors**: missing `;`, unbalanced brackets, malformed statements; parses the whole code using error recovery so several errors are reported |
| **Semantic analysis** | Checks the parse tree follows language rules; produces an annotated syntax tree | Reports **meaning errors**: type mismatch (e.g. string + int), undeclared variables, use before declaration |
| **Symbol table** | Data structure across all phases holding identifier names, types and scope | Does not detect errors itself, but provides the information that makes "undeclared" and "type mismatch" errors detectable |

Errors from all phases go to the **error handler**, which reports them and allows compilation to continue.

### Key points to include
- One-line role + one error sentence for each of the four.

### How to approach this question
Table format with an example error per row.

## 2023/24 · Q1(c) (20 marks)
> **Question:** Consider the following statement: `int x = "10" + 5;` Identify the compiler phase that would detect the error and justify your answer by explaining why and how that phase is responsible for detecting it.

**Lesson:** [[01.08 Front-End Phases and Error Detection]]

### Expected answer
**Phase: Semantic Analysis.**
- **Lexical analysis passes:** all lexemes are valid tokens: `int` (keyword), `x` (identifier), `=` (operator), `"10"` (string literal), `+` (operator), `5` (constant), `;` (punctuator).
- **Syntax analysis passes:** the structure `type identifier = expression ;` matches the grammar, so a parse tree is built.
- **Semantic analysis fails:** it checks whether the parse tree follows the **rules of the language**, including **type compatibility**. It looks up `x` in the symbol table (type `int`), finds that `"10"` is a string and `5` an integer, so `"10" + 5` adds a string to an integer, and the result cannot be assigned to an `int`. The lecture explicitly names "adding string to an integer" as a semantic check.
- Principle: syntax checks **form**; semantics checks **meaning**.

### Key points to include
- Name the phase · why earlier phases accept it · how semantic analysis detects it (type checking, symbol table).

### How to approach this question
Walk through phases 1 → 2 → 3, showing it passes, passes, fails.

## 2023/24 · Q1(d) (40 marks)
> **Question:** A software company is developing an **embedded system** with very limited memory and processing power. (i) Discuss why code optimization is especially important in this scenario. (ii) Which compiler phases would play the most critical role in improving execution speed and memory usage? Justify your answer.

**Lesson:** [[01.09 Back-End Phases - Intermediate Code, Optimization, Code Generation]]

### Expected answer
**(i) Why optimization is especially important**
- Embedded devices have **small memory (RAM/ROM)** and **slow processors**; unoptimized code may **not fit** in memory.
- Many have **real-time requirements**; slow code may miss deadlines, which is a failure.
- Often **battery-powered**: fewer instructions means lower energy use.
- Hardware cannot simply be upgraded, so efficiency must come from the compiler.
- Optimization removes unnecessary code and rearranges statements to make execution faster **without wasting CPU and memory**, exactly what such systems need.

**(ii) Most critical phases**
1. **Code Optimization:** directly reduces instruction count and memory usage (e.g. removing dead code, constant folding, eliminating repeated computations).
2. **Code Generation:** chooses efficient machine instructions and **allocates registers**, avoiding slow memory accesses and producing compact code.
3. **Intermediate Code Generation:** provides a simple, machine-independent form on which optimizations can be applied systematically.
- Supporting: the **symbol table** (efficient memory allocation for identifiers).
- Front-end phases mainly ensure **correctness**; back-end phases determine **speed and memory**.

### Key points to include
- (i) constraints (memory, CPU, power, real time) and consequences · (ii) optimization + code generation (+ ICG), each justified.

### How to approach this question
Two sections. For (ii), name each phase, explain how it improves speed/memory, and give a small example.

## 2023/24 · Q2(c) (20 marks)
> **Question:** What is **Intermediate Code Generation**? Why do compilers generate intermediate code instead of directly producing machine code from high-level languages?

**Lesson:** [[01.09 Back-End Phases - Intermediate Code, Optimization, Code Generation]]

### Expected answer
**Definition:** the phase after semantic analysis that generates code for an **abstract machine**, a representation **between the high-level language and machine language**, designed to be easy to translate into target machine code (Theory Notes 1). Example: `a = b + c * d` → `t1 = c * d; t2 = b + t1; a = t2`.

**Why not produce machine code directly?**
1. **Easier translation:** the big jump from high-level code to machine code is split into two simpler steps.
2. **Portability / re-targeting:** intermediate code is machine-independent; supporting a new processor only needs a new code generator (m languages + n machines need m + n parts instead of m × n compilers).
3. **Optimization:** machine-independent optimizations are easier on a simple, uniform intermediate form.
4. **Modularity:** the front end and back end can be developed and improved separately.

### Key points to include
- Definition with "abstract machine / between high-level and machine language" · at least 3 reasons · example.

### How to approach this question
Definition + example, then numbered reasons.

## 2023/24 · Q2(d) (40 marks)
> **Question:** A student writes a C program that **compiles successfully** but **produces incorrect output**. (i) Which compiler phase(s) might still have worked correctly and why? (ii) What types of errors are **not detected by the compiler**? Explain with examples.

**Lesson:** [[01.11 Errors a Compiler Cannot Detect]] · [[07.10 Limitations of Syntax Analysis]]

### Expected answer
**(i)** Since it compiled successfully, **all phases worked correctly**:
- **Lexical analysis:** every lexeme formed a valid token.
- **Syntax analysis:** the tokens followed the grammar; a parse tree was built.
- **Semantic analysis:** types were compatible and identifiers declared.
- **Intermediate code generation, optimization, code generation:** completed and produced an executable.
The compiler checks **form and language rules, not the programmer's intention**, so the program is valid but not what was intended.

**(ii) Errors not detected by the compiler:**
- **Logical errors:** wrong formula or condition, e.g. `area = l + w;` instead of `l * w`, or `for (i = 0; i <= n; i++)` (off-by-one).
- **Run-time errors:** depend on values during execution, e.g. division by zero, array index out of bounds, null pointer dereference, infinite loops.
- **Semantic problems beyond type rules:** e.g. using an **uninitialised variable**; wrong operator precedence (`avg = a + b / 2;`). The lecture notes that the syntax analyzer cannot determine whether a token is **initialised before use**.
These are found by **testing and debugging**.

### Key points to include
- (i) all phases succeeded, each justified · (ii) logical and run-time errors (+ uninitialised use) with code examples.

### How to approach this question
Two parts; give at least two code examples in (ii).
