## 2019/20 · Q1(a) (20 marks)
> **Question:** Compare and Contrast **Compiler** and **Assembler**.

**Lesson:** [[01.05 Compiler, Interpreter, Assembler and De-compiler]]

### Expected answer
**Compiler:** a program that translates code in a high-level language into assembly language without changing the meaning of the program, producing efficient target code.
**Assembler:** a program that translates assembly language into machine code; its output is an object file (machine instructions + data needed to place them in memory).

**Similarities:** both are translators; both are stages of the Language Processing System; both produce output closer to the hardware than their input; both detect errors in their input.

| Compiler | Assembler |
|---|---|
| Input: high-level language (C, Java) | Input: assembly language |
| Output: assembly code | Output: object file / machine code |
| Many phases (lexical, syntax, semantic analysis, ICG, optimization, code generation) | Simple, almost one-to-one mapping of mnemonics to instructions |
| Performs optimization | No real optimization |
| Comes first in the pipeline | Comes after the compiler and translates its output |

### Key points to include
- One definition each · at least 2 similarities · at least 4 differences · the pipeline order.

### How to approach this question
"Compare **and** contrast" means similarities **and** differences. A two-column table is quickest. Finish with: *source → compiler → assembly → assembler → object code*.

## 2019/20 · Q1(d) and 2021/22 · Q1(d) (40 marks)
> **Question:** Discuss the workflow of the **Language Processing System** with its inputs and outputs. (2021/22: "…of a Language Processing System…")

**Lesson:** [[01.03 Language Processing System]]

### Expected answer
1. **Diagram:** Source code → **Preprocessor** → **Compiler** → **Assembler** → **Linker** (+ library files / relocatable object modules) → **Loader** → **Memory**.
2. **Stage by stage:**

| Stage | Input | Work | Output |
|---|---|---|---|
| Preprocessor | Source code with directives | macro processing, file inclusion (`#include`), augmentation, language extension | Modified / pure high-level source |
| Compiler | Modified source | Translates through its phases (lexical → … → code generation) | Assembly program |
| Assembler | Assembly program | Converts assembly into machine instructions | Relocatable object file |
| Linker | Object files + library files + other relocatable modules | Merges files, locates referenced routines, resolves addresses (absolute references) | Executable machine code |
| Loader (part of OS) | Executable | Calculates program size, creates memory space, loads it, initialises registers | Program in memory, executing |

3. **Why it is a chain:** the hardware understands only binary, so the high-level program is lowered step by step. Each tool does one job (modularity, reusable libraries, machine-specific back end).

### Key points to include
- Correctly ordered **diagram** with the library input to the linker.
- **Input and output for every stage** (this is what "workflow with inputs and outputs" asks).
- Loader is part of the **operating system**.

### How to approach this question
At 40 marks: diagram (≈10) + one short paragraph or table row per stage (≈5 each) + a closing sentence on why the stages exist.

## 2020/21 · Q1(a) (20 marks)
> **Question:** *"A compiler is a program that converts Low-level language to assembly language. Similarly, an assembler is a program that converts the High-level language to machine-level language."* Do you agree with this statement? Justify your answer.

**Lesson:** [[01.05 Compiler, Interpreter, Assembler and De-compiler]]

### Expected answer
**No, I do not agree.** Both definitions are wrong; the inputs have been swapped.
- A **compiler** converts a **high-level** language (such as C) into **assembly** language (Theory Notes 1).
- An **assembler** converts **assembly** language into **machine-level** code (an object file).
- **Justification:** in the Language Processing System the compiler comes **before** the assembler, and the compiler's output (assembly) is the assembler's input: *source (high-level) → compiler → assembly → assembler → machine code*. An assembler never receives high-level code, and a compiler does not take low-level input.
- Additional contrast: the compiler analyses and optimizes through many phases; the assembler performs a near one-to-one translation.

### Key points to include
- Clear **"No"** · both corrected definitions · pipeline justification.

### How to approach this question
Always state the verdict first, then correct each sentence, then justify with the pipeline. A bare "no" earns almost nothing.

## 2020/21 · Q1(c) (20 marks)
> **Question:** Briefly explain the usages of the **Pre-Processor** in a Language Processing System.

**Lesson:** [[01.04 Preprocessor]]

### Expected answer
The preprocessor, generally considered part of the compiler, is the first tool in the LPS. It **produces input for the compiler**: it processes the directives in the source code and outputs modified (pure) high-level source. Its usages (Theory Notes 1):
1. **Macro processing:** replaces macros with their definitions, e.g. `#define PI 3.14` replaces every PI with 3.14.
2. **File inclusion:** inserts the contents of header files, e.g. `#include <stdio.h>`.
3. **Augmentation:** adds or removes parts of the code (e.g. conditional compilation `#ifdef … #endif`).
4. **Language extension:** lets programmers use extra constructs (e.g. function-like macros) that it expands into legal code.

It performs **text substitution only**; it does no syntax or type checking.

### Key points to include
- Position (before the compiler) and output (modified source) · all four usages · at least two examples.

### How to approach this question
Four short bullet points with an example each, plus one sentence about its position in the LPS.

## 2020/21 · Q2(a) and 2021/22 · Q1(b) (20 marks)
> **Question:** Briefly explain how a **C compiler** executes a simple C program on a host machine. (2021/22: "…a simple program on a host machine.")

**Lesson:** [[01.03 Language Processing System]]

### Expected answer
1. The **user writes** a program in C (high-level language) and saves it as a source file. (The **preprocessor** first expands `#include` files and macros.)
2. The **C compiler** compiles the program and translates it into an **assembly program** (low-level language).
3. An **assembler** translates the assembly program into **machine code** (an object file).
4. A **linker** links all the parts of the program together, including library code such as `printf`, producing **executable machine code**.
5. A **loader** loads the executable into **memory**, and the program is executed.

### Key points to include
- Five numbered steps · tool and artefact at each step (.c → assembly → object → executable → memory).

### How to approach this question
Number the steps exactly. A small left-to-right sketch adds presentation marks.

## 2021/22 · Q1(a) (20 marks)
> **Question:** What is meant by a **compiler** and how does it differ from an **Interpreter** and an **Assembler**?

**Lesson:** [[01.05 Compiler, Interpreter, Assembler and De-compiler]]

### Expected answer
**Compiler:** translates code written in one language (high-level) into another (assembly/machine) **without changing its meaning**, producing code that is efficient in time and space.

**Compiler vs Interpreter**

| Compiler | Interpreter |
|---|---|
| Reads the **whole program** at once; may take many passes | Reads and executes **one statement at a time** |
| Produces object/target code | Produces no separate object code |
| Reports **all** errors after reading the whole program | **Stops at the first error** |
| Translated program runs fast repeatedly | Slower on repeated execution, convenient for testing |

**Compiler vs Assembler**

| Compiler | Assembler |
|---|---|
| High-level → assembly | Assembly → machine code (object file) |
| Complex, many phases, optimizes | Near one-to-one translation |
| Comes first | Translates the compiler's output |

### Key points to include
- Compiler definition · whole-program vs statement-by-statement · error behaviour · input/output languages.

### How to approach this question
Define, then two small tables. Note that the assembler is a **later stage**, not an alternative.

## 2021/22 · Q2(a) (20 marks)
> **Question:** What are the uses of having a **Linker** and a **Loader** in the execution process?

**Lesson:** [[01.06 Linker and Loader]]

### Expected answer
**Linker:** links and merges the object files (possibly produced by separate assemblers) and library files into a single **executable file**.
- Searches for and **locates referenced modules/routines** (e.g. library function `printf`).
- Determines the **memory locations** where code will be loaded and converts references into **absolute references**.
- Makes **separate compilation** and **library reuse** possible.

**Loader:** **part of the operating system**; loads the executable into **memory** and starts execution.
- **Calculates the size** of the program (instructions and data).
- **Creates memory space** for it and copies it in.
- **Initialises registers** to begin execution.

Pipeline: assembler → **linker** (executable file on disk) → **loader** (running program in memory).

### Key points to include
- Two separate halves (~10 marks each), with 3 uses each · the hand-over (file on disk vs process in memory).

### How to approach this question
Write "Linker" and "Loader" as two headings with 3–4 bullet points each.

## 2022/23 · Q1(a) (20 marks)
> **Question:** What is the primary role of a **compiler** in programming?

**Lesson:** [[01.01 What is a Compiler]]

### Expected answer
- The compiler **translates** a program written in a high-level language (source) into a lower-level target language (assembly / machine code) that the hardware can execute.
- It does this **without changing the meaning** of the program.
- It makes the target code **efficient and optimized in time and space**.
- It performs **error detection and recovery**: it analyses the whole program (lexical, syntax, semantic analysis) and reports errors so that they can be fixed before execution.
- This allows programmers to write in readable, portable high-level languages instead of binary, because hardware only understands 0s and 1s.

### Key points to include
- Translation · meaning preserved · efficiency/optimization · error detection · why needed.

### How to approach this question
Lead with the lecture definition, then expand each idea in one or two sentences.

## 2022/23 · Q1(c) (20 marks)
> **Question:** What challenges would programmers face if compilers did not exist?

**Lesson:** [[01.02 Why Computers Need Translators]]

### Expected answer
Hardware understands only binary (electronic charge = 0/1). Without compilers programmers would have to write machine code or assembly directly:
1. **Difficult and cumbersome:** writing long sequences of 0s and 1s (the lecture's point).
2. **Poor readability and maintenance:** binary/assembly code is hard to read, review and modify.
3. **Error-prone:** one wrong bit causes silent bugs; no automatic lexical/syntax/semantic error checking.
4. **No portability:** machine code is specific to one processor; programs must be rewritten for each machine.
5. **No optimization support:** programmers would have to hand-optimize instruction order, registers and memory.
6. **Much longer development time and cost:** large software would become impractical.

### Key points to include
- At least 4–5 distinct challenges, each explained · a conclusion.

### How to approach this question
Start from "hardware understands binary", list the challenges as bullets, and conclude that compilers make high-level programming possible.

## 2022/23 · Q2(c) (20 marks)
> **Question:** Briefly explain how the **Language Processing System** bridges the gap between human-readable code and hardware operations.

**Lesson:** [[01.03 Language Processing System]]

### Expected answer
- **The gap:** humans write in high-level, English-like languages; hardware understands only binary instructions (electronic charge).
- The LPS closes the gap by **lowering the program in stages**:
  1. **Preprocessor:** expands macros and includes header files, giving pure high-level code.
  2. **Compiler:** translates high-level code into assembly (checking and optimizing it).
  3. **Assembler:** translates assembly into binary machine code (object file).
  4. **Linker:** combines object files and libraries into one executable.
  5. **Loader:** places the executable in memory and starts execution on the hardware.
- Each tool solves one part of the problem, so the same source program can run on a machine after passing through the chain.

### Key points to include
- The gap (human vs binary) · each tool's contribution · progressive lowering.

### How to approach this question
Short version of the LPS answer, framed around "bridging the gap". A small diagram helps.

## 2022/23 · Q2(d) (40 marks)
> **Question:** Could a single tool replace the compiler, assembler, linker, and loader? Justify your answer and explain the challenges.

**Lesson:** [[01.03 Language Processing System]] · [[01.06 Linker and Loader]]

> [!warning] Not covered directly in the lecture
> The lecture describes each tool but does not discuss merging them. The answer is reasoned from those roles.

### Expected answer
**Position:** In principle a single integrated tool *could* perform all four jobs (some environments, such as interpreters or JIT systems, combine translation and execution), but in practice it is **not desirable**, because each tool has a separate, well-defined responsibility.

**What each tool contributes (so what a single tool would have to do):**
- Compiler: analysis, optimization and translation of high-level code.
- Assembler: assembly → machine code (object files).
- Linker: combines separately compiled modules and libraries, resolves references.
- Loader: part of the OS; allocates memory, loads and starts the program.

**Challenges of a single tool:**
1. **Complexity:** one huge program would be hard to design, test and maintain.
2. **Loss of separate compilation:** today only changed files are recompiled and then re-linked; a single tool would rebuild everything each time.
3. **Libraries:** pre-compiled libraries (whose source may be unavailable) rely on a separate linking stage.
4. **Portability:** the front end is language-dependent and the back end machine-dependent; merging everything means rewriting the whole tool for each processor/OS.
5. **OS responsibility:** loading (memory allocation, register setup) is done by the operating system, not by a development tool.
6. **Flexibility and reuse:** separate tools can be improved or replaced independently (e.g. a better optimizer).

**Conclusion:** separation of concerns makes the system modular, efficient and portable, so the four tools remain separate.

### Key points to include
- A clear stance with justification · roles of each tool · at least 4 challenges · conclusion.

### How to approach this question
Structure: stance → roles → challenges (one paragraph each) → conclusion. At 40 marks depth matters more than length.

## 2023/24 · Q1(a) (20 marks)
> **Question:** Briefly explain why computers cannot directly execute or understand high-level programming languages such as C or Python.

**Lesson:** [[01.02 Why Computers Need Translators]]

### Expected answer
- Computer hardware understands instructions only in the form of **electronic charge**, which corresponds to **binary language**, with only two symbols, **0 and 1**.
- High-level languages such as C or Python use English-like keywords, symbols and structures (`while`, `print`, variables, functions) that have **no direct meaning to the hardware**.
- The processor can only execute its own **machine instruction set** (binary instructions specific to that CPU).
- So a high-level program must first be **translated**, by a compiler (whole program, e.g. C) or an interpreter (statement by statement, e.g. Python), and then assembled, linked and loaded into memory.
- High-level languages are designed for humans (readability, portability), not for direct execution.

### Key points to include
- Electronic charge / binary {0,1} · high-level keywords have no electrical meaning · translator needed (compiler/interpreter) · the LPS chain.

### How to approach this question
Three or four sentences of explanation plus a mention of the translation chain.

## 2023/24 · Q2(b) (20 marks)
> **Question:** Distinguish between the following terms: (i) Compiler (ii) De-compiler (iii) Interpreter (iv) Assembler

**Lesson:** [[01.05 Compiler, Interpreter, Assembler and De-compiler]]

> [!warning] De-compiler is not in the course materials
> The definition below is standard knowledge.

### Expected answer
| Term | Input → Output | How it works |
|---|---|---|
| **Compiler** | High-level → assembly / machine code | Translates the **whole program** (many phases), optimizes, reports all errors; produces target code |
| **De-compiler** | Machine / object code → high-level source | Works in **reverse**: reconstructs readable source from an executable; used for reverse engineering; original names and comments are lost |
| **Interpreter** | High-level → (executes directly) | Translates and executes **one statement at a time**; no object file; **stops at the first error** |
| **Assembler** | Assembly → machine code (object file) | Near one-to-one translation of mnemonics; output contains machine instructions + data to place them in memory |

### Key points to include
- For each term: **input language, output language, method** (≈5 marks each).

### How to approach this question
A 4-row table is the clearest answer. Make sure the de-compiler's **reverse direction** is stated.
