## 2019/20 · Q7(a) and 2020/21 · Q7(b) (20 marks)
> **Question:** What is meant by context-free grammar is **ambiguous**? Briefly explain with a suitable example. (2020/21: "…is ambiguous or unambiguous?…")

### Expected answer
- A grammar G is **ambiguous** if it has **more than one parse tree** (equivalently more than one left-most, or more than one right-most, derivation) for **at least one string**.
- **Unambiguous:** every string in L(G) has exactly one parse tree.
- **Example:** E → E + E | E – E | id, string `id + id – id`:
  - Tree 1: root E → E – E, with the left E → E + E: **(id + id) – id**.
  - Tree 2: root E → E + E, with the right E → E – E: **id + (id – id)**.
  - (Draw both trees.) Two trees for one string, so the grammar is **ambiguous**.
- Ambiguity is bad for compilers (different trees can give different meanings); there is no automatic method to detect or remove it; remedies: **rewrite** the grammar or impose **associativity and precedence**.

### How to approach this question
Definition + two drawn trees + one line on why it matters.

## 2019/20 · Q7(b) (20 marks)
> **Question:** Generate **Left Most** and **Right Most Derivation** for expression **(id + id) \* id + id** according to the following production rules. E → E + E · E → E \* E · E → (E) · E → id

### Expected answer
Top-level operator: the last `+` (with `*` binding tighter).

**LMD:**
E ⇒ E + E ⇒ E \* E + E ⇒ (E) \* E + E ⇒ (E + E) \* E + E ⇒ (id + E) \* E + E ⇒ (id + id) \* E + E ⇒ (id + id) \* id + E ⇒ (id + id) \* id + id

**RMD:**
E ⇒ E + E ⇒ E + id ⇒ E \* E + id ⇒ E \* id + id ⇒ (E) \* id + id ⇒ (E + E) \* id + id ⇒ (E + id) \* id + id ⇒ (id + id) \* id + id

Both correspond to the same parse tree (root `+`; its left child is `*` over `(id + id)` and `id`). Brackets are terminals from E → (E). (The grammar is ambiguous, so another tree with `*` at the root also exists.)

## 2020/21 · Q7(c) (20 marks)
> **Question:** Generate **Left Most** and **Right Most Derivations** for expression **(id + id \* id) + (id \* id)** according to the following production rules. E → E + E · E → E \* E · E → (E) · E → id

### Expected answer
**LMD:**
E ⇒ E + E ⇒ (E) + E ⇒ (E + E) + E ⇒ (id + E) + E ⇒ (id + E \* E) + E ⇒ (id + id \* E) + E ⇒ (id + id \* id) + E ⇒ (id + id \* id) + (E) ⇒ (id + id \* id) + (E \* E) ⇒ (id + id \* id) + (id \* E) ⇒ (id + id \* id) + (id \* id)

**RMD:**
E ⇒ E + E ⇒ E + (E) ⇒ E + (E \* E) ⇒ E + (E \* id) ⇒ E + (id \* id) ⇒ (E) + (id \* id) ⇒ (E + E) + (id \* id) ⇒ (E + E \* E) + (id \* id) ⇒ (E + E \* id) + (id \* id) ⇒ (E + id \* id) + (id \* id) ⇒ (id + id \* id) + (id \* id)

Assumption: inside the first bracket `*` has higher precedence (E + E, then E \* E on the right).

## 2020/21 · Q7(a) (20 marks)
> **Question:** Find out the derivations of the following grammar. G = ({S, A, B}, {a, b}, S, {S → AB, A → aA | a, B → bB | b})

### Expected answer
- A → aA | a generates a⁺; B → bB | b generates b⁺; so **L(G) = {aⁿbᵐ | n ≥ 1, m ≥ 1}** = a⁺b⁺ (ab, aab, abb, aabb, …).
- Example derivations:
  - ab: S ⇒ AB ⇒ aB ⇒ ab
  - **aabb, LMD:** S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aabB ⇒ aabb
  - **aabb, RMD:** S ⇒ AB ⇒ AbB ⇒ Abb ⇒ aAbb ⇒ aabb
- Parse tree for aabb: S with children A, B; A → a A → a; B → b B → b.

### How to approach this question
The question is open-ended: state the language, then give derivations (LMD and RMD) of one or two strings.

## 2019/20 · Q7(c) (20 marks)
> **Question:** Verify whether the grammar S → 0B | 1A, A → 0S | 1AA | ε, B → 1 | 1S | 0BB generates the following string or not. i. 0010101 ii. 110100101110

> [!warning] Correction
> The earlier topic map recorded the last rule as "0DD". The paper prints **B → 0BB**.

### Expected answer
**Invariants** (proved by checking every production; see [[07.06 Language of a Grammar and Membership Proofs]]): let d = #1 − #0.
1. d ≥ 0 for every string from S (with d ≥ −1 for A and d ≥ 1 for B).
2. Every non-empty string from S **ends with 1** (B always ends in 1; A is ε or ends in 1).

- **0010101:** four 0s, three 1s, so d = −1 < 0. **Not generated.**
- **110100101110:** ends with **0**. **Not generated.**

(Attempt for 0010101: S ⇒ 0B ⇒ 00BB ⇒ 001B ⇒ … the B's each need at least one more 1 than 0, and there are not enough 1s left. The derivation cannot finish.)

### How to approach this question
State and justify the invariant, then apply it. Show a partial derivation to demonstrate where it blocks.

## 2020/21 · Q7(d) and 2021/22 · Q8(d) (40 marks)
> **Question:** Verify whether the following grammar S → aB | bA, A → aS | bAA | ε, B → b | bS | aBB generates the following string or not. i. aababab ii. bbabaababbba iii. aaaaabbbb iv. abababbbbaaa

### Expected answer
**Invariants for the grammar as printed** (d = #b − #a):
- Productions: S → aB (−1 + d(B)), S → bA (1 + d(A)), A → ε (0), A → aS (−1 + d(S)), A → bAA (1 + 2d(A)), B → b (1), B → bS (1 + d(S)), B → aBB (−1 + 2d(B)).
- By induction: **d(S) ≥ 0, d(A) ≥ −1, d(B) ≥ 1**, so every string from S has **#b ≥ #a**.
- Every non-empty string from S **ends with b**.

| String | #a | #b | Ends with | Verdict |
|---|---|---|---|---|
| aababab | 4 | 3 | b | **Not generated** (#b < #a) |
| bbabaababbba | 5 | 7 | a | **Not generated** (ends with a) |
| aaaaabbbb | 5 | 4 | b | **Not generated** (#b < #a) |
| abababbbbaaa | 6 | 6 | a | **Not generated** (ends with a) |

> [!important] If A → ε is a misprint for A → a
> The well-known textbook grammar is S → aB | bA, A → **a** | aS | bAA, B → b | bS | aBB, which generates exactly the strings with **equal** numbers of a's and b's. Under that grammar strings i–iii are rejected (unequal counts) and **iv is generated**:
> S ⇒ aB ⇒ abS ⇒ abaB ⇒ ababS ⇒ ababaB ⇒ abababS ⇒ abababbA ⇒ abababbbAA ⇒ abababbbbAAA ⇒ abababbbbaAA ⇒ abababbbbaaA ⇒ abababbbbaaa.
> In the exam, answer for the grammar **as printed**, then add this alternative in two lines.

### Key points to include
- Count symbols first · state and justify the invariant · one verdict sentence per string · a derivation for any string that is generated.

## 2021/22 · Q8(a) (20 marks)
> **Question:** Consider the following grammar and find out the language can be generated. G = ({S}, {a, b}, S, {S → aSbb | abb})

### Expected answer
- Strings: abb, aabbbb, aaabbbbbb, …
- Each S → aSbb adds one a at the front and two b's at the end.
- **L(G) = {aⁿ b²ⁿ | n ≥ 1}**.
- Proof by induction: base abb = a¹b²; if S ⇒\* aⁿb²ⁿ then S ⇒ aSbb ⇒\* aⁿ⁺¹b²ⁿ⁺². No other strings, since these are the only productions. n ≥ 1 (no ε-rule).

## 2021/22 · Q8(b) (20 marks)
> **Question:** Consider a grammar G is given as follows; S → AB | aaB, A → a | Aa, B → b. Determine whether the grammar G is ambiguous or not for the string "aab".

### Expected answer
**Ambiguous.** Two distinct parse trees for "aab":
1. S ⇒ AB ⇒ AaB ⇒ aaB ⇒ aab (S → AB, A → Aa, A → a, B → b).
2. S ⇒ aaB ⇒ aab (S → aaB, B → b).

Tree 1 has root children (A, B) with A deriving aa; tree 2 has root children (a, a, B). Different trees, so the grammar is **ambiguous**. (Cause: S → aaB duplicates what S → AB already produces.)

## 2021/22 · Q8(c) (20 marks)
> **Question:** Generate **Left-most** and **Right-most** Derivations for the string "aabbabba" using a CFG given by S → aB | bA · S → a | aS | bAA · S → b | aS | aBB

> [!warning] Grammar as printed
> The left sides of lines 2 and 3 are printed as **S**, so A and B have no productions, and "aabbabba" cannot be derived literally. These are clearly the standard rules **A → a | aS | bAA** and **B → b | bS | aBB** (the right sides match). State this interpretation in your answer.

### Expected answer (with A → a | aS | bAA, B → b | bS | aBB)
**LMD:**
S ⇒ aB ⇒ aaBB ⇒ aabB ⇒ aabbS ⇒ aabbaB ⇒ aabbabS ⇒ aabbabbA ⇒ aabbabba
(rules: S→aB, B→aBB, B→b, B→bS, S→aB, B→bS, S→bA, A→a)

**RMD:**
S ⇒ aB ⇒ aaBB ⇒ aaBbS ⇒ aaBbaB ⇒ aaBbabS ⇒ aaBbabbA ⇒ aaBbabba ⇒ aabbabba
(the right-most B is expanded completely before the left B → b)

Both derivations use the same parse tree; they differ only in the order of replacement.

## 2022/23 · Q8(a) and 2023/24 · Q8(a) (20 marks)
> **Question:** For the grammar G = ({S}, {a, b}, S, {S → aSb | bSa | ab | ba}): i. What is the language generated by this grammar? ii. Derive the string "aabbab".

### Expected answer
**(i)** Strings: ab, ba; aabb, abab, baba, bbaa; aaabbb, aababb, …
Each rule adds a symbol at both ends, and the two added symbols are always **different** (a…b or b…a). So
**L(G) = { w ∈ {a,b}⁺ : |w| = 2n is even and wᵢ ≠ w₂ₙ₊₁₋ᵢ for every i }**, i.e. the second half is the reverse of the first half with a and b swapped. Every such string has equal numbers of a's and b's (but not every balanced string: abba ∉ L(G)).

**(ii) "aabbab" cannot be derived.** Matching positions 2 and 5 are both **a**, but this grammar always puts different symbols in matching positions. Attempt: S ⇒ aSb (positions 1 and 6: a, b ✔); the inner S must give **abba**, which starts and ends with the same symbol, so none of aSb, bSa, ab, ba applies. **Not in L(G)** (confirmed by parser).
Demonstration on a derivable string of the same length: **aababb**: S ⇒ aSb ⇒ aaSbb ⇒ aababb.

### How to approach this question
Give the language, then show the blocked derivation with the reason, plus a correct derivation of a nearby string.

## 2022/23 · Q8(b) and 2023/24 · Q8(b) (20 marks)
> **Question:** Consider the grammar G = ({S}, {a, b}, S, {S → aSb | bSa | SS | ε}): i. Is this grammar ambiguous for the string "abab"? (2023/24: "…Discuss.") ii. If ambiguous, provide two distinct parse trees for "abab".

### Expected answer
**(i) Yes, ambiguous.** The rule S → SS (together with S → ε) allows the same string to be split in more than one way.

**(ii) Two parse trees:**
- **Tree 1 (root S → SS):** S ⇒ SS ⇒ aSbS ⇒ abS ⇒ abaSb ⇒ abab. Each half is S → aSb with the inner S → ε: **(ab)(ab)**.
- **Tree 2 (root S → aSb):** S ⇒ aSb ⇒ abSab ⇒ abab, with the inner S → bSa and its inner S → ε: **a(ba)b**.

```text
Tree 1:        S                 Tree 2:      S
             /   \                          / | \
            S     S                        a  S  b
          / | \ / | \                        / | \
         a  S b a S b                       b  S  a
            |     |                            |
            ε     ε                            ε
```

Different root productions mean genuinely different trees: one string with two parse trees, so G is **ambiguous**.

## 2022/23 · Q8(c) and 2023/24 · Q8(c) (20 marks)
> **Question:** Generate **Left-most** and **Right-most** derivations for the string "aababab" using a CFG given by; G = ({S, A, B}, {a, b}, S, {S → aB | bA, A → aS | bAA | ε, B → b | bS | aBB})

### Expected answer
**"aababab" cannot be derived from this grammar** (confirmed by parser), so no left-most or right-most derivation exists.
- Reason: it has 4 a's and 3 b's. In this grammar every string derived from S has **#b ≥ #a** (invariant: d(S) ≥ 0, d(A) ≥ −1, d(B) ≥ 1 for d = #b − #a). (Under the textbook version with A → a, S generates only strings with equal a's and b's, so it would still not be derivable.)
- Showing the attempt: S ⇒ aB ⇒ aaBB ⇒ aabB ⇒ aabaBB ⇒ aababB ⇒ aababaBB: the prefix "aababa" already matches six symbols, but two B's remain and each B must produce at least one b; only one symbol ("b") is left. **Blocked.** (Other choices of rules block similarly, as the invariant guarantees.)

**Demonstrating the technique** on a derivable string from the same grammar, **aababb**:
- **LMD:** S ⇒ aB ⇒ aaBB ⇒ aabB ⇒ aabaBB ⇒ aababB ⇒ aababb
- **RMD:** S ⇒ aB ⇒ aaBB ⇒ aaBb ⇒ aabSb ⇒ aabaBb ⇒ aababb

> [!tip] What to write
> Do not invent a "derivation" that cheats. State that the string is not in L(G), give the counting reason, show where the attempt blocks, and then demonstrate LMD/RMD on a valid string. Examiners give method marks for this.

## 2022/23 · Q8(d) and 2023/24 · Q8(d) (40 marks)
> **Question:** i. Prove that the following grammar generates all strings of the form aⁿb where n ≥ 1. G = ({S, A, B}, {a, b}, S, {S → AB | aB, A → a | Aa, B → b}) ii. Prove that the following grammar generates all strings with an equal number of a's and b's. G = ({S}, {a, b}, S, {S → aSb | bSa | SS | ε})

### Expected answer
**(i)**
- B generates exactly {b}.
- A generates exactly a⁺: base A → a gives a; step A → Aa turns aᵏ into aᵏ⁺¹ (induction).
- **(⊆)** S → AB gives aⁿb (n ≥ 1); S → aB gives ab. Every generated string has the form aⁿb, n ≥ 1.
- **(⊇)** For n ≥ 1: S ⇒ AB ⇒ AaB ⇒ … (A → Aa applied n − 1 times) ⇒ aⁿB ⇒ aⁿb.
- So L(G) = {aⁿb | n ≥ 1}. ∎ (S → aB is redundant, which makes the grammar ambiguous for ab.)

**(ii)** Let d(w) = #a − #b.
- **(⊆)** S → ε: d = 0. S → aSb and S → bSa add one a and one b (d unchanged). S → SS: d = 0 + 0. Every production preserves d = 0, so every generated string is balanced.
- **(⊇)** Strong induction on |w| for balanced w. |w| = 0: S → ε. Otherwise scan w and track d of each prefix:
  - if d returns to 0 before the end, w = uv with u, v balanced and shorter: use S → SS;
  - otherwise w starts and ends with different symbols, w = a x b or b x a with x balanced and shorter: use S → aSb or S → bSa.
- So L(G) = {w : #a(w) = #b(w)}. ∎

### Key points to include
- Both directions (⊆ and ⊇) for each part · induction clearly stated · conclusion.
