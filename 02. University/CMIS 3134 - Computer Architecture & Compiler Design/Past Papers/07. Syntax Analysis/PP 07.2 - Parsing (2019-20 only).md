## 2019/20 · Q7(d) (40 marks)
> **Question:** Construct the **LL(1)/ Predictive Parser** for the following grammar. S → A · A → aDC · C → dC | ε · D → b · E → g

### Expected answer
**FIRST:** FIRST(S) = FIRST(A) = {a}; FIRST(C) = {d, ε}; FIRST(D) = {b}; FIRST(E) = {g}.
**FOLLOW:** FOLLOW(S) = {$}; FOLLOW(A) = {$}; FOLLOW(D) = (FIRST(C) − ε) ∪ FOLLOW(A) = {d, $}; FOLLOW(C) = FOLLOW(A) = {$}; E is unreachable (FOLLOW(E) = ∅).

**Table rule:** for X → α, put it under every t ∈ FIRST(α); if ε ∈ FIRST(α), also under every t ∈ FOLLOW(X).

| | a | b | d | g | $ |
|---|---|---|---|---|---|
| S | S → A | | | | |
| A | A → aDC | | | | |
| C | | | C → dC | | C → ε |
| D | | D → b | | | |
| E | | | | E → g | |

No cell has more than one entry, so the grammar is **LL(1)**. Example parse of `abd`: $S → $A → $CDa (match a) → $Cb (D → b, match b) → $Cd (C → dC, match d) → $ (C → ε) → **accept**.

### Key points to include
- FIRST and FOLLOW tables · parsing table · LL(1) conclusion · (optional) a sample parse.

## 2019/20 · Q8(a) (20 marks)
> **Question:** Compare and contrast **Top-Down Parsers** and **Bottom-Up Parsers**.

### Expected answer
**Similarities:** both read input left to right, use a CFG, build a parse tree and detect syntax errors.

| Top-down | Bottom-up |
|---|---|
| Builds the tree from the root (start symbol) down to the leaves | Builds from the leaves (tokens) up to the root |
| Traces a **left-most derivation** | Traces a **right-most derivation in reverse** |
| Operation: expand non-terminals (predict) | Operations: **shift** and **reduce** |
| e.g. recursive descent, LL(1) | e.g. shift-reduce, LR(0), SLR, LALR, CLR |
| Cannot handle left recursion; needs left factoring | Handles left recursion; works for a larger class of grammars |
| Easier to write by hand | More powerful; usually tool-generated |

## 2019/20 · Q8(b) (20 marks)
> **Question:** What is meant by **Back Tracking**? Briefly explain with a suitable example.

### Expected answer
**Backtracking:** when a top-down parser tries one production for a non-terminal, finds that it does not match the input, **undoes** that choice (resets the input pointer) and **tries another production**.

**Example:** S → cAd, A → ab | a; input `cad`.
1. S → cAd, match c.
2. Try A → ab: match a, but the next input is d ≠ b. Fail.
3. Backtrack: undo A → ab, reset the input to "ad".
4. Try A → a: match a; then match d. Success.

Backtracking can be very slow. Predictive (LL(1)) parsers avoid it by choosing the production from one look-ahead symbol and a parsing table.

## 2019/20 · Q8(c) (30 marks)
> **Question:** Develop the **Parser table for LR(0)** parser for the following context free grammar. S → AA · A → aA | b

### Expected answer
Augmented grammar: S′ → S; productions (1) S → AA, (2) A → aA, (3) A → b.

**LR(0) item sets:**
- I0: S′ → ·S, S → ·AA, A → ·aA, A → ·b
- I1 = goto(I0,S): S′ → S·
- I2 = goto(I0,A): S → A·A, A → ·aA, A → ·b
- I3 = goto(I0,a) = goto(I2,a) = goto(I3,a): A → a·A, A → ·aA, A → ·b
- I4 = goto(I0,b) = goto(I2,b) = goto(I3,b): A → b·
- I5 = goto(I2,A): S → AA·
- I6 = goto(I3,A): A → aA·

| State | a | b | $ | A | S |
|---|---|---|---|---|---|
| 0 | s3 | s4 | | 2 | 1 |
| 1 | | | accept | | |
| 2 | s3 | s4 | | 5 | |
| 3 | s3 | s4 | | 6 | |
| 4 | r3 | r3 | r3 | | |
| 5 | r1 | r1 | r1 | | |
| 6 | r2 | r2 | r2 | | |

No shift-reduce or reduce-reduce conflicts, so the grammar is **LR(0)**.

## 2019/20 · Q8(d) (30 marks)
