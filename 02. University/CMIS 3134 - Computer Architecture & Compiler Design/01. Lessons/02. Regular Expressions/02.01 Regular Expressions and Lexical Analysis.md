# 02.01 · Regular Expressions and Their Role in Lexical Analysis

> [!info] [[02.00 Regular Expressions|Lesson 2]] · Theory Notes 2 · Priority 🔴 High
> **Asked as:** "Differentiate between Regular Grammar and Regular Language" (2020/21 Q2b) · "What is meant by a Regular Expression? How do regular grammar and regular language differ from a regular expression?" (2021/22 Q3a, 2022/23 Q3a) · "What is meant by a Regular Expression? Why are regular expressions important in the design of a lexical analyzer?" (2023/24 Q3a)

## 1. What is a regular expression?

> [!abstract] Theory Notes 2
> "**Regular expression is an important notation for specifying patterns.** Each pattern matches a set of strings, so regular expressions serve as **names for a set of strings**. Programming language tokens can be described by regular languages. The specification of regular expressions is an example of a **recursive definition**. Regular languages are easy to understand and have **efficient implementation**."

In simple words: an RE is a short formula that **stands for a whole set of strings**. For example `(letter)(letter | digit)*` stands for every valid identifier.

## 2. Why is it used in lexical analysis?

> [!quote] Theory Notes 2
> "The lexical analyzer needs to scan and identify only a **finite set of valid string/token/lexeme** that belong to the language in hand. It **searches for the pattern defined by the language rules**. Regular expressions have the capability to express finite languages by defining a pattern for finite strings of symbols."

| Reason | Explanation |
|---|---|
| **Patterns for tokens** | Each token class (identifier, number, keyword, operator) is defined by a *pattern*. REs are the notation for writing those patterns. |
| **Finite description of an infinite set** | There are infinitely many identifiers. You cannot list them, but one RE describes them all. |
| **Precise and unambiguous** | An RE specifies exactly which lexemes are valid. |
| **Efficient implementation** | Every RE can be converted into a **finite automaton**, which can check strings quickly. The lecture: "A well-accepted solution is to use **finite automata for verification**." |
| **Automatic scanner generation** | Because RE → automaton is mechanical, lexical analyzers can be generated by tools (for example *lex/flex*, standard knowledge). |

## 3. RE vs Regular Grammar vs Regular Language

> [!abstract] Theory Notes 2
> "The **grammar defined by regular expressions** is known as **regular grammar**. The **language defined by regular grammar** is known as **regular language**."

So the three form a chain: **notation → rules → set of strings**.

| Term | What it is | Example |
|---|---|---|
| **Regular expression** | The **notation**: a pattern built with union, concatenation and Kleene closure | `a*b` |
| **Regular grammar** | The **set of production rules** defined by that pattern, which *generates* strings | `S → aS \| b` |
| **Regular language** | The **set of strings** the grammar generates (the result) | `{b, ab, aab, aaab, …}` |

### Regular Grammar vs Regular Language (2020/21 Q2b)

| Regular Grammar | Regular Language |
|---|---|
| A **generator / specification**: finite set of rules (variables, terminals, start symbol, productions) | The **output / result**: the set of all strings those rules generate |
| Always finite (finitely many rules) | Can be finite or **infinite** |
| Example: `S → aS \| b` | `L = {aⁿb : n ≥ 0}` = `a*b` |
| Can be **right linear** (`A → xB`) or **left linear** (`A → Bx`) (handwritten notes) | Recognised by a finite automaton; described by an RE |

> [!tip] One-line answer
> *The regular expression is the notation; the regular grammar is the set of rules it defines; the regular language is the set of strings that grammar generates.*

## 4. Example carried through all three

- RE: `(a+b)*abb`
- Regular grammar (right linear, illustrative): `S → aS | bS | aA`, `A → bB`, `B → b`
- Regular language: all strings over {a, b} ending in `abb`: `{abb, aabb, babb, aaabb, …}`

> [!note] Beyond the slides
> The grammar in this example was constructed for illustration. The lecture gives the definitions but no worked grammar for `(a+b)*abb`.

## 5. Exam-relevant points
- Definition: **notation for specifying patterns; names a set of strings; recursive definition; efficient implementation.**
- "Why important for lexical analyzer": patterns for tokens, infinite sets described finitely, converts to finite automata, efficient and precise.
