# 02.03 · RE Notation, Precedence, Associativity and the Recursive Definition

> [!info] [[02.00 Regular Expressions|Lesson 2]] · Theory Notes 2 · Priority 🟢 (never asked directly, but needed to read every RE correctly)

## 1. Notations

> [!abstract] Theory Notes 2
> If r and s are regular expressions denoting the languages L(r) and L(s), then
> - **Union:** `(r)|(s)` is a regular expression denoting $L(r) \cup L(s)$
> - **Concatenation:** `(r)(s)` is a regular expression denoting $L(r)L(s)$
> - **Kleene closure:** `(r)*` is a regular expression denoting $(L(r))^*$
> - `(r)` is a regular expression denoting $L(r)$ (grouping)

## 2. Precedence and associativity

> [!abstract] Theory Notes 2
> - `*`, concatenation `(.)`, and `|` (pipe sign) are **left associative**
> - `*` has the **highest** precedence
> - Concatenation `(.)` has the **second highest** precedence
> - `|` (pipe sign) has the **lowest** precedence of all

| Precedence | Operator | Meaning |
|---|---|---|
| 1 (highest) | `*` (and `+`, `?`) | repetition |
| 2 | `.` concatenation | sequence |
| 3 (lowest) | `\|` or `+` (union) | choice |

**How to read an RE without brackets:**
- `ab*` = `a(b*)`. The star applies to `b` only, so the strings are a, ab, abb, … (**not** abab).
- `a + bc*` = `a + (b(c*))`. Its strings are a, b, bc, bcc, …
- `0 + 10*` = `0 + (1(0*))`. Its strings are 0, 1, 10, 100, … (this is the lecture's first example).
- `(ab)*` is different from `ab*`: the brackets make the star apply to the whole `ab`.

## 3. Recursive definition of a regular expression

> [!abstract] Theory Notes 2
> A Regular Expression can be recursively defined as follows:
> 1. **ε** is a Regular Expression; it indicates the language containing an empty string: $L(\varepsilon) = \{\varepsilon\}$
> 2. **φ** is a Regular Expression denoting an empty language: $L(\varphi) = \{\,\}$
> 3. **x** is a Regular Expression where $L = \{x\}$
> 4. If X denotes $L(X)$ and Y denotes $L(Y)$, then
>    - **X + Y** is a RE with $L(X+Y) = L(X) \cup L(Y)$
>    - **X . Y** is a RE with $L(X.Y) = L(X) \cdot L(Y)$
>    - **R\*** is a RE with $L(R^*) = (L(R))^*$
> 5. If we apply any of the rules several times, the results are Regular Expressions.

| Rule | Expression | Language |
|---|---|---|
| Base 1 | ε | {ε} (one string, of length 0) |
| Base 2 | φ | { } (no strings at all) |
| Base 3 | x (a symbol) | {x} |
| Step 1 | X + Y | L(X) ∪ L(Y) |
| Step 2 | X . Y | L(X) · L(Y) |
| Step 3 | R* | (L(R))* |

> [!important] ε vs φ vs {ε}
> - **ε** is a *string* of length 0.
> - **{ε}** is a *set* containing one string (the empty string).
> - **φ = { }** is the *empty set*, containing nothing.
> - Concatenating with ε changes nothing ($\varepsilon R = R$); concatenating with φ gives φ ($\varphi R = \varphi$). See [[08.01 Regular Expression Identities]].

## 4. Example: building `(a+b)*abb` from the rules
1. `a`, `b` are REs (base 3).
2. `a + b` is a RE (union).
3. `(a+b)*` is a RE (star).
4. `(a+b)*a`, then `(a+b)*ab`, then `(a+b)*abb` are REs (concatenation, applied three times).

## 5. Exam-relevant points
- Use precedence correctly whenever you read or write an RE. Most "example strings" mistakes come from attaching `*` to too much.
- If asked "what is a regular expression?" at a theoretical level, quote the **recursive definition**.
