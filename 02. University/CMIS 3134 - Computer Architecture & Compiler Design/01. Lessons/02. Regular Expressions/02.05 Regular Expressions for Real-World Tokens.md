# 02.05 · Regular Expressions for Real-World Tokens

> [!info] [[02.00 Regular Expressions|Lesson 2]] · Theory Notes 2 + `compier note.pdf` pp. 5–6 · Priority 🔴 High (3 papers)
> **Asked as:** "Represent the following language tokens using regular expressions: Any Decimal Value · Any Identifier · Any NIC number that contains x or v at the end · Any Email address that ends with "@gmail.com"" (2021/22 Q3c, 2022/23 Q3c) · "Construct suitable REs for: a binary number · a valid Sri Lankan mobile number starting with 07 and containing 10 digits · a university registration number in the format YYYY/ABC/NNN (Example: 2026/FAS/015) · a password that starts with a letter, has at least 6 characters, and contains only letters and digits" (2023/24 Q3c)

## 1. The method (works for every token)

1. **Define building blocks** first: `letter`, `digit`, `sign`.
2. **Split the format** into fixed parts (literal characters like `07`, `/`, `@gmail.com`) and variable parts (digits, letters).
3. Write a small RE for each part, using `*`, `⁺`, `?` and exact repetition.
4. **Concatenate** the parts in order.
5. Give **one valid example** and **state any assumption**.

```text
letter = [a-z] | [A-Z]
digit  = [0-9]
sign   = [+ | -]
```

> [!note] Exact repetition
> The course writes repetition out in full, for example `(digit)(digit)(digit)`. A shorthand like `(digit)³` meaning "exactly 3 digits" is clear and acceptable if you define it. Write it out in full if you are unsure.

## 2. Patterns from the lecture and handwritten notes

| Token | RE | Source | Example |
|---|---|---|---|
| **Decimal** | `(sign)?(digit)+` | Theory Notes 2 | `-42`, `+7`, `123` |
| **Identifier** | `(letter)(letter \| digit)*` | Theory Notes 2 | `count`, `x1` |
| **Identifier (with _)** | `(letter)(letter \| digit \| _)*` | handwritten notes | `max_val` |
| **NIC (old format)** | `(digit)(digit)(digit)(digit)(digit)(digit)(digit)(digit)(digit)(V \| X)` | handwritten notes | `775772341V`, `789780129X` |

**Reading them:**
- *Decimal:* an **optional** sign, then **one or more** digits. The lecture's "decimal" means a whole number with an optional sign (in the sense of base-10), **not** a number with a decimal point.
- *Identifier:* **must start with a letter**, followed by **zero or more** letters or digits. This is the C rule for names.
- *NIC:* exactly **9 digits** followed by **V or X**.

> [!tip] If the question says "x or v" in lower case
> The question wording is "NIC number that contains **x or v** at the end". Allow both cases to be safe: `(digit)⁹(V | v | X | x)`.

## 3. Email address ending with `@gmail.com`

```text
Email = (letter)(letter | digit | _ | .)* @gmail.com
```

- A **letter first**, then any mix of letters, digits, underscore and dot, then the **literal** string `@gmail.com`.
- Example: `ranshitha01@gmail.com`.
- **Assumption to state:** which characters are allowed before the `@`. Gmail's real rules are more complex. The exam wants a sensible, clearly stated pattern.

> [!warning] Beyond the slides
> The lecture and handwritten notes do not give an email pattern. This one follows the identifier pattern and is the usual model answer.

## 4. 2023/24 Q3c tokens

| Token | RE | Explanation | Example |
|---|---|---|---|
| **Binary number** | `(0 + 1)⁺` | one or more binary digits; use ⁺ (not *) because the empty string is not a number | `1011` |
| **SL mobile number** | `07(digit)(digit)(digit)(digit)(digit)(digit)(digit)(digit)` | literal `07`, then 8 more digits = 10 digits in total | `0771234567` |
| **Registration number** `YYYY/ABC/NNN` | `(digit)(digit)(digit)(digit) / (L)(L)(L) / (digit)(digit)(digit)` where `L = [A-Z]` | 4 digits, literal `/`, 3 capital letters, literal `/`, 3 digits | `2026/FAS/015` |
| **Password** | `(letter)(letter + digit)(letter + digit)(letter + digit)(letter + digit)(letter + digit)(letter + digit)*` | 1 letter + **exactly 5** more letters/digits gives the minimum 6, then any number more | `Abc123xyz` |

> [!important] The password trap
> `(letter)(letter | digit)*` alone is **wrong**: it accepts a one-character password. The "at least 6" condition needs **five forced** `(letter|digit)` after the first letter, **then** a star.

> [!note] Mobile number variations
> Your handwritten notes write a telephone pattern starting with an optional `+94`. The 2023/24 question fixes the format: *starts with 07, 10 digits*. Answer exactly that. Optionally mention `(+94 7 | 07)(digit)⁸` as an extension.
> For the registration number, the example `2026/FAS/015` uses capital letters, so `[A-Z]` is the safe choice for `ABC`.

## 5. Practical explanation
A lexical analyzer uses exactly these patterns: `Identifier` to recognise variable names, `Decimal` for integer constants. Form validation on websites uses the same idea for emails, phone numbers and passwords (with regex syntax like `^07[0-9]{8}$`).

## 6. Exam-relevant points
- Define `letter`, `digit`, `sign` at the top. It earns structure marks.
- One RE + one example per part. State assumptions (case of letters, allowed email characters).
- Literal characters (`07`, `/`, `@gmail.com`) are written as they are.
