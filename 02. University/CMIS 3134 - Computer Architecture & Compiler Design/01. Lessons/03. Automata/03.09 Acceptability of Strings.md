# 03.09 · Acceptability of Strings by a DFA / NDFA

> [!info] [[03.00 Automata|Lesson 3]] · Theory Notes 3 · Priority 🔴 High (4 of 5 papers, 40 marks)
> **Asked as:** "Consider the following finite automaton and check whether the following strings are acceptable or not. Show each step." (2019/20 Q3d, 2020/21 Q3d, 2021/22 Q4d, 2022/23 Q4d) · and testing strings on your own DFA (2023/24 Q4d(ii))

## 1. The acceptance condition

> [!abstract] Theory Notes 3
> "A string is accepted by a DFA/NDFA **iff the DFA/NDFA starting at the initial state ends in an accepting state** (any of the final states) **after reading the string wholly**."
>
> A string S is accepted by (Q, Σ, δ, q0, F) iff $\delta^*(q_0, S) \in F$.
> The language accepted is $L = \{ S \mid S \in \Sigma^* \text{ and } \delta^*(q_0, S) \in F \}$.
> A string S′ is not accepted iff $\delta^*(q_0, S') \notin F$.
> The language not accepted (the **complement** of L) is $L' = \{ S \mid S \in \Sigma^* \text{ and } \delta^*(q_0, S) \notin F \}$.

## 2. Method for a DFA

1. Write the **transition table** from the diagram (prevents misreading arrows).
2. Identify **q0** and **F**.
3. For each string, apply δ **one symbol per line**, showing the current state.
4. State the final state and the verdict: *"ends in C, C ∈ F, therefore accepted."*

**Example** (2022/23 Q4d machine: A start, C final; A: a→B, b→A; B: a→B, b→C; C: a→B, b→A):

```text
abaaab:  A -a-> B -b-> C -a-> B -a-> B -a-> B -b-> C     C ∈ F  ⇒ ACCEPTED
babbbba: A -b-> A -a-> B -b-> C -b-> A -b-> A -b-> A -a-> B   B ∉ F ⇒ REJECTED
```

## 3. Method for an NDFA (important for the past-paper machines!)

> [!warning] The past-paper machines (2019/20, 2020/21, 2021/22) are NDFAs
> In those diagrams, state **A** has a self-loop on **a, b, c** *and* an arrow **A –b→ B**. So on input **b**, A can go to **A or B**. That is non-deterministic. In 2021/22, **B** also has two arrows on **b** (to C and back to A).
> Do not trace them as if they were DFAs. A single-path trace can wrongly reject a string that *is* accepted by another path.

**Two correct ways to present an NDFA trace:**

**(a) Set-of-states trace (most reliable):** keep the **set** of all states the machine could be in.

$$
S_0 = \{q_0\}, \qquad S_{i} = \bigcup_{q \in S_{i-1}} \delta(q, x_i)
$$

Accept if the final set contains a final state.

**(b) Accepting-path trace:** for an accepted string, show **one path** that ends in a final state. For a rejected string, argue that **no path** can reach the final state.

**Example** (2019/20 machine; A start, D final; A: a,b,c→A and b→B; B: a→C, b,c→A; C: a→C, b→D, c→A; D: a,b,c→D):

```text
bab:   {A} -b-> {A,B} -a-> {A,C} -b-> {A,B,D}    contains D ⇒ ACCEPTED
       accepting path: A -b-> B -a-> C -b-> D
bba:   {A} -b-> {A,B} -b-> {A,B} -a-> {A,C}      no D ⇒ REJECTED
```

**Shortcut for understanding:** in that machine, the only way to reach D is the path B –a→ C –(a)*→ C –b→ D, entered from A on b. So a string is accepted **iff it contains a substring of the form b a a\* b** (b, then one or more a's, then b). Use this to check your traces, but **still show the full trace** in the exam.

Full worked answers for every past-paper string: [[PP 03.2 - Acceptability and Designing Automata]].

## 4. Two traps to mention
1. **No transition defined:** if the machine has no move for the current symbol, that path **dies** and the string is rejected on that path. Say so explicitly.
2. **Symbol not in Σ:** the string is not over the alphabet, so it cannot be accepted.

## 5. Exam-relevant points
- 40 marks are for **complete, neat working**: table first, rule $\delta^*(q_0,S) \in F$ stated once, one line per symbol, explicit verdict.
- For NDFAs, use **sets of states** (or show an accepting path) and **say that the machine is non-deterministic**.
