# 01.10 · Symbol Table and Error Handler

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 + `compier note.pdf` p. 1 · Priority 🟡 Medium
> **Asked as:** "Briefly explain the use of having a Symbol Table in compilers" (2019/20 Q1c) · part of 2021/22 Q2d and 2023/24 Q1b.

## 1. Symbol Table: what it is

> [!abstract] Theory Notes 1
> "It is a **data-structure maintained throughout all the phases** of a compiler. All the **identifier's names along with their types** are stored here. The symbol table makes it easier for the compiler to **quickly search the identifier record and retrieve it**. The symbol table is also used for **scope management**."

So it is **not a phase**. It is a shared table that every phase reads from and writes to.

## 2. What it stores (example)

```c
int count;
float rate;
void f() { int count; }
```

| Name | Type | Scope | (other attributes, for example memory location) |
|---|---|---|---|
| `count` | int | global | … |
| `rate` | float | global | … |
| `f` | function → void | global | … |
| `count` | int | local to `f` | … |

The two `count` entries show **scope management**: the same name means different variables in different blocks.

> [!note] Beyond the slides
> The lecture mentions only names, types and scope. Memory location and the "who uses it" table below are standard textbook detail.

## 3. Why it is needed (uses)

| Use | Explanation |
|---|---|
| **Fast lookup** | Every phase repeatedly asks "what is this identifier?", so search and retrieval must be fast. |
| **Type checking** | Semantic analysis looks up declared types to check compatibility (for example to catch `int x = "10" + 5;`). |
| **Declaration before use** | If a name is not in the table, it was never declared, so an error is reported. |
| **Scope management** | Tells which declaration a name refers to in each block. |
| **Code generation** | Allocates memory locations and registers to identifiers. |

### Who uses it

| Phase | What it does with the symbol table |
|---|---|
| Lexical analysis | Creates entries for new identifiers |
| Syntax analysis | Adds structural information |
| Semantic analysis | Reads and adds type information, checks declarations |
| Intermediate code generation | Looks up names and temporaries |
| Code optimization | Uses information to decide what can be removed or reordered |
| Code generation | Allocates memory and registers |

## 4. Error Handler

Your handwritten notes draw an **Error Handler** box connected to all phases, next to the symbol table. It:
- receives errors from every phase,
- **records and reports** them with useful messages,
- applies **recovery** so compilation continues and **many errors can be reported in one run**. This is the "error detection and recovery" duty in the compiler definition ([[01.01 What is a Compiler]]).

## 5. Exam-relevant points
- Definition keywords: **data structure · maintained throughout all phases · identifier names + types · quick search/retrieve · scope management**.
- Say clearly it is **not a phase** and draw it spanning the phases.
- Give 3–4 uses with one example.
