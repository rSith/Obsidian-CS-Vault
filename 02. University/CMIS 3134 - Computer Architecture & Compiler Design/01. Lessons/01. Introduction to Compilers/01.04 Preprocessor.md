# 01.04 · The Preprocessor

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 · Priority 🟡 Medium
> **Asked as:** "Briefly explain the usages of the Pre-Processor in a Language Processing System." (2020/21 Q1c, 20 marks)

## 1. What is it?

> [!abstract] Definition (Theory Notes 1)
> "A preprocessor, generally considered as a **part of compiler**, is a tool that **produces input for compilers**. It deals with **macro-processing, augmentation, file inclusion, language extension**, etc."

It is the **first** tool in the [[01.03 Language Processing System]]. It works on the source code **as text**, before any real compilation starts.

## 2. Why is it used?

- To let programmers **reuse code** (header files) instead of copying it.
- To give **names to constants** instead of "magic numbers".
- To **include or exclude** parts of the code for different situations (debug vs release builds, different operating systems).
- To **extend the language** with shorthand constructs that it expands into legal code.

## 3. The four usages named in the lecture

| Usage | What it does | C example |
|---|---|---|
| **Macro processing** | Replaces every use of a defined name with its definition | `#define PI 3.14` turns every `PI` into `3.14` |
| **File inclusion** | Copies the whole contents of another file into the source | `#include <stdio.h>` |
| **Augmentation** | Adds or removes code sections (for example conditional compilation) | `#ifdef DEBUG … #endif` |
| **Language extension** | Lets the programmer use constructs not in the base language, which it expands into legal code | function-like macros such as `#define SQR(x) ((x)*(x))` |

> [!warning] Beyond the slides
> The lecture lists only the four names. The explanations and C examples are standard C usage added to make each item concrete. "Augmentation" is not explained in the notes. Reading it as conditional addition or removal of code is the usual interpretation.

## 4. How it works

1. It scans the source file for lines starting with `#` (preprocessor directives).
2. It performs **pure text substitution**: it does **not** check syntax or types.
3. Its output, the **modified / pure high-level source**, is what the compiler actually reads.

```c
#include <stdio.h>
#define MAX 100
int main() { int a[MAX]; printf("%d", MAX); }
```

After preprocessing, the compiler sees the full text of `stdio.h` followed by:

```c
int main() { int a[100]; printf("%d", 100); }
```

## 5. Important distinction

| Preprocessor | Compiler |
|---|---|
| Text substitution only | Full analysis: lexical, syntax, semantic |
| Does not understand C grammar or types | Checks grammar and types |
| Output: modified source code | Output: assembly code |
| Handles `#` directives | Never sees the `#` directives (already processed) |

## 6. Exam-relevant points
- State its **position** (first, before the compiler) and its **output** (modified source).
- Name **all four usages** and give **an example for at least two** (`#define`, `#include`).
- Say that it does **textual work only, with no syntax checking**.
