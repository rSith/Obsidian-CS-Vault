# 01.01 · What is a Compiler?

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 · Priority 🔴 High
> **Asked as:** "What is the primary role of a compiler in programming?" (2022/23 Q1a) · "List the three analyses performed at the front end…" (2022/23 Q1b) · part of every "compiler vs …" question.

## 1. What is it?

> [!abstract] Definition (Theory Notes 1)
> A **compiler** translates the code written in one language to some other language **without changing the meaning of the program**. It is also expected that a compiler should make the target code **efficient and optimized in terms of time and space**.

In simple words: you write a program in a language that is easy for *you* (C, Java). The compiler rewrites it in a language that is close to what the *machine* understands (assembly, then machine code). The program must still do exactly the same thing.

The lecture also says, in the Language Processing System section:

> "A compiler is a program that converts **high-level language to assembly language**."

## 2. Why is it used?

- Hardware only understands binary (see [[01.02 Why Computers Need Translators]]). Humans cannot sensibly write large programs in binary.
- The compiler lets us write **readable, portable, high-level** code and still get **fast, efficient** machine code.
- It **checks the program for errors** before it runs, and reports them.

## 3. The three ideas inside the definition

Examiners give marks for each idea separately, so name all three:

| Idea | Meaning |
|---|---|
| **Translation** | Source language (high-level) → target language (assembly / machine level) |
| **Meaning preserved** | The translated program must behave exactly like the original. |
| **Efficiency** | The target code must be optimized in **time** (runs fast) and **space** (uses little memory). This is why optimization is a phase of its own. |

## 4. Compiler design principles: front end and back end

> [!abstract] From Theory Notes 1
> "Compiler design covers basic **translation mechanism** and **error detection & recovery**. It includes **lexical, syntax, and semantic analysis as front end**, and **code generation and optimization as back-end**."

| | Front end (analysis) | Back end (synthesis) |
|---|---|---|
| Phases | Lexical analysis → Syntax analysis → Semantic analysis | (Intermediate code generation →) Code optimization → Code generation |
| Job | **Breaks the program down** and checks it is correct | **Builds the target program up** and makes it efficient |
| Depends on | The **source language** | The **target machine** |
| Output | A verified internal representation (annotated syntax tree) | Re-locatable machine code |

**Why the split matters (practical point):** the front end does not care which processor you target, and the back end does not care which language you wrote in. One front end can be paired with several back ends, so the same C compiler can produce code for different processors.

> [!note] Where does intermediate code generation belong?
> The typed notes list only "code generation and optimization" as the back end. Intermediate code generation sits between the two halves. Most textbooks put it with the back end (synthesis), and that is how it is drawn here. If you are asked for "the three analyses at the front end", the answer is **lexical, syntax, semantic**.

## 5. Two duties that run through the whole compiler

1. **Translation and optimization**, the main job.
2. **Error detection and recovery.** The compiler reads the *whole* program and keeps going after an error so it can report *many* errors in one run (unlike an interpreter, which stops at the first error, see [[01.05 Compiler, Interpreter, Assembler and De-compiler]]).

## 6. Example

```c
int area = width * height;
```

The compiler checks that `width` and `height` are declared and are numbers. It then produces something like (illustrative assembly, not from the notes):

```asm
MOV  R1, width
MUL  R1, height
MOV  area, R1
```

The meaning (multiply and store) is unchanged. Only the language changed.

## 7. Exam-relevant points
- Definition = **translate + meaning unchanged + efficient in time and space**. Learn the sentence.
- "Role of a compiler" (20 marks): definition → direction (high-level → assembly/machine) → efficiency/optimization → error detection & recovery → why it matters.
- Front end = **lexical, syntax, semantic analysis**. Say what each produces: tokens → parse tree → annotated syntax tree. See [[01.08 Front-End Phases and Error Detection]].
