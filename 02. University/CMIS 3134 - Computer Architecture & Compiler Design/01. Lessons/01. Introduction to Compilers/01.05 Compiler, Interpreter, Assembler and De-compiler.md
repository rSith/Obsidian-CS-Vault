# 01.05 · Compiler vs Interpreter vs Assembler vs De-compiler

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 · Priority 🔴 High (4 of 5 papers)
> **Asked as:** "Compare and contrast Compiler and Assembler" (2019/20 Q1a) · the **swapped-definitions** statement (2020/21 Q1a) · "What is meant by a compiler and how does it differ from an Interpreter and an Assembler?" (2021/22 Q1a) · "Distinguish between Compiler, De-compiler, Interpreter, Assembler" (2023/24 Q2b)

All four are **translators**: programs that convert a program from one language to another. What separates them is **(1) the input language, (2) the output language and (3) how they process it**.

## 1. Definitions

> [!abstract] Compiler (Theory Notes 1)
> Translates code in one language into another **without changing its meaning**, producing efficient target code. "A compiler is a program that converts **high-level language to assembly language**." It reads the **whole source code at once**, creates tokens, checks semantics, generates intermediate code and **may involve many passes**.

> [!abstract] Interpreter (Theory Notes 1)
> "An interpreter, like a compiler, translates high-level language into low-level machine language. The difference lies in the way they read the source code or input… An interpreter **reads a statement** from the input, converts it to an intermediate code, **executes it**, then takes the next statement in sequence. If an error occurs, an interpreter **stops execution and reports it**, whereas a compiler reads the whole program even if it encounters several errors."

> [!abstract] Assembler (Theory Notes 1)
> "An assembler translates **assembly language programs into machine code**. The output of an assembler is called an **object file**, which contains a combination of machine instructions as well as the data required to place these instructions in memory."

> [!warning] De-compiler is not in the course materials
> 2023/24 Q2b asks about a **de-compiler**, but none of the lecture notes or handwritten notes define it. The definition below is the standard one.
> **De-compiler:** a program that works in the **reverse** direction of a compiler. It takes **machine code / object code (an executable)** and tries to reconstruct an equivalent **high-level source program**. It is used for reverse engineering, recovering lost source code, and security analysis. The result is never identical to the original: variable names, comments and formatting are lost during compilation.

## 2. The comparison table

| | **Compiler** | **Interpreter** | **Assembler** | **De-compiler** |
|---|---|---|---|---|
| Input | High-level language | High-level language | Assembly language | Machine / object code |
| Output | Assembly (or machine) code | No stored object file; executes directly | Object file (machine code + placement data) | High-level source code |
| Unit of work | **Whole program**, possibly many passes | **One statement at a time** | Whole assembly file, near one-to-one mapping | Whole binary |
| Errors | Reads the whole program and **reports all errors together** | **Stops at the first error** | Reports errors in assembly | Not about error checking |
| Speed | Slower to start, compiled code runs fast repeatedly | Starts immediately, slower on repeated execution | Fast, simple translation | n/a |
| Direction | Down (high → low) | Down, with execution | Down (assembly → machine) | **Up** (low → high) |
| Example | `gcc` for C | Python interpreter | `as`, NASM | Ghidra, IDA (illustrative) |

> [!note] Beyond the slides
> The "speed" row and the tool examples are general knowledge, not from the notes. The rows on input/output, whole program vs one statement, and errors come directly from Theory Notes 1.

## 3. Compiler vs Assembler (compare **and** contrast)

**Similarities**
- Both are **translators** and part of the same [[01.03 Language Processing System]].
- Both produce output **closer to the machine** than their input.
- Both detect and report errors in their input.

**Differences**

| Compiler | Assembler |
|---|---|
| Input: **high-level** language | Input: **assembly** language |
| Output: **assembly** code | Output: **object file (machine code)** |
| Complex: six phases with analysis and optimization | Simple: mnemonics map almost one-to-one to machine instructions |
| Comes **first** in the pipeline | Comes **after** the compiler; it translates the compiler's output |

## 4. The "do you agree?" trap (2020/21 Q1a)

> *"A compiler is a program that converts Low-level language to assembly language. Similarly, an assembler is a program that converts the High-level language to machine-level language."*

**Answer: No.** The two definitions are wrong and swapped.
- A **compiler** converts **high-level** language into **assembly** language.
- An **assembler** converts **assembly** language into **machine-level** language.
- Justification: in the pipeline *source → compiler → assembly → assembler → object code*, the compiler's output is the assembler's input. An assembler never sees high-level code.

## 5. Why this matters in practice
- **C and C++** are compiled: you ship a fast executable.
- **Python** is usually interpreted, which makes it convenient for testing line by line, but it stops at the first runtime error.
- **Assemblers** are used for low-level system code and are always used behind the scenes by C compilers.
- **De-compilers** are used by security analysts to understand malware or legacy programs without source code.

## 6. Exam-relevant points
- Always state the **input → output pair** for each tool. That pair is what distinguishes them.
- Compiler vs interpreter: **whole program vs one statement**, **all errors vs stop at first error**, **object code vs no object code**.
- Point out that compiler and assembler are **not alternatives**. They are **consecutive stages**.
- A table earns presentation marks and is faster to write.
