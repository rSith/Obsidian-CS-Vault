# 01.02 · Why Computers Need Translators (Hardware, Binary and High-Level Code)

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 · Priority 🔴 High
> **Asked as:** "Briefly explain why computers cannot directly execute or understand high-level programming languages such as C or Python." (2023/24 Q1a) · "What challenges would programmers face if compilers did not exist?" (2022/23 Q1c)

## 1. What the lecture says

> [!quote] Theory Notes 1
> "Computers are a balanced mix of software and hardware. Hardware is just a piece of mechanical device and its functions are being controlled by compatible software. Hardware understands instructions in the form of **electronic charge**, which is the counterpart of **binary language** in software programming. Binary language has only two alphabets, **0 and 1**. To instruct, the hardware codes must be written in binary format, which is simply a series of 1s and 0s. It would be a **difficult and cumbersome** task for computer programmers to write such codes, which is why we have compilers to write such codes."

## 2. How it works, step by step

1. Hardware is electronic. At the lowest level it can only detect **charge present** or **charge absent**: two states.
2. Those two states are written **1** and **0**. So the only "language" the hardware truly understands is binary, with the alphabet $\{0, 1\}$.
3. A high-level language such as C or Python is made of English-like keywords (`while`, `int`, `print`), symbols and structure. A word like `while` has **no electrical meaning**.
4. Therefore every high-level program must be **translated** into binary machine code before the hardware can execute it.
5. That translation is done by a chain of tools, the [[01.03 Language Processing System]] (compiler → assembler → linker → loader), or by an interpreter.

## 3. Why not just write binary? (the "if compilers did not exist" answer)

| Problem | Explanation |
|---|---|
| **Unreadable** | A page of 0s and 1s cannot be understood, reviewed or maintained by humans. |
| **Error-prone** | One wrong bit gives a silent, hard-to-find bug. There is no error checking. |
| **Very long and slow to write** | A few lines of C become thousands of bits, so development time and cost explode. |
| **Not portable** | Binary is tied to one processor's instruction set. A new CPU means rewriting the whole program. |
| **No abstraction** | No variables, functions or loops. The programmer manages memory addresses and registers by hand. |
| **No optimization help** | The programmer alone is responsible for efficient instruction ordering and memory use. |

> [!warning] Beyond the slides
> The lecture gives only the core reason ("difficult and cumbersome"). The table's extra points (portability, abstraction, optimization) are standard reasoning used to earn full marks on the 20-mark question. They are not quoted from the notes.

## 4. Example

The C statement

```c
x = a + b;
```

might become several machine instructions, each of which is a binary pattern such as `10001011 01000101 11111000`. A programmer writing only binary would have to work out every such pattern by hand, for every statement, for one specific CPU.
