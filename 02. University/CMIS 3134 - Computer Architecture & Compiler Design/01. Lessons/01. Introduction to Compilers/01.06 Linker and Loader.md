# 01.06 · Linker and Loader

> [!info] [[01.00 Introduction to Compilers|Lesson 1]] · Theory Notes 1 · Priority 🟡 Medium
> **Asked as:** "What are the uses of having a Linker and a Loader in the execution process?" (2021/22 Q2a) · also needed for the LPS questions and 2022/23 Q2d.

## 1. Linker

> [!abstract] Definition (Theory Notes 1)
> "Linker is a computer program that **links and merges various object files** together in order to make an **executable file**. All these files might have been compiled by separate assemblers. The major task of a linker is to **search and locate referenced module/routines** in a program and to **determine the memory location** where these codes will be loaded, making the program instruction to have **absolute references**."

**Why is it needed?** A real program is never one file. It is:
- your own object file(s),
- **library code** (for example `printf` lives in the C library, not in your file),
- possibly other separately compiled modules.

**How it works:**
1. Takes all object files and library files.
2. **Searches for and locates** every routine the program refers to (for example finds `printf`).
3. **Resolves addresses.** Each object file was produced as if it started at address 0, so the linker recalculates addresses so all pieces fit together and every reference becomes an **absolute reference**.
4. Writes one **executable file** to disk.

## 2. Loader

> [!abstract] Definition (Theory Notes 1)
> "Loader is a **part of operating system** and is responsible for **loading executable files into memory and execute them**. It **calculates the size** of a program (instructions and data) and **creates memory space** for it. It **initializes various registers** to initiate execution."

**How it works:**
1. Reads the executable file from disk.
2. Calculates how much memory the program (instructions + data) needs.
3. Creates (allocates) that memory space and copies the program in.
4. Initializes the CPU registers and starts execution.

## 3. Linker vs Loader

| | Linker | Loader |
|---|---|---|
| Position | After the assembler | After the linker (last step) |
| Belongs to | The tool chain (development tools) | The **operating system** |
| Input | Object files + library files | Executable file |
| Main job | Merge files, locate routines, resolve references | Allocate memory, load, initialize registers, start execution |
| Output | Executable **file on disk** | Running **program in memory** |

## 4. Example

```c
#include <stdio.h>
int main() { printf("Hi"); return 0; }
```

- After assembling: `main.o` contains a call to `printf`, but no code for `printf`.
- **Linker:** finds `printf` in the standard C library, merges it with `main.o` and fixes the call address. The result is `main.exe`.
- **Loader:** when you run `main.exe`, the OS loader allocates memory, copies the program in, sets registers and jumps to `main`.

## 5. Exam-relevant points
- Treat "linker and loader" as **two half-answers** (about 10 marks each).
- Linker keywords: **merge object files · locate referenced modules/routines · absolute references · executable file**.
- Loader keywords: **part of OS · calculates size · creates memory space · initializes registers · executes**.
- Hand-over sentence: *the linker produces a file on disk, the loader turns it into a running program in memory.*
