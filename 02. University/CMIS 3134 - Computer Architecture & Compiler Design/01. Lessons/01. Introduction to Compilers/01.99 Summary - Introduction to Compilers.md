# 01.99 · Lesson Summary: Introduction to Compilers

> [!abstract] Back to [[01.00 Introduction to Compilers]] · Practice: [[PP 01.1 - Compilers, Translators and the Language Processing System]] · [[PP 01.2 - Phases of a Compiler]]

## Must know
- **Compiler:** translates code from one language to another **without changing its meaning**, making the target code **efficient in time and space**. Converts **high-level → assembly**.
- **Front end** = lexical + syntax + semantic analysis (source-language dependent). **Back end** = (intermediate code +) optimization + code generation (machine dependent).
- **Hardware** understands only **electronic charge = binary {0,1}**. High-level code must be translated.
- **LPS:** Source → **Preprocessor** → **Compiler** → **Assembler** → **Linker** (+ library files) → **Loader** → **Memory**.
- **C program on a host machine:** write C → compiler → assembly → assembler → object → linker → executable → loader → memory → execute.
- **Six phases:** Lexical → Syntax → Semantic → Intermediate code → Optimization → Code generation, plus **Symbol table** and **Error handler** across all phases. *Each phase takes the previous phase's output.*

## Important definitions
- **Preprocessor:** part of the compiler; produces input for the compiler: macro-processing, augmentation, file inclusion, language extension.
- **Interpreter:** translates and executes **one statement at a time**; **stops at the first error**.
- **Assembler:** assembly → machine code; output is an **object file** (machine instructions + placement data).
- **Linker:** merges object files into an **executable**; locates referenced modules/routines; gives **absolute references**.
- **Loader:** **part of the OS**; loads the executable into memory, calculates size, creates memory space, initializes registers.
- **Lexical analysis:** characters → lexemes → **tokens `<token-name, attribute-value>`**.
- **Syntax analysis:** tokens → **parse tree**; checks token arrangement against the **grammar**.
- **Semantic analysis:** checks the parse tree follows **language rules** (types, declared before use); outputs an **annotated syntax tree**.
- **ICG:** code for an **abstract machine**, between high-level and machine language.
- **Code optimization:** removes unnecessary code, rearranges statements, faster without wasting CPU/memory.
- **Code generation:** optimized intermediate code → **re-locatable machine code**.
- **Symbol table:** data structure kept across all phases; names + types; fast search; scope management.
- **De-compiler** (not in notes): machine/object code → high-level source (the reverse of a compiler).

## Important comparisons

| Compiler | Interpreter |
|---|---|
| Whole program, many passes | One statement at a time |
| Reports all errors | Stops at first error |
| Produces object code | No object code |

| Compiler | Assembler |
|---|---|
| High-level → assembly | Assembly → machine (object file) |
| Six phases, optimizes | Near one-to-one mapping |
| First in pipeline | After the compiler |

| Lexical analysis | Syntax analysis | Semantic analysis |
|---|---|---|
| chars → tokens | tokens → parse tree | parse tree → annotated tree |
| invalid token | missing `;`, unbalanced `()` | type mismatch, undeclared |

| Linker | Loader |
|---|---|
| Tool chain; makes an executable file | OS; puts the program in memory and runs it |

## Important examples
- `int x = "10" + 5;` → passes lexical and syntax; **semantic analysis** detects string + int.
- Compiles but wrong output → **logical** (`+` instead of `*`) or **run-time** (divide by zero) errors.
- Embedded systems → optimization is essential; key phases: **optimization, code generation, ICG**.
