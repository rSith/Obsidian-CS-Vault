# 06.02 · Tokens, Lexemes and Patterns (and the Token Categories)

> [!info] [[06.00 Lexical Analysis|Lesson 6]] · Theory Notes 6 + `compier note.pdf` p. 2 · Priority 🔴 High (needed for every tokenizing answer)

## 1. Definitions

> [!abstract] Theory Notes 6
> "**Lexemes** are said to be a sequence of characters (alphanumeric) in a token. There are some predefined rules for every lexeme to be identified as a valid token. These rules are defined by grammar rules, by means of a **pattern**. A pattern explains what can be a token, and these patterns are defined by means of **regular expressions**."

| Term | Meaning | In `int value = 100;` |
|---|---|---|
| **Lexeme** | The actual characters in the source code | `value` |
| **Pattern** | The rule describing what lexemes of a kind look like, written as an RE | `(letter)(letter \| digit)*` |
| **Token** | The category the lexeme is classified into, output as `<token-name, attribute-value>` | `<identifier, value>` |

> [!tip] One sentence for the exam
> A **lexeme** is the concrete text; a **pattern** (a regular expression) describes the shape of such lexemes; a **token** is the classified pair the analyzer passes to the parser.

## 2. Token categories

**Theory Notes 6:** "In programming language, **keywords, constants, identifiers, strings, numbers, operators and punctuations symbols** can be considered as tokens."

**Handwritten notes, "7 types of tokens":** special characters, identifiers (method names / variable names), operators, constants, keywords (void, double, int, return), punctuators `( ) { } ;`, literals.

| Category | What it covers | Examples |
|---|---|---|
| **Keyword** | Reserved words of the language | `int`, `void`, `if`, `else`, `return`, `double` |
| **Identifier** | Names chosen by the programmer: variables, functions | `main`, `age`, `a`, `printf` |
| **Constant / Number** | Fixed numeric values | `20`, `25`, `100` |
| **Literal / String** | Text in quotes | `"Max is %d"` |
| **Operator** | Arithmetic, assignment, relational, logical | `=`, `+`, `<`, `==`, `&&` |
| **Punctuator / Symbol** | Structural symbols | `(` `)` `{` `}` `;` `,` |
| **Special character** | Symbols with special roles | `#`, `&` |

> [!important] Distinctions that are marked
> - **keyword vs identifier:** `int`, `return` are keywords; `main`, `printf` are **identifiers** (a library function name is not a keyword).
> - **constant vs literal:** `25` is a constant (number); `"Age after 5 years: %d\n"` is a string **literal**, and the whole quoted string (with quotes) is **one** token.
> - **operator vs punctuator:** `=`, `+`, `<` are operators; `(`, `)`, `{`, `}`, `;`, `,` are punctuators.

## 3. The lecture's example

```c
int value = 100;
```

> "contains the tokens: `int` (keyword), `value` (identifier), `=` (operator), `100` (constant) and `;` (symbol)." (Theory Notes 6)

| Lexeme | Token |
|---|---|
| `int` | `<keyword, int>` |
| `value` | `<identifier, value>` |
| `=` | `<operator, =>` |
| `100` | `<constant, 100>` |
| `;` | `<punctuator, ;>` |
