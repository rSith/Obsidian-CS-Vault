# 06.05 · Tokenizing a C Program (the Exam Question)

> [!info] [[06.00 Lexical Analysis|Lesson 6]] · Theory Notes 6 + `compier note.pdf` p. 2 · Priority 🔴 High (4 of 5 papers)
> **Asked as:** "Perform a lexical analyzer to generate token(s) of the following program." 2019/20 Q1b and 2020/21 Q1b (Program 1, 20 marks); 2021/22 Q1c (20 marks) and 2022/23 Q1d (40 marks) (Program 2)

## 1. Method

1. Work through the code **strictly left to right, top to bottom**.
2. **Skip** whitespace and **comments** (they produce no tokens). Say this in one sentence.
3. Treat `#include <stdio.h>` as a **preprocessor directive**: it is handled by the preprocessor **before** lexical analysis ([[06.01 Role of the Lexical Analyzer]]). Say this, and optionally list it.
4. For every lexeme write `<token-name, attribute-value>`, or use a 2-column table **Lexeme | Token**.
5. Use the **longest match rule** for multi-character operators (`==`, `<=`) ([[06.04 Longest Match Rule and Rule Priority]]).
6. A **string literal including its quotes** is one token.
7. **Count** the tokens at the end. It shows completeness.

> [!tip] Format used in your handwritten notes
> `<keyword, int>`, `<identifier, main>`, `<punctuator, (>`, … (p. 2). The handwritten example program `int main(){ int x, a=2, b=3, c=5; x = a+b*c; printf("The value is %d", x); }` is tokenized this way.

## 4. Variations you may meet
- `void` and `int` are **keywords**; `main` and `printf` are **identifiers**.
- `\n` inside a string is part of the literal, not a separate token.
- `<` in `if(a < b)` is an **operator** (comparison), not a punctuator.
- Some answers list `#include` and `<stdio.h>` as `<preprocessor, #include>` and `<header, stdio.h>`. If you do, say that the preprocessor normally removes them before lexical analysis.

## 5. Exam-relevant points
- **Every** lexeme gets a token, including each bracket, comma and semicolon (marks are per token).
- Classify correctly: keyword/identifier, constant/literal, operator/punctuator.
- Say "whitespace and comments are removed".
- For the 40-mark version (2022/23), add a short explanation of the method and the token categories, and finish with the totals.
