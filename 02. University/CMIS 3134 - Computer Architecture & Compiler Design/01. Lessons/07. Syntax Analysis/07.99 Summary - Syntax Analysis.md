# 07.99 · Lesson Summary: Syntax Analysis

> [!abstract] Back to [[07.00 Syntax Analysis]] · Practice: [[PP 07.1 - Grammars, Derivations and Ambiguity]] · [[PP 07.2 - Parsing (2019-20 only)]]

## Must know
- **Syntax analysis (parsing) = phase 2.** Input: token stream; output: **parse tree**; parses the whole code even with errors (error recovery).
- **REs cannot check balanced tokens** such as parentheses, so a **CFG** is used, recognised by a **push-down automaton**. **CFG ⊃ regular grammar.**
- **CFG = (V, Σ, P, S):** non-terminals, terminals, productions, start symbol.
- **Derivation:** sequence of productions giving the string; decisions: which non-terminal, which production. **LMD** replaces the left-most non-terminal; **RMD** replaces the right-most.
- **Parse tree:** root = start symbol; interior nodes = non-terminals; leaves = terminals; in-order traversal = input; deeper operators are evaluated first.
- **Ambiguous grammar:** more than one parse tree for at least one string. Bad for compilers; **no automatic detection/removal**; fix by **rewriting** or **associativity + precedence**.
- **Limitations of the parser:** cannot check token validity, declaration before use, initialization before use, or type validity of operations. These are semantic analysis jobs.

## Important definitions
- **Associativity:** operand with operators on both sides; + − * / left-associative; ^ right-associative.
- **Precedence:** different operators sharing an operand; `2+3*4 = 2+(3*4)`.
- **Left recursion:** A ⇒ Aα (immediate) or via a loop (indirect). Causes infinite loops in top-down parsers. Fix: A → βA′, A′ → αA′ | ε.
- **Left factoring:** A → αβ | αγ becomes A → αA′, A′ → β | γ.
- **FIRST(α):** terminals that can start strings derived from α. **FOLLOW(A):** terminals that can appear right after A ($ for the start symbol).

## Important results (past papers)
- `S → aSbb | abb` → $\{a^n b^{2n} : n \ge 1\}$.
- `S → aSb | bSa | ab | ba` → even-length strings where matching positions differ; **"aabbab" is not derivable**.
- `S → aSb | bSa | SS | ε` → exactly the strings with equal a's and b's; **ambiguous** for "abab".
- `S → AB | aaB, A → a | Aa, B → b` → **ambiguous** for "aab".
- `S → AB | aB, A → a | Aa, B → b` → exactly $a^n b$, n ≥ 1.
- `S → aB | bA, A → aS | bAA | ε, B → b | bS | aBB` (as printed) → every string has #b ≥ #a and ends in b, so **none** of the 4 test strings is generated, and **"aababab" has no derivation**.
- 2019/20: B → **0BB** (not 0DD); 0010101 and 110100101110 are **not** generated.

## Important comparisons

| LMD | RMD |
|---|---|
| replace left-most non-terminal | replace right-most non-terminal |
| left-sentential forms | right-sentential forms |

| Regular grammar | CFG |
|---|---|
| finite automaton | push-down automaton |
| tokens | program structure |

| Top-down | Bottom-up |
|---|---|
| root → leaves, LMD | leaves → root, reverse RMD |
| LL(1) | LR(0), SLR, LALR |
