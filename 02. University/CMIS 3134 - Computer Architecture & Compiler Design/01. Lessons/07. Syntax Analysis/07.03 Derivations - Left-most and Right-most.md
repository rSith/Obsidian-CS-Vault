# 07.03 · Derivations: Left-most and Right-most

> [!info] [[07.00 Syntax Analysis|Lesson 7]] · Theory Notes 7 + `Compiler note.pdf` · Priority 🔴 High (all 5 papers)
> **Asked as:** "Generate Left Most and Right Most Derivation(s) for…" (2019/20 Q7b, 2020/21 Q7c, 2021/22 Q8c, 2022/23 Q8c, 2023/24 Q8c) · "Find out the derivations of the following grammar" (2020/21 Q7a)

## 1. What is a derivation?

> [!abstract] Theory Notes 7
> "A derivation is basically a **sequence of production rules, in order to get the input string**. During parsing, we take two decisions for some sentential form of input:
> - Deciding the **non-terminal which is to be replaced**.
> - Deciding the **production rule** by which the non-terminal will be replaced."

A **sentential form** is any string of terminals and non-terminals you can reach from S during a derivation. We write ⇒ for "derives in one step".

## 2. Left-most and right-most derivations

> [!abstract] Theory Notes 7
> - **Left-most derivation:** "If the sentential form of an input is scanned and replaced from **left to right**, it is called left-most derivation. The sentential form derived by the left-most derivation is called the **left-sentential form**."
> - **Right-most derivation:** "If we scan and replace the input with production rules, from **right to left**, it is known as right-most derivation. The sentential form derived from the right-most derivation is called the **right-sentential form**."

In practice:
- **LMD:** at every step, replace the **left-most non-terminal**.
- **RMD:** at every step, replace the **right-most non-terminal**.

## 3. The lecture's example

Production rules: E → E + E, E → E * E, E → id. Input: `id + id * id`.

| Left-most derivation (as in the notes) | Right-most derivation (as in the notes) |
|---|---|
| E ⇒ **E** * E | E ⇒ E + **E** |
| ⇒ **E** + E * E | ⇒ E + E * **E** |
| ⇒ id + **E** * E | ⇒ E + **E** * id |
| ⇒ id + id * **E** | ⇒ **E** + id * id |
| ⇒ id + id * id | ⇒ id + id * id |

(**Bold** = the non-terminal being replaced next.)

> [!important] Look closely: these two derivations build different trees
> The lecture's LMD starts with **E ⇒ E \* E** (so `*` is at the root, meaning (id + id) \* id), while its RMD starts with **E ⇒ E + E** (`+` at the root, meaning id + (id \* id)). The same string with **two different parse trees** shows that this grammar is **ambiguous** ([[07.05 Ambiguity]]).
> An LMD and an RMD of the **same** tree differ only in the **order** of replacements. For example, an LMD with `+` at the root: E ⇒ E + E ⇒ id + E ⇒ id + E \* E ⇒ id + id \* E ⇒ id + id \* id.

## 4. Worked example with two non-terminals (2020/21 Q7a)

G: S → AB, A → aA | a, B → bB | b. String `aabb`:

| LMD | RMD |
|---|---|
| S ⇒ **A**B | S ⇒ A**B** |
| ⇒ a**A**B (A → aA) | ⇒ Ab**B** (B → bB) |
| ⇒ aa**B** (A → a) | ⇒ **A**bb (B → b) |
| ⇒ aab**B** (B → bB) | ⇒ a**A**bb (A → aA) |
| ⇒ aabb (B → b) | ⇒ aabb (A → a) |

Same tree, same string; only the **order** differs: LMD finishes A first, RMD finishes B first.

## 5. Worked example: `(id + id) * id + id` (2019/20 Q7b)

G: E → E + E | E * E | (E) | id. Using the usual precedence (`*` binds tighter), the top-level operator is the last `+`.

**LMD:**
E ⇒ E + E ⇒ E * E + E ⇒ (E) * E + E ⇒ (E + E) * E + E ⇒ (id + E) * E + E ⇒ (id + id) * E + E ⇒ (id + id) * id + E ⇒ (id + id) * id + id

**RMD:**
E ⇒ E + E ⇒ E + id ⇒ E * E + id ⇒ E * id + id ⇒ (E) * id + id ⇒ (E + E) * id + id ⇒ (E + id) * id + id ⇒ (id + id) * id + id

The brackets are **terminals** produced by E → (E).

## 6. Tips for writing derivations
- One step per line, ⇒ between steps, the rule used in brackets if there is room.
- **Underline** the non-terminal you replace at each step.
- Plan the **parse tree first** (which production goes at the root), then write the derivation.
- In a grammar where every sentential form has **only one** non-terminal (like S → aB | bA, B → bS …), the LMD and RMD are **identical**. Say so: it is a correct observation, not a mistake.
