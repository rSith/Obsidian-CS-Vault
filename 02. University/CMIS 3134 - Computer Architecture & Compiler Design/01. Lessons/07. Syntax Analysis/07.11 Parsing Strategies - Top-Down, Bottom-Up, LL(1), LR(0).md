## 1. Top-down vs bottom-up parsing (2019/20 Q8a)

| | Top-down parser | Bottom-up parser |
|---|---|---|
| Builds the parse tree | From the **root (start symbol) down** to the leaves | From the **leaves (input tokens) up** to the root |
| Derivation it traces | **Left-most** derivation | **Right-most derivation in reverse** |
| Main operation | **Expand** a non-terminal using a production | **Shift** tokens onto a stack and **reduce** a right side to its left side |
| Examples | Recursive descent, **LL(1) / predictive** | Shift-reduce, **LR(0)**, SLR, LALR, CLR |
| Grammar restrictions | No left recursion; needs left factoring | Handles left recursion; larger class of grammars |
| Ease | Simpler to write by hand | More powerful, usually generated by tools (e.g. yacc) |

**Similarities:** both read the input left to right, both check the input against a CFG, both produce a parse tree and detect syntax errors.

## 2. Backtracking (2019/20 Q8b)

**Backtracking** is when a top-down parser **tries a production, finds that it does not match the input, undoes its work, and tries another production** for the same non-terminal. Brute-force recursive descent does this.

**Example:** grammar `S → cAd`, `A → ab | a`, input `cad`.
1. S → cAd: match `c`.
2. Try A → ab: match `a`, but the next input is `d`, not `b`. **Fail.**
3. **Backtrack:** undo A → ab and reset the input pointer to after `c`.
4. Try A → a: match `a`. Then match `d`. **Success.**

Backtracking is slow (it can take exponential time). **Predictive (LL(1)) parsers avoid it** by using one look-ahead token and a table.

## 3. LL(1) / predictive parser (2019/20 Q7d)

Grammar: S → A, A → aDC, C → dC | ε, D → b, E → g.

**Step 1: FIRST and FOLLOW** (worked in [[07.09 First and Follow Sets]]):

| NT | FIRST | FOLLOW |
|---|---|---|
| S | {a} | {$} |
| A | {a} | {$} |
| C | {d, ε} | {$} |
| D | {b} | {d, $} |
| E | {g} | ∅ (unreachable) |

**Step 2: table rules.** For each production X → α: put it in T[X, t] for every t ∈ FIRST(α); if ε ∈ FIRST(α), put it in T[X, t] for every t ∈ FOLLOW(X).

**Step 3: LL(1) parsing table:**

| | a | b | d | g | $ |
|---|---|---|---|---|---|
| **S** | S → A | | | | |
| **A** | A → aDC | | | | |
| **C** | | | C → dC | | C → ε |
| **D** | | D → b | | | |
| **E** | | | | E → g | |

No cell has two entries, so the grammar is **LL(1)**. (E is unreachable; its row is never used.) The language is `a b d*`.

**Example parse of `abd`:**

| Stack | Input | Action |
|---|---|---|
| $S | abd$ | S → A |
| $A | abd$ | A → aDC |
| $CDa | abd$ | match a |
| $CD | bd$ | D → b |
| $Cb | bd$ | match b |
| $C | d$ | C → dC |
| $Cd | d$ | match d |
| $C | $ | C → ε |
| $ | $ | **accept** |

## 4. LR(0) parser table (2019/20 Q8c)

Grammar: S → AA, A → aA | b. **Augment:** S′ → S. Number the productions: (1) S → AA, (2) A → aA, (3) A → b.

**Canonical LR(0) item sets:**
- **I0:** S′ → ·S, S → ·AA, A → ·aA, A → ·b
- **I1** = goto(I0, S): S′ → S·
- **I2** = goto(I0, A): S → A·A, A → ·aA, A → ·b
- **I3** = goto(I0, a) = goto(I2, a) = goto(I3, a): A → a·A, A → ·aA, A → ·b
- **I4** = goto(I0, b) = goto(I2, b) = goto(I3, b): A → b·
- **I5** = goto(I2, A): S → AA·
- **I6** = goto(I3, A): A → aA·

**LR(0) parsing table** (sN = shift and go to state N, rN = reduce by production N):

| State | a | b | $ | A | S |
|---|---|---|---|---|---|
| 0 | s3 | s4 | | 2 | 1 |
| 1 | | | **accept** | | |
| 2 | s3 | s4 | | 5 | |
| 3 | s3 | s4 | | 6 | |
| 4 | r3 | r3 | r3 | | |
| 5 | r1 | r1 | r1 | | |
| 6 | r2 | r2 | r2 | | |

No conflicts, so the grammar is **LR(0)**.

## 5. Stack implementation for "aabb" (2019/20 Q8d)

(Checked by simulation.)

| Stack | Input | Action |
|---|---|---|
| 0 | aabb$ | shift 3 |
| 0 a 3 | abb$ | shift 3 |
| 0 a 3 a 3 | bb$ | shift 4 |
| 0 a 3 a 3 b 4 | b$ | reduce A → b (goto 6) |
| 0 a 3 a 3 A 6 | b$ | reduce A → aA (goto 6) |
| 0 a 3 A 6 | b$ | reduce A → aA (goto 2) |
| 0 A 2 | b$ | shift 4 |
| 0 A 2 b 4 | $ | reduce A → b (goto 5) |
| 0 A 2 A 5 | $ | reduce S → AA (goto 1) |
| 0 S 1 | $ | **accept** |

Reading the reductions in order gives the right-most derivation **in reverse**: S ⇒ AA ⇒ Ab ⇒ aAb ⇒ aaAb ⇒ aabb.
