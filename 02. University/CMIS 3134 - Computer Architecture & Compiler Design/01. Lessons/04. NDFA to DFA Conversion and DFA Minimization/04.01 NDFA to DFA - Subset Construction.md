# 04.01 · NDFA → DFA Conversion (Subset Construction)

> [!info] [[04.00 NDFA to DFA Conversion and DFA Minimization|Lesson 4]] · Theory Notes 4 + `Compiler note.pdf` · Priority 🔴 High (all 5 papers)
> **Asked as:** "Find the equivalent DFA for the NDFA given by X = …" (2019/20 Q4d, 2020/21 Q6d) · "Find the equivalent DFA for the above NDFA machine given in part (b)" (2021/22 Q6c, 2022/23 Q6c, 2023/24 Q7c)

## 1. Problem statement (quote it at the top of your answer)

> [!abstract] Theory Notes 4
> "Let $X = (Q_x, \Sigma, \delta_x, q_0, F_x)$ be an NDFA which accepts the language $L(X)$. We have to design an equivalent DFA $Y = (Q_y, \Sigma, \delta_y, q_0, F_y)$ such that $L(Y) = L(X)$."

## 2. The idea in one sentence

**One DFA state stands for the *set* of NDFA states the machine could currently be in.** That is why DFA states are written as sets like `[a, b, c]`, and why the DFA can have up to $2^{|Q|}$ states (the power set, [[03.04 Formal Definition and the Transition Function]]).

## 3. The algorithm (6 steps, Theory Notes 4)

> [!abstract] Algorithm
> **Input:** an NDFA · **Output:** an equivalent DFA
> 1. Create the **state table** from the given NDFA.
> 2. Create a **blank state table** under possible input alphabets for the equivalent DFA.
> 3. Mark the **start state** of the DFA by q0 (same as the NDFA).
> 4. Find out the **combination of states** {Q0, Q1, …, Qn} for each possible input alphabet.
> 5. Each time we generate a **new DFA state** under the input alphabet columns, apply step 4 again; otherwise go to step 6.
> 6. The states which **contain any of the final states of the NDFA** are the final states of the equivalent DFA.

**How to compute a cell (step 4):**

$$
\delta_Y([p, q, r], x) = \delta_X(p, x) \cup \delta_X(q, x) \cup \delta_X(r, x)
$$

## 4. The lecture's worked example

NDFA (final state **e**):

| q | δ(q,0) | δ(q,1) |
|---|---|---|
| → a | {a,b,c,d,e} | {d,e} |
| b | {c} | {e} |
| c | ∅ | {b} |
| d | {e} | ∅ |
| \* e | ∅ | ∅ |

DFA (built row by row, new states processed in order):

| q | δ(q,0) | δ(q,1) | Final? |
|---|---|---|---|
| → [a] | [a,b,c,d,e] | [d,e] | |
| [a,b,c,d,e] | [a,b,c,d,e] | [b,d,e] | ✔ (contains e) |
| [d,e] | [e] | ∅ | ✔ |
| [b,d,e] | [c,e] | [e] | ✔ |
| [e] | ∅ | ∅ | ✔ |
| [c,e] | ∅ | [b] | ✔ |
| [b] | [c] | [e] | |
| [c] | ∅ | [b] | |

Example of showing the union (this is where the marks are):

$$
\delta([b,d,e], 0) = \delta(b,0) \cup \delta(d,0) \cup \delta(e,0) = \{c\} \cup \{e\} \cup \varnothing = [c,e]
$$

**Final states:** every set containing **e**, which gives 5 of the 8 states.

> [!tip] The dead state ∅
> When a set has no successor, write **∅**. In a strict DFA ∅ is a real state (the **dead state**) with self-loops on every symbol, because every state must have a transition for every symbol ([[03.05 Deterministic Finite Automaton (DFA)|validation rule 4]]). Your handwritten notes handle it this way. **Mention it even if you do not draw it.**

> [!note] This same NDFA was set in 2019/20 Q4d
> The 2019/20 paper renamed a…e as q0…q4 (final q4). The answer is the table above with that renaming. See [[PP 04.1 - NDFA to DFA Conversion]].

## 5. Presentation checklist
- [ ] Problem statement (X, Y, L(Y) = L(X)) and the 6 steps written out.
- [ ] NDFA table with ∅ where there is no move.
- [ ] DFA table built **row by row** from [q0], with unions shown for at least the first few cells.
- [ ] **Every new composite state gets its own row**. Keep a list and tick it off.
- [ ] Final states marked (every set containing an NDFA final state).
- [ ] Optional renaming (A, B, C, …) for readability, and the **DFA state diagram**.

## 6. Practical explanation
Lexical analyzer generators build an NDFA from the token REs (easy), then convert it to a DFA by exactly this construction (fast to run). See [[03.07 DFA vs NDFA]].

- Method marks: **problem statement + 6 steps**.
- Execution marks: **show unions**, **process every new state**, **mark final states**, **include ∅**.
