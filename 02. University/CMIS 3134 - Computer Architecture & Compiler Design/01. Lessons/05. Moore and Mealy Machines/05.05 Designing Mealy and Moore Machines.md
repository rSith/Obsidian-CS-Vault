# 05.05 · Designing Mealy and Moore Machines from a Word Problem

> [!info] [[05.00 Moore and Mealy Machines|Lesson 5]] · `Compiler note.pdf` (construction examples) · Priority 🔴 High (last 3 papers)
> **Asked as:** "Design a Moore machine for a binary input sequence such that if it has a substring 101, the machine outputs "a"; if the input has a substring 110, it outputs "b", otherwise it outputs "c"." (2021/22 Q7a) · "Design a Mealy machine… Output "M" immediately after detecting "01", "N" immediately after detecting "10", "O" otherwise." (2022/23 Q7a) · "Design a Mealy machine for a vending machine that accepts coins of 5 and 10. Once the total reaches or exceeds 20, the machine dispenses the item by producing "D". Otherwise, it produces "C"." (2023/24 Q6a)

## 1. Method: three questions

1. **What must a state remember?** Usually the **last one or two symbols** or a **running total**. Write each state's meaning in words.
2. **When exactly is the output produced?** "Immediately when this symbol arrives" points to **Mealy** (output on the transition). "Whenever we are in this situation" points to **Moore** (output on the state).
3. **What happens after an output?** Does the machine **reset**, or may patterns **overlap**? **State your assumption.**

Then give: the **6-tuple**, the **state diagram**, the **state table**, and a **verified trace**.

## 2. Examples from your handwritten notes (B.9, B.10)

| Task | Type | Design idea |
|---|---|---|
| **1's complement** of a binary string | Mealy | 1 state; `0/1`, `1/0` self-loops |
| **2's complement** (reading from the least significant bit) | Mealy | State A "no 1 seen yet": `0/0` stay, `1/1` go to B. State B "first 1 seen": `0/1`, `1/0` (complement the rest) |
| Print 'a' whenever "01" is encountered | Mealy (2 states) / Moore (3 states) | Track the previous symbol; output `a` on the transition that completes 01 |
| String ending with "aa" or "bb" | Mealy | Remember the last symbol; output the accept symbol when it repeats |
| Count occurrences of "abb" | Moore | States for prefixes ε, a, ab, abb; the abb state outputs 1 |

> [!note] Beyond the slides
> The handwritten notes show these designs as diagrams. The one-line descriptions above summarise them. The 2's complement design is the standard one, which is consistent with the notes.

## 3. Worked design: Mealy "M after 01, N after 10, O otherwise" (2022/23 Q7a)

State remembers **the previous symbol**:

| State (meaning) | input 0 | input 1 |
|---|---|---|
| → q0 (nothing read) | qA / O | qB / O |
| qA (last symbol 0) | qA / O | qB / **M** (just saw 01) |
| qB (last symbol 1) | qA / **N** (just saw 10) | qB / O |

Assumption: patterns may **overlap** (after `01`, the 1 can start `10`).
Trace `0110` → outputs **O M O N** (4 outputs for 4 inputs). Σ = {0,1}, O = {M, N, O}.

## 4. Worked design: vending machine (2023/24 Q6a) and its Moore form (Q6b)

**What to remember:** the running total, which can only be **0, 5, 10 or 15** (any total ≥ 20 dispenses and resets). Output depends on the coin just inserted, so it is a **Mealy** machine.

| State (total) | coin 5 | coin 10 |
|---|---|---|
| → S0 (0) | S5 / C | S10 / C |
| S5 (5) | S10 / C | S15 / C |
| S10 (10) | S15 / C | S0 / **D** (20) |
| S15 (15) | S0 / **D** (20) | S0 / **D** (25) |

**Assumptions to state:** after dispensing the machine **resets to 0** and **no change is given**.
Trace: 10, 5, 5 → C, C, D. Trace: 10, 10 → C, D. Σ = {5, 10}, O = {C, D}.

**Converting to Moore (2023/24 Q6b), using Algorithm 5:**
- Incoming outputs: S5 {C}, S10 {C}, S15 {C}, **S0 {D}** (only entered by dispensing).
- S0 is the **start** state but is only ever *entered* with output D. As a Moore state it would print D before any coin is inserted, which is wrong. So, following the idea of Step 3, keep a **start state S0 with output C** and add a **new state S0D ("just dispensed") with output D** for the dispensing arrows.

| State | coin 5 | coin 10 | Output |
|---|---|---|---|
| → S0 | S5 | S10 | C |
| S5 | S10 | S15 | C |
| S10 | S15 | S0D | C |
| S15 | S0D | S0D | C |
| S0D | S5 | S10 | D |

Check: input 10, 5, 5 → states S0 → S10 → S15 → S0D → outputs **C, C, C, D**, which is the Mealy output C, C, D with one extra leading symbol. ✔

## 5. Worked design: Moore "101 → a, 110 → b, otherwise c" (2021/22 Q7a)

For Moore, the output belongs to a state, so we need states meaning "**just completed 101**" and "**just completed 110**". States record the **longest useful suffix** seen so far:

| State (meaning) | 0 | 1 | Output |
|---|---|---|---|
| → S0 (no useful suffix) | S0 | S1 | c |
| S1 (ends in 1) | S10 | S11 | c |
| S10 (ends in 10) | S0 | SA | c |
| S11 (ends in 11) | SB | S11 | c |
| SA (just matched 101) | S10 | S11 | **a** |
| SB (just matched 110) | S0 | SA | **b** |

Overlap cases worth explaining: SA on 1 → "1011" ends in "11" → S11; SB on 1 → "1101" ends in "101" → SA (matches again).
Interpretation used: output a / b **at the moment** the substring is completed (as a sequence detector), c otherwise.
Trace `110101` → states S0, S1, S11, SB, SA, S10, SA → outputs **c c c b a c a** (7 outputs for 6 inputs).

> [!warning] Interpretation
> The question could also be read as "output **a** if the whole input *contains* 101 anywhere" (a one-off classification). The sequence-detector reading above is the usual one for Moore/Mealy questions. **State your reading in the exam.**

## 6. Exam-relevant points
- Say **why** it is Mealy or Moore (when the output is produced).
- Give state meanings, **diagram + table + 6-tuple**, and a trace.
- State assumptions: overlap, reset after output, no change given.
