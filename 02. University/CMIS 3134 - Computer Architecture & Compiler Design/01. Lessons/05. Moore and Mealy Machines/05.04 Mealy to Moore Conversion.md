# 05.04 · Mealy → Moore Conversion (Algorithm 5)

> [!info] [[05.00 Moore and Mealy Machines|Lesson 5]] · Theory Notes 5 + `Compiler note.pdf` · Priority 🔴 High (all 5 papers)
> **Asked as:** "Convert the following Mealy machine into the Moore machine." (2019/20 Q6c*, 2020/21 Q8c, 2021/22 Q7c, 2022/23 Q7c) · "Convert the Mealy machine in part (a) into a Moore machine" (2023/24 Q6b)

## 1. Why this direction is harder

A Moore state carries **one** output. If a Mealy state is entered **sometimes with output 0 and sometimes with output 1**, it cannot become a single Moore state. It must be **split** into copies, one per output.

## 2. The algorithm

> [!abstract] Theory Notes 5: Algorithm 5
> **Input:** Mealy machine · **Output:** Moore machine
> 1. Calculate the **number of different outputs for each state (Qi)** that are available in the state table of the Mealy machine.
> 2. If all the outputs of Qi are the same, **copy state Qi**. If it has n distinct outputs, **break Qi into n states** as Qin where n = 0, 1, 2…
> 3. If the **output of the initial state is 1**, insert a **new initial state** at the beginning which gives **0** output.

> [!important] "Outputs of Qi" means outputs on transitions **entering** Qi
> Look for every cell where Qi appears as the **next state**, and collect the outputs written next to it. The lecture's example confirms this reading. (Your handwritten notes do the same: B → Ba, Bb.)

**After splitting:**
- Every arrow that went to Qi with output o now goes to the copy **Qi_o**.
- **The outgoing transitions of every copy are identical** to those of the original Qi.
- Each copy's Moore output is its subscript.

## 3. The lecture's worked example

Mealy machine:

| Present | a=0: Next | a=0: Out | a=1: Next | a=1: Out |
|---|---|---|---|---|
| → a | d | 0 | b | 1 |
| b | a | 1 | d | 0 |
| c | c | 1 | c | 0 |
| d | b | 0 | a | 1 |

**Step 1: incoming outputs per state.**
- a: entered from b (0/1) and from d (1/1) → outputs {1} → **keep a** (output 1).
- b: entered from a (1/1) and from d (0/0) → {0, 1} → **split into b0, b1**.
- c: entered from c (0/1) and from c (1/0) → {0, 1} → **split into c0, c1**.
- d: entered from a (0/0) and from b (1/0) → {0} → **keep d** (output 0).

**Step 2: Moore table** (lecture result):

| Present | Next a=0 | Next a=1 | Output |
|---|---|---|---|
| → a | d | b1 | 1 |
| b0 | a | d | 0 |
| b1 | a | d | 1 |
| c0 | c1 | c0 | 0 |
| c1 | c1 | c0 | 1 |
| d | b0 | a | 0 |

> [!note] Step 3 and the lecture example
> In the lecture example the initial state **a** has output 1, yet the lecture does **not** add a new initial state. By Step 3 you should. The safe exam answer: apply Step 3, add **a′** with output **0** and the same outgoing transitions as a (`a′: 0→d, 1→b1`), and explain *"so the machine does not output a 1 before reading any input"*. Mention that a is still kept for the arrows that enter it.

## 4. Exam checklist
- [ ] Write the **3 steps**.
- [ ] Say the given table is **Mealy** (cells like `q3/0`).
- [ ] **Step 1 written out:** for every state, list the incoming outputs.
- [ ] Step 2: split where needed; say which states are unchanged and why.
- [ ] Redirect arrows to the right copy; **copies share the same outgoing transitions**.
- [ ] Step 3: check the initial state's output.
- [ ] Moore table (Next columns + Output column) and diagram (output inside each state).
- [ ] Verify: Moore output = one extra symbol at the front + the Mealy output.
