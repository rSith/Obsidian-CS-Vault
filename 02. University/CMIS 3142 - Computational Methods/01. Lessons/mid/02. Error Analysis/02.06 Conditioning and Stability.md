# 02.06 · Conditioning of a Problem and Stability of an Algorithm

> [!info] [[02.00 Error Analysis|Lesson 2]] · Lecture slides 18–22 · Priority 🟢 Low (in the syllabus, **not examined** in 2023–2026)

## 1. Conditioning (sensitivity of a **problem**) (slides 18–19)
A mathematical problem with input $x$ and output $y = f(x)$ is:
- **well-conditioned** if small changes in $x$ lead to small changes in $y$;
- **ill-conditioned** if small changes in $x$ can lead to large changes in $y$.

Conditioning belongs to the **problem itself**, not to the method used to solve it. No algorithm can give an accurate answer to a badly ill-conditioned problem in finite precision, because even storing the input already changes it slightly ([[02.03 Machine Precision and Arithmetic Round-off]]).

## 2. Condition number (slides 20–21)
$$
\text{condition number} = \frac{\text{change in solution}}{\text{change in input}}
= \frac{\left|\dfrac{\hat y - y}{y}\right|}{\left|\dfrac{\hat x - x}{x}\right|}
= \frac{|\Delta y|/|y|}{|\Delta x|/|x|}
$$

It can be approximated (slide 21) by
$$
\text{condition number} = \frac{|\Delta y|\,|x|}{|\Delta x|\,|y|}
= \left|\frac{f(x+\Delta x) - f(x)}{\Delta x}\right|\frac{|x|}{|f(x)|}
\approx \left|\frac{x\,f'(x)}{f(x)}\right|
$$

- Condition number ≈ 1 or less → well-conditioned.
- Condition number ≫ 1 → ill-conditioned (relative input errors are magnified).

### Worked examples
1. $f(x) = \sqrt{x}$: $\left|\dfrac{x\cdot\frac{1}{2\sqrt x}}{\sqrt x}\right| = \dfrac12$ → **well-conditioned** (input errors are halved). Matches the √2 example in [[02.05 Well-Posed Problems, Forward and Backward Error]].
2. $f(x) = \tan x$ near $x = 1.57$ ($\approx\pi/2$): $\left|\dfrac{x\sec^2x}{\tan x}\right|$ $= \left|\dfrac{2x}{\sin 2x}\right|$ is huge (about $2\times10^{3}$ at $x = 1.57$, and it grows without limit as $x\to\pi/2$) → **ill-conditioned**: a tiny change in $x$ swings $\tan x$ enormously.
3. $f(x) = x - 1$ near $x = 1$: $\left|\dfrac{x}{x-1}\right| \to \infty$ → subtracting nearly equal numbers is ill-conditioned (cancellation).

> [!note] For linear systems (beyond the slides)
> For $Ax = b$ the condition number is $\kappa(A) = \|A\|\,\|A^{-1}\|$. Nearly singular matrices have large $\kappa$, so Gaussian elimination, Cholesky, Jacobi etc. lose about $\log_{10}\kappa$ digits of accuracy. This information could not be verified from the available course materials.

## 3. Stability (sensitivity of an **algorithm**) (slide 22)
> An algorithm is **stable** if the result it produces is relatively insensitive to errors made during the computations. That is, the result it produces is the **exact solution of a nearby problem**.

In other words: a stable algorithm has a **small backward error**.

> **Stability of an algorithm does not guarantee an accurate computed solution. Accuracy depends on conditioning of the problem and stability of an algorithm.**

$$
\underbrace{\text{accuracy of result}}_{\text{forward error}} \;\approx\; \underbrace{\text{conditioning}}_{\text{problem}} \times \underbrace{\text{stability}}_{\text{algorithm (backward error)}}
$$

| | Well-conditioned problem | Ill-conditioned problem |
|---|---|---|
| **Stable algorithm** | ✅ accurate result | ❌ may be inaccurate (problem's fault) |
| **Unstable algorithm** | ❌ may be inaccurate (algorithm's fault) | ❌ inaccurate |

Kreyszig (Lecture 07 reading) also notes that iterative methods, *if they converge, are stable in general*.

## 4. Problems vs algorithms; data error vs computational error
> [!warning] Not on the slides
> These items are listed on the syllabus slide but no lecture slide covers them. This information could not be verified from the available course materials. Standard meanings:
> - **Problem vs algorithm:** a *problem* is the mathematical task ($y = f(x)$, solve $Ax = b$); an *algorithm* is a particular sequence of operations that computes it (Gaussian elimination, Cholesky, Jacobi…). Conditioning is a property of the problem; stability is a property of the algorithm.
> - **Data error vs computational error:** *data error* is error already in the input (measurement error, or storing $x$ as $fl(x)$); *computational error* is error added by the algorithm (round-off during arithmetic, truncation of an infinite process). Total error = data error propagated through the problem + computational error.

## 5. Important distinctions
| Conditioning | Stability |
|---|---|
| property of the **problem** | property of the **algorithm** |
| measured by the condition number | measured by backward error |
| cannot be fixed by a better method (only by reformulating the problem) | fixed by choosing a better algorithm (e.g. pivoting, Cholesky for SPD) |
