## 1. The GPA formula (from the 2025 paper)
$$
\text{GPA} = \frac{\sum_i (\text{credits}_i \times \text{grade point}_i)}{\sum_i \text{credits}_i}
$$

2025 example: one 2-credit unit (A), three 3-credit units (C, B, D), two 1-credit units (B−, A+):
$$
\text{GPA} = \frac{2(4.0) + 3(2.0) + 3(3.0) + 3(1.0) + 1(2.7) + 1(4.0)}{2+3+3+3+1+1} = \frac{32.7}{13} = 2.5153846\ldots
$$

| Treatment | Result (2 d.p.) | Error vs exact |
|---|---|---|
| Exact | 2.5153846… | 0 |
| **Rounded** | **2.52** | $2.5153846 - 2.52 = -0.0046154$ |
| **Chopped** | **2.51** | $2.5153846 - 2.51 = +0.0053846$ |

Here rounding **raises** the GPA, chopping **lowers** it, and the chopping error is larger.

## 2. Where rounding happens in a results system
```text
raw paper marks ──(scale e.g. /500 → /100)──► module mark ──(round to integer)──► grade (A, B…)
      ──► grade point ──(× credits, sum, ÷ credits)──► semester / final GPA ──(round to 2 d.p.)──► class
```
Every arrow can introduce round-off or chopping error, and **errors made early are carried forward** (slide 12: errors build up in large computations).

## 3. Impact of rounding at each stage

### 3.1 Scaling marks, e.g. a paper marked out of 500 scaled to 100 (2026 Q5(c)(i))
- Scaled mark $= \text{raw}/5$. Raw 372 → 74.4 → rounded **74**; raw 373 → 74.6 → rounded **75**.
- **Resolution is lost:** five different raw marks collapse to about one scaled mark; the maximum rounding error per scaling is **±0.5 mark** (= ±2.5 raw marks).
- If each question/section is scaled and rounded **separately** and then added, the errors **accumulate**: 5 sections × ±0.5 = up to **±2.5 marks** in the total.
- Chopping instead of rounding makes every student lose up to 1 mark per chop (always downward).

### 3.2 Rounding marks for grading (2026 Q5(c)(ii), 2023 Q3(b))
- Grades are given by **mark boundaries**. A tiny rounding difference near a boundary changes the **grade**, which is a big jump.
- Example (assumed boundary A ≥ 75): 74.5 → rounds to 75 → **A (4.0)**, but 74.4 → 74 → lower grade. A 0.1-mark difference in the unrounded mark becomes a whole grade-point step.
- **Chopping** (74.9 → 74) would deny the higher grade to everyone just below the boundary.

### 3.3 Calculating the GPA (2023 Q3(b), 2025 Q2(a)(b), 2026 Q5(c)(iii))
- Final GPA is rounded to 2 d.p. ⇒ error at most **±0.005** with rounding, up to **0.0099…** (always downward) with chopping.
- If **semester or year GPAs are rounded first** and then averaged, each rounding adds up to 0.005 and the errors can add up.
- The effect of one module's grade point on the final GPA: with 40 units × 3 credits = 120 credits (2025 assumption), a change $\Delta g$ in one module's grade point changes the GPA by $\dfrac{3\,\Delta g}{120} = \dfrac{\Delta g}{40}$.
- **Class boundaries** make the impact serious: with an assumed First Class threshold of 3.70, an exact GPA of 3.6950 rounds to **3.70 (First Class)** but chops to **3.69 (not First Class)**.

## 4. Maximum and minimum rounding error (2024 Q2(b))
**Assumptions to state:** GPA reported to 2 decimal places; grade points as given; rounding is "round half up"; intermediate values are kept exact unless stated.

| Case | Minimum error | Maximum error | Example |
|---|---|---|---|
| Final GPA rounded once (2 d.p.) | **0** (exact value already has ≤ 2 d.p., e.g. 3.25) | **0.005** (exactly half a unit) | 3.695 → 3.70 (error 0.005); 2.5153846 → 2.52 (error 0.0046) |
| Final GPA chopped (2 d.p.) | **0** | just under **0.01** | 3.6999 → 3.69 (error 0.0099) |
| Semester GPAs rounded, then averaged and rounded again | 0 | up to $0.005 + 0.005 = 0.01$ (intermediate error carried into the average, plus the final rounding); if rounded **sums** are added instead of averaged, $k$ roundings give up to $k\times0.005$ | 8 semester GPAs each rounded up by 0.005 → average already 0.005 too high before the final rounding |
| Module marks rounded before grading | 0 | **one grade step per module** near a boundary; e.g. +0.3 grade point (assumed B+ → A− step) in every one of 40 modules → GPA +0.3 | 74.5 → 75 in each module |

> [!tip] Why the max rounding error is half a unit
> Rounding to 2 d.p. picks the nearest multiple of 0.01, so the true value is never more than half the gap (0.005) away. Chopping always picks the multiple **below**, so the gap can be almost a full 0.01.

## 5. How to minimise the loss (2023 Q3(c), 2024 Q2(b), 2026 Q5(d))
1. **Keep full precision during the whole calculation** (use `double`), and **round only once, at the very end** (final GPA). Never round intermediate marks, semester GPAs or weighted totals.
2. **Use rounding (round half up), not chopping**, so errors are not always against the student and they partly cancel.
3. **Scale before rounding, and scale the total, not each part:** compute $\text{total raw}\times100/500$ once, with decimals kept.
4. **Use exact (integer) arithmetic where possible:** e.g. store grade points × 10 and credits as integers, so $\sum \text{credits}\times\text{gp}\times10$ is exact; divide only at the end.
5. **Define and publish a single rounding rule** (number of decimals, half-up) so the same student always gets the same result.
6. **Borderline review:** flag students within ±0.005 GPA (or ±0.5 mark) of a grade/class boundary for manual checking.
7. **Report more decimals** (e.g. 3–4 d.p.) internally even if 2 are printed.

## 6. Java program (2025 Q2(c)): read modules, compute GPA, round-off and chopping errors
```java
import java.util.Scanner;

public class GPAErrors {

    static double roundTo2(double x) { return Math.round(x * 100) / 100.0; }   // rounding
    static double chopTo2(double x)  { return Math.floor(x * 100) / 100.0; }   // chopping (x >= 0)

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        // (i) read module codes and credit values (and the grade point earned)
        System.out.print("Number of modules: ");
        int n = sc.nextInt();
        String[] code   = new String[n];
        int[]    credit = new int[n];
        double[] gp     = new double[n];
        for (int i = 0; i < n; i++) {
            System.out.print("Module code, credits, grade point (e.g. CMIS3142 2 4.0): ");
            code[i]   = sc.next();
            credit[i] = sc.nextInt();
            gp[i]     = sc.nextDouble();
        }

        // (ii) calculate the GPA = sum(credit x grade point) / sum(credit)
        double weighted = 0;
        int totalCredits = 0;
        for (int i = 0; i < n; i++) {
            weighted     += credit[i] * gp[i];
            totalCredits += credit[i];
        }
        double gpa = weighted / totalCredits;          // full precision value

        // (iii) round-off error and chopping error (2 decimal places)
        double rounded = roundTo2(gpa);
        double chopped = chopTo2(gpa);
        double roundOffError = Math.abs(gpa - rounded);
        double choppingError = Math.abs(gpa - chopped);

        System.out.printf("Exact GPA        = %.7f%n", gpa);
        System.out.printf("Rounded GPA      = %.2f   round-off error = %.7f%n", rounded, roundOffError);
        System.out.printf("Chopped GPA      = %.2f   chopping error  = %.7f%n", chopped, choppingError);

        // (iv) difference between the two errors
        System.out.printf("Difference (chopping - round-off) = %.7f%n", choppingError - roundOffError);
    }
}
```

Output with the 2025 data (tested):
```text
Exact GPA        = 2.5153846
Rounded GPA      = 2.52   round-off error = 0.0046154
Chopped GPA      = 2.51   chopping error  = 0.0053846
Difference (chopping - round-off) = 0.0007692
```

> The question says "read the module codes and credit values". A GPA also needs the **grade (point)** for each module, so the program reads it too. State this as an assumption in your answer.
