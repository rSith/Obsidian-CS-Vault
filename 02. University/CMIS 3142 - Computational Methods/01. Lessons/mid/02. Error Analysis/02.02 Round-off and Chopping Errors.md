# 02.02 · Round-off Error and Chopping (Truncation) Error

> [!info] [[02.00 Error Analysis|Lesson 2]] · Lecture slides 7–10 · Priority 🔴 High
> **Asked as:** the GPA scenarios in every paper ([[02.04 Rounding Errors in GPA Calculation]]) · "Describe … the impacts of chopping error in the GPA calculation" (2025 Q2(b)) · "Write separate Java methods that serve the same purpose as `Math.floor()` and `Math.ceil()`" (2023 Q3(d), 8 marks).

## 1. The two error types (slide 7)
When a number has more digits than can be stored, the extra digits must go. There are two ways to drop them: **round** or **chop**.

### 1.1 Round-off (rounding) error (slide 8)
> *A round-off error, also called rounding error, is the difference between the calculated approximation of a number and its exact mathematical value due to rounding.*

Rounding keeps the nearest representable value: look at the first dropped digit; if it is ≥ 5, increase the last kept digit by 1.

### 1.2 Chopping / truncation error (slide 9)
> *Truncation error is the difference between a truncated value and the actual value. A truncated quantity is represented by a numeral with a fixed number of allowed digits, with any excess digits "chopped off" (hence the expression "truncated").*

Chopping simply **deletes** the extra digits, without looking at them.

## 2. Worked example (slide 10)
*Assume a computer that can store 7 significant digits.* True value $4.2428576428\ldots$

| Method | Stored value | Error (true − stored) |
|---|---|---|
| Chopping | 4.242857 | $+0.0000006428\ldots$ |
| Rounding | 4.242858 | $-0.0000003572\ldots$ |

Rounding gives the smaller error here because the first dropped digit (6) is ≥ 5.

## 3. Maximum error
If $d$ = value of one unit in the last kept place (e.g. $d = 0.01$ for 2 decimal places):

| | Rounding | Chopping |
|---|---|---|
| Maximum absolute error | $\dfrac{d}{2}$ (e.g. 0.005) | just under $d$ (e.g. 0.00999…) |
| Sign of error | **either sign** (+ or −) | **always the same sign** (stored value ≤ true value for positive numbers) |
| Average error over many numbers | ≈ 0 (errors cancel) | ≈ $d/2$ (errors **add up**) |

## 4. Chopping vs rounding (slide 10)
- **Rounding is a better choice** since the sign of the error can be either positive or negative, leading to a **smaller total numerical error**. The error in chopping is **always positive and adds up**.
- **Rounding costs extra processing**, so most computers simply **chop off** the number.
- The error associated with rounding/chopping is called **quantization error**.

> [!note] Modern hardware
> IEEE 754 arithmetic rounds to nearest by default (that is why 0.1f ends in hex D, see [[01.03 IEEE 754 Single Precision]]). The slide's "most computers chop" is the lecturer's general statement. Casting `(int) 3.9` in Java still **chops** (gives 3).

## 5. `Math.floor()` and `Math.ceil()` in Java (2023 Q3(d))
- `Math.floor(a)`: the **largest whole number ≤ a** (rounds downward, toward −∞). `floor(3.30) = 3.0`, `floor(-3.30) = -4.0`.
- `Math.ceil(a)`: the **smallest whole number ≥ a** (rounds upward, toward +∞). `ceil(3.30) = 4.0`, `ceil(-3.30) = -3.0`.
- Casting `(long) a` **chops toward zero**: `(long) 3.3 = 3`, `(long) -3.3 = -3`.

```java
public class FloorCeil {

    // Same purpose as Math.floor(a): largest whole number <= a
    static double myFloor(double a) {
        long t = (long) a;          // casting chops toward zero: 3.30 -> 3, -3.30 -> -3
        if (a < t) t = t - 1;       // for negative non-integers, chopping went UP, so step down
        return (double) t;
    }

    // Same purpose as Math.ceil(a): smallest whole number >= a
    static double myCeil(double a) {
        long t = (long) a;          // chop toward zero
        if (a > t) t = t + 1;       // for positive non-integers, chopping went DOWN, so step up
        return (double) t;
    }

    public static void main(String[] args) {
        double[] tests = {3.30, -3.30, 5.0, -5.0, 0.7, -0.7};
        for (double v : tests)
            System.out.printf("%6.2f  myFloor=%5.1f Math.floor=%5.1f  myCeil=%5.1f Math.ceil=%5.1f%n",
                    v, myFloor(v), Math.floor(v), myCeil(v), Math.ceil(v));
    }
}
```

Output (tested):
```text
  3.30  myFloor=  3.0 Math.floor=  3.0  myCeil=  4.0 Math.ceil=  4.0
 -3.30  myFloor= -4.0 Math.floor= -4.0  myCeil= -3.0 Math.ceil= -3.0
  5.00  myFloor=  5.0 Math.floor=  5.0  myCeil=  5.0 Math.ceil=  5.0
  0.70  myFloor=  0.0 Math.floor=  0.0  myCeil=  1.0 Math.ceil=  1.0
```

**How it works:** the cast is a chop. For positive numbers chopping equals floor, so only ceil needs a correction (+1 when there was a fractional part). For negative numbers chopping equals ceil, so floor needs a correction (−1). The test `a < t` / `a > t` is true exactly when a fractional part was removed.

> [!tip] Rounding/chopping to 2 decimal places
> Chop: `Math.floor(x * 100) / 100.0` (for $x \ge 0$). Round: `Math.round(x * 100) / 100.0`. Used in the GPA program in [[02.04 Rounding Errors in GPA Calculation]].

## 6. Important distinctions
| Term | Meaning in **this** lesson (L02) | Meaning in **finite differences** (L09) |
|---|---|---|
| Truncation error | **chopping digits** of a number | **dropping higher-order terms** of a Taylor series |
| Caused by | finite storage of digits | approximating a derivative/infinite series |
| Reduced by | more digits, rounding | smaller step $\Delta x$, higher-order formula |

| Round-off error | Chopping error |
|---|---|
| nearest value kept | extra digits deleted |
| max $d/2$ | max ≈ $d$ |
| errors ± cancel | errors same sign, accumulate |
| slower (extra work) | faster |

## 7. Practical explanation
- **Money:** banks specify rounding rules (e.g. round half up) by law, because consistent chopping would always favour one side.
- **Grades/GPA:** chopping always lowers students' results; repeated rounding at intermediate steps can push a student across a class boundary (see 02.04).
- **Long computations** (millions of operations in matrix solvers) can accumulate chopping error into a visible drift.

## 8. Exam-relevant points

- Always state the **maximum error** (½ unit vs 1 unit) and the **sign behaviour** (cancel vs accumulate).
