## Why this lesson matters
Solving $Ax = b$ for large engineering problems (thousands of unknowns) is mostly a **storage problem**. A full $10\,000\times10\,000$ matrix of `double`s needs 800 MB. But most real matrices are **symmetric** (store half) and/or **sparse** (store only non-zeros). This lesson is about choosing a storage scheme and writing the Java methods (`elementAt`, store, display, multiply) that hide the scheme behind a common interface. It feeds directly into Cholesky ([[06.00 LU Decomposition and Cholesky]]), which works only on symmetric matrices.
