# 01.08 · Java Programs for IEEE 754

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Assignment 2 (slide 21) · Priority 🔴 High
> **Asked as:**
> - "Write a Java program to convert a given decimal number into IEEE 754 double precision notation" (2023 Q1(c), 8 marks; 2026 Q1(e), **15 marks**)
> - "… into the IEEE 754 double precision format **and vice versa**" (2024 Q1(c))
> - "Write a Java method to convert IEEE 754 double precision notation into IEEE 754 single precision notation" (2023 Q1(d), 5 marks)
> - "… single precision format to double precision format and vice versa. Mention the assumptions, if any" (2024 Q1(d))
> - Octal ↔ hex program (2025 Q1(d)) → see [[01.01 Number System Conversions]].

> [!tip] What the examiner wants
> The **algorithm**, not `Double.doubleToLongBits()`. Use the built-in only as a final check. Your code should visibly do: sign → binary of integer part → binary of fraction → normalise → add bias → pad fraction. All programs below were compiled and tested.

## 1. Decimal → IEEE 754 double, and back (2023 Q1(c), 2024 Q1(c), 2026 Q1(e))

```java
import java.util.Scanner;

public class DecimalToIEEEDouble {

    // ---------- decimal -> IEEE 754 double (manual algorithm) ----------
    static String toIEEEDouble(double x) {
        if (x == 0) return (1 / x < 0 ? "1" : "0") + " " + "0".repeat(11) + " " + "0".repeat(52);

        // Step 1: sign bit
        String sign = (x < 0) ? "1" : "0";
        x = Math.abs(x);

        // Step 2: integer and fractional parts in binary
        long intPart = (long) x;
        double frac = x - intPart;
        String intBits = Long.toBinaryString(intPart);      // repeated division by 2
        StringBuilder fracBits = new StringBuilder();
        while (frac > 0 && fracBits.length() < 1100) {      // repeated multiplication by 2
            frac *= 2;
            if (frac >= 1) { fracBits.append('1'); frac -= 1; }
            else           { fracBits.append('0'); }
        }

        // Step 3: normalise to 1.F x 2^e
        int e;
        String mantissa;                                    // bits after the leading 1
        if (intPart > 0) {
            e = intBits.length() - 1;                       // point moves left
            mantissa = intBits.substring(1) + fracBits;
        } else {
            int firstOne = fracBits.indexOf("1");           // point moves right
            e = -(firstOne + 1);
            mantissa = fracBits.substring(firstOne + 1);
        }

        // Step 4: biased exponent (bias 1023, 11 bits)
        int E = e + 1023;
        String expBits = String.format("%11s", Integer.toBinaryString(E)).replace(' ', '0');

        // Step 5: fraction padded / cut to 52 bits
        if (mantissa.length() < 52) mantissa = mantissa + "0".repeat(52 - mantissa.length());
        else mantissa = mantissa.substring(0, 52);

        return sign + " " + expBits + " " + mantissa;
    }

    // ---------- IEEE 754 double -> decimal ("vice versa") ----------
    static double fromIEEEDouble(String bits) {
        bits = bits.replace(" ", "");
        int S = bits.charAt(0) - '0';
        int E = Integer.parseInt(bits.substring(1, 12), 2);
        String F = bits.substring(12);

        double fraction = 0;                               // value of 0.F
        for (int i = 0; i < 52; i++)
            if (F.charAt(i) == '1') fraction += Math.pow(2, -(i + 1));

        double value;
        if (E == 2047) return (fraction == 0) ? (S == 0 ? Double.POSITIVE_INFINITY : Double.NEGATIVE_INFINITY) : Double.NaN;
        else if (E == 0) value = fraction * Math.pow(2, -1022);         // denormalised: 0.F x 2^-1022
        else             value = (1 + fraction) * Math.pow(2, E - 1023); // normalised: 1.F x 2^(E-1023)
        return (S == 1) ? -value : value;
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a decimal number: ");
        double x = sc.nextDouble();
        String ieee = toIEEEDouble(x);
        System.out.println("IEEE 754 double : " + ieee);
        System.out.println("Back to decimal : " + fromIEEEDouble(ieee));

        // check against Java's own conversion
        String check = String.format("%64s", Long.toBinaryString(Double.doubleToLongBits(x))).replace(' ', '0');
        System.out.println("Java check      : " + check.charAt(0) + " " + check.substring(1, 12) + " " + check.substring(12));
    }
}
```

**Sample run** (input `-13.625`):
```text
IEEE 754 double : 1 10000000010 1011010000000000000000000000000000000000000000000000
Back to decimal : -13.625
Java check      : 1 10000000010 1011010000000000000000000000000000000000000000000000
```

### How it works
| Step | Code | Theory |
|---|---|---|
| 1 | `sign = (x < 0) ? "1" : "0"` | $S$ bit |
| 2 | `Long.toBinaryString(intPart)` and the `while` loop | repeated ÷2 for the integer part, repeated ×2 for the fraction ([[01.01 Number System Conversions]]) |
| 3 | `e = intBits.length() - 1` or `-(firstOne + 1)` | move the point to get $1.F\times2^e$ |
| 4 | `E = e + 1023`, padded to 11 bits | biased exponent ([[01.04 Biased Exponent]]) |
| 5 | pad/cut to 52 bits | fraction field |
| Reverse | `(1 + fraction) * Math.pow(2, E - 1023)` | $(-1)^S\times1.F\times2^{E-1023}$; denormal and ∞/NaN cases handled |

> [!note] For single precision (Assignment 2)
> Change three things: bias **127**, exponent width **8**, fraction width **23**. The reverse becomes `(1 + fraction) * Math.pow(2, E - 127)` with 23 fraction bits and `E == 255` for ∞/NaN.

## 2. Single ↔ double conversion (2023 Q1(d), 2024 Q1(d))

### 2.1 Theory
- **Single → double (always exact):** $e = E_s - 127$, $E_d = e + 1023$, $F_d = F_s$ followed by 29 zeros.
- **Double → single (may lose information):** $e = E_d - 1023$, $E_s = e + 127$, $F_s$ = first 23 bits of $F_d$.

### 2.2 Assumptions to state (2024 Q1(d) asks for them)
1. **Overflow:** if $e > 127$ the number is too large for single → result is **±∞**.
2. **Underflow:** if $e < -126$ the number is too small → result is **±0** (denormalised singles not produced, for simplicity).
3. **Precision loss:** the last 29 of the 52 fraction bits are **chopped** (truncated). Real IEEE hardware **rounds to nearest**, so the last bit can differ by 1.
4. **Special values** are preserved: ±0 → ±0, ±∞ → ±∞, NaN → NaN.
5. Input is given as a valid bit string (exam version) or a Java `float`/`double` bit pattern (bit-operation version).

### 2.3 String version (easiest to write in an exam)
```java
public class IEEEConverter {

    // double (64-bit string) -> single (32-bit string)
    static String doubleToSingle(String d) {
        d = d.replace(" ", "");
        String S = d.substring(0, 1);
        int Ed = Integer.parseInt(d.substring(1, 12), 2);
        String Fd = d.substring(12);                       // 52 bits

        if (Ed == 2047) return S + " 11111111 " + (Fd.contains("1") ? "1" + "0".repeat(22) : "0".repeat(23));
        if (Ed == 0)    return S + " 00000000 " + "0".repeat(23);       // assumption: tiny -> 0

        int e  = Ed - 1023;                                 // true exponent
        if (e > 127)  return S + " 11111111 " + "0".repeat(23);         // overflow  -> infinity
        if (e < -126) return S + " 00000000 " + "0".repeat(23);         // underflow -> zero

        String Es = String.format("%8s", Integer.toBinaryString(e + 127)).replace(' ', '0');
        String Fs = Fd.substring(0, 23);                    // chop 52 -> 23 bits
        return S + " " + Es + " " + Fs;
    }

    // single (32-bit string) -> double (64-bit string)
    static String singleToDouble(String s) {
        s = s.replace(" ", "");
        String S = s.substring(0, 1);
        int Es = Integer.parseInt(s.substring(1, 9), 2);
        String Fs = s.substring(9);
        if (Es == 255) return S + " 11111111111 " + Fs + "0".repeat(29);
        if (Es == 0)   return S + " 00000000000 " + "0".repeat(52);     // assumption: (denormals) -> 0
        String Ed = String.format("%11s", Integer.toBinaryString(Es - 127 + 1023)).replace(' ', '0');
        return S + " " + Ed + " " + Fs + "0".repeat(29);    // exact: append 29 zeros
    }

    public static void main(String[] args) {
        String d = "1 10000000010 1011010000000000000000000000000000000000000000000000"; // -13.625
        String s = doubleToSingle(d);
        System.out.println(s);                 // 1 10000010 10110100000000000000000
        System.out.println(singleToDouble(s)); // back to the original 64 bits
    }
}
```

### 2.4 Bit-operation version (works on real `float`/`double` values)
```java
public class SingleDoubleConverter {

    // IEEE 754 single (32-bit pattern) -> IEEE 754 double (64-bit pattern)
    static long singleToDouble(int s) {
        long sign = (s >>> 31) & 1;              // 1 bit
        int  E    = (s >>> 23) & 0xFF;           // 8 bits
        long F    = s & 0x7FFFFF;                // 23 bits

        long Ed, Fd;
        if (E == 0xFF) {                          // infinity or NaN
            Ed = 0x7FF;  Fd = F << 29;
        } else if (E == 0 && F == 0) {            // +0 or -0
            Ed = 0;      Fd = 0;
        } else if (E == 0) {                      // denormalised single: normalise it
            int e = -126;
            while ((F & 0x800000) == 0) { F <<= 1; e--; }   // shift until hidden 1 appears
            F &= 0x7FFFFF;                        // drop the hidden 1
            Ed = e + 1023;  Fd = F << 29;
        } else {                                  // normal number
            int e = E - 127;                      // remove single bias
            Ed = e + 1023;                        // add double bias
            Fd = F << 29;                         // 23 bits -> 52 bits (append 29 zeros)
        }
        return (sign << 63) | (Ed << 52) | Fd;
    }

    // IEEE 754 double (64-bit pattern) -> IEEE 754 single (32-bit pattern)
    // Assumptions: overflow -> infinity, underflow -> zero, extra 29 bits chopped.
    static int doubleToSingle(long d) {
        int  sign = (int) ((d >>> 63) & 1);
        int  E    = (int) ((d >>> 52) & 0x7FF);
        long F    = d & 0xFFFFFFFFFFFFFL;        // 52 bits

        int Es, Fs;
        if (E == 0x7FF) {                         // infinity / NaN
            Es = 0xFF;  Fs = (F == 0) ? 0 : 0x400000;
        } else if (E == 0) {                      // zero or double denormal -> too small
            Es = 0;     Fs = 0;
        } else {
            int e = E - 1023;                     // true exponent
            if (e > 127)       { Es = 0xFF; Fs = 0; }          // overflow
            else if (e < -126) { Es = 0;    Fs = 0; }          // underflow
            else { Es = e + 127; Fs = (int) (F >>> 29); }     // keep first 23 fraction bits
        }
        return (sign << 31) | (Es << 23) | Fs;
    }

    public static void main(String[] args) {
        long db = singleToDouble(Float.floatToIntBits(-13.625f));
        System.out.println(Double.longBitsToDouble(db));                               // -13.625
        System.out.println(Float.intBitsToFloat(doubleToSingle(Double.doubleToLongBits(0.1))));   // 0.099999994
        System.out.println(Float.intBitsToFloat(doubleToSingle(Double.doubleToLongBits(1e300)))); // Infinity
    }
}
```

**Key bit tricks:** `>>>` shifts right without sign extension; `& 0xFF` keeps 8 bits; `& 0x7FFFFF` keeps 23 bits; `<< 29` turns a 23-bit fraction into the top of a 52-bit fraction.

> [!example] Chopping vs rounding, visible in the output
> Converting the double 0.1 by **chopping** gives `0x3DCCCCCC` = 0.099999994, while Java's `(float) 0.1` **rounds** to `0x3DCCCCCD` = 0.1f. That last-bit difference is exactly the "why D?" question from slide 20 ([[01.03 IEEE 754 Single Precision]]) and the chopping-vs-rounding comparison in [[02.02 Round-off and Chopping Errors]].
