# 01.02 · Scientific Notation and Floating-Point Representation

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Lecture slides 14–15 · Priority 🟢 (never asked on its own, but every Q1 conversion uses it)

## 1. What is it?
**Scientific notation** writes a number as *(a number with one non-zero digit before the point) × (base raised to a power)*. When the leading digit is non-zero, the form is called **normalised**.

**Floating-point representation** is the computer version of binary scientific notation. The point "floats": instead of a fixed number of digits after the point, the exponent says where the point goes.

## 2. Why is it used?
It lets one fixed-size word store both **very large** numbers ($10^{38}$) and **very small** numbers ($10^{-38}$) with the same number of significant digits. A fixed-point format (fixed digits before and after the point) cannot do both.

## 3. How does it work?

### 3.1 Decimal scientific notation (slide 14)
$$
-123{,}000{,}000{,}000{,}000 = -1.23\times10^{14} \qquad 0.000\,000\,000\,000\,000\,123 = +1.23\times10^{-16}
$$

### 3.2 Binary scientific notation (slide 14)
Move the binary point until exactly one `1` is in front of it, and count the moves as the power of 2:

$$
110\,1100\,0000\,0000_2 = 1.1011\times2^{14}
$$

(the point moved 14 places left).

> [!warning] Slide typo
> Slide 14 writes $-0.0000\,0000\,0000\,0001\,1011_2 = -1.1101\times2^{-16}$. Moving the point 16 places right gives $-1.1011\times2^{-16}$. The digits after the point must stay in the same order (1011), so **$-1.1011\times2^{-16}$** is correct.

### 3.3 The three pieces of a floating-point number (slide 15)

| Piece | Meaning | Effect of more bits |
|---|---|---|
| **Sign** (1 bit) | 0 = non-negative, 1 = negative | — |
| **Exponent** | the power of 2 (where the point is) | **more exponent bits → greater range** |
| **Mantissa** (fraction / significand) | the significant digits after the leading 1 | **more mantissa bits → greater accuracy** |

The format is a **fixed-size representation**: 32 bits (single) or 64 bits (double), always with 1 sign bit.

```text
| sign | exponent | mantissa |
```

## 4. Worked example
Write $45.625$ in normalised binary:
1. $45 = 101101_2$; $0.625 = 0.101_2$ (0.625×2 = 1.25 → 1; 0.25×2 = 0.5 → 0; 0.5×2 = 1.0 → 1).
2. $45.625 = 101101.101_2$.
3. Move the point 5 places left: $1.01101101\times2^5$.

This is exactly the lecture's IEEE example ($+101101.101 = +1.01101101\times2^5$), continued in [[01.03 IEEE 754 Single Precision]].

## 5. Practical explanation
The trade-off **range vs accuracy** is why we have both `float` (8-bit exponent, 23-bit mantissa) and `double` (11-bit exponent, 52-bit mantissa). Scientific simulations, matrix solvers and GPU graphics all choose a format by asking "how big/small do my numbers get, and how many correct digits do I need?"

## 6. Important distinctions
| Fixed point | Floating point |
|---|---|
| Point is at a fixed position | Point position is stored in the exponent |
| Small range, constant absolute precision | Huge range, constant **relative** precision |
| Example: money in cents | Example: `float`, `double` |

## 7. Exam-relevant points
- Be able to say: *sign, exponent, mantissa; more exponent bits → range; more mantissa bits → accuracy*. This sentence fits the "difference between single and double" question.
