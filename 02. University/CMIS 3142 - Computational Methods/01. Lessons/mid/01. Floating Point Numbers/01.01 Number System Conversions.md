# 01.01 · Number System Conversions (Binary, Octal, Hexadecimal)

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Lecture slides 10–13 · Assignment 01 · Priority 🟡 Medium
> **Asked as:** "Write a Java program to convert an octal number to hexa-decimal number and vice versa" (2025 Q1(d)). Every IEEE 754 conversion question also depends on this.

## 1. What is it?
A **number system (base / radix)** is a way of writing numbers using a fixed set of digits, where each position is worth a power of the base.

| System | Base | Digits | Example |
|---|---|---|---|
| Binary | 2 | 0, 1 | $1011_2$ |
| Octal | 8 | 0–7 | $17_8$ |
| Decimal | 10 | 0–9 | $15_{10}$ |
| Hexadecimal | 16 | 0–9, A–F (A = 10 … F = 15) | $F_{16}$ |

## 2. Why is it used?
Computers store everything in **binary**. To put a decimal number into IEEE 754 format you must first write it in binary, *including the fractional part*. Octal and hex are short-hand for binary (1 octal digit = 3 bits, 1 hex digit = 4 bits), which is why IEEE 754 patterns are usually written in hex (e.g. `0x3F400000`).

## 3. How does it work?

### 3.1 Binary → decimal (positional value)
Each digit is multiplied by a power of 2. Digits **after the binary point** use negative powers. The lecture's example:

$$
10.01_2 = 1\times2^1 + 0\times2^0 + 0\times2^{-1} + 1\times2^{-2} = 2 + 0 + 0 + 0.25 = 2.25
$$

Compare with decimal: $23.47 = 2\times10^1 + 3\times10^0 + 4\times10^{-1} + 7\times10^{-2}$.

### 3.2 Decimal → binary, integer part (repeated division by 2)
Divide by 2 repeatedly and read the **remainders from bottom to top**.

Example $654_{10}$:

| ÷2 | Quotient | Remainder |
|---|---|---|
| 654 | 327 | 0 |
| 327 | 163 | 1 |
| 163 | 81 | 1 |
| 81 | 40 | 1 |
| 40 | 20 | 0 |
| 20 | 10 | 0 |
| 10 | 5 | 0 |
| 5 | 2 | 1 |
| 2 | 1 | 0 |
| 1 | 0 | 1 |

Reading upwards: $654_{10} = 1010001110_2$.

> [!tip] Faster by hand: subtract powers of 2
> $654 = 512 + 128 + 8 + 4 + 2 = 2^9 + 2^7 + 2^3 + 2^2 + 2^1 \Rightarrow 1010001110_2$.
> Memorise $2^0 \dots 2^{11}$: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024, 2048.

### 3.3 Decimal → binary, fractional part (repeated multiplication by 2)
**Algorithm (lecture slide 11):** *repeatedly multiply the fraction by two until the fraction becomes zero.* The integer part produced at each step (0 or 1) is the next bit, read **top to bottom**.

Example $0.8125$:

| Fraction × 2 | Result | Bit |
|---|---|---|
| 0.8125 × 2 | 1.625 | 1 |
| 0.625 × 2 | 1.25 | 1 |
| 0.25 × 2 | 0.5 | 0 |
| 0.5 × 2 | 1.0 | 1 (fraction now 0 → stop) |

So $0.8125 = 0.1101_2$ (check: $0.5 + 0.25 + 0.0625$).

### 3.4 The "beware" case: finite decimal ≠ finite binary
Lecture slide 12: $0.1_{10}$ never reaches zero:

$0.1 \to 0.2 \to 0.4 \to 0.8 \to 1.6 \to 1.2 \to 0.4 \to 0.8 \to 1.6 \to 1.2 \to \dots$

$$
0.1_{10} = 0.0\overline{0011}_2 = 0.000110011001100\dots_2
$$

The pattern repeats forever, so **0.1 cannot be stored exactly** in any binary floating-point format. *"The more bits, the [closer the] binary representation gets to $0.1_{10}$."* This is the origin of **round-off error** ([[02.02 Round-off and Chopping Errors]]).

### 3.5 Octal ↔ hexadecimal (2025 Q1(d))
The cleanest method goes **through binary** (or through decimal in code):

1. **Octal → binary:** replace each octal digit by its 3-bit group.
2. **Binary → hex:** regroup into 4-bit groups from the right, pad with leading zeros, replace each group by a hex digit.

Example: $752_8$
- $7 \to 111$, $5 \to 101$, $2 \to 010$ ⇒ $111101010_2$
- Regroup in 4s: $0001\ 1110\ 1010$ ⇒ $1EA_{16}$
- Check through decimal: $7\times64 + 5\times8 + 2 = 490 = 1\times256 + 14\times16 + 10$ ✓

Hex → octal is the reverse: 4-bit groups out, 3-bit groups in.

## 4. Java syntax
Assignment 01 asks for these by hand-written algorithms. For the exam, show the algorithm (the examiner wants to see the loops), and optionally mention that Java has built-ins (`Integer.toBinaryString`, `Integer.parseInt(s, 8)`, `Integer.toHexString`).

```java
// Integer part: decimal -> any base (2, 8 or 16) by repeated division
static String toBase(int n, int base) {
    String digits = "0123456789ABCDEF";
    if (n == 0) return "0";
    String result = "";
    while (n > 0) {
        result = digits.charAt(n % base) + result; // remainder becomes next digit (left side)
        n = n / base;
    }
    return result;
}

// Fractional part: decimal fraction -> binary by repeated multiplication
static String fractionToBinary(double f, int maxBits) {
    String bits = "";
    while (f > 0 && bits.length() < maxBits) { // maxBits stops infinite patterns like 0.1
        f = f * 2;
        if (f >= 1) { bits += "1"; f = f - 1; }
        else        { bits += "0"; }
    }
    return bits;
}

// Any base -> decimal (integer) by positional value (Horner's method)
static int toDecimal(String s, int base) {
    String digits = "0123456789ABCDEF";
    int value = 0;
    for (char c : s.toUpperCase().toCharArray())
        value = value * base + digits.indexOf(c);
    return value;
}

// Octal <-> hexadecimal through decimal
static String octalToHex(String oct) { return toBase(toDecimal(oct, 8), 16); }
static String hexToOctal(String hex) { return toBase(toDecimal(hex, 16), 8); }
```

**How the code works:**
- `toBase` is the repeated-division table from 3.2, written as a loop. `n % base` is the remainder; it is placed on the **left** because remainders are read bottom-up.
- `fractionToBinary` is the repeated-multiplication table from 3.4. The `maxBits` limit is essential: without it, `0.1` loops forever.
- `toDecimal` uses Horner's rule: $752_8 = ((7)\times8 + 5)\times8 + 2$.

## 5. Practical use
- Debuggers and memory dumps show floats in hex (`0x3DCCCCCD` for 0.1f).
- File permissions (Unix `chmod 755`) are octal; colours (`#1EA0FF`) and memory addresses are hex.
- Money should not be stored as binary floating point because values like 0.10 are not exact.

## 6. Important distinctions
| Integer part | Fractional part |
|---|---|
| Repeated **division** by 2 | Repeated **multiplication** by 2 |
| Read remainders **bottom → top** | Read integer parts **top → bottom** |
| Always terminates | May **never terminate** (0.1) |

## 7. Exam-relevant points
- Show the working table: examiners give method marks.
- For fractions, state the stopping rule (fraction = 0, or bit limit reached).
- Octal ↔ hex: explain "via binary (3-bit ↔ 4-bit groups)" or "via decimal".
