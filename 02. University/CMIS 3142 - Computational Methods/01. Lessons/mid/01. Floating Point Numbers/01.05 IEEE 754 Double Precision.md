# 01.05 · IEEE 754 Double Precision (64-bit) and Single vs Double

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Lecture slides 22–23, 28 · Priority 🔴 High
> **Asked as:** "Describe the difference between IEEE 754 single precision and double precision" (2023 Q1(b), 4 marks) · "Represent −13.625 in IEEE 754 double-precision format" (2026 Q1(c), 5 marks) · Java decimal → double (2023, 2024, 2026; see [[01.08 Java Programs for IEEE 754]]).

## 1. What is it?
**Double precision** is the 64-bit IEEE 754 format (Java `double`). It works exactly like single precision but with a wider exponent and a much longer fraction.

| Field | Bits | Bit positions |
|---|---|---|
| Sign S | **1** | 63 |
| Exponent E | **11** | 62–52 |
| Fraction F | **52** | 51–0 |

**Normalised rule (slide 23):**
$$
\text{value} = (-1)^S \times 1.F \times 2^{\,E-1023}, \qquad E \neq 00\ldots0\ (0) \text{ and } E \neq 11\ldots1\ (2047)
$$

## 2. Why is it used?
Most scientific and engineering computing needs about 15–16 correct decimal digits and a range far beyond $10^{38}$. Long iterative calculations (Jacobi, Gauss-Seidel, SOR, Cholesky) **accumulate round-off error**, and double precision keeps that error small. It is Java's default type for decimal literals (`3.14` is a `double`).

## 3. How to convert decimal → IEEE 754 double
Same 6 steps as single precision ([[01.03 IEEE 754 Single Precision]]), but:
- bias = **1023**, exponent field = **11 bits**,
- fraction padded to **52 bits**.

### Worked example (2026 Q1(c)): $-13.625$
1. **Sign:** negative → $S = 1$.
2. **Binary:** $13 = 1101_2$; $0.625 \times 2 = 1.25 \to 1$, $0.25\times2 = 0.5 \to 0$, $0.5\times2 = 1.0 \to 1$ ⇒ $0.101_2$. So $13.625 = 1101.101_2$.
3. **Normalise:** $1101.101 = 1.101101\times2^{3}$ → $e = 3$.
4. **Biased exponent:** $E = 3 + 1023 = 1026 = 10000000010_2$ (11 bits).
5. **Fraction:** $F = 101101$ followed by 46 zeros (52 bits).
6. **Result:**

```text
1 | 10000000010 | 1011010000000000000000000000000000000000000000000000
1100 0000 0010 1011 0100 0000 ... 0000  = 0xC02B400000000000
```

> [!tip] Single-precision version of the same number, for comparison
> $E = 3 + 127 = 130 = 10000010$ → `1 10000010 10110100000000000000000` = `0xC15A0000`. Only the exponent width/bias and fraction length change.

## 4. Single vs double precision (2023 Q1(b))

| Feature | Single precision | Double precision |
|---|---|---|
| Total size | 32 bits (4 bytes) | 64 bits (8 bytes) |
| Sign bits | 1 | 1 |
| Exponent bits | 8 | 11 |
| Fraction (mantissa) bits | 23 (+ hidden 1 = 24 bits precision) | 52 (+ hidden 1 = 53 bits precision) |
| Bias | 127 | 1023 |
| Normalised value | $(-1)^S\times1.F\times2^{E-127}$ | $(-1)^S\times1.F\times2^{E-1023}$ |
| Exponent range (normalised) | −126 to +127 | −1022 to +1023 |
| Denormalised value | $(-1)^S\times0.F\times2^{-126}$ | $(-1)^S\times0.F\times2^{-1022}$ |
| Largest normalised | $(2-2^{-23})\times2^{127} \approx 3.4\times10^{38}$ | $(2-2^{-52})\times2^{1023} \approx 1.8\times10^{308}$ |
| Smallest normalised | $2^{-126}\approx1.18\times10^{-38}$ | $2^{-1022}\approx2.2\times10^{-308}$ |
| Smallest denormalised | $2^{-149}\approx1.4\times10^{-45}$ | $2^{-1074}\approx4.9\times10^{-324}$ |
| Decimal digits of accuracy* | about 7 | about 15–16 |
| Java type | `float` | `double` |
| Memory/speed | half the memory, faster | more memory, slower on some hardware |

\*The "about 7 / 15–16 digits" row follows from 24 and 53 bits ($24\log_{10}2 \approx 7.2$, $53\log_{10}2\approx 16$). It is not written on the slides.

**One-sentence answer:** *double precision uses 64 bits (1 sign, 11 exponent, 52 fraction, bias 1023) instead of 32 bits (1, 8, 23, bias 127), so it has a much larger range (more exponent bits) and higher accuracy (more mantissa bits) at the cost of twice the memory.*

## 5. Converting between single and double (2023 Q1(d), 2024 Q1(d))
- **Single → double:** always exact. $e = E_s - 127$; $E_d = e + 1023$; copy the 23 fraction bits and append 29 zeros.
- **Double → single:** may lose information.
  - $E_s = E_d - 1023 + 127$. If $E_s \ge 255$ → **overflow** → ±∞. If $E_s \le 0$ → **underflow** → denormalised or 0.
  - Keep only the first 23 of the 52 fraction bits → **round-off (precision loss)**.
  - Special values carry over: ±0 → ±0, ±∞ → ±∞, NaN → NaN.

Java code: [[01.08 Java Programs for IEEE 754]].

## 6. Practical explanation
- Machine-learning training often uses 32-bit (or even 16-bit) floats to save memory; numerical linear algebra and finance use 64-bit doubles to limit error.
- In this course, use `double` in every Java solver (Gaussian elimination, Cholesky, SOR) unless told otherwise.

## 7. Exam-relevant points
- For "describe the difference", give **at least 4 rows** of the table (size, bits per field, bias, range, precision).
- For conversion, remember **11 exponent bits** and **bias 1023**; the most common slip is using 127.
- 52 fraction bits are tedious: write the significant bits then "followed by 46 zeros".
