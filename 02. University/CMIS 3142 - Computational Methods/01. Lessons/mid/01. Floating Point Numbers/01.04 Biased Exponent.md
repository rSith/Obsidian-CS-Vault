# 01.04 · Biased Exponent and the Hidden 1

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Lecture slides 17–18 · Priority 🟡 Medium
> **Asked as:** "What is meant by biased exponent in IEEE 754 format? Why is bias used?" (2026 Q1(a), **10 marks**).

## 1. What is it?
A **biased exponent** stores the true exponent $e$ as an **unsigned number $E = e + \text{bias}$**. To get the true exponent back you subtract the bias.

Lecture definition (slide 17):
> *"To provide for negative exponents, we will use a biased exponent. A bias is a number that is approximately midway in the range of values expressible by the exponent. We subtract the bias from the value in the exponent to determine its true value."*

| Format | Exponent bits | Range of stored $E$ | Bias | True exponent (normalised) |
|---|---|---|---|---|
| Single | 8 | 0 … 255 | **127** $= 2^{7}-1$ | $E - 127$, from −126 to +127 |
| Double | 11 | 0 … 2047 | **1023** $= 2^{10}-1$ | $E - 1023$, from −1022 to +1023 |

(E = 0 and E = all 1s are reserved for special values, so they are not used by normalised numbers.)

## 2. Why is bias used?
1. **To represent negative exponents without a sign bit or two's complement.** Small numbers like $0.75 = 1.1\times2^{-1}$ need negative exponents. Slide 18: *"Exponent: not two's-complement representation; unsigned interpretation minus bias."*
2. **Easy comparison and sorting.** With a biased (unsigned) exponent, a larger exponent field means a larger number. Two positive floats can be compared **as if they were plain unsigned integers**, bit pattern by bit pattern. This makes comparison hardware simple and fast.
3. **Clean special values.** Zero becomes all 0 bits ($E = 0$, $F = 0$), the smallest possible pattern. The all-ones exponent is free to mark ∞ and NaN.

> [!note] Beyond the slides
> Points 2 and 3 are standard reasons from IEEE 754 practice. The slides give only point 1 explicitly. For a 10-mark answer, give all three.

## 3. How does it work? (worked examples)

**Encoding** $e = -1$ (from $0.75 = 1.1\times2^{-1}$):
$$
E = e + 127 = -1 + 127 = 126 = 01111110_2
$$

**Encoding** $e = 9$ (from $654 = 1.010001110\times2^9$):
$$
E = 9 + 127 = 136 = 10001000_2
$$

**Decoding** $E = 10011010_2 = 154$:
$$
e = 154 - 127 = 27
$$

**Same exponent in double precision:** $e = -1 \Rightarrow E = -1 + 1023 = 1022 = 01111111110_2$.

| True exponent $e$ | Single $E$ (8 bits) | Double $E$ (11 bits) |
|---|---|---|
| −126 | 00000001 | 01110000001 |
| −1 | 01111110 | 01111111110 |
| 0 | 01111111 | 01111111111 |
| +1 | 10000000 | 10000000000 |
| +127 | 11111110 | 10001111110 |

## 4. The hidden 1 (slide 18)
For a **normalised** binary number there is **always a 1 to the left of the binary point** ($1.F$). Since it is always 1, IEEE 754 *"does not waste a bit on this 1"*. It is the **hidden 1** (implicit leading bit). The 23 stored bits give **24 bits of precision** in single precision (53 in double).

The exception is $E = 0$ (and $E = 255$), where the hidden bit is not 1. That is how zero and denormalised numbers are stored ([[01.06 Special Values and Denormalized Numbers]]).

## 5. Practical explanation
Sorting algorithms and databases can sort IEEE floats with integer comparison tricks because of the biased exponent. Hardware comparators for float and int can be shared.

## 6. Important distinctions
| Biased exponent | Two's-complement exponent |
|---|---|
| $E = e + 127$, stored unsigned | negative numbers have leading 1s |
| Larger pattern = larger value → easy compare | Pattern order does not match value order |
| Used by IEEE 754 | Not used for IEEE exponents |

## 7. Exam-relevant points (model answer outline for 10 marks)
1. Definition: stored exponent = true exponent + bias; true = stored − bias.
2. Bias values: 127 (8-bit, single), 1023 (11-bit, double); about midway in the range.
3. Reason: negative exponents without sign bit/two's complement.
4. Reason: comparison of floats like unsigned integers; zero = all zeros.
5. One encode example ($0.75 \to E = 126$) and one decode example.
