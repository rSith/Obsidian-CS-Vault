# 01.03 · IEEE 754 Single Precision (32-bit)

> [!info] [[01.00 Floating Point Numbers|Lesson 1]] · Lecture slides 16–21 · Assignment 2 · Priority 🔴 High
> **Asked as:** convert 654, −456, 512, −128 (2023 Q1(a), 8 marks) · convert 256, 1023, 364 (2025 Q1(c)) · convert IEEE bits → decimal (2026 Q1(b), 10 marks).

## 1. What is it?
**IEEE 754** is the international standard that says exactly how a real number is stored in binary. **Single precision** uses **32 bits** (Java `float`).

## 2. Why is it used?
Before IEEE 754, each computer maker used its own format, so the same program gave different answers on different machines. The standard makes floating-point results **portable and predictable**, and defines special cases (zero, infinity, NaN) so that programs do not crash on them.

## 3. Components (bit layout)

| Field | Symbol | Bits | Bit positions |
|---|---|---|---|
| Sign | S | **1** | 31 |
| Exponent (biased) | E | **8** | 30–23 |
| Fraction (mantissa) | F | **23** | 22–0 |

```text
 S  EEEEEEEE  FFFFFFFFFFFFFFFFFFFFFFF
 1     8                23            = 32 bits
```

**Normalised rule (slide 16):**

$$
\text{value} = (-1)^S \times 1.F \times 2^{\,E-127}, \qquad E \neq 00000000 \text{ and } E \neq 11111111
$$

- $S$: 1 → negative, 0 → non-negative.
- $1.F$: the leading `1` is **not stored** ("hidden 1"), only the bits after the point (F).
- $E-127$: the stored exponent is **biased** by 127 (see [[01.04 Biased Exponent]]).

## 4. How to convert decimal → IEEE 754 single (algorithm)

1. **Sign:** $S = 0$ if the number is positive, $1$ if negative. Work with $|x|$ from now on.
2. **Binary:** convert the integer and fractional parts to binary ([[01.01 Number System Conversions]]).
3. **Normalise:** write as $1.F \times 2^{e}$ (count how many places the point moves; left = positive $e$).
4. **Biased exponent:** $E = e + 127$, written as 8 bits.
5. **Fraction:** $F$ = bits after the point, **padded with zeros on the right** to 23 bits (or rounded if longer).
6. Write $S \mid E \mid F$ and, optionally, group into 4s and convert to hex.

### Reverse: IEEE 754 single → decimal
1. Split into S (1), E (8), F (23).
2. $e = E - 127$.
3. Value $= (-1)^S \times 1.F_2 \times 2^{e}$. Shift the point $e$ places and convert to decimal.

## 5. Worked examples

### Example A (lecture slide 16): $+101101.101_2 = 45.625$
- $S = 0$
- $101101.101 = 1.01101101\times2^5$ → $e = 5$
- $E = 5 + 127 = 132 = 10000100_2$
- $F = 01101101\,000\,0000\,0000\,0000$ (8 bits + 15 zeros = 23)

```text
0 | 10000100 | 01101101000000000000000   = 0x42368000
```

### Example B (slide 19): $0.75$
- $0.75 = 0.11_2 = 1.1\times2^{-1}$ → $F = 1000\ldots0$
- $E - 127 = -1 \Rightarrow E = 126 = 01111110_2$, $S = 0$

```text
0 | 01111110 | 10000000000000000000000
0011 1111 0100 0000 0000 0000 0000 0000 = 0x3F400000
```

### Example C (slide 20): $0.1$ and "why D at the end?"
- $0.1 = 0.0\overline{0011}_2 = 1.\overline{1001}\times2^{-4}$
- $E = 127 - 4 = 123 = 01111011_2$
- The fraction $1001\,1001\,1001\,1001\,1001\,100\,|\,1\,1001\ldots$ is **infinite**. Only 23 bits fit. The bits after the cut start with `1` followed by non-zero bits (more than half of the last place), so IEEE 754 **rounds up** the last bit: $\ldots100 \to \ldots101$.

```text
0 | 01111011 | 10011001100110011001101
0011 1101 1100 1100 1100 1100 1100 1101 = 0x3DCCCCCD
```

The final hex digit is **D (1101)** instead of C (1100) because of **rounding to nearest**. The stored value is therefore slightly *larger* than 0.1: a round-off error ([[02.02 Round-off and Chopping Errors]]).

### Example D (exam 2023 Q1(a)(i)): $654$
- $654 = 1010001110_2 = 1.010001110\times2^9$
- $E = 9 + 127 = 136 = 10001000_2$, $S = 0$
- $F = 010001110$ + 14 zeros

```text
0 | 10001000 | 01000111000000000000000   = 0x44238000
```

### Example E (decoding, exam 2026 Q1(b)(i)): `0 10000010 10100000000000000000000`
- $S = 0$ (positive)
- $E = 10000010_2 = 130 \Rightarrow e = 130 - 127 = 3$
- $1.F = 1.101_2$
- $1.101_2\times2^3 = 1101_2 = 13$

**Answer: $+13.0$**

All the other exam conversions (−456, 512, −128, 256, 1023, 364, and the second 2026 pattern) are worked in [[PP 01 - Floating Point Numbers]].

## 6. Practical explanation
- Java `float`, C `float`, GPU shaders and most machine-learning inference hardware use (or derive from) 32-bit IEEE 754.
- You can check any answer in Java: `Integer.toBinaryString(Float.floatToIntBits(0.75f))` prints the 32-bit pattern (leading zeros dropped).

## 7. Important distinctions
| Normalised (this note) | Denormalised |
|---|---|
| $E$ from 1 to 254 | $E = 0$ |
| Hidden bit is **1** ($1.F$) | Hidden bit is **0** ($0.F$) |
| exponent $E - 127$ | exponent fixed at $-126$ |
See [[01.06 Special Values and Denormalized Numbers]].

## 8. Exam-relevant points
- Show all 6 steps with labels (S, binary, normalised form, $E = e + 127$, F, final pattern). Method marks are given even if one bit is wrong.
- **Powers of 2 are a trap:** $512 = 1.0\times2^9$ so $F$ is **all zeros**; $-128 = -1.0\times2^7$.
- Always pad $F$ on the **right**, never on the left.
- Write the final answer as 32 bits grouped (1 | 8 | 23); hex is a bonus.
