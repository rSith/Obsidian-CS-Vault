## Why this lesson matters
A computer has only a fixed number of bits (32 or 64) to store a real number like $-13.625$ or $0.1$. **Floating-point representation** is the agreed way of packing a real number into those bits. Everything else in the course (error analysis, matrix solvers, iteration) runs on top of floating-point numbers, so their limits (rounding, overflow, underflow) are where computational error starts.

In the exam, **Question 1 has been about IEEE 754 in every paper** (2023, 2024, 2025, 2026). It always mixes three types of sub-question:
1. 🧠 a theory part (difference single/double, bias, denormalised numbers, special values, overflow/underflow, ranges),
2. 🔢 hand conversions (decimal ↔ IEEE 754 bits),
3. 💻 a Java program (decimal → IEEE 754 double is the favourite: 3 papers).

> [!tip] How to study this lesson
> 1. Learn binary conversion of fractions (01.01) until it is automatic.
> 2. Memorise the bit layout table (1/8/23 and 1/11/52) and the two formulas $(-1)^S \times 1.F \times 2^{E-127}$ and $(-1)^S \times 1.F \times 2^{E-1023}$.
> 3. Practise every conversion in [[PP 01 - Floating Point Numbers]] by hand (no calculator was allowed in 2024).
> 4. Write the decimal → double Java program once from memory (01.08).
