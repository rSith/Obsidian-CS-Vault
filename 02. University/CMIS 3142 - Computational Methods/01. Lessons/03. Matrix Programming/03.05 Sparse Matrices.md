# 03.05 · Sparse Matrices and How to Represent Them

> [!info] [[03.00 Matrix Programming|Lesson 3]] · Lecture slides 14–16 · Priority 🟡 Medium
> **Asked as:** "What is to be done to use the above [sparse symmetric] program to do the same for sparse matrices?" (2026 Q2(c), 15 marks) · sparse matrix class in the hierarchy (2024 Q3).

## 1. What is it?
> **A sparse matrix is a matrix in which most of the elements are zero.** (slide 14)

The opposite is a **dense** (full) matrix. There is no exact cut-off; in practice a matrix is treated as sparse when storing only the non-zeros saves memory and time.

## 2. Why is it used?
Large engineering and scientific problems (finite difference grids, circuits, networks, finite element models, recommender systems) give matrices with **millions of rows but only a few non-zeros per row**. In a finite difference grid ([[09.00 Finite Difference Method]]), each node's equation involves only its neighbours, so each row has about 5 non-zeros whatever $n$ is.

| $n$ | Full storage | Sparse (5 non-zeros/row, value + column index) |
|---|---|---|
| 10 000 | $10^8$ doubles ≈ 800 MB | 50 000 × 12 B ≈ 0.6 MB |

Iterative methods (Jacobi, Gauss-Seidel, SOR) are popular for sparse systems because they only need $A$ times a vector, which never touches the zeros ([[05.00 Iterative Methods - Jacobi and Gauss-Seidel]]).

## 3. Representation schemes

### 3.1 Linked-list (orthogonal list) representation (slides 15–16)
The lecture's picture uses two kinds of nodes:

```text
Header node                 Element node
+-------------+             +-----+--------+-------+
| IndexValue  |             | row | column | value |
+------+------+             +-----+--+-----+-------+
| down | right|             | down/up  |   right   |
+------+------+             +----------+-----------+
```

- There is one **header node per row and per column** (H0, H1, H2, … on slide 16). A main header node holds the matrix size.
- Each **non-zero** becomes an element node holding `row`, `column`, `value`.
- `right` links the next non-zero **in the same row**; `down` links the next non-zero **in the same column**. The lists are **circular** (the last node points back to the header).
- **Advantage:** insertions and deletions are cheap; the matrix can grow and change shape.
- **Disadvantage:** each element costs extra memory for pointers, and access needs list traversal.

> [!note] Slide 16 diagram
> The slide shows a 5-row example built this way. The node values in the scanned image are too small to read, so this note describes the structure only.

### 3.2 Triplet (coordinate) representation
Three parallel arrays (or one array of objects): `row[k]`, `col[k]`, `value[k]` for the $k$-th non-zero. Simple to build and to read from a file; used in the `SparseMatrix` class of [[03.04 Abstract Matrix Class and Inheritance]].

$$
\begin{bmatrix}0&0&3\\4&0&0\\0&5&6\end{bmatrix}
\;\Rightarrow\;
\begin{array}{c|cccc} k & 0&1&2&3\\\hline \text{row}&0&1&2&2\\ \text{col}&2&0&1&2\\ \text{value}&3&4&5&6\end{array}
$$

### 3.3 Compressed row storage (row-start array)
Values row by row `a[]`, their column numbers `columnNums[]`, and `rowStart[i]` = where row $i$ begins in `a[]` (with `rowStart[m] = nElements`). For the matrix above: `a = [3, 4, 5, 6]`, `columnNums = [2, 0, 1, 2]`, `rowStart = [0, 1, 2, 4]`.

This is the **general (non-symmetric) version** of the lecture's sparse symmetric scheme (`a`, `diagonal`, `columnNums`, `nElements`), which is covered in [[03.06 Sparse Symmetric Matrices]].

## 4. From sparse symmetric to general sparse (2026 Q2(c))
What must change in the sparse symmetric program:

| Part | Sparse symmetric | General sparse |
|---|---|---|
| Matrix shape | square $n\times n$ | any $m\times n$ (store both sizes) |
| What is stored | **lower triangle only** ($j \le i$) | **every** non-zero, whole row |
| Row boundaries | `diagonal[i]` (diagonal ends each row; diagonal always stored) | `rowStart[i]` array of size $m+1$ (no diagonal assumption; rows may be empty) |
| Reading input | read $j = 0..i$ for each row | read $j = 0..n-1$ for each row (or triplets) |
| `elementAt(i, j)` | if $j > i$ **swap** $i, j$ first | **no swap**: look up row $i$ directly |
| Memory | about half of the general case | stores both $A[i][j]$ and $A[j][i]$ |
| Count non-zeros | off-diagonal values count **twice** | `nElements` exactly |
| Multiply | product not symmetric → full/general result | dimensions must match: $(m\times n)(n\times p)$ |
| Display stored elements | row from `diagonal` | row from `rowStart` |

### Java: general sparse version (tested)
```java
import java.util.Arrays;
import java.util.Scanner;

public class SparseGeneral {
    double[] a;          // non-zero values, row by row
    int[] columnNums;    // column number of each stored value
    int[] rowStart;      // rowStart[i] = position in a[] where row i begins; rowStart[m] = nElements
    int nElements, m, n; // number stored, rows, columns

    void readAndStore(Scanner sc) {
        System.out.print("Rows and columns: ");
        m = sc.nextInt(); n = sc.nextInt();
        a = new double[m * n]; columnNums = new int[m * n]; rowStart = new int[m + 1];
        nElements = 0;
        for (int i = 0; i < m; i++) {
            rowStart[i] = nElements;
            for (int j = 0; j < n; j++) {            // the WHOLE row is read (no symmetry)
                double value = sc.nextDouble();
                if (value != 0) { a[nElements] = value; columnNums[nElements] = j; nElements++; }
            }
        }
        rowStart[m] = nElements;
        a = Arrays.copyOf(a, nElements);
        columnNums = Arrays.copyOf(columnNums, nElements);
    }

    double elementAt(int i, int j) {                 // no swapping of i and j any more
        for (int k = rowStart[i]; k < rowStart[i + 1]; k++)
            if (columnNums[k] == j) return a[k];
        return 0.0;
    }

    void displayFull() {
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) System.out.printf("%8.2f", elementAt(i, j));
            System.out.println();
        }
    }

    double[][] multiply(SparseGeneral B) {           // (m x n)(n x p): only non-zeros of A used
        double[][] C = new double[m][B.n];
        for (int i = 0; i < m; i++)
            for (int k = rowStart[i]; k < rowStart[i + 1]; k++)       // A(i, col) != 0
                for (int j = 0; j < B.n; j++)
                    C[i][j] += a[k] * B.elementAt(columnNums[k], j);
        return C;
    }

    int countNonZeros() { return nElements; }        // every stored value is one non-zero

    public static void main(String[] args) {
        SparseGeneral A = new SparseGeneral();
        A.readAndStore(new Scanner(System.in));
        A.displayFull();
        System.out.println("non-zeros = " + A.countNonZeros());
        for (double[] r : A.multiply(A)) System.out.println(Arrays.toString(r));
    }
}
```

Sample input `3 3 / 0 0 3 / 4 0 0 / 0 5 6` gives `non-zeros = 4` and $A^2$ = `[0, 15, 18] [0, 0, 12] [20, 30, 36]`.

## 5. Important distinctions
| Linked list | Arrays (triplet / compressed row) |
|---|---|
| dynamic: easy insert/delete | fixed after building; insert is costly |
| pointer overhead per element | compact |
| traversal to access | fast row access (compressed row) |

| Sparse | Dense (full) |
|---|---|
| mostly zeros | mostly non-zeros |
| store non-zeros + positions | store everything |
| iterative solvers preferred | direct solvers (GE, Cholesky) fine |
