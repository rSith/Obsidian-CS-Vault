# 02.03 · Machine Precision and Round-off in Arithmetic

> [!info] [[02.00 Error Analysis|Lesson 2]] · Lecture slides 11–13 · Priority 🟢 Low (not asked directly; the accumulation idea is needed for every GPA question)

## 1. Machine precision (slide 11)

**In simple words:** machine precision (also called **unit round-off**, written $\varepsilon_{\text{mach}}$) is the **largest possible relative error** made when a real number is stored as the nearest floating-point number.

**Lecture definition:** let $fl$ be a floating-point number system. The unit round-off or machine precision $\varepsilon_{\text{mach}}$ is the real number that satisfies
$$
\left|\frac{fl(x) - x}{x}\right| \le \varepsilon_{\text{mach}}
$$
for any real number $x$ such that $\text{UFL} < x < \text{OFL}$.

- $fl(x)$ = the floating-point number actually stored for $x$.
- UFL = underflow level (smallest positive normalised number), OFL = overflow level (largest number). Outside that range, overflow/underflow happens instead ([[01.07 Ranges, Overflow and Underflow]]).

### Values for IEEE 754
With $p$ bits of precision (24 for single, 53 for double):

| | Rounding to nearest | Chopping |
|---|---|---|
| $\varepsilon_{\text{mach}}$ | $2^{-p}$ | $2^{-(p-1)}$ |
| Single ($p = 24$) | $2^{-24}\approx5.96\times10^{-8}$ | $2^{-23}\approx1.19\times10^{-7}$ |
| Double ($p = 53$) | $2^{-53}\approx1.11\times10^{-16}$ | $2^{-52}\approx2.22\times10^{-16}$ |

> [!note] Beyond the slides
> The slide gives only the definition. The numeric values above come from standard numerical analysis. Some books (and Java's `Math.ulp(1.0)` $= 2^{-52}$) call the gap between 1 and the next float "machine epsilon", which is twice the rounding unit round-off. Either is accepted if you state which one you mean.

**Meaning:** a `double` keeps about 16 significant decimal digits; a `float` about 7.

## 2. Round-off errors with arithmetic manipulations (slide 12)
Round-off error happens not only when storing numbers but also during calculations:

- **Large computations:** if a process performs a **large number of computations**, round-off errors may **build up** to become significant. Each operation adds a tiny error of up to $\varepsilon_{\text{mach}}$ relative; after millions of operations these can add up.

## 3. Adding a large and a small number (slide 13)
Before adding, the computer must line up the exponents, so the small number's mantissa is **shifted right** to the large number's scale and its digits fall off the end.

Example: add $0.001 + 4000$ with a **4-digit mantissa** and 1-digit exponent:
$$
4\times10^{3} + 0.000001\times10^{3} = 4.000001\times10^{3} \;\to\; 4.000\times10^{3}
$$
The $0.001$ is **completely lost**. Doing this many times (e.g. adding 0.001 to 4000 a thousand times) gives 4000 instead of 4001.

> [!tip] Practical fix
> Add small numbers together **first**, then add the large one; or keep more digits (double). The same idea solves the GPA problem: **keep full precision until the final step**.

## 4. Related effects (not on the slides)
- **Subtractive cancellation:** subtracting two nearly equal numbers loses significant digits (e.g. $1.23456 - 1.23455 = 0.00001$ has only 1 significant digit left).
- **Accumulation in loops:** `for (double t = 0; t != 1.0; t += 0.1)` never stops, because 0.1 is not exact ([[01.01 Number System Conversions]]).
